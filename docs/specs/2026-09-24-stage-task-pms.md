# 正式版本节点任务与 Feature PM 分层

- 状态：实现并通过门禁；待下一个正式版本实跑验证用量与返工
- 负责人：主 Agent（工作流控制面）
- 创建日期：2026-09-24
- 最后更新：2026-09-24
- 架构决定：[ADR-0021](../adr/0021-版本节点任务与PM分层.md)

## 问题

一个阶段 PM 接收多个不同成果，导致上下文、失败恢复和提交规模放大。独立任务拆分与排期节点又提前拆了 Feature PM 应自行决定的内部步骤。多 PM 若沿用现有完整门禁合同，会对中间树重复跑全量并失效。

## 范围与非目标

建立一个版本的逻辑 Version PM、每节点零到多个交付任务、每项任务一个 Feature PM，以及任务级交接、串行写入、独立审查、集成树完整门禁和历史兼容。维持策划对制作人隐含意图的既有对齐门禁。

本次不改变游戏产品、核心语义或大版本发布；不自动创建下一个正式版本；不开放共享工作区内多写进程；不以模型降级替代流程优化。

## 用户流程

制作人给出方向，秘书查重并启动正式版本。Version PM 在节点开始时建立有界任务合同并由秘书按依赖逐一派发。Feature PM 自行拆内部步骤，交付一项成果与证据并提交。Version PM 汇总验收节点，秘书通知并推进。开发成果集成后在最终树运行完整门禁，独立 QA 与制作人门禁照常进行。

## 验收标准

- [x] 新正式版本看板不出现独立任务拆分、版本排期节点；旧归档版本保持可读。
- [x] 一个节点可有多个稳定任务，每项由不同 Feature PM 运行与独立提交；一个任务可含多个内部执行任务。
- [x] 任务合同包含范围、交付物、验收、依赖、来源修订和写入范围；不能越过制作人或设计审核门禁。
- [x] 同时仅有一个写进程，实际路径越界或多个活写进程阻断；只读审查不修改产品实现。
- [x] 前驱只传有限、带来源的结论；过期输入重新核对，不重新注入整版原始记录。
- [x] 执行 Agent 不跑全量门禁；同一最终树只有一份有效 `verify:full`，QA 和 pre-push 复用；任何相关变化使其失效。
- [x] 多任务、异常恢复、范围变更、QA 缺陷、候选退回和旧版兼容均可在测试中复现。
- [x] 中枢可区分节点、任务、Feature PM、执行 Agent 与各自证据和用量。

## 验证计划

单元与集成测试覆盖状态迁移、合同校验、派发顺序、占用、门禁指纹和恢复；E2E 检查中枢层级与待办；在可运行宿主执行 `npm run verify:full` 并实际操作项目中枢。记录版本/任务 Agent 调用与 token、重复文件读取、同树全量门禁、审查退回和返工；质量优先，不能把未知用量记为零。

本次通过合成状态和真实浏览器验证新版看板、任务详情、旧节点移除与历史兼容；真实多 PM 运行及成本对照须在下一次由制作人立项的正式版本中观察，不能把合成验收当作生产实跑。
