# 同时释放多个法术

- 状态：已实现
- 负责人：Codex
- 创建日期：2026-09-13
- 最后更新：2026-09-13

## 问题

演武场当前只允许每个实体存在一个施法实例。玩家按下另一个已绑定槽位时会被直接拒绝，无法组合持续、引导与即时法术，也无法检验多法术共同消耗资源的效果。

## 目标

- 玩家可以通过不同槽位同时释放多个法术。
- 并发法术共享同一份当前法力和神识上限，不复制资源。
- 演武场能清楚显示当前并发数量、各法术进度与总神识占用。
- 玩家和妖兽继续使用同一套施法管线。

## 非目标

- 本次不移除或重做冷却。
- 本次不增加法术优先级、队列、主动取消键或自动资源抢占。
- 本次不实施动态距离计价、统一实体或元法术五大类重构。

## 用户流程

1. 玩家在推演台编写并验证至少两个法术。
2. 玩家进入演武场，把两个法术绑定到不同槽位并开始演武。
3. 第一个法术仍在执行时按下第二个槽位；两个法术同时推进并显示在 HUD 中。
4. 两个法术的元法术调用从同一法力池扣费，变量从同一神识池占用。
5. 资源不足时只让争用失败的施法走火入魔；受击时全部可打断法术结束。
6. 玩家暂停、继续、重开或返回推演台修改，再重复测试。

## 验收标准

- [x] 不同槽位可以各自启动一个施法实例，并同时保持活跃。
- [x] 同一槽位在其施法结束前不能再次启动。
- [x] 并发 VM 的实时神识占用总和不超过实体神识上限，结束或打断后占用归还。
- [x] 并发 VM 从同一当前法力池原子扣费，法力不会因延迟结算而透支。
- [x] 受击打断所有可打断实例，并按实例记录打断数。
- [x] 移动减速采用活跃施法中的最严格倍率。
- [x] HUD 显示总神识占用与所有活跃施法的独立进度。
- [x] 暂停冻结全部实例；重开清空实例、输入和共享资源账户。

## 技术方案

采用 [`../adr/0007-并发施法与共享资源账户.md`](../adr/0007-并发施法与共享资源账户.md) 的语义。VM 通过可选资源钩子向战斗层申请法力和神识；未提供钩子时继续按单次推演的本地预算运行。

战斗层按 `actorId → slot → CastInstance` 持有实例，通过统一查询和删除方法维护资源释放，避免 UI、渲染器或测试依赖内部容器形状。

## 验证计划

- 单元/集成：不同槽位并发、同槽位拒绝、共享法力、共享神识、资源归还、批量打断和移动减速。
- E2E：在演武场连续触发两个不同槽位，观察多个施法状态同时出现。
- 手工体验路径与视口：桌面与窄屏下完成“绑定两个长法术 → 同时触发 → 暂停/继续 → 受击或重开”。
