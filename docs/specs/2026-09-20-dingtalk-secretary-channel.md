# 钉钉常驻秘书通道

- 状态：已完成，等待平台凭据联调
- 负责人：Codex
- 创建日期：2026-09-20

## 问题

手机版 Sites 在 ChatGPT 内嵌浏览器中存在布局和交互兼容问题，外部移动网络访问 `chatgpt.site` 还会遇到 TLS 路由失败。制作人真正需要的是随时向常驻秘书发送自然语言、接收进度简报并处理少量决策，而不是在手机上操作完整桌面看板。

## 目标

- 将通讯入口定义为秘书内核之外的 Channel/View，不让钉钉 SDK 进入状态机、版本流程或调度器。
- 使用钉钉 Stream 模式接收制作人自然语言，不要求电脑暴露公网端口。
- 将秘书答复、任务完成、阻塞和待办事件发送回钉钉。
- 校验制作人身份、去重平台重投消息，并保持凭据只存在于环境变量。
- notice guard 空闲时仍不调用模型；钉钉长连接只承担事件唤醒。

## 非目标

- 本轮不开发钉钉小程序或复制完整项目中枢。
- 本轮不把 Sites 改为公开站点，也不继续投入其手机交互适配。
- 本轮不允许任意钉钉用户触发项目调度。
- 本轮不把钉钉会话记录作为项目真相；项目状态仍以 `.daoyan-agent/secretary/` 为准。

## 设计

1. `secretary-channel` 定义平台无关的入站、通知与通道生命周期接口。
2. notice guard 只负责登记入站消息和发布结构化通知，不感知钉钉消息格式。
3. `dingtalk-secretary-channel` 使用官方 Stream SDK，把文本消息转换为统一入站消息；答复优先使用消息携带的会话回调，异步项目事件通过机器人单聊接口主动通知制作人。
4. 通道通过发送者白名单、平台消息 ID 和已有收件箱 ID 保证授权与幂等。
5. 未配置钉钉凭据时通道不启动，不影响 CLI、HTTP、网页或其他 webhook。
6. 通知先进入持久 outbox，离线通道仍保留为待发目标并按失败通道重试；原会话回复失败时降级为机器人主动通知，外部网络等待受硬超时约束。
7. 本机收件监听优先启动，通道连接和历史 outbox 恢复在后台进行，外部积压不能阻塞秘书接收新消息。
8. inbox 重启恢复会识别已提交的秘书状态和版本评审来源，不会重复排期或重复推进版本阶段。

## 验收标准

- [x] 通讯通道接口不依赖钉钉 SDK，notice guard 状态机也不导入钉钉类型。
- [x] 钉钉凭据完整时 Stream 通道随 notice guard 启动并在停止时释放连接。
- [x] 未授权发送者被忽略，重复平台消息只入队一次。
- [x] 授权文本消息进入现有自然语言收件流程，不要求消息类型或命令参数。
- [x] 秘书答复可回到原钉钉会话，异步任务事件可发送到配置的通知会话。
- [x] 未配置或断开的钉钉通道不影响本机秘书和任务执行。
- [x] 单元、集成和完整门禁通过，部署步骤与凭据边界有长期文档。
