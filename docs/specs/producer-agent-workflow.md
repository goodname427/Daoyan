# 制作人到秘书的 Agent 调度

- 状态：已实现
- 负责人：Codex
- 创建日期：2026-09-13
- 最后更新：2026-09-13

## 问题

制作人只负责产品方向，却需要额外判断任务复杂度和选择模型；所有工作默认使用最强模型又会浪费 token。现有开发门禁没有负责自动分析、分派、升级和汇总的秘书层。

## 目标

- 制作人可以只用产品语言提交方向或问题。
- 秘书自动生成可校验的任务合同，选择不同模型并处理失败升级。
- 执行结果经过固定完整门禁和独立审查后才允许提交推送。
- 新会话、失败执行和模型配置变化都有稳定恢复入口。

## 非目标

- 第一版不并行修改多个 worktree。
- 不建立基于历史 token 数据的机器学习路由器。
- 不让模型生成的任意 shell 命令被调度器直接执行。
- 不自动决定大版本发布。

## 用户流程

1. 制作人在 Codex 主任务中描述方向，不选择模型或拆分方式。
2. 秘书读取项目事实，形成目标、验收标准、非目标和任务依赖。
3. 秘书按风险分配模型，执行者顺序完成任务；失败时自动升级。
4. 调度器运行 `npm run verify:full`，独立审查者检查完整差异。
5. 发现问题时自动修复并重新验证；通过后形成提交并推送。
6. 秘书实际体验受影响路径，只向制作人汇报结果和真正需要的产品决策。

## 验收标准

- [x] `producer:plan` 能只读生成并校验结构化计划。
- [x] 完整入口要求干净工作区，并按计划依赖顺序调用配置模型。
- [x] 任务失败、门禁失败和审查失败有次数受限的自动升级或修复。
- [x] 完整门禁与独立审查通过前不会自动提交。
- [x] 成功后自动 Conventional Commit 和推送，网络失败时仅临时使用项目代理。
- [x] 本地运行记录可恢复且不会进入 Git。
- [x] 路由、依赖排序、计划校验和提交信息回退有单元测试。

## 技术方案

采用 [`../adr/0008-制作人秘书与异构模型调度.md`](../adr/0008-制作人秘书与异构模型调度.md) 的单一入口设计。

`agents/policy.json` 保存模型和运行上限；两个 JSON Schema 约束可选深度规划与审查输出。`scripts/agent-dispatcher.ts` 默认用本地风险规则建立零-token 计划，再通过 `codex exec` 使用工作区执行者和只读审查者；`--deep-plan` 才调用低成本规划模型。纯路由和校验逻辑位于 `scripts/agent-routing.ts`，可在不调用模型的情况下测试。

## 验证计划

- 单元：策略校验、计划依赖、循环拒绝、模型升级和提交信息。
- 集成：CLI 帮助、只读 `producer:plan` 实际调用和脏工作区保护。
- 交付：`npm run verify:full`。
- 手工体验：在 Codex 主任务中只给产品方向，确认秘书不要求制作人选择模型。
