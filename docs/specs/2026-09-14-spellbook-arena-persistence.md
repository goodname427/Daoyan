# 法术书与演武配置持久化

- 状态：已完成；完整交付门禁通过
- 日期：2026-09-14

## 问题

刷新应用或关闭桌面端后，玩家的法术书、演武属性和槽位绑定都会回到默认值；也无法把一套可用配置带到另一台设备或在升级前自行备份。

## 目标

- 自动恢复最近一份可用的法术书与演武配置。
- 从界面导出带版本号的 JSON 存档，并可导入恢复。
- 存档格式演进时能迁移无版本的 v0 数据；对损坏、无法解析或来自未来版本的数据安全拒绝并提示原因。

## 非目标

- 云同步、多存档槽位、跨设备自动同步与跨会话编辑历史。
- 保存编辑器中暂时无法解析的 DSL 草稿。
- 改变核心 AST、DSL、资源、战斗或蓝图执行语义。

## 用户流程

1. 玩家在推演台修改有效法术，或在演武场调整属性和槽位绑定；应用自动写入本地存档。
2. 刷新或重启后，应用读取同一份存档，推演台和演武场继续使用它。
3. 玩家点击“导出存档”得到 JSON；在另一实例点击“导入存档”并选择该文件，验证后立即恢复共享状态。
4. 损坏、含无效法术书或来自未来版本的文件不会覆盖当前状态，界面显示导入失败原因。

## 验收标准

- [x] 可观察到有效法术书、属性与绑定在刷新后恢复。
- [x] 可从界面导出和导入一份版本化 JSON 存档。
- [x] 无版本 v0 数据迁移为 v1，并以默认值补全后来新增的演武设置。
- [x] 损坏、无效或未来版本存档不会覆盖当前状态，且给出可理解的失败信息。
- [x] 自动保存不写入编辑过程中的无效 DSL，避免把下一次启动变成坏存档。
- [x] 启动时拒绝未来版本本地存档后，不会用默认配置覆盖原始存档；玩家后续有效修改仍可保存。
- [x] 即使导入法术书与当前内容相同，已打开的演武 Battle 也会立即采用导入的属性和槽位绑定。
- [x] 导入属性必须满足演武场控件的合法范围；越界数据会被拒绝，不会进入 Battle 或改变资源消耗语义。

## 技术方案

- `src/app/persistence.ts` 是唯一浏览器存储边界，保存 `{ version, spellSource, arenaAttrs, arenaBindings }`；核心和游戏层不接触 `localStorage`、文件或下载 API。
- `App` 仍是法术书与演武配置的单一所有者：启动时从该边界读取，状态变更后保存，导入通过同一验证/迁移函数再替换共享状态。
- 当前写入 schema 为 v1；缺少 `version` 的旧形状按 v0 处理。属性和绑定做安全的增量补全，法术书必须经既有 `parseSpellbook` 验证。演武属性范围由 UI 与持久化边界共享同一契约；任何已给出的属性值越界都会拒绝整份存档，避免非法资源或施法语义进入战斗。

## 验证计划

- 单元：编码/解码往返、v0 迁移、损坏法术书和未来版本拒绝，以及负法力倍率、非正施法速度和超上限属性等恶意导入拒绝。
- E2E：导出、刷新恢复、导入成功与失败提示，以及同源法术书导入后已运行 Battle 的属性/施法绑定同步，已纳入并通过完整交付门禁。
- 手工：推演台编辑 → 演武场配置 → 刷新恢复；导出 → 导入 → 检查两页共享状态。
- 结果：早期受限执行环境曾在启动 Vite/`esbuild` 子进程时遇到 `spawn EPERM`，该环境限制不属于产品缺陷；后续父进程已在可执行环境成功完成 `npm run verify:full` 完整交付门禁。
