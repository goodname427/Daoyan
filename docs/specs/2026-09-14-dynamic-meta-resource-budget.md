# 动态元法术资源预算纵向切片

- 状态：已实现，待 Feature PM 完整门禁与独立审查
- 日期：2026-09-14

## 问题与玩家价值

旧动态价格依赖寿命、速度、威力等人为最大值，超出后同价或失败；距离与实体关系又无法在只看 AST 时形成可信的有限全局上界。玩家既不能持续投入资源换取更大效果，也容易把界面中的基础数字误读成保证足够的上界。

本切片让有限效果请求持续增加法力与施法时间，并让分析器诚实显示“已知预算 + 动态”，同时用一个 `设置位置(entity, vec2)` 入口验证 Actor 与 Projectile 的统一 Transform 控制和关系计价。

## 范围

- 元法术以同一 `cost` 契约结算法力与 tick。
- 迁移现有感知、实体创建、实体控制和属性控制中受效果、距离或关系影响的调用。
- 静态分析传播直接已知参数；分支与循环不确定写入保守标记为动态。
- 推演台、蓝图、演武场和生成参考不再把动态预算显示为有限上界。
- 保留旧 `manaCost` 外部扩展的兼容上界检查。

## 非目标

- 不加入神识强度、控制抗性或随机成功率。
- 不实现指定场景的精确预算预览。
- 不改动冷却、法术生命周期、并发施法或通用 ECS 存储。
- 不改变每位所有者最多 16 个 Projectile 的数量约束。

## 验收标准

- [x] 有限的寿命、速度、威力、伤害、距离、持续时间与倍率请求不再被旧最大值截断，法力和 tick 随请求增加。
- [x] VM 在效果前结算动态法力与 tick，非法或仍含未知项的运行时价格不扣费、不产生效果。
- [x] 分析器对可解析参数给出固定预算，对运行时参数、目标状态和分支不确定值显示动态预算。
- [x] `设置位置` 可经同一能力语义控制 Actor 与 Projectile，自有、友方、敌方关系影响法力与 tick。
- [x] 并发施法继续从同一当前法力池扣费，既有弹道生命周期与所有权失败语义无回归。
- [x] 聚焦核心、实体和战斗测试通过，`npm run verify` 已按本轮约定执行。
- [ ] `npm run verify:full`、真实浏览器体验与独立 Agent 审查由 Feature PM 统一完成。

## 技术约束

- 采用 [ADR 0011](../adr/0011-无界效果与动态资源预算.md)；不改变 AST，也不让 `src/core/` 依赖 UI。
- `manaBudget.dynamic=false` / `tickBudget.dynamic=false` 才允许称为静态上界；兼容字段 `manaWorst` / `tickWorst` 在动态时只代表已知部分。
- 所有运行时 tick 必须是有限非负整数，法力必须是有限非负数。
