# 正式版本生命周期与可视化秘书

- 状态：候选版本，等待制作人体验
- 负责人：Codex
- 创建日期：2026-09-20
- 最后更新：2026-09-20

## 问题

当前所谓“版本”只是多个 Feature 的顺序运行。制作人无法看到从方向到策划、开发、测试和体验的完整进度，也无法在同一界面查看节点证据、自己的待办并与常驻秘书交流。

## 目标

- 建立可恢复、可归档的正式版本状态机。
- 区分正式版本、开发批次、Feature 和发布。
- 展示当前阶段、全部节点、任务完成情况、Bug 和制作人待办。
- 节点可进入详情，查看摘要、责任人、时间和仓库证据。
- 在状态页直接向现有常驻秘书发送自然语言消息并看到近期对话。
- 保持 notice guard 空闲零模型消耗。

## 非目标

- 本轮不接入公网或特定聊天平台。
- 本轮不让网页直接审批、改状态或写策划文档；制作人仍通过自然语言回复秘书。
- 本轮不改变游戏推演台和演武场。
- 本轮不自动发布大版本。

## 用户流程

1. 制作人打开可视化秘书。
2. 首屏看到当前正式版本、当前环节、总体进度和自己的待办。
3. 点击流程节点，查看负责人、状态、摘要、时间和对应文档或运行证据。
4. 查看 Feature、任务、缺陷与近期完成记录。
5. 在对话区直接提出方向、询问状态或回复待办。
6. 消息进入同一个 notice guard；页面刷新后显示秘书答复和状态变化。

## 验收标准

- [x] 正式版本包含固定阶段、节点状态、审批、待办、任务和缺陷结构。
- [x] 非法阶段跳转会被拒绝；被驳回的制作人评审会回到对应撰写阶段。
- [x] notice guard 提供本机状态页、状态 API 与对话提交 API。
- [x] 状态页在桌面和窄屏下无横向溢出，当前环节和制作人待办位于首屏。
- [x] 每个阶段节点都可打开详情；存在文档证据时可以阅读。
- [x] 对话提交后能看到发送状态，并最终出现在秘书近期对话中。
- [x] 看板不产生轮询模型调用；浏览器只轮询本机结构化状态。
- [x] 旧开发批次明确降级为内部能力，正式版本文档和工作流完成迁移。
- [x] 单元测试覆盖生命周期、审批回环和公开状态；E2E 覆盖看板主路径与对话。

## 风险

- notice guard 可能已由旧代码启动，看板首次部署需要重启一次守卫。
- 浏览器状态页只能访问显式允许的版本文档，不能成为任意文件读取入口。
- 运行状态位于 Git 忽略目录，长期结论必须同步到 `docs/versions/`。
