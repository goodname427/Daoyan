## 问题、范围与非目标

当前消息意图、正式版本、PM 恢复和公开活动已有各自实现，但新方向去向、阶段风险依据、全队列恢复对账与独立测试结论还缺少共同合同。旧恢复记录可能使已交付工作重复派发，待审结果也容易被误读为正式版本验收通过。

目标是让制作人通过自然语言得到确定、可审计、跨重启一致的版本去向，并让内部执行可按风险缩减而不绕过审批和验收。本规格只约束本版本已批准的内核范围，不重新规划项目。本纵向切片不启动生产秘书、不迁移 `.daoyan-agent/` 现场，也不改变游戏运行时。

非目标：游戏玩法/DSL/资源/存档变更、聊天平台替换、工作台布局重做、自动发布、空闲轮询或从路线图自行立项。风险等级不是制作人要选择的选项。

本执行任务只交付架构决策与迁移边界：保留并核对现场相关代码及测试，补齐 ADR、规格和长期文档，不承担整个版本的实现或生产迁移。设计验收以不变量核对、状态所有权、兼容映射、可回退条件和证据缺口明确为准；运行验收、独立审查与制作人体验仍按下文版本合同执行。已采纳 ADR 不等于版本已验收。

## 用户流程与意图去向

1. 消息经过现有统一收件入口，按稳定请求 ID 去重。先关联当前等待事项和对话，再判断问题、方向、回复或继续；保留原输入、判断来源与公开理由。
2. 确认方向后查重并读取正式版本事实；下表中的“活动版本”包含 drafting、running、waiting-producer 和 paused，不能把暂停版本当作不存在。
3. 持久保存去向与版本修订后才答复；重放请求返回原结果，不重复建版本、并入范围、审批或通知。
4. 已批准的内部工作经过对账后自动推进；到达固定门禁时给制作人具体产物，取得该轮有效回复后继续。

| 输入与状态                     | 可观察结果                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| 新方向，无活动版本             | 自动建立草案并关联来源消息，产出策划后进入立项评审；不自动批准开发                     |
| 新方向，活动版本未冻结         | 若在已批准目标内则并入、更新范围修订与风险；若改变承诺则进入重新评审，不能沿用过期批准 |
| 新方向，活动版本已冻结         | 写入下一版本候选并告知去向；只有制作人明确改变当前承诺才能进入范围变更评审             |
| 已完成或已排期的同一方向       | 答复或关联现有工作，不重复立项                                                         |
| “现在做到哪一步了？”、状态查询 | 只答复事实，不创建版本或工作项                                                         |
| “采用兼容方案”、明确评审回复   | 只关联对应待办、版本和文档修订；无明确目标或过期时保留待确认，不建版本                 |
| “继续”                         | 对账后恢复已批准工作；没有可执行事项则说明空状态，不创造任务或批准门禁                 |
| 模糊消息、模型不可用、事实冲突 | 保存输入，保守答复/待确认；不默认当作新方向或批准                                      |
| 当前版本归档后仍有候选         | 保留候选并休眠，等制作人方向与立项批准，不自行开启下一正式版本                         |

本版本方向已获得制作人批准，不重新请求相同批准。接入已有版本时保留真实批准及来源证据；不能由迁移器根据“正在开发”倒推批准记录。

尚未首次立项评审的草案可以吸收相关方向，统一提交该草案修订评审。冻结前的“并入”不自动扩大已批准承诺；范围修订与审批文档修订分开记录，只有确实改变审批内容时才使原批准失效。

### 风险与阶段策略

风险至少记录等级（low/medium/high/critical）、影响范围、状态迁移、跨进程并发、外部依赖、可回退性、评估者、时间、依据、策略修订。模型路由等级不是风险事实本身。无法判断时采用完整执行；本内核因涉及持久状态和跨进程恢复，基线为 high，不自动降级。

每阶段策略记录 stage、mode（execute/reduced/skip）、reason、evidence、decidedBy、decidedAt、policyRevision、适用范围修订；选择理由和最终执行结果分开保存。重启复用既有决策，范围或风险改变时追加新修订而非覆盖旧理由。

| 阶段 / 条件                    | 允许的自适应边界                                                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 方向、版本策划                 | 可以合并文档篇幅，不能缺目标、范围、非目标和可观察验收                                                                     |
| 立项评审、最终制作人体验       | 必须执行，保留角色、文档修订、评审轮次与来源消息；策略 skip 必须被拒绝                                                     |
| 不可逆决策、主策升级的详细策划 | 作为阻塞门禁持久化，制作人批准前不能执行相关动作；不必新增顶层阶段                                                         |
| 详细策划与主策审核             | 低风险且现有规格足够时可缩减；没有独立模块策划时可标记无需执行，并记录复用证据                                             |
| 拆分、排期、开发               | 拆分同时提交机器可读工作项与依赖；可缩减任务数量；没有对应工作时可标记无需执行，实际存在工作时不能跳过依赖、范围与交付证据 |
| QA                             | 可按影响面调整深度；没有可测试运行时变化时可标记无需执行，策略要求执行时仍须独立验收、必要集成/回归和版本完整门禁          |
| 缺陷修复                       | 无待修缺陷时可 skip，并引用独立 QA 的无缺陷结论；有缺陷则必须修复复验                                                      |
| 候选构建                       | 无需新增体验产物且已有可复现入口时可标记无需执行；否则须提供构建、测试报告、版本说明、风险和候选标识                       |
| 归档                           | 必须保存审批、测试、缺陷与候选证据；不可把 review-ready 自动归档                                                           |

保留现有相邻阶段推进约束；无需执行要显式记录为 skipped，不能由推进函数覆盖为 completed，也不进入版本进度分母。方向记录、版本策划、制作人立项评审、制作人体验和归档不可跳过。失效审批、未解决阻塞缺陷或执行策略缺少必需证据时，推进必须失败且不产生部分状态更新。

### 启动与恢复对账

对账对象为所有 active、tracking、retry-wait 项及活动指针引用项；按稳定 itemId 与 runDirectory/运行轮次关联快照，补充发现有明确归属的运行。扫描运行证据不等于扫描仓库路线图。

顺序为：恢复未完成事务 → 校验状态和证据归属 → 判定该轮次快照 → 核实 PM/子 Agent 身份 → 保存全体对账结果 → 重建活动指针及定时器 → 再选可运行项。文件时间或裸 PID 都不足以证明归属；旧快照不能覆盖新的执行轮次。发现多个活跃写进程或无法确认旧进程归属时停止新增派发并公开阻塞，不自行终止未知进程。

| 对账证据                           | 处理                                                                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 本轮 `delivered`                   | 队列项停止派发，清空该项 retryAt、进程引用和恢复计数；保留报告和历史尝试证据                                                |
| 本轮 `review-ready`                | 兼容旧队列可投影为 delivered，但扩展结果必须明确 awaiting-review；不重跑开发，正式版本停在实际测试/审批节点，不伪造正式交付 |
| 本轮 `waiting-producer`            | 清理重试时间，保留/恢复对应待办，不自动继续                                                                                 |
| 真实 PM 或子 Agent 仍运行          | 挂接跟踪，不重新启动；待审快照也不能允许另一写进程与其重叠                                                                  |
| 可恢复失败且已确认执行进程退出     | 按持久重试策略恢复；外部访问阻塞保留明确恢复条件                                                                            |
| 快照丢失、损坏、互相冲突或未知版本 | 保留现场并阻塞相关派发；不能当成新工作，也不能因 retryAt 到期强行启动                                                       |

清理活动指针仅在其仍引用该项时执行；所有项处理完再统一计算定时器，不能让清理 A 的陈旧恢复状态取消 B 的真实恢复。回放同一快照不重复完成通知、不重置完成时间或重试倒计时。

终态快照和存活进程同时出现时，先取消开发重试，但保留独立的进程占用记录及退出监听；确认写进程退出后才清除进程引用并放行其他任务。终态结果优先于旧失败快照，进程占用约束始终优先于新派发。

### 测试职责与缺陷闭环

Feature Agent 保留 `npm run typecheck` 与定向测试，自测记录必须关联真实工作项、执行身份、代码修订和公开证据；阶段放行只采信每个工作项在当前范围的最后一条记录，后续失败不得由历史通过掩盖。本执行任务另按当前合同运行 `npm run verify`；版本级测试职责下沉完成前，不因本规格提前删除现有门禁。独立测试 Agent 和实现者使用不同运行身份，该约束不因代码修订变化而失效；通过报告必须关联代码修订、验收项、至少一条退出码为 0 的命令与公开证据。关键产物独立审查仍按 ADR-0013 执行。

缺陷沿 `open → fixing → verify → closed`，复验失败回到 open/fixing；关闭只能由独立测试结果驱动。阻塞/高风险未解决缺陷不能生成可验收候选，deferred 必须有公开依据与责任人，不能用来隐去阻塞。修复后使受影响的旧测试结论失效，测试 Agent 完成复验与必要回归后才收束。

进入 fixing 生成新的 `fixAttemptId`；提交 verify 时通过 `transitionVersionBug` 的代码修订参数保存 `fixCodeRevision`。独立 QA 的 `bugFixes` 显式列出已复验缺陷及修复轮次，登记时校验缺陷处于 verify 且代码修订一致；关闭时再次核对轮次、代码修订、当前范围、独立身份、成功结果和复验 suite。closed → open 以及 verify → fixing 都使上一轮证据失效。旧 v1 未绑定记录继续可读，不推造修复轮次或复验；旧 verify 缺陷须重新进入 fixing、提交修订并重新测试。

缺陷修复和缺陷复验是同一顶层节点内的两个持久步骤。第一步由开发 Agent 修改代码并将缺陷送入 verify；第二步必须新建独立测试事项，只消费待复验缺陷且不修改产品实现。测试事项完成后，以实际测试过的候选修订登记 QA 并逐项关闭缺陷，两个步骤不能复用同一事项或执行身份。

所有内部阶段都必须提供 `<documentRoot>/<stage>.md`，不得回退引用 charter 或 `docs/status.md` 冒充本阶段产物。主策审核、开发、QA、缺陷修复与复验另有机器可读 JSON 合同；阶段运行本身的 `report.status=已交付` 和代码审查 pass 只证明任务执行成功，不能替代这些产品结论。开发结果逐项匹配正式 work item；QA 的 passed/failed、测试命令和 bugs 清单相互一致；修复与复验逐项匹配当前缺陷及修复轮次。测试角色若修改 `docs/` 外文件，结果拒绝写入并回到自动修复，而不是改写候选修订掩盖漂移。

决策待办使用可选 `decisionGateId`，看板按门禁调用 `resolveDecisionGate`，阶段评审待办继续使用 `recordApproval`，二者不相互消费或代为推进。对话决议在门禁的 `resolutionHistory` 中绑定请求 ID、结论和时间；写入门禁后发生中断时，重放只恢复该请求原结果。旧待办按阶段、摘要、创建时间唯一匹配迁移，重复迁移不变，歧义拒绝自动写入。被拒绝的不可逆决策及升级策划仍阻断推进，并产生关联原门禁的重新审批待办；同一门禁取得新的明确批准后才解除，其他决策不能使其恢复运行。拒绝范围增量不阻止按原承诺继续。

### 公开日志

允许事件类别为 input、plan/progress、action、file、test、error、decision、blocker、usage；只接收显式公开结构化字段。计划只描述将执行/已完成步骤，决策只描述结论和公开依据；禁止采集私有推理字段、隐藏思维链或完整原始模型流，不能仅靠关键词过滤后公开。

测试事件保留命令、范围、退出码和脱敏错误摘要，文件使用仓库相对路径；凭据、通道秘密和无关本机信息不写入公共事件。历史原始日志不迁入、不读取，也不按关键词推断公开内容；缺失历史公开事件标记不可用。同一日志写入在进程内串行化，事件持久去重并分配单调序号、按游标读取；看板重连能续读，并把事件与当前心跳、恢复点中的明确调度状态合并，避免首次门禁事件遮蔽后续审查或修复进度；截断展示不等于删除审计历史。时间由服务端记录并校准；token 记录已知输入/输出/总量与来源，未知为 null，累计按运行去重，不推算隐藏 token。

## 迁移、兼容与回退合同

1. 仅在实际配置的秘书状态根、正式版本状态根及关联运行目录实施；支持现有环境变量覆盖，不触碰游戏存档。先暂停新派发并确认所有写进程静止；保留消息入箱或暂停入口，不能在切换时丢消息。
2. 以迁移 ID 备份秘书状态/收件/答复/事件/outbox、releases/current 与历史快照、未完成事务、关联恢复点和报告，记录路径、源格式、哈希和迁移时间。备份不得包含通道环境凭据。不可只备份 current.json。
3. 先验证快照及待恢复事务中的 v1 信封和新增扩展版本，再完成合法的现有事务恢复。损坏或未来格式返回显式错误并保留原字节，不使用“读取失败即空状态”的默认路径。
4. v1 缺扩展时生成保守完整阶段策略与迁移来源，历史执行依据标记 legacy-unknown。ID、时间、scopeFrozen、charterRevision、审批及其 sourceRequestId、完成节点键、收件关联和 outbox 去重键原样保留；不倒推历史风险或补造批准。
5. 先预览差异再原子提交，迁移标记与数据一并落盘。中断重启可重放，第二次迁移不得追加重复策略、审批或通知；归档历史保持只读语义，不能回到运行队列。
6. 对全队列对账，清理已交付/待审项陈旧恢复，检查强制门禁和单写者后才开启新调度。迁移结果本身不能让版本跨过门禁。
7. 降级前再次停写并备份新状态。没有新增事实时恢复完整旧快照；存在新增事实时必须由降级工具保留输入、审批、交付与去重记录，将扩展另存只读证据，并将不可表达的未完成项阻塞，禁止简单删除扩展继续运行旧程序。工具未实现或投影不安全时，只能暂停运行并保持新状态。

### 读取副作用与中断恢复边界

`readFormalVersion` 在读取 current 前调用事务恢复；`listFormalVersions` 和 `readFormalVersionById` 也走该入口。有效待写事务会重写 current/历史并删除事务文件。因此备份工具必须先复制原始文件，不能先调用这些函数探测生产数据。current 不存在时还有 `docs/versions/current.json` 种子回退；迁移清单必须标明实际来源，不能把运行目录缺失误判为没有版本。两个 normalizer 都会修改传入对象，预览在副本上进行，失败后丢弃内存结果并保留原文件。

下表是迁移工具和收束演练必须满足的合同，尚未全部由现有自动化证明。当前锁与 rename 保证的范围不能扩大解释成秘书、正式版本和通知的跨目录事务。

| 中断位置                                  | 重启时允许的恢复                       | 必须保留的证据与限制                                               |
| ----------------------------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| 备份/校验/预览期间                        | 保持原状态；校验整组副本后才能提交     | 根路径、源文件哈希、格式、事务及引用关系；无有效清单不得覆盖生产   |
| 正式版本事务已写，历史或 current 尚未写完 | 在锁内先校验事务，再完成两文件恢复     | 异常事务保留三个文件原字节；有效旧事务不能补造批准或重新激活归档   |
| pending intake 已写，正式版本尚未写       | 按原 requestId、目标版本和预期去向重放 | 目标已切换且原操作未落盘时阻塞，不能重新计算去向覆盖新版本         |
| 正式版本已写，收件完成记录/答复尚未写     | 用原请求的范围修订或决议恢复原结果     | 不重复范围、批准或候选；不得消费另一个门禁；补答复与通知须单独验证 |
| 通知已送达，发送结果尚未持久化            | 沿用 outbox 重试及稳定关联键           | 业务操作幂等；外部通知允许至少一次投递的重复，不能承诺恰好一次     |
| 迁移后产生新消息、审批或运行结果          | 停写后保留增量并做安全降级投影         | 恢复迁移前快照会丢事实，禁止直接还原；无安全工具时保持暂停         |

迁移工具的输入校验必须区分“字段缺失”与“字段存在但损坏”，核对 ID 唯一性、待办/门禁、收件/目标版本、QA/修复轮次以及 current/历史/事务的关联；现有部分字段校验不能替代这一放行条件。校验失败既不能当空状态立项，也不能保存已部分规范化的对象。归档状态只允许既有一致性修复，不倒推补造历史审批或测试。

### 迁移清单与数据来源核验

以下是迁移工具的放行合同，不表示当前 normalizer 已实现整组校验。本次架构复核不修改生产状态或扩展信封。

| 核验项           | 代码事实与迁移要求                                                                                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行状态与种子   | `readFormalVersion` 在运行 `current.json` 不存在时读取仓库 `docs/versions/current.json`；仅设置 `DAOYAN_RELEASE_STATE_DIR` 不能隔离种子。清单必须记录仓库根、两个实际状态根、种子路径/哈希及每个源文件是否存在。隔离演练使用隔离仓库根与种子副本，关联运行目录也须复制并在演练副本中显式映射，不能沿绝对引用访问生产运行。 |
| 扩展缺失与损坏   | 两个 normalizer 已按自有属性是否存在区分旧数据和损坏扩展：仅字段确实缺失才允许补扩展，显式 `null`、`false`、`0` 或非法对象会停止自动写入和派发。迁移预览仍必须在写入前对原始属性做同样校验并保留原字节，不能依赖规范化后的默认值。                                                                                         |
| 多份版本事实     | `listFormalVersions` 对同 ID 按 `updatedAt` 选择投影，不能用该结果替代 current、历史和事务原文的核验。清单需保留各自 `stateRevision`、版本 ID、阶段、归档标记与哈希；只有合法待写事务支持的中间状态才能自动恢复，其余冲突保留现场并停止迁移，不以时间较新作为批准或交付证据。                                              |
| 归档一致性修复   | 现有 `normalizeFormalVersion` 会把非归档阶段上的 `status: archived` 修正为运行/待审，也会补齐归档阶段的节点。迁移预览必须显式列出这些变化并核对审批、运行终态及归档证据；未消歧前不开放派发，不能把修复后的 running 当作重新开发的授权。                                                                                   |
| 文件存在性与回退 | 备份清单同时记录不存在的文件；无新增事实的回退必须恢复文件集合，不能只复制旧文件而留下升级新建的 current、历史或事务。仅处理清单锚定且哈希匹配的迁移产物，出现其他增量立即转入保留增量分支，不递归清空状态目录；恢复后再次核验种子选择和全部引用。                                                                         |

公开日志的串行队列只在单个进程、同一路径键内生效，没有跨进程日志锁。恢复前单写者检查必须包括旧 PM、执行 Agent 和日志写者；不能凭并发追加单元测试批准两个进程同时写同一 `public-events.jsonl`。这些限制不改变状态所有者或固定产品门禁。

### 回退判定与验收证据

| 停写后的事实                                          | 允许的回退动作                                                   | 恢复调度前的判定                                                                            |
| ----------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 迁移后没有任何新增输入、审批、事件或运行结果          | 核对迁移清单哈希后整组恢复备份，连同事务和去重记录一起恢复       | 版本/事项 ID、冻结、审批、完成节点、outbox 与原清单一致；先全队列对账，不直接恢复旧定时器   |
| 已产生新增事实且可安全表达为旧格式                    | 降级工具保留增量和只读扩展证据；将旧格式无法执行的项转为持久阻塞 | 所有新增事实有对应记录或证据引用，固定门禁未失效，已交付/待审项无陈旧重试，重复执行无新通知 |
| 未来/损坏格式、未知进程归属、缺少降级工具或投影有歧义 | 保持暂停及原文件，输出公开阻塞与恢复条件                         | 未解决前不得启动旧写者，也不得把异常状态视为空状态重新立项                                  |

由秘书收束时保存迁移 ID、源/目标格式、根目录、文件清单及哈希、预览差异、演练命令/退出码、对账结果和回退结果。迁移验收至少覆盖：旧 v1 重复规范化不变；未知扩展事务拒绝时三个文件字节不变；收件各提交点中断重放无重复副作用；迁移后新输入/批准/交付在降级中不丢失；归档历史与待审运行不重新入队。现有 `test/version-lifecycle.test.ts` 已覆盖普通事务恢复、扩展幂等、嵌套损坏和未来事务三文件原字节保留，`test/secretary-state.test.ts` 覆盖缺扩展、未来版本与嵌套损坏拒绝；这些用例不能代替尚未执行的全提交点故障注入与生产降级演练。
