# 元法术与统一实体 vNext 核心纵向切片

- 状态：已实现并通过完整门禁与秘书体验验收
- 负责人：执行 Agent
- 创建日期：2026-09-13
- 最后更新：2026-09-13

## 问题

玩家目前只能用 `发射` 一次性生成固定行为的 Projectile；`entity` 句柄不能引用它，也无法组合创建、配置、激活和探查。旧元法术分组与真实 I/O 职责不一致，固定价格也让距离与请求强度没有代价。

## 目标

- 固化元法术分类、统一句柄、能力判定、失败语义和动态价格上界。
- 让一个默认法术实际走通“创建 Projectile → 控制 → 激活 → 可探查”的完整链路。
- 保留现有 Actor、旧法术和战斗主流程兼容。

## 非目标

- 不把 Actor 全量迁移为通用 ECS，也不一次性迁移所有旧元法术。
- 不加入神识强度、伤害类型、友方/敌方强制控制或场景估价界面。
- 不移除冷却，不改变按键触发与并发施法规则。
- 不持久化实体或法术书。

## 用户流程

1. 玩家在推演台查看按职责重组后的元法术目录，动态价格显示为“法≤上界”。
2. 玩家编写或选择“御剑·手动”，创建有限寿命的弹道并获得 `entity` 句柄。
3. 法术设置该句柄对应弹道的方向、速度和威力，然后激活。
4. 同一句柄可交给 `实体存在` 与 `探查`；进入演武场后弹道按配置移动并正常命中。
5. 创建数超限、句柄失效、能力不符、非所有者控制或参数越界时，调用返回 `空`/`false`，不产生越权或部分修改。

## 验收标准

- [x] Actor 与 Projectile 句柄不会重号，且可由统一查询解析。
- [x] DSL 能创建、配置、激活并探查 Projectile，默认“御剑·手动”使用新链路。
- [x] 未激活 Projectile 不移动、不碰撞、不渲染，但仍过期并占用每所有者 16 个的上限。
- [x] 弹道控制仅允许所有者，能力或参数不匹配返回 `false` 且目标不变。
- [x] 创建失败返回 `空`；失效句柄可用 `实体存在` 判断。
- [x] 动态价格按距离或请求效果变化，VM 拒绝超过注册静态上界的定价。
- [x] 静态分析继续使用动态元法术的最坏价格，聚焦测试验证实扣不高于上界。
- [x] 旧 `发射` 和现有 Actor 用户流程保持可用。

## 技术方案

- [ADR 0009](../adr/0009-统一实体句柄与能力判定.md) 定义统一句柄、能力、分类、所有权与失败。
- [ADR 0010](../adr/0010-动态元法术价格与静态上界.md) 定义请求效果、动态价格和静态契约。
- `World` 使用单一实体 ID 计数器并提供统一/能力查询；现有 Actor 专用 API 保留。
- Projectile 使用 `active` 区分配置期和运行期。新元法术只修改所有者的 Projectile。
- `MetaDef.mana` 是静态基础上界，可选 `manaCost` 给出运行时基础价；分析器无需复制公式。

## 验证计划

- 单元/集成：统一句柄、完整 DSL 链路、能力/所有权失败、创建上限、动态实扣与静态上界、现有战斗回归。
- E2E：沿用推演台目录、单次推演、法术绑定和演武场弹道主路径。
- 手工体验路径与视口：推演台查看动态上界并推演“御剑·手动”；演武场绑定后发射，观察弹道创建、飞行与命中。
