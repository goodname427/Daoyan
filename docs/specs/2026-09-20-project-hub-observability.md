# 项目中枢可观测性与操作效率

- 状态：已完成
- 负责人：Codex
- 创建日期：2026-09-20
- 最后更新：2026-09-20

## 问题

当前项目中枢只能看到版本节点的抽象状态，无法判断是否真的有 Agent 在执行、执行到哪一步或为什么暂停。版本归档节点存在终态不一致，节点只能打开一份文档，页面采用长瀑布布局，制作人待办也只能阅读，不能直接采用秘书建议。

## 目标

- 如实展示当前执行中、休眠、等待和暂停的 Agent 数量与类型。
- Agent 详情展示任务输入、结构化计划、模型、阶段、进程、耗时、运行目录、错误和近期输出。
- 正式版本归档后立即进入 100% 完成态，并保留可切换的版本快照。
- 每个节点展示全部关联文档，同时提供整个版本档案入口。
- 桌面端采用固定视口三栏工作台，各区域独立滚动，避免整页瀑布。
- 制作人待办提供推荐默认方案和备选方案，可在中枢直接确认。
- 当前额度阻塞任务显示为等待而不是执行中，并可自动等待额度恢复后重试。

## 非目标

- 不展示模型私有推理或隐藏思维过程；“上下文”仅指任务输入、结构化计划和可审计输出。
- 不在本轮接入公网、账号体系或聊天平台。
- 不允许历史版本上的操作修改当前项目状态。
- 不修改游戏玩法。

## 用户流程

1. 制作人打开项目中枢，从版本选择器选择当前或历史正式版本。
2. 首屏看到版本概要、真实 Agent 运行数量和需要处理的待办。
3. 点击 Agent 查看任务、模型、当前阶段、上下文、错误和近期输出。
4. 点击版本节点，从关联文档列表中切换阅读，也可查看该版本全部档案。
5. 对待办直接采用秘书推荐方案，或选择其他方案并确认。
6. 在同一工作台继续与秘书交流，不需要滚动到页面底部。

## 验收标准

- [x] 归档版本节点为已完成，版本进度为 100%，秘书不会继续显示“正在归档”。
- [x] 每次正式版本写入均保存按版本 ID 命名的快照，API 可列出并读取历史版本。
- [x] 版本选择器切换后，流程、文档、任务和缺陷同步切换；历史版本只读。
- [x] Agent 区区分运行、休眠、等待、暂停和完成，运行数量只统计真实存活的执行进程。
- [x] Agent 详情包含可审计上下文和输出，不暴露模型私有推理。
- [x] 节点支持多文档，且只有该版本明确关联的仓库文档可以被读取。
- [x] 桌面端在常见视口中无整页纵向滚动，三栏区域内部滚动；窄屏仍可完整使用。
- [x] 待办支持推荐方案一键执行和备选方案确认；历史版本不提供操作。
- [x] 当前额度阻塞任务可计划自动重试，并在页面明确展示重试时间。
- [x] 单元、接口与 Playwright E2E 覆盖归档、版本切换、Agent 详情、多文档和待办操作。

## 风险

- 旧运行记录格式不完全一致，Agent 详情必须允许字段缺失并明确标注未知。
- 日志可能很长，接口只能返回截断后的近期输出，页面不得一次加载整个日志。
- 版本快照位于 Git 忽略的运行目录，长期结论仍以 `docs/versions/` 为准。
