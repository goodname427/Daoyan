# ADR 0008：开发采用制作人到秘书的单一入口与异构模型调度

- 状态：已采纳
- 日期：2026-09-13

## 背景

制作人负责产品方向而不直接参与代码开发。要求制作人判断任务复杂度、选择模型、拆分实现和追踪测试，既转移了错误的责任，也会导致所有任务默认使用最强模型，产生不必要的 token 消耗。

Codex 可以用不同模型启动独立执行，但原生同一 Agent 树不能完整承担异构模型路由、项目门禁、Git 收束和失败升级。项目需要一个稳定的仓库级秘书层。

## 决策

1. 制作人只向当前主 Agent 提供方向、反馈与产品决策；主 Agent 是秘书和最终交付负责人。
2. 秘书把自然语言方向转换为结构化任务合同，自动确定验收标准、非目标、依赖和风险层级。
3. 模型不由制作人选择。任务按 `economy → standard → advanced → critical` 路由，失败时逐级升级。
4. 不为使用多 Agent 而拆分；能够由一个常规模型可靠完成的纵向切片保持单任务。
5. 第一版执行者按依赖顺序共享一个开始时干净的工作区；执行者不得 commit、push、tag，统一由秘书在门禁和独立审查通过后处理。
6. 调度计划和审查使用 JSON Schema 约束；调度器只执行仓库固定门禁，不执行模型在计划中生成的任意命令。
7. 自动修复和升级有明确次数上限。超过上限时保留报告并停止，不能无限消耗。
8. 只有产品方向冲突、不可逆选择、大版本发布或缺失外部权限时才询问制作人。

## 理由

- 单一入口让制作人能够持续用产品语言工作，不需要学习工程组织结构。
- 风险驱动的逐级升级比按任务名称静态猜测更可靠，也避免简单任务占用最强模型。
- 顺序交接牺牲部分速度，但避免多个 Agent 在共享状态和同一文件上产生难以审查的冲突。
- 固定门禁与独立审查把“Agent 说完成了”转换为仓库可以验证的交付事实。

## 后果

- 新会话必须先读取 `AGENTS.md`，默认接管秘书职责。
- 仓库新增 `agents/` 策略与 Schema、`scripts/agent-dispatcher.ts` 和本地运行记录目录。
- 模型变化只需更新策略文件；计划合同和工作流不依赖具体模型名称。
- 后续若引入并行 worktree、token 计量或远程任务队列，应扩展本 ADR，不得绕过干净工作区、门禁和最终责任人规则。
