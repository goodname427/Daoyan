# ADR 0010：请求效果采用动态价格并保留静态上界

- 状态：已被 [ADR 0011](./0011-无界效果与动态资源预算.md) 部分取代
- 日期：2026-09-13

## 背景

固定元法术价格不能表达距离、请求强度、目标抗性和实体关系。同一价格下，威力 1 与威力 100、近处探查与跨场探查没有资源差异；但若只在运行时任意计价，静态分析就无法继续承诺可信上界。

> 2026-09-14 起，有限效果请求不再依赖人为输入上限，分析器改为显式的动态预算。本文保留首次纵向切片的历史决策；当前契约以 ADR 0011 为准。

## 决策

1. 强度类元法术统一采用“请求效果”语义：玩家传入想达到的速度、威力、距离或持续时间，系统据此计算法力。不会把同一个数在不同元法术中有时解释为效果、有时解释为投入法力。
2. 每个动态元法术同时声明：
   - `mana`：受支持输入域内的静态基础法力上界；
   - `manaCost(ctx, args)`：本次运行时基础价格。
     VM 要求运行时价格是有限非负数且不超过 `mana`；定义违反契约时终止施法，而不是静默低报。
3. 动态参数必须有系统定义的有限输入域。越界请求按领域失败处理，不产生效果；本次尝试已发生的世界 I/O 成本不退。当前 Projectile 纵切明确限制寿命、速度和基础威力。
4. 静态分析继续把 `mana` 累加为法术的全局基础上界；运行时与指定场景展示实际价格。已知施法者时，场景法力上界和实扣还要乘其有效 `manaCostMul`。
5. 距离、关系、请求强度和以后加入的抗性只能改变确定性价格或可达阈值，不引入随机成功率。神识强度若加入，必须与“神识上限”分开命名；它可影响探查/控制成本和最大可达范围，但不影响变量空间。
6. 自身状态、自己创建的实体、友方和敌方可以使用不同价格曲线；所有权折扣必须由元法术显式定义，不能由对象种类隐式猜测。
7. `castSpeed` 仍只把 tick 映射为真实时间，`manaCostMul` 仍只影响法力。动态 tick 可在后续用同样的上界契约引入，本阶段不把两种倍率混用。

## 理由

- “请求效果”最接近玩家写程序时的直觉，法术源码能直接表达预期结果。
- 注册时上界与运行时价格分离，既允许场景差异，又保护“静态上界不得低于实测”的核心不变量。
- 有限输入域把不可分析的无界强度变成显式规则，也能在蓝图和参考文档中展示。
- 确定性对抗比随机失败更适合调试、复现和优化法术。

## 后果

- 固定价格元法术无需迁移；没有 `manaCost` 时 `mana` 仍是固定实扣。
- `探查` 已按施法者到目标的距离结算，基础价格不超过 12；弹道寿命、速度和威力按请求值结算。
- 元法术参考和界面用“≤”标识动态静态上界。分析器当前显示基础上界；带属性与目标数据的场景估价仍是后续增强。
- 动态价格实现必须增加“实扣不超过静态上界”的测试，外部元法术同样受 VM 契约保护。
