# ADR 0003：TypeScript + 无引擎 + Electron 打包

- 状态：已采纳
- 日期：2026-09-12

## 背景

用户要求：

1. 不使用 Unity / Godot 这类现成游戏引擎，偏好轻量框架
2. 项目以「全 AI 开发」为主，技术栈要对 AI 友好
3. 最终要能打包成 exe 交给别人直接使用，而不是发源码让人自己编译

## 决策

| 层面     | 选择                        | 理由                                                      |
| -------- | --------------------------- | --------------------------------------------------------- |
| 语言     | TypeScript（strict）        | 类型即文档，静态检查能挡住大部分错误；对 AI 最友好        |
| 核心逻辑 | 纯 TS，零 UI 依赖           | 可在 Node 下无头运行与测试，AI 能在终端验证正确性         |
| 渲染     | Canvas2D → 后期 PixiJS      | 只是库不是引擎；前期够用，粒子量上来再换 WebGL            |
| 节点编辑 | React Flow（后期）          | 成熟，产出的是数据而非绑定引擎                            |
| 桌面外壳 | Electron → 可换 Tauri       | 纯 JS 工具链最稳；Tauri 体积小但要装 Rust，等游戏跑通再换 |
| 测试     | Vitest（environment: node） | 与 Vite 同源，无需额外配置                                |

## 理由

- **AI 友好优先于一切**：核心可在终端无头验证，是最重要的一条。
  如果核心逻辑必须开浏览器才能测，AI 的迭代速度会断崖式下降。
- **打包不绑架架构**：核心与 UI 完全解耦，最后套一层外壳即可，
  随时可以从 Electron 换成 Tauri 或其它方案。

## 后果

- `src/core/` 严禁 import 任何浏览器 API 或 UI 框架，由 lint 与 tests（node 环境）共同约束
- 打包方案推迟到游戏可玩之后再定，现在不引入 Rust 工具链
- 若 Electron 二进制下载在本机受限，退路是把 `dist/` 静态产物 + 本地 HTTP 服务打包
