## 问题、范围与验收

当前角色按输入直接改坐标，弹道按方向、标量速度和固定伤害飞行；创建费用没有可审计的储能去向。直接改速度、改位置、重复穿透命中以及最低伤害保底都可能绕过新版本的运动来源和能量限额。

本项固定实际速度与驱动上限、惯性与基础移动功率、弹道分池储能、碰撞伤害、传送、旧弹道迁移及回退。验收是明确覆盖旧 ADR 的冲突条款，给出可计算锚点、失败边界与后续测试要求。非目标是实现物理或账本、重做项目排期、引入完整刚体引擎、开放任意动能转换、采纳另两项属性/探查与事件/执行上下文 ADR，或生成开发阶段总报告。

## 决策一：实际运动由核心效果与积分产生

每个具备运动能力的实体声明有限二维 `velocity`（世界单位/秒）、非负有限 `speedMax`（主动驱动速率上限，0 禁止主动提速）、阻力参数、运动来源和授权账户。`position`、显示朝向和 `velocity` 是三个独立状态；读取朝向或设置朝向不能改变速度向量。相同能力组合在 Actor、Projectile 和合成实体上走同一合同，不在通用执行器中按实体种类选择免费路径。

输入和 AI 只提交目标运动意图；已付冲量一次改变速度，持续驱动在已付覆盖区间内施加力。降低 `speedMax` 不裁剪已有速度；超出上限时禁止继续增加超限方向的主动速度，只允许减速或不增速的转向。提高上限不自动加速，修改上限本身也不注入能量。失去授权、眩晕或供能不足停止主动驱动，已有速度继续按阻力、碰撞和寿命积分；主动制动/转向也必须有授权和费用。

核心按模拟时间推进，并在输入变化、0.25 秒结算、寿命、控制到期和碰撞时刻分段，不能按渲染帧数扣费。相同意图时间线在小步或大步推进下须得到相同结算次数和容差内的轨迹。暂停不推进积分、补给或费用；自然积分与碰撞检测不为玩家新增逐帧 DSL 调用或 VM tick。

首版物理锚点如下，作为可测试的初始参数，而非已体验的结论：

- 角色原型线性阻力 `lambda = 20 / 秒`。无驱动时 `v(t+h) = v(t) × exp(-20h)`，位移为 `v(t) × (1-exp(-20h))/20`；静止不自行移动。
- 有普通移动授权时，目标向量 `u = 归一化意图 × 有效 speedMax × 施法减速系数`，以 `dv/dt = 20 × (u-v)` 趋近；超限情形先限制主动分量，再应用同一阻力。施法减速只影响驱动目标，不抹掉惯性。零输入撤销驱动。
- 弹道原型默认 `lambda = 0`：一次已付冲量后匀速滑行，不逐帧扣法力；有限寿命仍限制飞行距离。其他阻力必须由原型显式声明，不能因欠费临时增加阻力。
- 首版碰撞采用耗散规则，不引入反弹增能或实体间动能转移。阻挡边界去掉朝障碍内的速度法向分量，切向保留；重叠修正只作最小分离，不增加速度。耗散记损耗，不能成为另一实体的储能。弹道出界/过期清理，命中按下文处理；高速路径须作扫掠检测并按接触时刻、稳定实体 ID 排序，不能跳过中途目标。

普通移动的体验边界：保持原基础移动速率、斜向归一化、施法减速、玩家/妖兽共用规则和场地边界；新增起停惯性是本版本已批准变化，不声称逐帧等价。正常余额下，从静止持续驱动 0.15 秒达到目标速率的约 95%；松开后 0.15 秒降至约 5%，剩余总滑行距离不超过松开速率的 `1/20`（基础速率 140 时为 7 世界单位）。30/60/120 Hz、施法中移动和近边界走位都须在后续体验中检查。若需突破此边界，先修订本合同并记录体验理由，不能通过恢复直接坐标写入绕过。

## 决策二：基础移动使用独立的世界功率账户

普通角色移动不消耗施法法力，但必须消耗世界授予的运动功率。该能力由原型授予；玩家与妖兽规则相同，Projectile 默认没有。单位为不可兑换的 `Wm`，不得与法力或下面的 `E` 相加。

| 参数           | 采纳值与规则                                                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 容量与初始余额 | 容量 `4 Wm`，新世界创建角色时余额 `4 Wm`；重新施法、切页、重新取得句柄不重置                                                                                                 |
| 补给           | 每模拟秒 `4 Wm`，封顶 4；暂停、死亡/失去该能力时不补给，不累计离线时间                                                                                                       |
| 基准           | `s0` 为创建时未受控制层影响的基础移动速率，在本次世界内固定；仅 `s0 > 0` 时授予基础驱动，原基础速率 0 仍允许静止实体存在、不计算除法；提高上限不能抬高补给或凭空取得基础驱动 |
| 驱动功率       | `P = 4 × max(1, (                                                                                                                                                            | u   | /s0)^2) Wm/秒`，只在有非零驱动意图时消费；未使用不收费 |
| 结算           | 依 ADR 0017 每 0.25 秒效果前原子预付 `P × 0.25`；有限尾段仍预付一周期，提前撤销不退；同源更新先付新周期，不复用旧款                                                          |
| 不足           | 不发布该周期主动驱动，惯性保留；下一合法周期可重新尝试，不能靠每帧重试获得部分免费驱动                                                                                       |

基础速率持续移动每周期花 1、补 1，能够长期走位；静止最多存一秒基础驱动所需功率。两倍目标速率每周期花 4，仅靠基础账户不能持续，后续超额驱动需显式付费运动效果，不能因一个上限倍率免费获得持续额外功率。普通移动不新增玩家 VM tick；其世界授权、补给、预付和余额必须可审计，状态容量有界。临时转向或按键变化造成的新预付亦受余额约束，不能无限免费刷新。

世界功率不能转成法力、注能、退款、扫描或伤害；由其产生的运动及碰撞也不能间接灌入可兑换账户。基础账户不接受法球提款，不随所有权变化转给另一实体。授权日志由核心保有有界摘要，不能为每渲染帧无限追加记录。

## 决策三：创建、注能与运动储能分账

创建费是正价世界 I/O，不算储能。新弹道建立 `motion/damage/scan` 三个独立非负余额（单位 `E`），每笔注入绑定稳定的 `effectId/entityId/payerId/sessionId`、模拟时刻、源账户、池、损耗、退款受益人和交易序号。池容量与行为额度必须显式、有界；余额不足或超容量整笔拒绝，不能静默截断付款后仍声称足额供能。只有经过授权的原子扣款才能增加余额，不能根据 `damage` 或初速度事后补造付款。

本版换算锚点为 `1 法力 -> 0.8 E + 0.2 E 转换损耗`；三池均如此，注能不可享受法力折扣。释放伤害采用 `1 E -> 最多 1 点减伤前伤害`。这些是游戏计量单位，不是现实焦耳。创建费、控制费与 VM tick 另计，分析和实扣必须共用注册价格规则；不能在 Battle 或 UI 复制价格。普通世界操作的合法折扣不产生可退储能。跨池直接转账本版拒绝，避免同一单位同时支持运动和命中；后续开放转换须另行声明转换费与损耗。

运动锚点：取弹道标准速率 `sRef = 380`，等效动能 `K(v) = |v|² / sRef² E`。冲量把 `v` 变成 `vNext` 时，预先从 motion 扣除 `max(0, K(vNext)-K(v)) + |vNext-v|²/sRef²`；前项为做功，后项为不可逆操控损耗。减速释放的旧动能也记耗散、不退回余额。因而从静止到 380 需要 2 E，反向到 -380 需要 4 E，即使速率不变也不能免费转向。算术溢出或无法给出有限费用时拒绝，不封顶价格后照常发布效果。

`K` 是已做功的物理状态，不能同时记作未使用 motion 余额或可退款资产。本版不允许把它再次转入任何池，故账本累计“已做功”不因物理阻力降低而回退；物理耗散只在运动子账中细分，不能在总式中把同一份已做功又加一次损耗。

三种法球模式统一消费此合同：

1. **一次冲量**：创建或冲量事务先付运动费用再发布速度；之后只积分，无持续法力费用。
2. **持续推进**：每 0.25 秒先从 motion 预留该周期有限驱动计划的费用上界，再发布推力。连续驱动加速度为 `a` 时，按功率 `max(0, 2 × v·a / sRef²) + 0.25 × |a|²/sRef²` 在模拟时间上积分，分别记做功和操控损耗；阻力不计入 a，不能把连续效果按渲染子步反复套用瞬时冲量的平方项，否则费用随帧率改变。未做功预留在周期结束回到原池，不能提前被退款或并发消费；超出预留额的计划必须重新预付，不得透支。耗尽停止主动推力，不能自动清零速度。
3. **追踪**：每周期先支付 scan 读取费用，再以获准快照制定并预付转向/推进计划。首版一次主动扫描至少耗 `1 E`，复杂扫描还须按统一价格增加法力/tick 或能量成本。scan 不足不产生新目标信息；motion 不足不转向。不得复用失去权限的旧快照继续追踪；独立且已付的直线推进可执行至其覆盖边界。

退款只针对有真实注入来源且未使用、未被预留的余额：每剩余 `1 E` 最多退 `1 法力`，且不超过该笔原始未退款付款；转换损耗不返还。例：注能 10 法力得到 8 E，消费 3 E 后最多退 5 法力，不是 10，也不是 6.25。创建费、已做功、已扫描、已释放伤害和控制费均不退。终止先撤销后续驱动、核销已做功并释放未用预留回原池，再退款；死亡、取消、过期、重复销毁只能结算一次。退款发给建立时记录的受益账户，账户已失效则记终止损耗，不猜测新账户。会话与事件终止顺序由事件 ADR 补齐，本文要求所有顺序下均幂等、不透支。

按原始付款折合的能量总式为：`注入总额 = 各池未用余额（含预留） + 累计已做功 + 已释放伤害能量 + 已扫描 + 转换/操控/终止损耗 + 已退款折合额`。法力账另核扣款与退款，Wm 另核世界补给与驱动；护体吸收属于已释放伤害的内部去向，不能重复计入总损耗。浮点容差只能处理舍入残差并记入损耗，不能让账户负数或净增能。

## 决策四：碰撞只释放伤害池，本版不开放动能转伤害

采纳明确的单一路径：碰撞命中请求 `D`，以伤害池余额 `B` 结算 `released = min(D, B)`，原子扣除同量 E 后再送入生命伤害处理。旧 `Projectile.damage` 只可作为请求值，不能当作能源。威力或伤害倍率只确定请求值并且各作用一次，不能让 `released` 突破 B。`B = 0` 时不伤血、不触发成功伤害事件；缺生命能力或命中无效不能扣出伤害后伪报成功。

固定护体之后生命损失为 `min(当前生命, max(0, released - max(0, 有效护体)))`，不再使用旧 `max(1, …)` 保底；负护体不能把本次已释放能量放大成更多生命伤害。护体吸收、过量伤害均不退款。例：余额 0.4、请求 10、护体 0 时最多损失 0.4；护体 1 时损失 0，0.4 E 仍已释放。伤害倍率提高只会加速消耗余额，不增加可用能量。

穿透每个目标独立扣款，按碰撞顺序更新余额后才能处理下一个；命中去重仍有效。默认非穿透命中后销毁，剩余余额按退款规则结算；穿透无足够余额时可降低本次伤害至余额，不能借下一次命中透支。速度只受运动、阻挡碰撞或销毁影响，扣 damage 不同时扣一次 motion，也不能把持续存在的全动能额外再算一份伤害。

本版拒绝碰撞动能转伤害效果，理由是基础世界功率不可攻击化，而当前原型尚无混合来源动能的可靠归属。将来若开放，必须另写 ADR：限定可转换来源、从 K 原子划转并按 `KNext = K - transferred` 同时降低速率、转换率不超过 1、损耗入账、基础功率来源排除，且不得与伤害池重复结算。仅写“撞得快伤害高”或在扣池后保留同额全动能不构成守恒实现。

## 决策五：传送是独立的高价原子效果

位置只能由核心积分、碰撞修正、受控创建或专门传送改变。新法术不能借 `设置位置(..., 0)` 或旧 `移动` 直接调用坐标 setter。传送必须具备 Transform 及对应传送 binding，并经关系、权限、目标存续、有限坐标、边界和落点占用检查；仅有 Transform 不自动获得传送许可。越界直接拒绝，不先裁剪成较近合法位置；落点与阻挡实体重叠也拒绝，沿途不作飞行命中。

传送成功为一次 commit，无维持期、无到期回弹；保留原朝向与速度，不附赠制动或冲量，后续积分从新位置继续。任何失败都不部分移动、不扣部分成功费用、不留下位移记录；可保留统一的正尝试价及不可泄漏私有信息的拒绝原因。

高价锚点采用成功前的实际距离 `d`：法力 `G + A × (20 + d/10) × (1+r)`，tick `ceil(G + A × (4 + d/50) × (1+r))`，其中关系 A 为自身/自有/友方/非己方 `1/1/2/8`，非己方 G 为 4、其他为 0，r 为非负传送抗性。未知目标、位置、关系或抗性预算标动态。零距离仍收正价并保留速度，不能伪装成免费重置；成功事务在价格及付款确定后再次验证落点并原子发布。具体拒绝尝试价与授权接口由属性/探查 ADR 共用，不能另设绕过路径。

## 决策六：迁移只接纳可证明等价，回退只使用旧副本

迁移继续是 AST 到 AST，DSL、蓝图、本地存档和导入使用同一入口，全量成功才替换可运行法术书。新增明确的语义/存档版本标记以区分旧价格与新守恒合同；标记用于选择迁移校验，不能作为运行时免付费开关。旧版本不认识的新数据保持原样，不覆盖。不得保存半迁移本，也不得在加载后凭空恢复飞行弹道、余额、付款记录或会话。

| 旧输入                                                  | 新合同及迁移条件                                                                                                                                                                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `发射(起点, 方向, 威力)` 与已规范化的五参创建           | 保留参数求值顺序、起点安全偏移、380/2.4 默认锚点、创建时威力作用一次、句柄与失败结果；新创建须原子支付创建费、初始冲量及足额单次 damage 储能，再发布已激活实体。存续本身不逐帧收费。不能把旧价格差额免费补能     |
| 一参创建、方向/速度/威力设置、激活链                    | 仅在无逃逸/中途观察、可保序且空间、寿命、伤害、失败、神识和法力/tick 皆等价时折叠；否则定位拒绝并保留原文及最后可运行 AST，不能再让 legacy-only 别名直接写新账户外的速度/伤害                                    |
| 旧 speed 倍率、弹道方向覆写、位置 commit、`移动`/`瞬移` | 不机械改名为 speedMax、转向或传送：即时变速、免费改航向、边界裁剪、价格和返回值均须比较。不能证明等价就拒绝；明确的新写法由玩家确认修改，不能以迁移静默改变旧意图                                                |
| 旧 Projectile.damage、穿透和存档中的运行状态            | 静态创建请求必须预留足额单次命中池；不足拒绝创建，不默认静默削弱旧伤害。运行时穿透可按余额降低伤害，但若这改变旧程序的多次命中结果，则该旧程序迁移拒绝。运行状态没有可信注能来源时不导入，不从伤害字段伪造池余额 |

现有旧价锚点并非总能保留。例如标准速率 380、威力 18、施法者威力倍率 1、普通费用倍率 1 时，旧发射创建价为 `10 + 0.15 × 18 = 12.7`；新合同仅初始运动 2 E 与伤害 18 E 就需注能 25 法力，另有正创建费与 tick。因此这组旧程序**不能宣称自动等价迁移成功**，必须给出具体法术/行号、旧新费用及供能缺口诊断，保留旧原件。新默认/示例法术可按新合同重写并重新验收，但不得覆盖用户同名法术。既有迁移测试证明的是旧合同等价，后续必须补新的反例而非删除数据保护断言。

本决策接受已批准的“等价或定位拒绝”边界，不承诺所有旧法术在新世界可执行。保存最后可运行旧 AST 不表示允许它进入新世界免付费运行；恢复其执行必须切回兼容旧程序及其副本。若后续发现必须丢弃用户数据或产品要求所有旧法术自动执行，则交制作人裁决，不能偷偷加入隐藏补贴。

回退顺序：停止新世界与新入口写入，幂等结束活动效果并保存可读诊断，保留新版法术书/配置增量及迁移前原文和存档副本；只有通过旧格式兼容检查的旧副本可以交旧程序运行。不得把当前 velocity/池余额倒推成旧 speed/damage、把已消费能量退款、从旧存档重建世界功率历史，或覆盖新版增量。重新启用新实现时从新世界开始，不能恢复不可信的旧运行会话。本文为纯文档修改，回退本项文档不改变现有运行态。

## 备选与取舍

| 方案                                             | 结论与理由                                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 保留直接位移和固定伤害，只增加费用说明           | 拒绝：没有可核算来源，速度覆写和穿透仍能制造世界效果                                                 |
| 所有惯性运动逐帧扣施法者法力                     | 拒绝：把一次做功重复收费，帧率影响费用，无法表达脱离会话的已付弹道                                   |
| 所有运动和伤害共用一个可退款池，允许任意动能转换 | 拒绝：基础移动可成为攻击/退款来源，动能与余额易双计；本版选分池、禁止跨池及动能转伤害                |
| 用 speedMax 强制钳制实际速度，或欠费立即停球     | 拒绝：抹去惯性，减速属性变成免费制动；采用有来源驱动与固定阻力                                       |
| 新旧程序永久分支执行或免费补足旧储能             | 拒绝：第二套语义或隐藏补贴破坏统一账本；选择版本化迁移、定位拒绝与旧副本回退                         |
| 完整刚体引擎及动量交换                           | 暂不采用：当前只需可审计移动、躲避和命中；采用有限能力、确定积分与耗散碰撞，代价是不模拟真实弹性碰撞 |
