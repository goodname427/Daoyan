# ADR 0009：统一实体句柄并按能力判定操作

- 状态：已采纳
- 日期：2026-09-13

## 背景

DSL 的 `entity` 过去只能引用 Actor，Projectile 使用另一套会与 Actor 重号的 ID。玩家只能调用把创建、配置和激活绑死的 `发射`，无法保存飞行物句柄、转向或探查。若直接让 Projectile 伪装成完整 Actor，又会凭空产生生命、法力和施法能力。

元法术旧分组也混合了数据类型与职责：向量计算单列、列表长度放在感知、发射放在操控、结束施法放在按键，玩家难以从分类预测一次调用是否读取或改变世界。

## 决策

1. 一次 `World` 生命周期内，Actor、Projectile 与未来世界对象共用单调递增且不复用的正整数 ID。DSL 仍把它作为不透明 `entity` 句柄，不允许根据数值猜测实体种类。
2. 统一句柄不要求统一属性全集。世界对象声明能力；当前能力集合为 Identity、Transform、Vitality、Caster、Movement、Projectile 与 Modifiers。操作先检查所需能力。
3. 玩家可理解的世界能力按五类组织：
   - 运算符：纯数值、布尔、向量和列表计算。
   - 按键状态：只读取虚拟输入。
   - 状态探查：读取实体或世界状态。
   - 实体创建：按受控原型创建实体并返回句柄。
   - 实体控制：改变自身、拥有物或其他允许目标。
     `结束施法` 不伪装成按键读取，单列为跨领域的“施法控制”。
4. 控制权限按自身、自己创建的实体、友方、敌方区分。每个元法术显式声明可控制关系；本纵切的弹道配置只允许所有者，不能借持有句柄越权控制。
5. 状态探查以单属性调用为基础，便于玩家只为所需信息付费。当前 `探查(entity)` 读取任何带 Transform 能力的实体位置。
6. 失败语义保持确定性：
   - 创建失败返回 `空` 句柄。
   - 控制因句柄失效、能力缺失、越权或参数越界失败时返回 `false`，且不产生部分修改。
   - 查询可先用 `实体存在` 判断句柄；对失效句柄的具型读取返回该类型的中性值。
   - 这些领域失败不随机触发走火入魔；资源、类型或执行上限失败仍由 VM 终止施法。
7. Projectile 必有有限寿命，但不因此获得 Vitality；未来原型可以同时拥有寿命与可受伤生命。每位所有者同时最多保有 16 个 Projectile，包含未激活对象，过期、命中销毁或场景清理后释放名额。
8. 本阶段继续使用统一固定减伤，不引入伤害类型。移除冷却也保持为后续独立迁移，避免同时改变句柄、计价与触发节奏。

## 理由

- 单一 ID 空间消除 Actor/Projectile 重号，使句柄能安全跨元法术保存和传递。
- 能力判定保留组合空间，而不把所有对象塞进臃肿继承树或过早引入完整 ECS。
- 所有权和确定性失败让玩家能推理法术结果，也阻止通过猜测 ID 控制敌方对象。
- 数量上限与有限寿命共同关闭“创建但不激活以无限囤积对象”的绕过路径。

## 后果

- `World.entityById` 解析统一句柄，Actor 专用调用继续使用 `byId`，便于渐进迁移。
- Projectile 增加种类与激活状态；战斗只移动、碰撞和渲染已激活弹道，但未激活弹道仍会消耗寿命与创建名额。
- 新增“创建弹道 → 设置方向/速度/威力 → 激活弹道 → 探查”的纵向切片；`发射` 暂作兼容入口。
- 新实体原型必须先定义能力、所有权、失败、寿命与数量上限，不得只向 `World` 塞入新的旁路数组。
