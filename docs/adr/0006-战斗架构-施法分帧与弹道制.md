# ADR 0006：施法改为分帧执行，攻击改为弹道制

- 状态：已采纳
- 日期：2026-09-12

## 背景

阶段一的法术是「一次性同步跑完」：调用 `VM.run()` 瞬间得出结果，
「耗时」只是一个用于比较的抽象数字。这在推演台里够用，
但一旦进入实时战斗就有两个致命问题：

1. 没有真实施法时间 → 玩家感受不到「耗时」这个维度，也就没有取舍
2. 攻击瞬时命中 → 无法躲，玩家「走位」毫无意义

而用户明确要求：玩家要靠**不断移动、躲位**来配合自己写的程序击败敌人。

## 决策

### 一、VM 改为可中断的分帧执行

```ts
vm.start(spell); // 起手
vm.advance(tickBudget); // 每帧推进 tickBudget 个 tick
vm.isRunning / vm.spentMana; // 查询状态
```

- `TICK_MS = 10`，即 1 tick = 10ms；每帧预算 = `dt * 1000 / TICK_MS`
- **法力按增量扣减**：每帧扣掉本帧新消耗的部分。
  被打断时已消耗的法力不退 —— 这是「走火入魔」的实际代价
- 保留 `run()` 作为同步便捷接口（推演台、测试、无头沙盒用）

### 二、攻击改为弹道制

`发射` 不再做瞬时射线判定，而是在世界里生成有飞行时间的弹道；
`伤害`（直接扣血）与 `近战斩击` 保留为「不可躲」的贴身手段，定价更高。

- 弹道速度 380，受击半径按单位半径 + 弹道半径判定
- 因此玩家可以用走位躲开自动锁定的飞剑 —— 这就是「躲位」的落点

### 三、玩家与妖兽走同一条施法管线

`Actor` 统一表示施法者，只有 `faction` 不同。
妖兽的攻击同样是「法术」，同样消耗神识 / 法力 / 耗时，同样会被打断。
区别只在于谁触发：玩家靠按键，妖兽靠 AI 计时器。

## 理由

- 一套管线 ⇒ 玩家能理解妖兽的行为逻辑，也能预判它的施法前摇
- 弹道制 + 施法前摇 ⇒ 「躲位」才真正有意义，而不需要额外的闪避系统
- 法力按增量扣减 ⇒ 打断有真实代价，玩家会更谨慎地选择出手时机

## 后果

- `World` 必须区分阵营：感知类元函数只返回「与施法者敌对」的单位
- 战斗层通过 `world.onDamage` 钩子实现「受击打断施法」，
  核心层不依赖战斗层
- 静态分析的「耗时上界」现在对应真实时间上限（tick × 10ms），
  UI 上的施法进度条可以直接用 `spentTicks / tickWorst`
- 妖兽 AI 的移动是 TS 驱动的（保证平滑），攻击才走法术；
  后续若要把移动也程序化，需要引入「设置期望速度」类元函数
