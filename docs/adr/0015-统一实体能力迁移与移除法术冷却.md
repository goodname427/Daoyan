# ADR 0015：旧元法术按实体能力判定并移除法术冷却

- 状态：已采纳
- 日期：2026-09-20

## 背景

统一实体句柄已经覆盖位置、弹道创建和弹道控制，但旧的生命、伤害与目标属性元法术仍直接按 Actor 查询。与此同时，法术注解、战斗运行时和演武属性仍维护冷却；它与法力、tick、同槽施法互斥及按键边沿重复承担节奏限制。

## 决策

1. `生命`、`伤害`、`迟滞`、`虚弱`、`蔽识`、`破防` 先解析统一实体句柄，再检查 Vitality 或 Modifiers 能力。
2. 缺少能力、句柄失效或参数非法时，查询返回类型中性值，控制返回 `false`，且不产生部分修改；成功控制返回 `true`。
3. 删除 `SpellMeta.cooldown`、`Attributes.cooldownMul`、战斗冷却表与界面冷却展示。已有 `@cooldown` 注解作为旧格式输入被接受，但规范化 DSL 不再输出它；旧存档中的 `cooldownMul` 由属性白名单自然丢弃。
4. 玩家普通法术仍只响应一次按下边沿；同一槽位在施法结束前仍不能重入。duration/channel 结束后，下一次新的按下可以立即起手。
5. 妖兽的 `attackInterval` 是 AI 决策节奏，不是法术冷却；它继续限制 AI 尝试频率，并且不再受玩家属性倍率影响。

## 理由

- 元法术不再根据句柄对应的存储数组猜测对象类型，后续实体只需声明能力即可复用失败契约。
- 法力、tick、施法占用、受击打断、实体上限和输入边沿已经能形成可解释的约束，删除冷却可减少一套与资源系统并行的隐藏节奏规则。
- 兼容读取后规范化丢弃旧字段，能让本地存档和导入文件平滑迁移，不需要提高存档版本或让玩家手工修改法术书。

## 后果

- 旧目标控制元法术的返回类型由 `void` 变为 `bool`；把它们当语句使用的现有法术保持兼容，新法术可以显式处理失败。
- 同一法术在前一次施放结束后可立即再次触发，实际频率由执行 tick、法力和玩家再次按下决定。
- `attackInterval` 仍是战斗 AI 参数，不能作为玩家法术冷却重新暴露。
