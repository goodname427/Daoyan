# ADR-0022：模块详细策划与制作人取舍回退

- 状态：已采纳
- 日期：2026-09-27
- 决策者：制作人（对详细策划与评审材料的反馈）

## 问题

版本策划指出方向后，详细策划仍被规划为一份整版扩写稿。主策随后把六类理论缺口压成 A/B 选择，却没有解释玩家效果、优缺点和推荐理由。制作人退回升级策划时，生命周期还把版本停在重新审批门禁，无法回到详细策划修订。

## 决策

1. 版本策划确定目标、范围、方向和模块轮廓；Version PM 进入详细策划节点时识别实际受影响模块及跨模块合同，按可独立审阅的模块设计成果派给 Feature PM。一个任务可覆盖一个有内聚边界的模块，不把调研、写作、验证等内部分步拆成多个 PM。确实只有一个模块时说明理由。
2. 各模块详细策划展开职责、状态与资源归属、核心规则或算法、对外合同、模块交互、玩家可见流程、成功/失败/空状态、反例、验收情形及假设。共用世界公理只保留一份权威正文；模块文档引用它，Version PM 收束时核对整体一致性。
3. 主策先自行推荐可从已批准方向推导的细节。只有真正需要制作人取舍的产品问题才升级；升级材料使用通俗语言说明每项方案的规则、玩家体验、优点、代价、跨模块影响、推荐选项和理由，以及不决定时阻塞的范围。字母选项不构成充分的评审材料。
4. 制作人退回 `producer-escalated-design` 后，保存原话和选择，关闭当前门禁并返回 `module-design`，再由策划和主策修订、复审。此退回不等于批准开发；新一轮仍可在真正需要制作人决定时建立新的门禁。不可逆架构决策被拒绝时仍暂停等待明确重新批准。

## 后果

详细策划可能产生多个 Feature PM 任务与文档，但只对各自交付做轻量直接检查。修订轮次由版本阶段时间戳区分，旧交付保留审计记录。正式版本运行状态只能经秘书和生命周期 API 改变，不手工编辑状态 JSON。
