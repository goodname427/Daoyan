# ADR 0004：AST 是唯一真相，且必须可 JSON 序列化

- 状态：已采纳
- 日期：2026-09-12

## 背景

玩家最终用**可视化节点图**编写法术，但节点图开发量大，
需要先用一个低成本前端验证玩法。风险在于：先做的前端会变成一次性代码。

## 决策

**定义一份可 JSON 序列化的 AST 作为唯一 IR**，所有前端都只是「产出 AST 的另一种方式」：

```
DSL 文本 ─┐
          ├→ AST(IR) ─→ 静态分析器 ─→ 消耗面板
节点图 ───┘        └→ 编译器 → 字节码 → 受限 VM
```

AST 定义在 `src/core/ast.ts`，不含任何函数/类实例，可 `JSON.stringify`。

## 理由

- 先用 DSL 验证玩法**不浪费一行代码**：分析器、编译器、VM 全部复用
- 节点图只是第二个前端，接入时核心零改动
- AST 序列化后**直接就是「秘籍」分享码**，无需另做一套格式

## 后果

- `src/core/ast.ts` 是最敏感的文件，改动需要同步 DSL 解析器和未来的节点图
- 任何新增语法特性，必须同时考虑「在节点图上怎么表达」——
  如果节点图表达不了，说明这个特性设计得不够「图形化」，应重新设计
- 不得把运行时状态（如槽位号）混进 AST；槽位分配是编译期的事
