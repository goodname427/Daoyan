# ADR-0016：自适应版本编排与兼容迁移边界

- 状态：已采纳（运行纵向切片已实现并补齐事务预校验；生产备份与降级演练待版本收束）
- 日期：2026-09-21
- 所属版本：`adaptive-project-office-2026-09-21`
- 依据：制作人已批准本版本方向，并要求保持现有状态兼容、可迁移、可回退；本决策不引入新的不可逆产品语义。

## 背景与代码事实

[ADR-0012](./0012-事件驱动常驻秘书与交付PM分层.md) 确定事件驱动秘书与 Feature PM 分层，[ADR-0013](./0013-正式版本生命周期与可视化秘书.md) 已将正式版本与开发批次分开，并禁止凭候选列表自动开启下一正式版本。[ADR-0014](./0014-秘书通讯通道与钉钉Stream适配.md) 保持通讯通道无排期所有权。

当前 `scripts/secretary-state.ts` 使用 `version: 1`，`scripts/version-lifecycle.ts` 使用 `schemaVersion: 1`，正式版本写入已有锁、修订检查和两文件事务恢复。阶段必须相邻推进，审批校验角色、文档修订与评审轮次。`normalizeSecretaryState` 与 `normalizeFormalVersion` 已补充 v1 扩展的保守读时迁移和嵌套记录校验，后者仍负责归档一致性修复；它们不等于生产备份、预览和降级工具。

`scripts/secretary-notice-guard.ts` 的 `coordinateOnce` 已按 `reconciliationTargets` 对账 active、tracking、retry-wait 及活动指针项；`reconcileItem` 对 `review-ready` 另存 `awaitingReview`，终态快照仍有归属进程时保持 tracking，占用结束后才投影为队列 delivered。这只能表示该开发运行停止派发，不能证明版本通过制作人体验。`scripts/agent-dispatcher.ts` 已有定向任务、交付验证、独立审查与 token 汇总；正式版本也已定义 Feature 自测、独立 QA 和缺陷复验记录，但尚不能据此宣称独立版本测试闭环已验收。

本次接管保留现场相关实现并补齐两个可运行边界：`recoverPendingVersionWrite` 在触碰 current、历史和事务文件前规范化并校验扩展；两个 normalizer 均拒绝损坏的嵌套编排记录。未知扩展事务拒绝时三个文件保持原字节。收件事务还会先持久保存目标版本与预期去向，重放时锚定该目标；若活动版本已变化且原操作未落盘，则公开阻塞而不是改投新版本。生产备份、完整故障注入及保留增量的降级工具仍由版本收束完成。

## 决策

1. **保留状态所有者。** 秘书拥有收件意图、跨版本候选、运行对账及通知；正式版本拥有范围、风险、阶段策略、审批、测试与缺陷结论；PM 的运行目录提供执行证据。Channel 和看板仅作为入口与投影。编排代码保持在 `scripts/`，不进入游戏核心、游戏存档或 React 场景状态。
2. **先判意图，再确定去向。** 只有真实新方向可自动建立待立项评审的正式版本草案；自动建立草案不等于批准开发。问题、查询、上下文回复、继续不能创建版本。已有未归档版本时，冻结前按已批准目标核对后并入，冻结后默认进入下一版本候选；候选不自动转为正式版本。改变已批准承诺必须重新取得对应修订的批准。模糊输入保留原消息和公开待确认理由，不猜测批准。
3. **风险控制执行深度，不撤销产品门禁。** 保留阶段 ID 和顺序，持久记录每阶段执行、缩减或无需执行的公开理由及证据。方向记录、版本策划、立项评审、最终制作人体验和归档不可跳过；主策升级给制作人的详细策划也必须等待制作人。其余节点可由阶段策略声明无需执行，不适用节点不计入进度分母，不能伪装成已完成。凡策略要求执行的独立验收和统一完整交付门禁仍须有真实结果。
4. **先对账，后派发。** 启动、恢复定时器、继续和每次启动 PM 前，对账所有 `active`、`tracking`、`retry-wait` 项及活动指针引用项，不能只查活动指针。通过运行归属、轮次、快照及真实 PM/子 Agent 进程身份判定；已交付或待审运行停止重试，正式版本仍保留其审批状态。陈旧事件不能清除另一项活动运行，也不能启动第二个工作区写进程。
5. **执行与验收分责。** Feature Agent 提供类型检查与定向自测；独立测试 Agent 提供验收、集成、回归和缺陷复验，独立审查不代替测试。所有结论关联所测修订和运行；开发标记修复只能进入待复验，不能自己关闭缺陷。
6. **公开日志是独立数据契约。** 只持久化允许公开的任务输入、结构化计划进度、动作、文件、测试结果与错误、公开决策/阻塞、时间和 token。按字段白名单投影并脱敏，不保存或展示私有思维链；未知 token 为不可用，不能填为零。原始模型输出不自动成为公开日志。

7. **迁移预览与运行恢复分开。** `readFormalVersion` 会先恢复待写事务，`listFormalVersions`、`readFormalVersionById` 间接调用它；这些入口不是只读预览 API。升级必须先在停写状态下备份原始字节，再在隔离副本校验和恢复。正式版本的两文件事务只覆盖 current 与对应历史快照，不覆盖秘书收件、答复、outbox 和运行日志；跨状态重放仍以原请求和原目标为边界。外部通知沿用 ADR-0014 的至少一次投递，不宣称跨平台恰好一次。

## 兼容与回退

2026-09-21 独立审查修复补充可回退的 v1 可选字段：秘书事项保存 `waitingSnapshot` 和 `acknowledgedWaitingSnapshot`，只确认已观察的具体等待快照；正式版本保存 `codeRevision` 和 `qaInvalidatedThrough`（修复/自测发生时已有 QA 条数），要求后续独立回归覆盖该代码修订。旧记录不补造确认或测试，新字段显式损坏则拒绝写入；旧等待在处理前补对账，旧修复与 QA 修订矛盾时阻止候选。恢复确认须和重试状态一起备份，QA 边界须和原测试数组一起保留，禁止混跑旧写者或删除这些扩展后继续派发。这里没有新增不可逆产品语义，也不代表生产迁移已执行。

事实查重先核对是否同一原文方向，词面或语义主题关联不能复用旧承诺的批准。该规则覆盖运行中、已排期和已完成事实；非同一方向仍由正式版本范围/冻结合同决定去向。

本轮独立审查补充：本地无法确认的新方向使用既有 `needs-confirmation`，回复标点和致谢不构成立项依据；范围主题相似不代表批准内容相同，首次草案之外的非同一方向保守进入范围评审。缺失、损坏或不可识别的运行快照使用既有 `missing` 对账结果和 tracking 状态阻塞整队列，保留归属证据并等待内部修复后对账，禁止因工作区干净或缺少恢复文件改为新运行。沿用 v1 字段，无新增迁移或不可逆产品语义；历史批准不倒推修改。

2026-09-21 行为复审补充：等待上下文保留新方向识别与语义分流；重试定时器由全队列协调统一安排，被待决事项或写进程阻塞的到期重试等待解除阻塞事件；候选入口对所有修复策略统一校验最新、当前范围且包含回归的可信独立 QA 通过结论。这些修正不新增持久字段，不改变 v1 迁移格式，不补造旧 QA 证据，也不倒推改写已经归档的版本。

采用现有 v1 信封上的可选、独立版本化编排扩展，不修改旧阶段和状态枚举；具体字段、迁移顺序及测试矩阵见[规格](../specs/2026-09-21-adaptive-project-office-kernel.md)。新代码读旧状态时补保守策略，保留已有 ID、审批、范围冻结、证据与去重键；不能把缺失信息补成已批准、已测试或已交付。未来信封或扩展版本必须保留原文件并停止该状态的自动写入和派发，不能当作无版本而另行立项。

兼容旧数据不代表允许新旧写进程混跑。升级前停止派发并核实 PM/执行进程退出，备份秘书、正式版本、事务及关联运行证据；新读写器和迁移器完整部署后才恢复调度。迁移须幂等、原子落盘、可中断重放，并先对账再安排重试。

原子落盘指单个文件替换；多文件一致性依赖事务恢复及请求重放，不表示多个状态根的整体原子切换。normalizer 会修改传入对象，预览使用深拷贝，校验失败的对象不得继续保存。已有信封读取仅校验部分旧字段，扩展嵌套校验也不构成任意损坏输入的完整证明；迁移器必须在写入前校验整组快照和引用关系，具体中断点及放行证据见规格。

迁移还须记录文件不存在的事实和仓库版本种子：只回拷已有文件会遗留升级新建状态，仅覆盖运行状态根也不能隔离种子回退。两个 normalizer 已在运行时按属性存在性区分缺失扩展与 `null` 等损坏值；迁移预览仍须先验证原始属性并保留原字节。迁移还须揭示 current/历史/事务冲突及归档修复，读时修复不得直接授权重新派发。公开日志仅有进程内追加串行化，单写者约束不能因日志测试通过而放宽。具体清单和恢复判定见规格“迁移清单与数据来源核验”；本条限定可回退实现条件，不批准不可逆语义，也不宣称降级工具已交付。

审查修复沿用上述可回退扩展：待办可选 `decisionGateId` 将具体决策与阶段评审隔离；旧记录只在阶段、摘要、创建时间唯一匹配时补关联，歧义拒绝写入。被拒绝的不可逆/升级策划门禁继续阻止推进，不能由其他决定解除。缺陷可选 `fixAttemptId`、`fixCodeRevision` 与 QA 可选 `bugFixes` 绑定修复证据；未绑定的历史 QA 保留但不能关闭当前待复验缺陷，已归档或已关闭历史不倒推修改。新修复需记录新轮次与代码修订并取得独立复验。这是已有审批和测试合同的修复，不新增不可逆产品语义。

回退也需停写。迁移前备份只允许在确认没有迁移后新事件时整组恢复；已有新消息、审批或交付时，必须先导出并保留增量，使用降级投影保留当前业务事实和去重键，将旧代码不能安全表达的活动项转为阻塞待处理。禁止仅回退代码后让旧调度器继续消费扩展状态，或恢复旧 `retryAt` 重跑已交付工作。若无法安全降级，保持暂停并提供只读证据，不删除新数据。

## 不变量核对

| 现有约束                               | 本决策的边界                                     |
| -------------------------------------- | ------------------------------------------------ |
| 无头核心、AST 唯一 IR、单向依赖        | 仅改项目编排，不新增核心依赖或第二套游戏语义     |
| 神识/法力/耗时、静态预算、默认禁止递归 | 不改变资源定价、分析、VM 或 DSL                  |
| Actor/实体句柄与施法同构               | 不改变世界或施法管线                             |
| 推演台与演武场分责、共享状态单一所有者 | 不迁移游戏存档；秘书与正式版本各自拥有其领域状态 |
| ADR-0012 事件休眠与进程归属            | 对账由事件触发，不增加空闲模型调用或项目轮询     |
| ADR-0013 审批、冻结、独立评审          | 保留强制审批和文档修订校验；草案与执行批准分离   |
| ADR-0014 通道与凭据隔离                | 通道无独立排期；凭据不进入日志或 Agent 输入      |

本 ADR 补充 ADR-0013 的自适应执行与数据兼容机制，不恢复 ADR-0012 中已被 ADR-0013 收紧的“从项目状态承接下一版本”行为。

## 后果与未选择方案

- 保留旧阶段后，看板可展示执行或跳过及其理由，不能把跳过伪装成完成。
- notice guard 不是只读投影：活动正式版本没有制作人、额度或外部访问阻塞时，它必须持续建立当前阶段任务、消费交付证据并推进到下一真实阻塞；普通内部节点空闲属于编排故障。
- 加法扩展便于回退，但必须覆盖所有读写入口并提供明确降级工具；不能依赖旧程序保留未知字段。
- 不采用模型直接修改状态或直接执行计划中的任意命令；语义判断只是建议，状态转换由确定性校验执行。
- 不以待审报告自动归档，不把 PID 存在等同于该任务进程，不通过删除恢复文件“修好”旧状态。

## 验收边界

2026-09-21 的运行纵向切片已在 v1 信封内加入可选编排扩展、保守读时迁移、嵌套校验、全队列对账、固定门禁、独立 QA/缺陷复验合同和公开事件日志；待恢复事务会先校验扩展，拒绝异常时不改原文件。它没有迁移 `.daoyan-agent/` 现场，也没有改变游戏语义。生产备份、升级/降级演练、完整门禁、独立审查与制作人体验仍由秘书在版本收束阶段执行，实际结果见[开发记录](../dev/2026-09-21.md)。
