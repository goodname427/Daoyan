# ADR-0016：自适应版本编排与兼容迁移边界

- 状态：已采纳（分作用域证据、选择性恢复、候选对账及隔离迁移演练已实现；生产迁移仍待版本收束）
- 日期：2026-09-21
- 所属版本：`adaptive-project-office-2026-09-21`
- 依据：制作人已批准本版本方向，并要求保持现有状态兼容、可迁移、可回退；本决策不引入新的不可逆产品语义。

## 背景与代码事实

[ADR-0012](./0012-事件驱动常驻秘书与交付PM分层.md) 确定事件驱动秘书与 Feature PM 分层，[ADR-0013](./0013-正式版本生命周期与可视化秘书.md) 已将正式版本与开发批次分开，并禁止凭候选列表自动开启下一正式版本。[ADR-0014](./0014-秘书通讯通道与钉钉Stream适配.md) 保持通讯通道无排期所有权。

当前 `scripts/secretary-state.ts` 使用 `version: 1`，`scripts/version-lifecycle.ts` 使用 `schemaVersion: 1`，正式版本写入已有锁、修订检查和两文件事务恢复。阶段必须相邻推进，审批校验角色、文档修订与评审轮次。`normalizeSecretaryState` 与 `normalizeFormalVersion` 已补充 v1 扩展的保守读时迁移和嵌套记录校验，后者仍负责归档一致性修复；它们不等于生产备份、预览和降级工具。

`scripts/secretary-notice-guard.ts` 的 `coordinateOnce` 已按 `reconciliationTargets` 对账 active、tracking、retry-wait 及活动指针项；`reconcileItem` 对 `review-ready` 另存 `awaitingReview`，终态快照仍有归属进程时保持 tracking，占用结束后才投影为队列 delivered。这只能表示该开发运行停止派发，不能证明版本通过制作人体验。`scripts/agent-dispatcher.ts` 已有定向任务、交付验证、独立审查与 token 汇总；正式版本也已定义 Feature 自测、独立 QA 和缺陷复验记录，但尚不能据此宣称独立版本测试闭环已验收。

本次开发在既有 v1 信封上增加可选 `validationEvidence` 与秘书 `itemResolutions`：前者记录 Task/Feature/Version 的代码树、路径、命令、配置、输入输出和轮次，后者记录取消、替代、合并或交付对原候选的稳定反向闭合。缺失字段按旧状态迁移为空集合，显式损坏停止写入。隔离演练已覆盖原始字节备份、缺失文件清单校验和保留编排增量的降级投影；未触碰生产 `.daoyan-agent`，生产停写迁移和完整故障注入仍由后续 Version QA 执行。

## 决策

1. **保留状态所有者。** 秘书拥有收件意图、跨版本候选、运行对账及通知；正式版本拥有范围、风险、阶段策略、审批、测试与缺陷结论；PM 的运行目录提供执行证据。Channel 和看板仅作为入口与投影。编排代码保持在 `scripts/`，不进入游戏核心、游戏存档或 React 场景状态。
2. **先判意图，再确定去向。** 只有真实新方向可自动建立待立项评审的正式版本草案；自动建立草案不等于批准开发。问题、查询、上下文回复、继续不能创建版本。已有未归档版本时，冻结前按已批准目标核对后并入，冻结后默认进入下一版本候选；候选不自动转为正式版本。改变已批准承诺必须重新取得对应修订的批准。模糊输入保留原消息和公开待确认理由，不猜测批准。
3. **风险控制执行深度，不撤销产品门禁。** 保留阶段 ID 和顺序，持久记录每阶段执行、缩减或无需执行的公开理由及证据。方向记录、版本策划、立项评审、最终制作人体验和归档不可跳过；主策升级给制作人的详细策划也必须等待制作人。其余节点可由阶段策略声明无需执行，不适用节点不计入进度分母，不能伪装成已完成。凡策略要求执行的独立验收和统一完整交付门禁仍须有真实结果；后者唯一由 Feature PM 在最终代码树执行并作为 Feature scope 证据，Version QA 只复用匹配事实。
4. **先对账，后派发。** 启动、恢复定时器、继续和每次启动 PM 前，对账所有 `active`、`tracking`、`retry-wait` 项及活动指针引用项，不能只查活动指针。通过运行归属、轮次、快照及真实 PM/子 Agent 进程身份判定；已交付或待审运行停止重试，正式版本仍保留其审批状态。陈旧事件不能清除另一项活动运行，也不能启动第二个工作区写进程。
5. **执行与验收分责。** Feature Agent 提供类型检查与定向自测；独立测试 Agent 提供验收、集成、回归和缺陷复验，独立审查不代替测试。所有结论关联所测修订和运行；开发标记修复只能进入待复验，不能自己关闭缺陷。
6. **公开日志是独立数据契约。** 只持久化允许公开的任务输入、结构化计划进度、动作、文件、测试结果与错误、公开决策/阻塞、时间和 token。按字段白名单投影并脱敏，不保存或展示私有思维链；未知 token 为不可用，不能填为零。原始模型输出不自动成为公开日志。

7. **迁移预览与运行恢复分开。** `readFormalVersion` 会先恢复待写事务，`listFormalVersions`、`readFormalVersionById` 间接调用它；这些入口不是只读预览 API。升级必须先在停写状态下备份原始字节，再在隔离副本校验和恢复。正式版本的两文件事务只覆盖 current 与对应历史快照，不覆盖秘书收件、答复、outbox 和运行日志；跨状态重放仍以原请求和原目标为边界。外部通知沿用 ADR-0014 的至少一次投递，不宣称跨平台恰好一次。
8. **验证证据按作用域失效，不按工作区整体失效。** Task、Feature、Version 各有唯一责任者。可复用证据绑定作用域、输入输出、候选验证树、代码修订、路径集合、命令与配置指纹；Task 的声明建议路径和从任务文件静态解析出的只读直接模块依赖共同构成持久输入清单，实际 `changedFiles` 构成输出指纹，路径外未修改依赖变化也必须使本 Task 及下游失效。Feature 候选验证树覆盖代码、测试、验证配置及章程、范围、规划、设计、任务拆分和门禁前生成的 `development.json`/`development.md`，只排除门禁后生成的 `qa`、`bugfix`、`bugfix-reverification`、`candidate`、`producer-acceptance`、`archived` Markdown/JSON 报告；修改开发逐项命令、退出码或结论必须使 Feature/pre-push 证据失效，真正的后置结论不会自行失效 Feature 证据。开发结果先按已校验的工作项依赖拓扑排序再登记 Task 证据，JSON 排列顺序不能改变证据边。Version QA 复用 Feature 事实时还必须核验命令明细确实包含成功的 `npm run verify:full`，定向测试不能冒充完整门禁。恢复点还持久保存当时相对 HEAD 的脏路径与内容哈希/删除标记；普通续跑只把该基线之后新增、修改、删除或还原到 HEAD 的路径归属到当前计划，再保留仍可验证的已完成 Task 并沿依赖重排失效项。接管前已存在且内容未变的无关脏现场不得阻断恢复，旧恢复点缺少可选基线时继续按当前完整脏路径保守判断；仅当恢复后增量无法安全归属时才拒绝普通续跑。公开事件构造必须提供真实轮次和代码修订，不能写入 `r1/unknown` 占位；模型计算、命令执行、等待制作人、等待额度、恢复和空闲时间由对应状态边界采集，旧事件未知值保持不可用。规划/纯文档阶段使用轻量 Profile，正式版本其余阶段维持既有产品门禁。

9. **异常恢复与同运行修复分离。** 恢复只处理进程崩溃、主机或守卫重启、外部服务/额度阻塞和持久证据损坏；普通测试或格式失败、审查 finding 与局部修复由同一 PM 从失败命令或未关闭 finding 持续闭环，不能在固定两轮后上抛。只有无进展重复、真实外部阻塞或进程异常才建立恢复点。`runDirectory` 已登记而恢复快照尚未创建时显式处于 `bootstrapping` 短暂宽限，不能记录为 `missing`；PM、dispatcher 与 worker 分别对账，附着监听和主 `launch()` 子进程的 close 路径都必须等待并重读终态快照。worker 退出事件必须再次核验 PM 身份；PM 仍存活时保持 tracking 并重新绑定其进程引用，包装进程退出不能直接标记 missing/retry-wait。恢复点持久保存快速门禁的已完成/待执行子命令及独立审查通过事实，并绑定候选验证树和配置指纹；匹配的完整门禁证据存在时直接跳过快速门禁与独立审查。聚合快速门禁在中段失败后，从失败子命令继续并依次执行所有尚未运行的后续子命令。完整门禁每个 Feature 最终树只生成一次，pre-push 复用代码树和配置指纹匹配的证据；公开状态分别统计真实启动、异常恢复和局部修复轮次，从遗留 `active` 快照恢复视为进程崩溃，与 `recoverable` 恢复一样增加异常恢复次数，并在交付后清理陈旧摘要。

## 兼容与回退

2026-09-21 独立审查修复补充可回退的 v1 可选字段：秘书事项保存 `waitingSnapshot` 和 `acknowledgedWaitingSnapshot`，只确认已观察的具体等待快照；正式版本保存 `codeRevision` 和 `qaInvalidatedThrough`（修复/自测发生时已有 QA 条数），要求后续独立回归覆盖该代码修订。旧记录不补造确认或测试，新字段显式损坏则拒绝写入；旧等待在处理前补对账，旧修复与 QA 修订矛盾时阻止候选。恢复确认须和重试状态一起备份，QA 边界须和原测试数组一起保留，禁止混跑旧写者或删除这些扩展后继续派发。这里没有新增不可逆产品语义，也不代表生产迁移已执行。

事实查重先核对是否同一原文方向，词面或语义主题关联不能复用旧承诺的批准。该规则覆盖运行中、已排期和已完成事实；非同一方向仍由正式版本范围/冻结合同决定去向。

本轮独立审查补充：本地无法确认的新方向使用既有 `needs-confirmation`，回复标点和致谢不构成立项依据；范围主题相似不代表批准内容相同，首次草案之外的非同一方向保守进入范围评审。缺失、损坏或不可识别的运行快照使用既有 `missing` 对账结果和 tracking 状态阻塞整队列，保留归属证据并等待内部修复后对账，禁止因工作区干净或缺少恢复文件改为新运行。沿用 v1 字段，无新增迁移或不可逆产品语义；历史批准不倒推修改。

2026-09-21 行为复审补充：等待上下文保留新方向识别与语义分流；重试定时器由全队列协调统一安排，被待决事项或写进程阻塞的到期重试等待解除阻塞事件；候选入口对所有修复策略统一校验最新、当前范围且包含回归的可信独立 QA 通过结论。这些修正不新增持久字段，不改变 v1 迁移格式，不补造旧 QA 证据，也不倒推改写已经归档的版本。

采用现有 v1 信封上的可选、独立版本化编排扩展，不修改旧阶段顺序；秘书事项增加 `cancelled`、`superseded`、`merged` 终态，仅由可审计对账迁移或稳定事项关系产生，不作为新的运行态。取消、替代、合并和交付都能沿 `secretary:<id>` 关系反向闭合原候选；统计时，被后继引用的源事项即使没有自引用关系，也先归一到同一个关系根，由活动状态覆盖 backlog，避免源候选与后继重复计数。更正通知成功后立即原子保存 `correctionSentAt`，不依赖后续状态变化。具体字段、迁移顺序及测试矩阵见[规格](../specs/2026-09-21-adaptive-project-office-kernel.md)。新代码读旧状态时补保守策略，保留已有 ID、审批、范围冻结、证据与去重键；不能把缺失信息补成已批准、已测试或已交付。未来信封或扩展版本必须保留原文件并停止该状态的自动写入和派发，不能当作无版本而另行立项。

兼容旧数据不代表允许新旧写进程混跑。升级前停止派发并核实 PM/执行进程退出，备份秘书、正式版本、事务及关联运行证据；新读写器和迁移器完整部署后才恢复调度。迁移须幂等、原子落盘、可中断重放，并先对账再安排重试。

原子落盘指单个文件替换；多文件一致性依赖事务恢复及请求重放，不表示多个状态根的整体原子切换。normalizer 会修改传入对象，预览使用深拷贝，校验失败的对象不得继续保存。已有信封读取仅校验部分旧字段，扩展嵌套校验也不构成任意损坏输入的完整证明；迁移器必须在写入前校验整组快照和引用关系，具体中断点及放行证据见规格。

迁移还须记录文件不存在的事实和仓库版本种子：只回拷已有文件会遗留升级新建状态，仅覆盖运行状态根也不能隔离种子回退。隔离备份工具现在以原始字节 SHA-256、存在性清单和同根拒绝规则生成原子备份，降级投影把旧格式事实与不可表达的编排扩展分开保存；它们不等于已经执行生产迁移。两个 normalizer 已在运行时按属性存在性区分缺失扩展与 `null` 等损坏值；迁移预览仍须先验证原始属性并保留原字节。迁移还须揭示 current/历史/事务冲突及归档修复，读时修复不得直接授权重新派发。公开日志仅有进程内追加串行化，单写者约束不能因日志测试通过而放宽。

审查修复沿用上述可回退扩展：待办可选 `decisionGateId` 将具体决策与阶段评审隔离；旧记录只在阶段、摘要、创建时间唯一匹配时补关联，歧义拒绝写入。被拒绝的不可逆/升级策划门禁继续阻止推进，不能由其他决定解除。缺陷可选 `fixAttemptId`、`fixCodeRevision` 与 QA 可选 `bugFixes` 绑定修复证据；未绑定的历史 QA 保留但不能关闭当前待复验缺陷，已归档或已关闭历史不倒推修改。新修复需记录新轮次与代码修订并取得独立复验。这是已有审批和测试合同的修复，不新增不可逆产品语义。

回退也需停写。迁移前备份只允许在确认没有迁移后新事件时整组恢复；已有新消息、审批或交付时，必须先导出并保留增量，使用降级投影保留当前业务事实和去重键，将旧代码不能安全表达的活动项转为阻塞待处理。禁止仅回退代码后让旧调度器继续消费扩展状态，或恢复旧 `retryAt` 重跑已交付工作。若无法安全降级，保持暂停并提供只读证据，不删除新数据。

## 不变量核对

| 现有约束                               | 本决策的边界                                     |
| -------------------------------------- | ------------------------------------------------ |
| 无头核心、AST 唯一 IR、单向依赖        | 仅改项目编排，不新增核心依赖或第二套游戏语义     |
| 神识/法力/耗时、静态预算、默认禁止递归 | 不改变资源定价、分析、VM 或 DSL                  |
| Actor/实体句柄与施法同构               | 不改变世界或施法管线                             |
| 推演台与演武场分责、共享状态单一所有者 | 不迁移游戏存档；秘书与正式版本各自拥有其领域状态 |
| ADR-0012 事件休眠与进程归属            | 对账由事件触发，不增加空闲模型调用或项目轮询     |
| ADR-0013 审批、冻结、独立评审          | 保留强制审批和文档修订校验；草案与执行批准分离   |
| ADR-0014 通道与凭据隔离                | 通道无独立排期；凭据不进入日志或 Agent 输入      |

本 ADR 补充 ADR-0013 的自适应执行与数据兼容机制，不恢复 ADR-0012 中已被 ADR-0013 收紧的“从项目状态承接下一版本”行为。

## 后果与未选择方案

- 保留旧阶段后，看板可展示执行或跳过及其理由，不能把跳过伪装成完成。
- notice guard 不是只读投影：活动正式版本没有制作人、额度或外部访问阻塞时，它必须持续建立当前阶段任务、消费交付证据并推进到下一真实阻塞；普通内部节点空闲属于编排故障。
- 加法扩展便于回退，但必须覆盖所有读写入口并提供明确降级工具；不能依赖旧程序保留未知字段。
- 不采用模型直接修改状态或直接执行计划中的任意命令；语义判断只是建议，状态转换由确定性校验执行。
- 不以待审报告自动归档，不把 PID 存在等同于该任务进程，不通过删除恢复文件“修好”旧状态。

## 验收边界

2026-09-21 的开发切片已补齐分作用域证据、选择性恢复、`bootstrapping` 宽限、终态重读、同运行 finding 迭代、完整门禁证据复用、六类耗时和秘书候选反向闭合；隔离备份/降级投影演练通过无头回归。它没有迁移 `.daoyan-agent/` 现场，也没有改变游戏语义。生产迁移、允许子进程环境中的完整门禁、真正独立审查、Version QA 与制作人体验仍由后续阶段收束，实际结果见[开发记录](../dev/2026-09-21.md)。

交付前审查进一步把这些合同接到真实链路：dispatcher 按计划的有效 Profile 选择验证阶段，`light` 不再误入代码门禁，`version` 不再重放 Feature 门禁；notice guard 接纳开发和 QA 报告时正式登记 Task/Feature/Version `validationEvidence` 并传递复用指纹；快速门禁失败只复核失败子命令并继续其后的未执行子命令，修复后的独立审查只消费修复边界增量，异常恢复按验证树和配置指纹复用阶段事实。两条历史排期迁移绑定生产状态中既有事项的稳定 ID，后续候选只能通过显式 `secretary:<id>` 关系闭合；没有该关系的事项始终回退到自身唯一 ID，即使文案相同也分别计数。三处代码树指纹都把尚未提交的受控删除记录为 `[deleted]`，使 pre-push 能安全回退或复用，而不会在读取缺失文件时退出。

最终行为审查确认并修复了三个实现偏差：worker 退出不再复用 PM 退出结论；排期更正不再整批末尾保存，而是在每条成功发布后原子落盘；Task 输出指纹不再局限于建议路径，而是覆盖实际改动并单独保留建议路径输入指纹。公开修订失败消息另有精确中文断言。以上均为既有决策的可回退实现修复，不增加状态版本或产品语义。

交付前证据复审进一步收紧三条既有边界：任何包装进程退出都必须携带其实际 PID/identity，并与重读快照中的当前 PM 身份及存活状态核对；QA/缺陷复验只能用接纳时实时计算的候选树、完整门禁命令和验证配置指纹消费 Feature 证据；Task 证据只读取执行 Agent 报告的逐命令结果，计划验收命令、Feature 完整门禁和 Version QA 命令不能被推定或投影为 Task 成功事实。这些校验不增加持久格式版本，旧报告缺少逐命令事实时必须补做直接验证，不能自动补造通过记录。

本轮交付前审查继续修正三个既有合同的实现：开发逐项清单在 Feature 完整门禁前形成并进入候选验证树，QA 与复验等后置阶段报告才从验证树排除；章程、范围、规划、设计和任务拆分仍作为输入参与指纹。Task 恢复点新增可复算的 `inputPaths`，把路径外未修改的相对模块依赖纳入输入指纹，旧恢复点仍保守回退到声明路径；排期事实先解析 `secretary:<id>` 关系根，再应用活动优先级，即使源候选没有人为自引用也只计数一次。三处均为现有 v1 可选数据和确定性计算的可回退修复，不改变产品门禁或正式版本阶段顺序。
