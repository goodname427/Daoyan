# ADR 0011：有限效果请求不封顶并显式标记动态资源预算

- 状态：已采纳
- 日期：2026-09-14
- 后续覆盖：[ADR 0019](./0019-属性探查与资源账本.md) 覆盖决策 1、6、7 中与六属性安全域、探查授权、不可折扣费用及外部状态神识预算冲突的部分；域内动态定价、无伪上界和非法定价拒绝继续有效。新合同采纳不表示运行时已迁移。
- 取代：[ADR 0010](./0010-动态元法术价格与静态上界.md) 中“动态价格必须有有限输入域并由单值静态上界覆盖”的约束

## 背景

ADR 0010 用寿命、速度、威力等人为最大值换取全局静态上界。这会让数值 100 与 10000 在边界外同价或直接失败，玩家无法继续用更高法力和更长施法时间交换更强效果。距离、实体关系和运行时目标状态本来也无法从 AST 得到可信的有限全局上界。

继续展示一个看似精确的单值会破坏资源面板的可信度；继续限制有限请求则会破坏“自由编写法术”的产品方向。

## 决策

1. 有限且满足领域方向的效果请求不设人为最大值。数值越大，法力和 tick 按确定性公式继续增加；非有限值与不满足领域条件的值仍失败且不产生效果。
2. `MetaDef.mana` 与 `ticks` 在存在新 `cost` 定价器时表示固定基础成本，不再表示全局上界。`cost` 同时计算本次调用的法力与 tick。
3. 分析器的资源结果由“已知数值 + 是否仍含动态项”组成：
   - 参数和目标状态都可知时，给出固定预算；
   - 距离、关系或请求值未知时，保留可计算的基础部分并标记 `dynamic`；
   - 只有 `dynamic=false` 时，数值才能称为该输入下的静态上界。
4. 分支分别分析后合并静态值；路径给出不同请求值时退化为动态。循环可能改写请求值时同样保守退化，不能采用最后分析路径的值伪装成固定预算。
5. VM 在效果发生前结算本次法力与 tick，并拒绝抛错、非有限、负数、非整数 tick 或运行时仍含未知项的定价。旧 `manaCost` 扩展继续受 ADR 0010 的有限上界兼容契约保护。
6. 同一 Transform 控制入口可作用于 Actor 与 Projectile。关系倍率只看自身、自有实体、友方或敌方，不按对象种类分叉；当前倍率依次为 1、1、2、8。距离和关系都可同时影响法力与 tick。
7. `manaCostMul` 只缩放法力，`castSpeed` 只把结算后的 tick 映射为真实时间。神识仍有可判定的容量上界，不受本 ADR 影响。

## 理由

- 玩家可以用资源而不是硬编码数值上限决定效果规模。
- “基础 + 动态”诚实表达静态分析能知道和不能知道的部分，不再用伪上界换取界面上的单值。
- 法力与时间使用同一动态定价入口，避免只提高法力却让巨大效果瞬间完成。
- 统一关系倍率使同一种能力对 Actor、Projectile 和未来实体保持相同语义。

## 后果

- 原有 `manaWorst`、`tickWorst` 字段为兼容调用方继续保留；当对应 `manaBudget.dynamic` 或 `tickBudget.dynamic` 为真时，它们只代表已知预算部分，不得展示为上界。
- 推演台、蓝图和演武场必须把未解析项显示为“基础/预算 + 动态”。指定场景的精确预演仍是后续能力。
- 巨大但有限的请求可能在 VM 中因法力不足或 tick 上限而失败，这是资源约束，不是领域上限。
- 动态定价新增或修改时必须同时覆盖公式单调性、VM 实扣、分析器动态传播和非法定价失败。
