# ADR 0007：并发施法使用独立执行实例与共享资源账户

- 状态：已采纳
- 日期：2026-09-13

## 背景

当前战斗层以 `actorId → CastInstance` 保存施法状态，同一实体任意时刻只能运行一个法术。这既不符合修仙者同时维持、引导和释放多个术法的产品预期，也让“神识上限决定同时持有多少状态”只在单个 VM 内成立。

并发施法不能只把单个实例改成数组：多个 VM 会同时消费同一实体的法力与神识，受击、移动减速、按键生命周期和界面反馈也必须有一致语义。

## 决策

1. 一个实体可以同时运行多个 `CastInstance`；施法实例以触发槽位区分，同一槽位在实例结束前不可重入。
2. 每个实例拥有独立 VM、按键状态、生命周期和跨帧 tick 信用，并按实体的完整施法速度独立推进。元法术整步执行产生的预算超支由后续帧偿还；并发不会平分 tick，并发代价由共享资源约束承担。
3. 同一实体的 VM 共享实时资源账户：
   - 元法术执行时原子扣除实体当前法力，余额不足的实例立即失败。
   - 变量声明时占用实体当前神识，释放、返回、失败或打断时归还；所有实例占用之和不得超过神识上限。
4. 受击会打断该实体当前全部可打断实例；不可打断实例继续执行。打断次数按实际被打断的实例计数，已消耗法力不退。
5. 施法移动减速取所有活跃实例中最严格的倍率，避免并发绕过引导或施法减速。
6. 战斗表现和 HUD 必须能够显示多个活跃法术及总神识占用。
7. 现有冷却规则暂时保留；移除冷却属于元法术与资源模型 vNext 的独立决策，不与本次并发改造混合。

## 理由

- 按槽位区分符合玩家输入心智，也能防止按键重复事件制造同一法术的无限实例。
- 实时共享而非预留静态峰值，允许两个法术在不同阶段复用神识，更准确地表达“同时持有状态”。
- 每个 VM 独立推进，才能真正产生同时施法；若平分 tick，只是把单队列伪装成并发。
- 共享账户放在 VM 的可选资源钩子中，保持 `src/core/` 无 UI 依赖，并保留推演台与无头运行的独立资源结算。

## 后果

- `Battle` 的施法集合从“每实体一个实例”变为“每实体、每槽位一个实例”，调用方应通过查询接口读取活跃实例。
- VM 增加可选资源账户钩子以及显式取消能力；战斗层负责把钩子连接到 Actor 当前资源。
- 单 VM 的静态上界仍然有效；多个法术并发时，总神识是各实例当前占用之和，不等于各自峰值的固定相加。
- 后续引入法术优先级、主动取消或资源抢占时，应在本 ADR 基础上另行定义，不得依赖 Map 遍历顺序形成隐式规则。
