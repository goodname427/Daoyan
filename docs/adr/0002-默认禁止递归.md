# ADR 0002：默认禁止递归，后期用「轮回术」解锁

- 状态：已采纳
- 日期：2026-09-12

## 背景

玩家希望「函数可以互相调用，消耗叠加」。一旦允许递归，
叠加次数不可判定（停机问题），静态总消耗无法计算，
玩家就看不到「这个法术要花多少法力」——而消耗可见性是本作的核心体验。

## 决策

**分阶段图灵完备：**

1. **当前境界（默认）**：调用图必须是 **DAG**
   - 禁止递归
   - 循环次数必须是字面量常量（`repeat N`）
   - `for` 遍历列表时，静态最坏消耗按**列表容量**计
   - 结果：所有消耗**编译期精确可算**
2. **高境界解锁「轮回术」**：允许递归与可变次数循环
   - 每次递归额外占一格神识（栈帧），深度天然被神识上限封死
   - 带 fuel（步数预算），超支即走火入魔

## 理由

- 可分析性优先：消耗面板要能给出「上界」，这是优化动机的来源
- 但也要给后期留表达力天花板，否则后期内容会枯竭
- 「递归深度 = 剩余神识」这个映射本身就很优雅，与主题契合

## 后果

- 静态分析器必须做**环检测**，在创建阶段就拒绝递归并给出可读错误
- 循环次数的常量约束是语言级的，节点图编辑器也要保证（不能连出可变次数循环）
- 解锁「轮回术」时需要：去掉环检测 + 引入递归栈帧计费 + 走火入魔表现
