**结论：退回详细策划补全（`changes-requested`）。** 六项 `mdp-*` 模块方案已交付，主策复审已将它们与[意图对齐](./intent-alignment.json)、[唯一世界理论](./world-theory-draft.md)、跨模块接口、未列举玩法和旧原型逐项对照。有限条件下的报价、账本、事件顺序、授权及推演台至演武场的纸面脚本已有可复算候选；但首批正向成立条件尚未写成同一套可核验的逐体证书，因此整版方案尚不闭合，也不进入游戏开发。本次只审核纸面规则与未来验收，不以新规则尚未可玩作为退回理由。

## 本轮退回的验收条件

相比上一轮，独立读取/维持报价、有限身份判据、H/B 逐笔链及普通行动的条件价格已经补入；本轮不以这些相同笼统缺口重复退回。主策与策划应在既有方向内交付以下纸面合同，并由下轮主策按反例复核：

1. 对起步、续步、维持、H/B 等首批成功路径，统一列 `M` 付款、物理正功或预存梯度、材料 `Q[k]`、耗损/回收、反作用、合法尝试和原子失败余态。若无法证明 `M→正功`，只可在有证物理来源域声明成功。
2. 为 `M1/A1` 的关键回路、损伤、维持/保存/恢复截止和身份连续，以及 `M1/B1/J1/A1` 的程序、事件、记忆、储池和神识峰值，给逐体条件证书及无证拒绝路径；用同一证书重算最后一击、迟到补源、H/B 和普通行动。
3. 将这些前提接回唯一理论和同一 AST 的授权、事件、报价合同；在推演台→演武场→返回的纸面矩阵中明确成功、失败、空、域外和跨入口等价的可执行验收步骤，并列旧内容处理与 ADR 覆盖点。

**当前无须制作人立即取舍。** 推荐保持已批准的有限有证来源、无证拒绝与死后独立授权关闭，由主策补足上述合同。若策划要改为法力本身无其他来源即可产生正功、开放环境热/法力回收，或允许死者派生程序独立提款，则会改变玩家可用行为、资源风险和现行 ADR；届时须先给制作人通俗比较、跨模块影响及推荐理由，不能在本轮审核中暗定。完整方案闭合后再交制作人审阅；此前不选开发切片。
