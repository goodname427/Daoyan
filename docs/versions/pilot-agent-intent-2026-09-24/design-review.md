## 已核对的设计

- [意图对齐记录](./intent-alignment.json)把属性驱动、统一实体、资源守恒和事件化法术作为共通原则；减速、破防、法球碰撞与追踪只是检验例子。[唯一世界理论](./world-theory-draft.md)及[五份模块细则的汇总](./module-design.md)分别说明自然接触与付费作用、资源来源与去向、实体存在与生命、程序能力与授权、现实输入与世界请求。旧[整版策划](./world-rule-design.md)仅是待复核的历史解读。
- [主策审核记录](./design-review-findings.md#相邻玩法及指定反例账本)逐笔核对接力护送、自修复信标、`100/20` 储备挪用、失供与额外注能、创建者死亡、场外及连续碰撞、遗体再损和回收套利。修士、法球、稳定物、机关与人工生命按结构、来源、权限和事件判断，不由实体名称获得免费效果。
- [玩家往返合同](./design-review-findings.md#推演台演武场同一法术书)涵盖推演台编辑、预算、单步推演，演武场绑定与观察，再回同一法术书修改，以及成功、拒绝、空状态和鼠标、键盘、手柄、AI、实体事件的等价请求。现有代码与测试只证明旧原型的局部入口；本节点没有新规则的可玩体验证据。
- [旧实现与 ADR 对照](./design-review-findings.md#旧策划代码测试体验与-adr-对照)标明统一句柄、原子账和确定事件的可复用部分，也标明固定寿命、自动回复与驱动、动能致伤、三池换算及死亡后授权的冲突。新语义若获批准，必须先以 ADR 明确覆盖现行合同；旧法术与存档不限制原型期设计，但不等价转换须定位拒绝或隔离。

## 退回原因与补全要求

1. **共同价格和资源闭合**：[资源细则](./mana-ledger-design.md)与[程序细则](./programmable-spells-design.md)尚无可执行的法力到做功、材料改变、合法尝试价和静态上界合同。普通驱动取源、环境可用性及回收循环须用同一账本证明；未知价格继续标为“待定价”，不能作为零价效果。
2. **生命、材料与可表达域闭合**：[生命细则](./life-identity-design.md)的休眠、死亡与同一身份阈值仍未定义；[物理细则](./physics-material-design.md)的接触和材料精度未形成统一验收尺度。自修复信标在当前窄材料域内只能修复结构，无法组合出生命回路复苏，须选择可证明的表达边界，更新理论和模块验收，不能暗加专名修复能力。
3. **事件、授权与完整体验闭合**：同刻接触、补源、维持、临界、撤权和事件派发需要确定权威顺序；死亡后独立程序的期限、额度、字段权限及容量需要一致的跨实体合同。[桥接细则](./player-bridge-design.md)应把失败余态、私有信息和可见账目接到推演台、演武场的同一体验链。旧 UI 帧序或实体类型不得代替世界规则。

[审核记录的六类比较](./design-review-findings.md#六类已选方向后的闭合问题)已给出候选方案、玩家效果与代价。主策应在制作人已选方向内采纳或修正推荐，补齐阈值、报价、反例和跨模块接口；确实超出已批准方向的产品冲突或不可逆选择，再以通俗的 A/B 体验、优点、代价、跨模块影响及推荐理由提交制作人。补全后的**同一篇**世界理论和模块方案再交制作人审阅。此前不选开发切片、不制作预设、不改敌方修士或游戏代码。
