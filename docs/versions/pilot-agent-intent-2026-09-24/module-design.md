## 整链核对与复审焦点

1. **物理、资源、生命。** 自然 `C/N→X` 与法术 `Tx↔A/X` 分账；物理包、反作用、热和逐种材料先有可取下界，资源再按同版本和 grant 报价付款。生命只消费已提交的结构和到期到账事实；后阶段补源不倒填前一维持窗口。没有包来源时不能用法力余额补出正功，也不能以欠费直接宣告死亡。
2. **程序、授权、事件。** 装载、唤醒和每笔提交重验逐体容量、记忆、付款与 grant。`DeathBarrier` 正证才撤派生权；创建者死亡不抹法球或机关的物理结构、既有余额与惯性。旧 `mdq` 的 `9/7/14 tick` 和 J1 `0 B` 方向槽已由 `mds-capacity-1` 与理论中的 `10/6 tick`、`64 B` 槽及完整路径预算取代；逐体容量仍须实测才能签装载成功。
3. **未点名情形。** 接力护送 H 把获准感知、有限方向记忆、承力施力和自然接触组合；自修复信标 B 把接触、封闭转入、获准读取和惰性壳修复组合。同一程序交给修士、球、机关或人工生命，按结构、账户、授权、材料和版本判断；缺能力、无权、欠费和物理缺证要给不同结果。修壳不自动恢复原生命身份；同一动能或回收余量不能重复记账。
4. **玩家入口。** 推演台编辑同一 AST 并显示条件预算与明确拒因，演武场按同一法术书绑定、触发并观察交易/事件，返回修改后以新 hash 重报价。获准空读可以付读价；无权与不存在目标不泄漏私有事实。旧 DSL/蓝图、预设、敌方修士、绑定和存档须按[桥接策略](./player-bridge-design.md)逐项等价、重写或隔离，不能让旧价格和专名效果绕过新合同。这些仍是设计中的玩家流程与验收情形，并未实际体验。
