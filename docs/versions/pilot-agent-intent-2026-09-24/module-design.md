## 跨模块合同核对

1. **自然事实与付费事实分别记账。** 物理层先记录自然运动与接触 `C`，包括双方冲量、材料损耗和环境去向；球上事件唤醒的法术若通过授权与报价，才由资源层记交易并由物理层记新作用 `A`。接触本身不免费追加旧 `damage` 池伤害，后续术式失败不回滚已发生的接触。[物理细则](./physics-material-design.md#默认演化与唯一结算)、[资源细则](./mana-ledger-design.md#事务顺序及跨模块接口)。
2. **来源、能力与生命分开。** 主动起步、推进、修复和读取从获准来源付款；已付惯性继续按默认物理演化。资源层保管余额与来源凭证，物理层保管材料 `X`，生命层依据已提交的结构和供能判回路状态。`M=0`、HP 摘要、固定寿命或创建者死亡均不能单独抹除实体或判死亡。[资源细则](./mana-ledger-design.md#逐笔记录与守恒)、[生命细则](./life-identity-design.md#存在生命与施法是三个维度)。
3. **程序只请求获准的世界作用。** DSL 与蓝图共用 AST；分析器、报价与 VM 使用相同原子和价格语义，神识记有限状态，tick 记程序工作，默认物理步长 `Δt` 不是 VM tick。事件只携获准字段；多请求在最新共享余额、授权及材料上重验，预检失败不留下本笔世界作用。[程序细则](./programmable-spells-design.md#唯一程序合同与状态所有权)、[资源细则](./mana-ledger-design.md#事务顺序及跨模块接口)。
4. **现实输入不成为世界公理。** 鼠标、手柄候选、AI 与实体事件只传设备无关意图。固定世界初态、执行实体、权限、账户、目标、模拟时刻、事件先史及随机种子时，世界结算应同价、同效果、同失败余态。UI 探查、暂停、配置与表现不能赠送目标私有信息、法力或额外模拟时间。[桥接细则](./player-bridge-design.md#设备无关意图与统一请求)、[理论正文](./world-theory-draft.md#现实桥接与同一世界请求)。

两项未逐条点名的玩法用于交叉验收：**接力护送**要求同一程序在修士、法球和机关上仅因结构、授权、来源与记忆能力产生差异；**遗体旁自修复信标**要求零余额时先由获准来源转入，再付读取与局部材料改接价，缺材料、越权或回路不可恢复时给出不同余态。两者均不能靠载体专名或 UI 特权补齐。[理论反例账](./world-theory-draft.md#跨实体与边界反例的交易明细)与六份细则提供规则和验收轨迹，**没有**新规则已在游戏运行的体验证据。

## 设计审核须闭合的边界

- 六项方向选择已写入[理论正文](./world-theory-draft.md#六项选择在同一模型中的含义与硬缺口)并分别落到模块；有效质量/接触/材料采用 A，普通驱动、法力做功/环境/回收、生命/身份、元法术最小集、程序载体/授权采用 B。选择限定论证方向，未给出可执行价格、材料粒度或身份阈值。
- **待证明后才能开放的作用**：`M→冲量/结构` 报价及算法工作量、普通身体驱动的来源与补给、环境可用性和回收上界、局部材料改接域、合法尝试价。未知报价标“待定价/不可表达”，不能当零价；已付散逸直接回收仍不在候选表达域。
- **待统一时序与身份合同**：同刻补源、接触、维持、死亡及事件的权威顺序；休眠复苏是否同一身份；死亡后独立程序的授权期限、事件字段和载体容量。模块稿将它们列为待审核，不以旧 `alive`、HP 或固定 `life` 字段替代。
- **待玩家入口合同**：瞄准与 UI 公共字段、手柄及按键映射、暂停期间意图缓存和恢复序、动态账本可见粒度、旧原件隔离/拒绝与回退。当前推演台、演武场只证明旧法术书的编辑、预算、绑定和战斗往返；新材料、生命与跨实体程序不可称为已可玩。
- **现行决策影响**：候选双边可损接触、有源普通驱动、结构寿命与新账户域与 ADR 0017–0020 及现行代码的局部合同冲突。保留可复用的统一句柄、授权裁剪、原子预留、确定事件和终止去重；新规则若通过审核，须明确 ADR 覆盖、旧法术/存档原件及不等价诊断。原型期不以兼容约束新理论，本节点不修改代码、旧 ADR、预设或敌方修士。

主策下一门禁应按上述合同交叉反证，尤其检查一个作用是否同时要求未证明的材料、价格或授权。若仍需制作人取舍，材料须用通俗文字写明各方案的玩家效果、优势、代价、推荐选项和理由；不能把 `A/B` 字母或代理验收当作制作人已认可全部规则。设计审核与必要的制作人复审完成前，不选择开发切片或启动游戏开发。
