# dev-world-a3：World/VM 首批三行为接入与实测

## 范围与接入

问题：旧 World 的 `movePower`、自动回蓝、固定寿命和 `hitProjectile`/`damage` 无法充当本批有限世界事实。范围是 J1 一次有源杆推、D1 一次有源起步、B1 自然首撞后 B4 一次普通惰性 `k0` 壳修。非目标是续步、攻击、重复法球付费响应、更多预设、敌方修士和关键回路或旧 `LifeId` 复苏。

`src/core/metas/firstBatch.ts` 把阶段和原读注册成共享元法术；原 DSL 经 `parseSpellbook`、`compileProgram` 的规范 AST/hash 进入 `VM`，VM 将扣款委托给 `World` 的逐 payer 账本。这九个有界执行入口标记为 `internalOnly`：`getMeta`、编译器和 VM 仍可调用，`publicMetas` 不将其列入玩家公开目录，因此现有 94 项元法术参考不因尚未接入 UI 的开发入口而变化。`World` 持有实体、重力势能来源、有限能量与材料 lot、热汇、锚、授权、容量、同版原读、付款收据和自然接触事实。`src/core/canonical.ts` 生成规范 AST 的 SHA-256；`b4Audit.ts` 定义 B4 固定 19 笔读的投影、价与先序。首次接触只由 `advanceNaturalContacts` 计算双端冲量、耗散、材料阈值和 `C→N→X`；B4 锁与作用只接受该自然 `X` 的来源证据。旧命中/HP 不参与这条新路径。

读端只验证 World 已登记的同版事实。J1/D1 的热 R0 在 VM 取得来源之前付款；主源/包、独立辅源/工作 lot、热/环境、锚和 D1 足/砖 `c1` 均按 readId 保存每端 `{value,error,version,grantId}`。B4 的审计回调被 World 库存、身体证书和同版校验约束；仓缺席、伪造数量、阈值或 gap 均不能凭回调创造读值。付款先后与事实提交依阶段固定；已发生的自然事实及付款不因后续失败回滚。

场景 `reset()` 清除有限世界登记、会话、锁、自然身体和接触、转移事实及付款收据，并重新开放初始来源登记和接触策略；实体数字句柄计数仍跨 reset 前进，避免旧句柄指向新场景。J1/D1 容量证书登记时须与执行体当前材料结构版本相同，会话准入及每次读/阶段执行前再次核对，执行体在期间自然破壳便停止后续动作。B1 破壳只接受归属该身体的附着与碎片 lot；B4 计划、锁和作用把目标 ID、自然 X、身体绑定的附着 lot、lot owner、数量与结构版本联核，不能将 A 的壳修记入 B 的 lot。

## 失败余态与适用边界

World 拒绝无势能来源、无权、隐藏/失鲜、未知价版或容量、无废料容量、同一 lot 竞争、无锚、无 D1 接触证书、读值伪造与 POST 失证；已付读/装载和先前自然 `C→N→X` 留存。B1 热汇不足时接触整体拒绝，速度与材料不变；正数面板缺附着或碎片任一库存时，阈值虽达到也只签双端 C，材料结果为 unknown，不扣附着量或签 N/X。若一端已有库存证据并破壳、另一端未定，先扣已证形变功，具名热汇只暂存剩余耗散；总形变与实际热量仍标未定，不能将暂存额冒作实测热。若候选形变功超过总耗散，则撤去该接触的临时材料转移与 N/X，保留双端 C，材料标未定，耗散暂存于热汇。缺 X 的壳修拒绝。同刻多接触没有组证书时给确定失败余态；同一共享材料 lot 按端序扣减，第二端不能重复取得。死亡使须随 issuer 存活的授权失效；事件先提交再按授权裁剪。B4 重放不再扣第二次法力或制造第二个修复事实。定向测试和无头边界脚本覆盖这些分支；本轮未声称域外扩展语义已实现。

本次没有发现需重新决定的已批准世界规则冲突。上述边界的失败是明确条件和确定余态，不再把先前实现缺陷称作“规则未闭合”。旧通用 `hitProjectile`、自动回蓝和固定寿命仍供域外旧玩法使用；本批新事实走独立显式来源与成本，UI/Battle 按键尚未接入，不能将旧原型响应列为本批成功。

## ADR 与验证限制

[ADR-0024](../../adr/0024-自然接触与旧运动命中语义覆盖.md) 覆盖 ADR-0018 对旧自动 `Wm`、三池能量、固定寿命和 damage/HP 自然命中的解释；已付惯性、传送原子性和来源守恒仍有效。ADR-0017 的统一句柄/能力、ADR-0019 的字段读权与正价、ADR-0020 的先提交事件与死亡撤权继续约束新链。旧 VM Actor 付款仅留给域外旧元法术；本批阶段/原读通过 World 逐 payer/grant 收据付款，按键耦合不进入核心入口。

当前沙盒对 Vitest 配置及 `tsx` 所需的 esbuild 子进程返回 `spawn EPERM`，故本轮没有正式 Vitest 或 `npm run docs:check` 通过证据。Node 24 的仓库外临时 loader 直接执行 `test/entity-vnext.test.ts` 中 14 个相关测试体和实际元法术参考生成脚本的 `--check` 模式，后者确认公开目录仍为 94 项且现有参考页同版；`node scripts/check-docs.mjs` 也退出 0。审核发现的 `world.ts` 空值过滤使用了 `!= null`，现改为分别严格比较 `null` 和 `undefined`；类型、定向 lint 与格式检查结果记于任务证据。快速/完整门禁由调度器在本 Agent 退出后执行。此前秘书 dashboard 20 秒超时属于控制面，按独占写入合同留给原 PM 修复，不以本任务代码签销。
