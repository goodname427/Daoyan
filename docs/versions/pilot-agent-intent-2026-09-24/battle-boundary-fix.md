# DV01：旧活动 Battle 首批三术缺证拒绝修复

## 问题、范围、非目标与验收

DA06 的独立策划实玩发现 DV01：旧活动 Battle 将 `J1执行` 绑定鼠标左键后，界面没有稳定公开缺证拒因，全场施法统计又会随妖兽行为增长，玩家无法区分“本次 J1 被拒绝”和“其他单位施法”。本修复只统一旧 Battle 对 `J1执行`、`D1执行`、`B4修壳` 的准入边界，并补直接自动化与开发复走证据。

验收以三术在任何旧 Battle 来源进入 VM、控制会话、付款和成功记录之前被拒绝为准；玩家须看到缺少同版来源、授权和容量证书，并能把无关妖兽施法造成的全局统计变化与本次拒绝分开。普通沙盒与演武场内独立有限世界观察的职责不变。

本轮不实现 TB02 持久截图能力、TB03 六入口选择器或 TB04 隔离旧档/窄屏/控制台能力，不引入活动波次有限世界迁移、持续移动、攻击、第二次 B4 付费响应或任何新世界公理，也不修改策划验收结论。

## 受验代码树与修复边界

- 基线：`a41c0b8f59ca45ba9ac55b12477d53d05f012431`
- 五份实现/测试差异指纹：`5897f31734cf03fd623c1130ccff83a76ac268e0`，由 `git diff --binary -- src/game/battle.ts src/app/CombatView.tsx test/combat.test.ts test/render.test.tsx e2e/candidate.spec.ts | git hash-object --stdin` 取得。
- `Battle` 只有一个首批三术拒绝函数。槽位触发、鼠标/键盘等槽位标签、妖兽 AI 槽位和实体事件响应都在创建 VM、控制会话或付款前进入同一拒绝分支。
- 每次拒绝留下独立的失败记录：法术名、来源、统一公开拒因，以及 `vmCreated=false`、`controlSessionCreated=false`、`manaPaid=0`、`successRecorded=false`。事件来源仍产生失败响应，不产生成功响应。
- 界面把原“施法”改称“全场施法起手（含妖兽）”，并单列“旧 Battle 首批拒绝”。拒绝卡明确显示本次 VM、控制会话、玩家法力扣除、有限世界付款及成功施法记录均为 0；全场数字随后被妖兽改变也不会冒作三术成功。
- 重开 Battle 清空本局拒绝记录，不改变普通旧法术、普通沙盒或独立有限世界观察的执行合同。

## 定向自动化

- `test/combat.test.ts`：覆盖三术直接槽位、鼠标输入、任意槽位标签、妖兽 AI 标签及实体事件来源；直接监测 VM/控制会话工厂未调用，并核对玩家法力、账本付款、活动 cast、控制记录、世界作用事实与成功统计不增加。另有反例证明普通妖兽施法可继续增加全局统计，而 J1 拒绝记录仍为失败。
- `test/render.test.tsx`：从真实 `App` 加入三术，绑定左键/数字 1/数字 2，触发后核对统一拒因、0 副作用、无活动 cast、无有限世界收据，并核对含妖兽的全局统计说明。
- `e2e/candidate.spec.ts`：增加同一候选路径，包含鼠标 J1 复现、D1/B4 键位触发、账户/收据/活动 cast 断言和页面截图附件。

标准 Vitest 与 Playwright 命令最初在加载 Vite 或启动进程时被宿主以 `spawn EPERM` 拒绝，未进入断言；历史失败退出码完整保存在[任务证据](./tasks/development-dev-battle-boundary-a1.json)。当时作为不放宽断言的直接补证，一次性 Node bundle 对当前源码实际执行同组 Battle 断言并通过：三术和五类来源均被拒绝，VM/控制会话创建数为 0，玩家法力 `300→300`，payer 已付 `0→0`，成功施法起手 0，三条事件响应均为 `failed`。临时脚本和 bundle 已删除。

2026-10-04 在集成修订 `da0ad4709155c1f697c35e952e3e1ecf39ad530b` 复核五份受验实现/测试文件仍与原修复提交 `c80f240` 一致后，只补跑此前未进入断言的标准定向自动化：`npm test -- test/combat.test.ts test/render.test.tsx` 退出 0，2 个文件共 70 项通过；`node scripts/run-playwright.mjs test e2e/candidate.spec.ts --grep "candidate-old-Battle-rejects-first-batch-spells"` 退出 0，Chromium 场景 1 项通过。Playwright 的本地报告、通过状态和截图附件路径一并写入任务证据；未重跑已匹配的类型、Lint、既有实玩或完整门禁。

## DA06 实际应用复走

2026-10-03 使用当前源码通过仓库现有 esbuild 可执行文件生成一次性浏览器 bundle，以 `127.0.0.1:4318` 本机回环地址打开；该 origin 为本任务临时隔离存档，未使用 Electron 默认用户目录。操作完成后页面、服务与临时目录均已关闭/删除。
