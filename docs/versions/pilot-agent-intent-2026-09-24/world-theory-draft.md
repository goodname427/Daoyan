# 道衍世界的统一理论（策划草案）

**版本**：`pilot-agent-intent-2026-09-24` · 策划修订 `2` · 范围修订 `13`

**状态**：策划修订 `2` 的立项评审已获批准，制作人已给出 `A/B/B/B/B/B` 六项方向。上一轮六份模块稿的交付不等于本轮通过；[主策审核](./design-review.md)以 `changes-requested` 退回详细策划，特别要求闭合 F3 的信标表达边界与 F4 的共同因果和价格阈值。本文是本版唯一可编辑的世界理论正文。本轮在已批准方向内给出可反证的同刻顺序和限制域；参数、身份规则、不可逆架构及完整方案仍待审核，不得据此开始游戏开发。

## 摘要：我们究竟在解释什么

道衍不是“所有变化都由法术造成”的世界。世界即使没有施法者，也按自身规律演化。实体是世界中可辨认的局部结构；生命是其中能自主取得来源、维持关键组织的一类过程。法术由具有执行能力的实体发起：它把法力从某账户转给世界或其他实体，经过时间和权限检查，换取一次有界的世界交互。现实玩家的鼠标、键盘与屏幕只是向这个世界传达意图并展示结果的桥接。

在这个框架下，**伤害既不是法力，也不是宇宙中漂浮的“伤害点”**。世界里实际发生的是结构、运动或功能状态改变；“受伤”是这种改变削弱了实体原有组织或能力后的判定。没有法术的碰撞也可能造成损伤；法术则可以付费制造导致损伤的作用。生命与非生命实体都能受损，但只有生命有“死亡”；实体失去可辨认结构叫瓦解或消失，二者不必同一时刻发生。

**这篇理论的用途是支撑可编程世界。** 解释一个现成法球只能证明该例子说得通；还须让玩家用同一组可调用的基础能力，把感知、判断、动作、事件响应和状态记忆组合成我们未命名的法术。若某个效果只能靠新增“追踪球”“反伤盾”“自爆”专用接口实现，理论对游戏的核心承诺仍不合格。

范围修订 `13` 的制作人反馈是“大方向基本差不多”，委托主策与策划补全细节、用反例检查；随后批准策划修订 `2` 的**立项评审**，要求继续详细策划。该批准不等于认可本文全部候选公理、参数、不可逆架构取舍或启动开发。下文的“应/须”表示待审核的推荐合同，不表示当前代码已满足。

## 一、最少的世界前提

以下是**候选公理组**。空间、时间和状态是描述世界不可缺的语言；“熵方向”及其与法力的关系仍须制作人评审。

1. **状态与因果。** 世界在模拟时间 `t` 有完整状态 `W(t)`：空间关系、材料与组织结构、运动、各处法力、程序/记忆、控制权限及环境条件。状态变化必须有可追踪的先因；世界事件是已发生变化的记录，不是另一个无源力量。
2. **默认演化。** 没有施法请求时，世界依自身规则 `N(W, Δt)` 演化。惯性、接触、材料变化、扩散和自然局部形成均属于此类。候选的熵方向要求封闭系统的可用差异不能凭空增长；局部有序可以靠外部差异形成，不能据此断言“任何东西都自然掉血”。
3. **法力只转移。** 每笔法力交易同时记来源减量与接收处增量；世界也是明确的接收方。所谓费用、损耗、溢出或散逸须说明进入哪个环境账户。守恒的是总量，**可用性**可能因分布变散而下降；否则付给世界后立即无损吸回，会制造永久免费做功循环。
4. **法术是付费干预。** 具有执行结构、程序、授权和可支付来源的实体可提出术式请求。世界按原子元法术检查目标、权限、法力、执行时间与状态，原子提交读取或效果。组合逻辑由普通法术表达；一个可组合的“追踪”或“爆炸流程”不因常用而变成元法术。
5. **组织决定能力。** 实体的储法力、收集、感知、移动、执行、修复和抵抗能力来自其实际结构及状态，不由 `Actor`、`Projectile`、血肉或非生命标签赠送。授权决定可否动用能力，余额决定能否支付，结构决定能否承受效果。

形式上可把一次世界推进写成：

```text
W(t + Δt) = NΔt(W(t)) + 按因果顺序提交的合法术式状态转移
法力交易 = (来源 - m，接收处 + m，效果或获准读取，耗时 τ)
```

`+` 在这里表示有序组合，不是把整个世界化成一个可任意相加的数字。每个术式都应给出前置条件、效果、来源/去向及失败时的原子性。若闭环回到完全相同的世界状态、法力分布和可用差异，就不能额外留下伤害、运动、情报或结构；否则存在无源效果。**熵方向不能单独推出所有转移函数或价格**，材料规律和具体原子效果仍需定义。

### 跨模块因果与账户：同一笔事实只有一个所有者

`W` 至少区分运动与有限形状、材料/连接/功能结构 `X`、各账户及环境分区的法力 `M`、可取得来源及可用差异 `U`、执行结构/有限记忆、授权和已提交事实。`U` 是策划为检验做功与回收提出的账本约束，不是可与 `M` 相加的“第四种法力”。接触、热、自然失稳、已付冲量后的滑行由默认演化产生；主动探查、转移、驱动、施力或改结构必须指出执行者、付款账户、获准来源、受益与反作用、模拟时刻及工作量。普通驱动选择 B 的含义是**主动驱动也从有来源的 `M` 付款**；它仍可通过身体或机关的真实结构将作用施于地面，不能把驱动改称“基础功率”后免费补给。自然求解的计算步长不作为角色的施法 tick；程序读取、判断和世界请求的工作计 tick，记忆/订阅占有界神识或实体结构容量。

一笔合法请求先核验实体的结构能力与字段权限，再给可支付价格和可观察失败边界；报价不得泄漏未获准的私有状态。读取只是带时刻、获准字段的快照；世界效果由资源模块记唯一交易 ID，物理模块记唯一作用/接触 ID，生命模块从提交后的结构和来源判状态，程序模块只接收获准事实。预检失败不写本笔效果；已经提交的自然接触、先前读取或转入不因后续请求失败而回滚。事件信封不赠送新冲量、材料、法力或私有探查；多个响应在最新共享余额上稳定排序。相同 `W`、事件先史、授权、请求、模拟时刻与随机种子，对修士、法球、机关或人工生命采用同价同失败合同；差别只由实际结构、材料、来源和权限解释。

### 同刻权威顺序：F3/F4 的共同因果合同

以下是**本轮策划推断的权威候选顺序**，以模拟时刻和单调世界序号排序，不以渲染帧、回调先后或实体数组顺序排序。同一模拟时刻 `t` 的各阶段只读取此前已提交的状态；已提交事实不倒带。阶段内的并列请求按进入世界时确定的序号串行，每笔在最新共享余额、结构和授权上重新预检。若真实物理接触的先后不能由时间及接触 ID 稳定确定，物理模块须给同初态可复算的确定性规则；不能让平台遍历顺序决定谁先死或谁先领款。

1. **自然接触与默认演化**：先求解 `N(W, Δt)` 中到期的运动、接触、形变、散逸，提交唯一 `C` 与材料/动量去向；由此失去的执行结构立刻使后续请求缺能力。接触信封暂入队，不同步运行术式。无真实接触的擦边没有 `C`。
2. **事先获准的到期补源**：处理在 `t` 之前已有授权与来源声明的转入。逐笔查来源可用量、容量、授权与报价，来源总转出覆盖净转入、启动价和散逸；失败不造余额，也不偷读私有值。由本刻 `C` 才触发的信标 B3 不在此阶段抢跑，留到事件阶段。
3. **已到完成时刻的主动作用**：依世界序号让到期攻击、驱动等请求逐笔在自然结果和已提交补源上复检、付款及原子提交。`100/20` 的最后一击若与下一维持窗口恰好同刻，攻击在此阶段先尝试；若自然接触已毁执行结构或前笔用尽授权/余额，则不提交。旧快照不免复检。新申请的授权最早在下一逻辑边界生效，不能在本刻回填先前拒绝。
4. **到期维持与继续失稳**：以阶段 3 后余额依序结算各维持义务；预先补到的来源可用，未到或未经授权的补源不可预支。失供只提交本窗口未维持与结构退化，不直接等同死亡；已提交攻击和自然接触不退款。窗口早于攻击的情况是较早的模拟时刻，先按其真实时刻结算，不能套用本段同刻优先级。
5. **生命与身份判定、撤权和清理**：生命模块据最新关键回路、来源及连续记录发布存活、休眠、不可恢复死亡或身份未知事实；余额零、HP 零不单独决定身份。确定死亡或结构失效后，先撤来自该主体的未来提款、控制、派生授权及失效订阅，幂等结算未用预留。首批关闭控制者死后继续运行的独立授权：`postDeathGrantUnavailable`，可执行期限、额度和响应次数均为零；仍有自己生命、账户与授权的其他实体不因此自动死亡。未知身份不暗授原主体私权。
6. **事件派发与响应**：仅在上述事实与撤权提交后，按 `(simTime, worldSequence, subscriptionSequence)` 对提交时已存在的候选订阅逐个复检结构、授权、字段、队列和最新余额；先前自然 `C` 不因拒绝响应而消失。响应中的每笔转入、读取、修复或施力另有交易/作用 ID，按程序先后付款；响应改动结构后须在下一响应或下一逻辑边界前重新判生命及撤权，不能用事件前身份继续私有读取。事件后继排在当前候选之后，不能递归抢在接触结算前。

此顺序给出**可证明的相对先后**。现行整合以[物理 `physical-mdq-1`](./physics-material-design.md#正功逐体材料与回路证书mdq-physics-有限候选)、[同版资源交叉证书](./mana-ledger-design.md#正功来源材料扣回与报价交叉证书mdq-mana)、[生命 `mdq-life-1`](./life-identity-design.md#mdq-life-逐体签证从物理与净到账导出判据)及[载体 `mdq-program-1`](./programmable-spells-design.md#carriercapacitycertificate-mdq-program-1逐体分项峰值与换证)为准。接触未裁定不产生命中事实；连续证据不足返回 `unknown`；死后独立授权首批关闭。域外读取、维持、关键回路编辑与自由回收仍不可执行，候选尚待整版审核，不是现行代码或已覆盖 ADR。

### 共同报价与唯一因果记录（本轮策划推导）

五份模块细则共用下列**部分函数合同**，不各自为“移动”“伤害”或“修复”另定价格。请求描述符 `D = (作用种类, 目标与获准字段, 材料域及局部区域, 期望状态差/冲量, 持续窗口, 反作用接收方, 执行结构, 付款账户及授权, 来源分区, 模拟时刻, 已获准快照版本)`；它只含报价者获准观察的输入。实体种类、UI 设备、预设名称、死亡换伤害标签都不是折扣参数。目标抗性、距离、材料承受、环境可用量若会改变价，必须是获准且新鲜的报价输入；缺失时返回 `待定价`，不能由隐藏私值推断价或按零价通过。自然接触不调用法力报价，但须交物理来源与去向。

`Quote(D, W可见) ⇀ (m毛支出, τ执行工作, s峰值状态, 动态依赖, 静态上界, 作用上限, 合法尝试价规则)` 是仅在**已定义的窄作用域**内有值的函数。`m` 用法力最小账本单位 `M`，`τ` 用整数 VM tick，`s` 用神识/载体容量单位；持续与期限用模拟秒。冲量用有效质量乘速度的单位，做功与耗散用同一有效能量单位；`X` 记材料种类、数量、连接和功能裕度，不与 `M` 相加；`U` 是已有 `M` 中在固定授权下可取的子集上界，不是另一份法力。[P0](./mana-ledger-design.md#单一-quote域与静态证书)给 `D0` 施力、惰性改接和指定封闭转入纸面证书；[R0](./mana-ledger-design.md#r0字段投影范围与实际观察工作)给获准有限读取，[K0/V0](./mana-ledger-design.md#k0v0关键回路维持与保存不借控制租约)给已登记回路的到期维持/保存独立证书。它们共用报价、互斥预留、毛预算和世界序号，**不共用系数**；不存在从 P0 推出的免费读取、生命价或任意材料价。域外感知、未登记回路、超出下述 `M1/A1` 已证窗口的身体代谢与开放回收仍为 `unknownPrice`/不可表达。报价若含动态项只报条件和保守上界，无法证明有限上界就显示动态/无界；任何静态资源上界均不得低于同输入实耗。每种原子作用必须证明价格为正、作用有界、来源可付和回收环不增可用余额，才能把相应 `D` 加入可执行域。域外材料返回 `不可表达`，不得借通用“改结构”或旧 `damage` 池绕行。

**成功与合法尝试的互斥结算。** 同一原子请求的成功价 `p` 与已报价的失败尝试价 `pAttempt` 是两个互斥终态；在进入可能收费的世界求证前，按 `max(p,pAttempt)` 从同一获准账户锁一次额度，成功从该锁额结算 `p`，已做合法求证而作用未提交时从中结算 `pAttempt`，其余解锁；无求证的拒绝全额解锁。成功价已含同一次求证，不再另扣尝试费。若预留后账户恰好为零，仍可由这笔预留支付本请求的尝试费；并发后笔只能使用扣除该锁额后的最新可用余额。任何已结 `Tx-attempt`、此前独立读取或转入均不因后笔失败回滚。未知尝试价、未授权来源或未能锁足互斥上界时不得先做收费求证；有限循环、事件与并发的静态毛界按每笔互斥最大值及可执行次数累计，不以退款或未来转入抵减。R0、K0、V0 与 P0 各自仅在已登记的合法世界求证后允许 `1 M/2 tick/S=2` 的候选尝试分支；无权、域外、公开欠费、未知价或尚未求证时为零本笔世界交易，已做本地 VM 工作仍计 tick。

到期回路只消费[K0/V0 窗口证书](./mana-ledger-design.md#k0v0关键回路维持与保存不借控制租约)的实际结算：K0 已登记 `e=3,r=1` 时毛 20、净达 12、`13 tick/S=8`，V0 已证保存态 `a=c=1` 时毛 8、净达 3、`7 tick/S=5`；两者不同时填同一功能窗口。阶段④分别按最新结构/来源/授权锁成功毛价，成功 `Tx-maintain/Tx-preserve ↔ A` 后由阶段⑤消费，欠费则无本笔成功 `Tx/A`，自然失供须另以真实 `N→X` 证明。阶段⑤由[生命模块](./life-identity-design.md#mdo-life-承接的-k0v0-证书与阈值)独占版本化 `LifeAssessment`：先判结构存在，再用关键回路裕度、到期净供给和真实 `X` 判 `viable/critical/dormant/dead/unknown`，最后以结构、记忆、控制三条连续链判 `LifeId` 的 `same/new/none/unknown`。样例 `h=2→1` 只有在有证的可达救援路径下为 `critical`；`h=1→0` 也须真实不可逆断接证据才能死；仅逾期或余额零不签死亡。死亡只发一次幂等 `DeathBarrier(L)`，先撤主体及派生提款、控制和订阅，再在阶段⑥派事件；原生命终结后 `LifeId` 不复用，遗体再损只增残余结构事实。未知身份冻结原主体私权，不把信标材料修补、旧 HP 或账户余额当身份凭证。

### `mdo-theory`：两条整链的有限证书复算

以下是 `mdo-theory` 阶段的**历史条件夹具**，用于追踪 H/B 的先后与余额；当前可签证边界、工作 tick、正功和材料余态一律以[下方 `mdq-theory` 同版整链](#mdq-theory四证书的同版因果链)为准，不能将本节表中的“成功”当成现实可执行结果。[账本 R0/K0/V0](./mana-ledger-design.md#获准读取与关键回路的独立资源证书mdo-mana-候选)、[账本 D0/P0](./mana-ledger-design.md#首批共同报价与来源证书mdn-mana)和[物理 D0](./physics-material-design.md#首批有限材料域与精度证书mdn-physics)的数字不是现行价格、全物种阈值或通用自动脚本。`Tx-read/transfer` 的 `A=null`；`Tx` 与主动 `A` 一对一互引，`X` 仅引用对应 `C/A/N`。程序本地判断/记忆另计实际 AST tick 与有限状态容量，不造第二笔世界观察或免费刷新快照。

**反例及生命/授权边界。** R0 以同一 `b=1,N=2,f=2` 获准空查询仍锁/实扣 9、做 10 tick、返回带时刻空集合；同请求命中数不改价。隐藏目标与不存在的指定句柄若无目标/字段权，在枚举前均给不可区分的 `deniedOrUnavailable`，无目标存在位、报价侧信道或本笔观察 `Tx`。球在 H1 后只剩 `0–11 M` 而 H2 需 12 时，本地欠费拒绝 H2，已付 H1、记忆和球既有惯性保留；机关没有真实施力部位/锚链则 `noStructure/noCapability`，即使账户够也没有 H2 冲量。B4 供应不足 `2q` 时 `missingMaterial`，不得先修一半，B1/B3/B2 不退；若是关键回路而非惰性壳则报 `unexpressible`，不能伪称缺料或低价修好。创建者在阶段⑤死亡时，其主体/派生 grant 和订阅先由 `DeathBarrier` 撤销；依此权能的球或信标阶段⑥拒绝 `grantRevoked/postDeathGrantUnavailable`，但惯性、先前 `C/X/Tx/A` 与自身材料留存；另一仍有效主体凭自己的账户和独立普通授权可继续自己的行为，**不继承**死者私权。信标请求遗体身份、关键回路、私有账户或越权结构值时 R0 域外或字段拒绝，B1/B3 不等于授予这些值；此前获准 B2 只含普通外壳字段。任何 `LifeAssessment=unknown` 都不发旧 `LifeId` 私权；确认死亡只发一次幂等 `DeathBarrier(L)`，以后遗体再损只添 `ResidualStructure/X`。保存态同 ID 苏醒仅在 K0/V0 已付窗口、未越不可逆界且结构、记忆、控制三链连续并有另行可报价的关键回路修复路径时才能重判；本信标 D0 只有惰性修壳，**原身份复苏域外**，后成新闭环须另签新 `LifeId`，缺证为 `unknown`。首批非零独立死后响应授权关闭，不让遗体剩余执行槽或旧 owner 绕行。

**准确断点与玩家影响。** 上述 H/B 数字只使证书夹具可复算：R0 尚未覆盖私有生命字段、任意范围/传感器，P0 尚未覆盖普通身体代谢，但本轮 A0/K0/V0 在有证脚地/回路窄域给了条件报价；未登记反作用和任意材料仍域外，转入只覆盖具名封闭来源；超域 `unknownPrice`/`unexpressible`，玩家暂不能写任意观察、驱动或修复。自然材料承受、真实接触轨迹和具体程序载体/容量若缺证，H3 或事件响应只能标 `unknown`/拒绝，不能演成必撞或必触发。K0/V0 已给已登记回路的窗口价及样例裕度，未登记物种阈值、超出 M1/A1 已证扰动的失供物理 `X`、记忆/控制连续损失容限和可修关键回路仍未闭合，玩家可看到临界/身份未定，却不能由修壳取得复苏承诺。首批死后 grant 为零，玩家不能编写死者遗留信标继续提款的程序；开放它需要另行审阅签发者、独立预付源、期限、额度、字段与撤销。旧 ADR 0017–0020 的 HP、`0.25s` 控制周期、三池/旧探查价、固定寿命及死后会话边界可能要新 ADR 明确覆盖；旧 DSL/蓝图/预设的探查、创建弹道、追踪、伤害和旧存档的 `hp/manaRegen/life/owner` 可能不等价，须隔离或决定迁移。此处只列影响，不批准新原子、ADR、迁移或游戏开发。

**组合闭合判据**：新行为若可由获准观察、有限计算/记忆、有来源转移、施力、允许范围内的局部结构作用与事件再启动组成，不加专名元法术。若做不到，先指出缺的是哪一种不可再组合的世界作用、结构能力或信息权限，并在可报价、可做静态预算及跨实体反证前保持“不可表达”。元法术选择 B 把可编辑材料域缩窄，不能借宽泛的“任意修复”暗开全材料写入；载体选择 B 以可核验的结构容量决定装载和运行，不能把“只有 Actor 能施法”改写成隐藏白名单。代码当前的 AST 唯一 IR、无头核心、静态上界不小于实耗、默认禁止递归仍是现行约束。

### `mdq-theory`：四证书的同版因果链

**问题、范围与状态。** 以下只整合[物理 `physical-mdq-1`](./physics-material-design.md#正功逐体材料与回路证书mdq-physics-有限候选)、[资源 `mdq-mana` 同版报价](./mana-ledger-design.md#正功来源材料扣回与报价交叉证书mdq-mana)、[生命 `mdq-life-1`](./life-identity-design.md#mdq-life-逐体签证从物理与净到账导出判据)和[程序 `CarrierCapacityCertificate mdq-program-1`](./programmable-spells-design.md#carriercapacitycertificate-mdq-program-1逐体分项峰值与换证)。本节不重定价、物理阈值或载池。重放键须同为 `(entityId, P/X/structureVersion, materialLotId, energyLotId, contact/anchorVersion, environmentVersion, grant/source/quoteVersion, programHash/ASTVersion, simTime, worldSequence, seed)`；生命另核到期/救援截止及结构、记忆、控制三链。**已证**指有限账式或失败不回滚的蕴含，**条件**指还须具名实测签证，**未知**指来源或测量缺证，**不可表达**指明确超出首批作用域。工作包和摄取包的上游装载当前无证；下列需要正功或摄取的成功流水只作条件复算，缺证的真实请求报 `unknownPrice/undeterminedEnergy`，不签 `Tx↔A`。

**共同因果。** ①物理对真实接触和有源自然失供分别签唯一 `C-id/N-id→X-id`，列双方动量、逐种 `Q[k]`、储能 `U物理`、动能 `K`、结构功 `S`、热声 `H` 与具名接收方；自然笔不扣 `M`。②事先获准补源签独立 `Tx-transfer-id`，来源毛扣覆盖净到账、启动与散逸；本刻 `C` 唤醒的转入留到⑥。③主动原子据最新物理描述符、结构/容量、字段 grant 和账户给 `Quote`，分别锁毛额、物理包与材料，成功同刻签 `Tx-id↔A-id→X-id`，目标与反作用体一起核算，失败释放未提交锁。④到期 K0/V0 另报另付；欠费或无包不造维持 `Tx/A`，真实梯度和材料响应才另签 `N→X`。⑤生命只消费同版已提交事实；不可逆终界及三链齐证才发一次 `DeathBarrier(lifeId, terminalXVersion)`，先撤主体和派生提款、控制、订阅、会话；缺证给 `LifeAssessment=unknown` 与独立的身份关系。⑥按 `(simTime, worldSequence, subscriptionSequence)` 对 `C/A/L` 的事件 ID 双时点裁剪 grant，再复检本体队列、程序、容量和账户；每个响应原子获取新 ID，队列满或后笔失败不回滚先前事实。只有已知成功价、足额预留、确做有界求证而被先序换版，才结互斥尝试价。`M` 付款不能直接生成物理 `E0`，逐种材料、tick 与神识各自计量。

### 世界的最小物理层：现实原则，抽象精度

制作人明确补充：世界存在近似现实的物理规律，两个实体会碰撞；修士移动也应来自施力，而不是输入直接指定坐标或凭属性值生成速度。**本理论推荐保留这种因果，但只模拟玩法需要的有效物理量**：空间中的位置和形状、结构决定的有效惯性、速度、接触、冲量、阻力及结构承受能力。质量和几何可用简化值代表，不必模拟分子、流体或全部真实材料。物理求解步长记为 `Δt`，表示模拟时间增量；`tick` 专指程序执行工作量。默认演化不向角色收取 VM tick，数值推进也不重新创造运动。

```text
无外力：速度延续；位置按速度推进
施力持续一段时间：冲量 J = ∫F dt；实体动量改变 Δp = J
两实体接触：接触冲量在二者之间交换；形变、摩擦和环境带走不可恢复的运动能量
```

这里的“力”不是一个新的法术名，也不是扣血指令。世界默认的接触、惯性、阻力、重力若存在、材料形变和热耗散无需逐帧施法。主动施力则必须回答**谁对谁施力、反作用给谁、可用做功从哪里来**：修士借地面反作用移动，普通主动驱动按选择 B 从有来源的法力账户付款；法球靠已付初始冲量继续飞行，主动变向再付费；机关借锚点推动屏障也须付款并把反作用交给地面。场地作为巨大反作用体可以在原型中不显示位移，但不能在理论上消失。

**法力账与物理功账不能互相冒充。** 选择 B 暂不设可与法力独立补给、兑换的普通驱动 `P` 池。肌肉的生理过程、机关马达和法术施力可以有不同结构与效率，凡产生新的主动驱动，都须从获准的 `M` 来源付款，并写明反作用、已做功及环境去向；“体力”“电池”若以后成为独立储备，必须先证明其来源和换算，再升级制作人。已付冲量后的惯性运动不重复收费。法力总量转移守恒；若付给世界的法力能换取运动、热或结构改变，须有可用性下降与作用上界，不能付费后无损收回同一份可用法力而保留动能。碰撞的机械能流向形变/环境热，动量流向地面或环境；这不是法力凭空消失。信息读取或方向控制即使几乎不增加动能，也有世界交互和执行成本，不能只用 `Δ动能` 定价。选择 B 先将尚无转换/回收上界的操作标为不可表达，不能把受限域冒称无套利证明。

**碰撞与损伤只结算一次。** 接触先改变双方运动和结构；若作用超过目标结构的承受范围才形成物理损伤。接触事件随后可触发球上已预付或有余额的术式，产生另一笔有来源的法术作用。若法球本身在碰撞中破裂，其已有结构或运动能量可散入环境；不能同时保留全部原动能、再从独立 `damage` 池释放同一作用并额外给一份“碰撞伤害”。简化碰撞可以使用二维圆形、有效质量与有限恢复系数，省略内部应力细节，但必须保持接触双方和环境的冲量及能量去向可追踪。

这套最小物理**是本轮推荐模型，不是已批准实现合同**。它与现行不支持动能致伤、允许 `Wm` 自动补给及简化位置分离的 ADR 0018/代码有冲突；在世界理论通过反例前，不直接修改运行时或宣称旧 ADR 被覆盖。

## 二、实体、存在、生命

**实体**是能够在一段时间内保持身份可追踪的局部组织，不是世界最基本的物质粒子。创建实体意味着从已有材料、法力和结构中组织出新的可辨认边界，并给它初始状态、程序与权限；“创建成功”不允许凭空给它伤害池、法力池、材料或寿命。结构彻底失去身份时，实体句柄终止；剩余物质与法力继续按世界规则存在或转移。

不同实体的存续来自相同问题：它在当前环境下是否稳定？若自然会散逸，失稳速率是什么？能否付费维持或修复？稳定石块或稳定材质造物可以长期存在，无需每秒法术；由不稳定术式聚成的法球可能必须持续维持，停止后逐渐散开。**法球的可施法余额耗尽，不自动等于球体消失**；球体结构耗尽也不自动表示其法力“消失”，剩余部分须有去向。固定 `life` 秒数若要保留，只能是由具体结构与环境推算出来的展示值，不是世界原因。

**生命**是实体中一种有边界的、自主维持关键组织的持续过程。它能从可取得的来源获得维持所需的资源，通过内部调节与修复在扰动下继续保持功能；意识、血肉、繁殖和施法能力本身都不是定义条件。材料自然代谢有实际来源与废物去向，不因默认演化而自动补给法力；凡维持回路使用术式或身体产生普通主动驱动，均从有来源的法力账户付款。生命维持程序若是自动术式循环，也要服从同一执行和账本规则。具备完整自维持组织的人工造物同样可以活着；只被外部不断注能的普通法球不因此自动成为生命。

**生命、休眠、死亡与身份分判。** 有自主取源和调节回路且仍在维持的实体是活体；供能暂断、结构尚保有可恢复回路时进入候选休眠状态，修复和重新供源可使它复苏。关键回路越过不可恢复边界才判死亡，但材料遗体、独立执行回路和残余法力仍可能存在。制作人选择 B 允许休眠/修复后的生命恢复，**没有批准“修好即同一个人”**：同一身份需要另定记忆/控制/结构连续性判据，越界重建可是一条新生命。余额零、HP 零、实体句柄终止、失去施法能力各是不同事实。熵方向尚不能解释第一种生命怎样形成；自然形成或法术创造都须交代初始材料、组织与来源。

### 维持生命的法力可以主动挪用

制作人提出的“100 点法力，其中 20 点必须留给自己，平时只能用 80 点；拼命时把最后 20 点也用于更强的一击，随后死亡”是对统一模型的重要检验。这里的 **20 不是不可触碰的专用生命值**，而是按当前身体状态、环境和下一次维持窗口估计的应付法力。账户仍只有有来源的实际余额；“安全可施法 80”是扣除近期维持义务后的建议额度。若维持费用随伤势或环境改变，安全额度也随之改变。

一种可核对的时序是：修士有 `100`，下一次维持需要 `20`；通常先保留 `20`，最多向攻击术式支付 `80`。若自愿向一记有界范围术式支付 `100`，这笔法力先从自身转给世界或目标并产生**实际定价且可扩大的效果**，而不是因为“必死”额外赠送伤害。按[同刻权威顺序](#同刻权威顺序f3f4-的共同因果合同)，已完成的攻击若与维持恰好同刻，先在自然接触后的有效结构上提交，再尝试本刻维持；若下一维持在较早时刻已使结构失效，后来攻击不能成功。余额耗尽但有事先获准的同刻补源时，可在攻击前入账；由同刻事件才触发的补源须等事件阶段，不能倒灌先前维持。维持失败后结构按默认规律退化，生命模块在阶段 5 依未决阈值判休眠或死亡，遗体是否消散是另一件事。即使失供与攻击落在同一模拟时刻，也不能凭“自爆”额外赠伤或让已失去执行结构的实体事后施法。

这不是修士专属的“自爆规则”：有储备和维持义务的人工生命也可作同样选择；没有生命维持义务的法球可以耗尽自己的余额而不必死亡，只会停止施法或在结构失稳时瓦解。若环境允许及时吸收新法力，付尽余额也未必必死；若要保证此招以死亡为代价，需要明确当前环境无法在临界窗口补足，或让术式同时主动拆解自身维持结构。后者造成的爆裂只能释放**确有储存的结构或运动能量**，不能再给一份无来源的“牺牲伤害”。维持窗口、可用补给和失稳阈值仍待定义。

## 三、伤害的本质

先区分四个常被混写的量：**作用**是一次碰撞、热、术式或其他影响；**结构变化**是材料连接、形态、位置或内部状态改变；**损伤**是这些变化削弱了目标原有组织或能力；**死亡/瓦解**是越过特定功能或身份阈值的结果。“伤害值”只是对损伤程度的简化读数，不是第五种从攻击者流向目标的物质。

设实体当前结构为 `X`，可定义一个或多个可观察的完整度/功能裕度 `I(X)`。当一次合法相互作用使目标的关键裕度下降，才称它受损；生命体失去维持循环叫死亡，非生命结构失去身份叫瓦解。同一实体可以在仍有材料、甚至还能施法时遭受局部损伤。夺走法力、眩晕或改变位置可能有害，但未必是**结构损伤**；不能把所有负面效果都偷偷映射为 HP 扣减。

### 两条致伤路径使用同一结果判定

1. **自然相互作用。** 高速碰撞可转移动量、产生变形和断裂；侵蚀、热与环境失稳也可改变结构。它们不需要碰撞者“施放伤害法术”，但必须遵循默认世界的动量、材料和耗散规则。稳定只表示在当前无扰条件下不自发瓦解，**不表示不可被打碎**。
2. **法术干预。** 施法实体付法力给世界或目标，调用有界原子操作，例如施加冲量或改变某种局部结构关系；世界据此结算后续相互作用与结构变化。魔法伤害由目标结构变化推导，不由一个 `伤害 = 18` 命令直接改写宇宙的 HP。修复同样须有材料、结构目标、法力来源和耗时，不能只是 `HP += n`。改变结构的元操作具体是什么、能否由更小操作组合，仍是开放问题。

因此，制作人提出的“法球碰到敌人 → 触发伤害法术”是一个**主动攻击设计**：接触事件提交后，球上回路使用自己的授权与余额施法，才产生约定的魔法效果。与此同时，碰撞本身仍可能造成符合材料和运动规则的物理损伤；若本原型忽略它，应标为战斗模拟精度的取舍，不能宣称世界里接触绝不会伤人。球碰撞后是否消失，还取决于它自身是否被撞坏或主动解构；命中不应直接删球。

护体或“装甲”应是结构或术式对作用的吸收、偏转、隔离机制。被挡住的动量、热或法力效果必须有去向，护体自身也可能损伤或付费；**固定减伤、最低伤害保底和全局威力倍率只是游戏数值约定**，没有解释机制前不应晋升为世界公理。HP 可以是玩家可读的功能裕度摘要；“HP 归零死亡”只是特定模型的阈值实现，不能替代上述生命条件。

> **当前判断**：伤害不是独立的本质元法术；它是有来源的自然作用或法术作用造成目标结构/功能退化后的结果。“改变结构”或其他致伤操作是否应有元法术、原子粒度和价格尚未论证，暂不把现有 `伤害(目标, 数值)` 当作最终原语。

## 四、从同一规律推导其余现象

| 现象               | 因果解释                                                                                   | 无源或失败时                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **创建法球**       | 从已有构成中组织结构，创造者付世界效果费，并按需向球体的结构储池和施法储池转入有限法力     | 无材料、无授权或付款失败则不创建；不会因为参数写了“法球”就凝结。                                     |
| **法球寿命**       | 构成与环境决定散逸；已付维持可延缓，稳定材质可长期存续                                     | 不稳定结构沿默认演化瓦解，余量转入明确环境账户；余额归零与瓦解不同。                                 |
| **法球飞行与追踪** | 初始冲量后按惯性运动；追踪由有来源的感知、计算和再次施力组成                               | 欠费停止主动感知/驱动，已有速度按阻力和碰撞演化。                                                    |
| **爆炸与最后一击** | 事件触发程序，把有限储备经有界作用分配到范围目标；生命体也可挪用近期维持储备扩大效果       | 储备不足时不免费释放效果；挪用后若维持失供，按生命规则失稳或死亡。自身结构自然爆裂另按已有储能结算。 |
| **法力恢复**       | 从已获准且可报价的有限环境、物品或另一实体账户转入自身，受来源、容量、速率、权限和时间约束 | 零可用法力不必堵死吸收：启动费可由来源总转出量承担；未声明价或来源耗尽则失败。已付散逸不可直接回收。 |
| **修士施法速度**   | 执行结构在单位模拟时间可完成的逻辑工作量                                                   | 快速执行缩短实际时间，不减少程序步骤或世界作用价。法球若有回路也有执行吞吐。                         |
| **算法优化**       | 减少实际读取、世界作用、工作状态占用或执行步骤                                             | 任意 `manaCostMul` 不能在效果不变、工作不变时免费折扣。                                              |
| **生命失供**       | 自主维持交易停止，关键组织按环境规律退化；可恢复区间可休眠                                 | 有来源的补给/修复可使生命恢复；是否同一身份另判。不可恢复临界后判死亡，遗体未必消失。                |

对五类实体的判定采用同一顺序：先看材料边界是否仍可辨认而判**存在**；接触或已付术式改变 `X` 后判**损伤/瓦解**；再看是否有自主取源与关键维持回路而判**生命/休眠/死亡**；最后检查执行结构、容量、授权和可支付账户而判**能否施法**。物体名称只供玩家阅读，不作为分支条件。

| 实体     | 从默认演化及已付改变得到的结论                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 修士     | 身体材料形成可辨认结构；自然接触可伤身，术式另付价。维持回路自主取源时活着，失供先退化/休眠、越过不可恢复临界才死亡；有执行结构、授权和余额才可施法，普通起步也须从 `M` 付款。                   |
| 法球     | 已有材料经获准组织与初始冲量形成球；稳定构成可长期存在，不稳定构成失供后散逸，碰撞可破裂。外部注能不自动使它成为生命；装得下程序、记忆且有独立授权/余额时可施法，创建者死亡不抹除已付惯性。      |
| 稳定物   | 石块或稳定材质球在当前环境无持续维持费，仍可被碰撞损坏；缺自主回路不算生命。仅在另有实际执行结构、授权和付款来源时才能施法，稳定或静止本身不赠资格。                                             |
| 固定机关 | 锚定结构可长期存在，也会损伤；它未必能平移自身，却可借推杆和地面反作用付费推动别物。自动执行不等于生命，自主取源并维持关键回路才可能活；程序容量与授权决定能否施法。                             |
| 人工生命 | 由已有材料和有来源的组织作用形成，具自主取源、调节、修复关键回路时可活；失供可休眠并在可恢复区间复苏，身份另判。其结构同样会受损；执行能力、权限、账户和程序容量决定施法，生命标签本身不赠能力。 |

## 五、可编程世界是否真的能产生未预设的玩法

**统一理论的验收对象不是一组示例法术，而是一套可组合的世界操作。** 每个玩家行为应能拆成五个环节：取得获准信息、在法术内部计算、对世界发起原子作用、保存有限状态、由时间或世界事件再次启动。语言可以为这些环节提供方便的写法；世界必须为它们提供跨实体一致的执行、付款、授权和失败合同。缺一环，玩家就只能编辑一次性效果，无法真正编写自主行为。

| 必需环节 | 共同规则                                                                               | 若只提供专用玩法接口会怎样                                                   |
| -------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 感知     | 实体按结构、距离、权限和法力价格读取世界状态；得到带时刻的有限快照                     | 只能查询策划预设的“敌人”或“目标”，无法自己定义威胁、友军或环境条件。         |
| 计算     | 条件、向量、数值、列表和自定义法术在同一 AST/VM 中组合，付出可核算的神识与耗时         | “追踪”“反弹”“散射”只能各写一个内置分支，算法优化失去意义。                   |
| 作用     | 创建、转移、施力、改变可说明的结构/关系等真正不可再组合的世界操作，按实际效果付法力    | 直接 `伤害(目标, 数值)`、设置寿命或整体改伤害倍率会绕过物理与生命因果。      |
| 记忆     | 由实体结构承载有限的程序、局部状态和已付资源，明确占用、控制权及失效条件               | 法球或机关不能记住上次接触、剩余目标和下一步计划，只能使用硬编码行为枚举。   |
| 再启动   | 创建者可把玩家编写的程序与授权交给实体；获准的接触、失供、定时等事件按有界顺序唤醒程序 | 事件系统即使在引擎内部存在，玩家仍无法写“碰撞时施法”“受伤后反制”或自主法球。 |

这里的**闭合性**很关键：一次法术创建的实体应能按同一规则持有程序、订阅事件、读取状态、付款并作用于其他实体；作用产生的事件又可唤醒获准程序。修士、法球、机关和人工生命可因结构、余额和授权不同而失败，不能因为类别不同而获得完全不同的语言。世界事件记录已发生的事实；订阅、过滤和排队是程序使用这些事实的方式，不能把事件当作无源伤害或免费持续探查。

例如玩家想造一个我们未命名的“碰墙一次后改追另一目标、撞敌后才释放范围效果”的球：创建者先用有来源的构成与法力生成可运行实体、授予有限程序和事件权限；球上定时程序付费探查、在本地比较目标并付费施力；接触墙的事实使有限记忆加一，后续程序据此改变选择；接触修士的事实唤醒另一段普通法术，从球自己的余额支付范围作用。余额耗尽时只停止付费行为，结构是否瓦解仍按世界物理判断。这里不需要名为“追踪球”“反弹球”或“爆炸球”的元法术，却需要真实可用的创建、记忆、绑定、探查和世界作用原子。**这条链目前不能由玩家从公开接口完整写出**，所以它是底座待证目标，不是已经交付的玩法。

**当前公开目录还不是这个底座。** [94 个公开元法术的参考](../../reference/meta-spells.md)按现有实现分为运算符 30、按键状态 4、状态探查 36、实体创建 1、实体控制 22、施法控制 1。它们是接口清单，不等于 94 条独立世界公理：

| 当前入口类型与证据                                                               | 对涌现式玩法的判断                                                                                                       |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 运算符、向量和 `结束施法`                                                        | 多数是语言/VM 操作，不应因为注册在元法术表就被称为改变世界的原子规律。随机数还需有可复现的世界随机源或明示为程序随机性。 |
| 四项按键状态；状态探查中的 `准星方向`                                            | 现实设备输入已渗入法术接口；应先转成设备无关的施法意图或获准上下文，AI 与球上程序也能得到相同语义。                      |
| 其余逐字段探查、`扫描敌人`、仅位置/生命监控                                      | 付费读取和快照有价值，但“敌人”与监控字段被写死；要检验一般的空间查询、字段权限及有界付费观察能否组合出玩家自己的筛选。   |
| 唯一创建入口 `创建弹道(起点,方向,速度,基础伤害,存活时间)`                        | 把生成、冲量、伤害和寿命包装成一种物体，不能据此创建具有玩家程序、事件和结构状态的通用实体。                             |
| `近战斩击`、`伤害`、三类注能池、法球推进/追踪/滑行、`设置存活时间`、整项属性倍率 | 有些是当前方便的组合效果或战斗数值入口，不满足“不可由更小操作组合”的元法术判据；须逐项追问底层作用、来源与可替代表达。   |

更直接的断点是[当前法术编写指南](../../reference/spell-authoring.md#当前能力边界)明确写着：玩家法术没有事件订阅、跨次施法常驻变量，也没有用户自定义实体类型；[`Battle.subscribeSpellEvent`](../../../src/game/battle.ts) 已在引擎内做 Actor 事件响应，却尚未成为玩家可赋予任意实体的通用能力。因此“世界可以派发事件”与“玩家能编程一个自行施法的法球”是两件不同的事。参考文档描述当前实现，不应被候选理论写成已实现的能力。

公开目录还缺能表达**通用法力转移/吸收、结构修复、把程序与有限状态交给实体、由玩家声明事件绑定**的入口。`调整法力回复`只修改既有数值，并没有说明法力来源；给 `创建弹道`增加更多参数，也不能代替通用创建与程序承载。拟增的原子作用须同时通过四项检验：它改变的是可描述的世界状态；不能由现有原子操作按同一效果组合；其能力、权限、来源和价格可在不同实体上解释；玩家能把其输出继续作为其他程序的输入。否则应是普通法术、语言功能或桥接适配，而非新元法术。

**用未预设的组合来反证底座。** 选取寻敌法球、碰撞后改变策略的机关、消耗自身维持储备的最后一击、吸收环境法力后修复自身的人工生命，以及玩家临时想到的一种新行为。对每个例子只允许调用同一组基础操作、权限、账本、事件和有限存储；若必须增设按玩法名称命名的元法术，就回到原子规则审查。预设法术和敌方修士最终可作为这些规则的示例与压力测试，**不作为玩家可做事情的白名单**。

涌现也有边界：有限的世界状态与原子操作不可能表达一切想象。我们要明确哪些现象属于当前可表达域，哪些需要新增真正不可分解的世界作用；新增时先检查它是否能同时作用于未点名实体。每次程序调用必须有可核算的资源上界或显式动态界限，长期自主行为按事件/时间逐次付费、占用有限状态并受因果深度与队列容量约束。这样不用开放无限递归或免费常驻循环，也能让玩家设计跨时间的复杂行为。

### 同一程序的两个未点名相邻情形

1. **接力护送。** 玩家写一个“获准看见受保护者偏离路线 → 记录上次方向 → 施力把可移动的屏障送到下一处接触点”的程序，分别交给修士、法球和固定机关。三者都先付观察费、占有限记忆、按已获准的施力结构与接触条件付作用费；固定机关不能平移自身，但若有锚定在地面的推杆等实际结构，仍可推动屏障并把反作用交给地面。缺相应施力结构或接触条件时才明确拒绝，仍可付费发出获准提示；球的余额耗尽后停下主动行为而保留惯性。屏障与目标碰撞另走自然冲量，不能因“护送”免费挡伤。当前玩家无法给通用实体装载该程序，故这是理论可组合目标，**现有公开接口未闭合**。
2. **遗体旁的自修复信标。** 同一段“接触事实 → 取得获准付款来源 → 读取获准普通外壳摘要 → 在得到材料时付费修复”的程序可交给法球、机关或人工生命。执行者若已有可用余额，可先付自身读取；若余额为零，只能先依据预先获准、有限且可报价的来源请求转入，启动价从该来源总转出量内支付，再付费读取，不能免费探查来源或私有遗体状态。遗体没有活体特权；首批死后独立授权关闭，遗体残存结构不能继续触发该程序，未来只有另行闭合签发者、预付来源、期限、额度及字段并获审核后才能开放。无授权不能读取私有遗体信息，无可用来源或无修复材料则修复作用失败且不留下修复，先前已提交的转入或读取另行保留，证书内合法求证失败才按互斥尝试价结算。修复还必须落在选择 B 的可编辑材料域内；域外请求报告不可表达，不能因“自修复”名称扩域。人工生命能否复活另由维持回路和身份阈值判断。当前只有内建监控、事件和有限实体池，没有玩家可赋予任意实体的程序/材料合同，故仍未闭合。

两例均从感知、计算、原子作用、有限状态、事件再启动构造，且逐项暴露**缺能力、缺授权、欠费、缺材料**的不同失败；以后若需增加新原子，必须说明既有原子为何无法组合出该世界变化，并让新原子对未点名实体同样可解释。

| 相邻玩法的逐笔检查 | 来源与付款                                                                                                           | 作用、反作用或耗散                                                                                         | 失败与账本边界                                                                                                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 接力护送           | 执行者以自有或明确授权的法力账户付观察、计算和主动施力费用；屏障若以自身结构主动驱动，也须另付有来源的法力。         | 施力改变屏障动量，反作用由执行者、地面或世界承担；锚定机关可借地面施力，随后碰撞把冲量分给接触双方及环境。 | 观察越权不泄露路线；机关缺施力结构或接触条件才无新增位移，球欠费后只保留惯性。账本分别记观察、主动做功、屏障与目标的结构变化，不能把挡伤当免费术式。                                                   |

### 元法术与算法工作量审计

现有 [94 项公开目录](../../reference/meta-spells.md)是接口数而非 94 个不可约世界作用。以下是**逐职责审计**，尚未证明每一项的最终最小价格；目前 `effectCost` 用请求量线性加法与分段 tick，[`controlPrice`](../../../src/core/pricing.ts) 按关系、强度、时长和周期定价，[`sensePrice`](../../../src/core/pricing.ts) 按距离、公开防护和关系定价；[`VM`](../../../src/core/vm.ts) 逐调用及循环累计 tick、检查动态价与余额。这些证明了现行**计算规则可定位**，不证明单价具有最终物理解释。

| `设置朝向`、`调整速度`、`强化伤害`、`设置存活时间`、`调整感知`、`调整护体`、`调整生命上限`、`调整法力上限`、`调整法力回复`、`调整神识上限`、`调整施法速度`、`调整法力消耗`（12）                                                                     | 同形控制现行基础 2/1 加动态，按关系、强度、时间和周期报价；前二者可映到执行/运动能力，护体与感知须映到结构，存活时间、伤害与全局倍率只是摘要。上限变化不赠余额；回复要有来源，施法提速不减少 tick，法力消耗倍率不能任意折扣读取、转移或材料。 |
| `结束施法`（1）                                                                                                                                                                                                                                      | VM 控制流，现行 0 法力、0 tick；不得撤销已提交世界效果或已做工作。                                                                                                                                                                            |

上述各行合计 `30+4+36+1+22+1=94`。这完成**逐名归类和现行报价形状审计**，没有完成最终原子性证明、价格系数或物理换算。特别是查询、移动和修复的算法优化只可减少真实调用、观察范围、状态占用或做功；若外部效果不变而资源支出变少，应能在逐笔工作账中指出减少了什么，否则是任意折扣。

## 六、哪些是世界本质，哪些是创建出的概念

这里的“本质”不是声称道衍有真实宇宙的全部物理定律，而是**若删去这一规则，前述因果便无法统一解释**。“创建出的概念”依旧可以对玩家非常有用，但应能映射回更底层的规律。

| 层级                       | 放在这里的概念                                                                                                               | 判定与后果                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **世界前提/候选公理**      | 模拟时间与因果次序、空间/接触关系、默认演化、材料与结构状态、法力账户间转移、付费术式的原子世界作用、结构决定能力            | 修士、法球、石块和机关一律适用；熵方向尚需反证后才可能采纳。二维坐标和具体时间单位是模型选择。                                     |
| **从前提推导的过程与性质** | 实体存续、散逸、运动、碰撞、伤害、修复、生命、死亡、事件、施法吞吐、吸收能力                                                 | 不能再有按实体名字写死的费用、寿命、死亡或施法特权。事件记录事实；订阅只是对事实的处理方式。                                       |
| **法术语言与游戏表达**     | AST、变量/列表、神识上限、tick、HP、护体、`power`、`manaRegen`、`castSpeed`、元法术中文名称、法术书/预设、敌方战术、数值价格 | AST 是共享实现合同；状态占用、工作量与成本有真实世界语义，但具体单位、展示指标和术式编写方式是游戏设计。名称与字段不决定世界本体。 |
| **现实桥接与运行工具**     | 鼠标左键、键盘槽位、屏幕坐标、HUD、音效、渲染帧率、暂停、重开、推演台编辑、存档导入、测试预置                                | 把人的意图转成设备无关的请求，或展示获准结果；不能创建免费法力、跳过权限，不能作为元法术。AI 与玩家用同一世界请求合同。            |

### 当前十项属性的归位

| 当前属性      | 理论中的来源；数值的身份                                               |
| ------------- | ---------------------------------------------------------------------- |
| `hpMax`       | 关键结构功能裕度的界面摘要；非死亡本因。                               |
| `manaMax`     | 储池的结构容量；上限变化不生成法力。                                   |
| `manaRegen`   | 一段时间内真实转入法力的统计结果；不是无源自动加值。                   |
| `shenshiMax`  | 执行结构可容纳的工作状态；非生命回路也可能具有。                       |
| `speed`       | 在驱动、材料及环境条件下的主动能力；与实际速度和惯性分开。             |
| `castSpeed`   | 执行吞吐的显示倍率；法球回路与修士适用同一工作原则。                   |
| `power`       | 若保留，须由某类作用的输入与耦合效率导出；全局伤害倍率缺因果。         |
| `manaCostMul` | 若保留，须能证明改变了真实工作或转换效率；任意全局折扣会破坏价格解释。 |
| `perception`  | 感官/探查结构、范围与权限的派生指标；看见不等于获准读取所有状态。      |
| `armor`       | 对特定作用的吸收、偏转或隔离能力摘要；固定数值减伤不是基本定律。       |

### 现有架构不变量的性质审计

这里逐组审视[当前 20 条架构不变量](../../architecture/invariants.md)的**解释位置**，不是宣布它们已失效。已采纳 ADR 和运行代码在新决策形成前仍是当前实现合同。

| 现行条款                                                        | 在统一理论中的位置                                                      | 需检验的边界                                                                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1–2、7–9：无头核心、AST、依赖方向和场景所有权                   | 实现架构与产品工作流，不是世界物理                                      | 无头运行有助于验证同一世界规则；推演台/演武场分工不应改变世界结算。                                                                               |
| 3–5：神识/法力/tick、静态预算、禁递归与容量                     | 资源解释与语言安全合同                                                  | 法力的世界作用价格仍须说明；神识可对应工作状态、tick 可对应执行工作，但循环限制和预算算法是可选的模型表达。                                       |
| 6、10–12：统一句柄、控制属性、commit/overlay/maintain、效果收费 | 统一实体接口及术式结算合同                                              | 句柄统一是必要手段，却不能代替材料与结构；控制的层、时长、费用需要从实际结构变化和持续付费推导；`0.25` 秒结算单位及属性 descriptor 不是自然规律。 |
| 13–14：惯性、世界运动功率、运动/伤害/扫描分池                   | 惯性和相互作用属于默认世界候选；分池是当前账本设计                      | 不可兑换的世界运动功率若无来源，会违背法力有源转移；固定伤害池和“不开动能转伤害”是简化结算，须与自然碰撞可能致伤的世界解释区分。                  |
| 15–17：回复定价、探查权限、五类预算/退款                        | 授权与原子交易是世界交互合同；倍率、账户划分和预算单位是设计            | 回复不能是无源加值；信息读取价格、权限和退款要逐笔可核对，但不得由报价、日志或界面旁路获得世界私有信息。                                          |
| 18–20：事件顺序、死亡撤权、蓄力与输入                           | 因果事件与执行状态是世界内机制；排队上限、防重和按键映射是运行/桥接设计 | 死亡应由生命条件推导，再触发撤权；球的授权不能无限续借；松键只表达释放意图，不能成为世界里的物理作用。                                            |

这一审计揭示了**同一条现行不变量常同时含世界语义和实现约定**。将来必须逐条拆分，而不是整段照搬或整段废弃。例如“惯性继续”可进入默认演化，“每 `0.25` 秒扣一次费”只是数值离散化；“碰撞事件有序”描述因果，“命中扣固定 damage 池”是旧战斗抽象。当前理论仍未为 94 个公开元法术逐一证明原子性与价格，不能据此宣称目录审计完成。

## 七、与当前实现及既有决策的冲突

| 可核对的现状                                                                                                                                                      | 理论提出的问题                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| [`World.tickActor`](../../../src/core/world.ts) 直接按 `manaRegen × dt` 增加 Actor 法力；普通运动的 `movePower` 也按时间补回                                      | 两条补给都缺世界内来源；若继续存在，必须解释来源、转移、可用性与它们和生命维持的关系。       |
| [`World.damage`](../../../src/core/world.ts) 对 Actor 做固定护体减伤、扣 HP、在零点设死亡；[`hitProjectile`](../../../src/core/world.ts) 接触后直接释放 damage 池 | 世界作用、结构损伤与生命终态被合并为数值和类别分支；法球自身损伤及碰撞触发术式没有同构表达。 |
| [`Battle.updateProjectiles`](../../../src/game/battle.ts) 递减 `life`，碰撞后按穿透数移除                                                                         | 固定倒计时与命中删除都不能单独解释结构散逸或解体。                                           |
| [`Attributes`](../../../src/core/attributes.ts) 将 HP、回复、威力、护体等并列为可加/乘的数值                                                                      | 有些是状态视图，有些是结构能力，有些只是价格/界面参数；不可全部当作平级物理量任意改写。      |
| [`metas/input`](../../../src/core/metas/input.ts) 让法术读取“按键”；[`设置法球追踪`](../../../src/core/metas/entity.ts) 是专门入口                                | 现实桥接和可组合行为被放入元法术层；需按原子判据重新审计公开目录。                           |

物理层还有一项直接证据：[`Battle.separate`](../../../src/game/battle.ts) 用平均位置推开 Actor 并清除部分速度，未按双方有效惯性分配接触冲量；[`World.applyImpulse`](../../../src/core/world.ts) 修改目标速度，但当前价格和反作用未组成闭合的物理账。它们可作为简化原型运行，却不能证明“近似现实的碰撞物理”已经成立。ADR 0018 明确暂不采用完整刚体和动能致伤，本轮推荐的最小物理需要在理论确认后重新裁定该边界。

本理论与已采纳 [ADR 0017](../../adr/0017-统一实体控制属性模型.md)–[0020](../../adr/0020-事件执行上下文与生命周期.md) 的若干结算约定存在冲突，尤其是固定命中、独立世界运动功率、属性倍率与旧资源处理。**本文只是新方向的候选论证，不覆盖 ADR，也不宣称当前代码已经符合它。** 若模型通过反例与制作人评审，先以新 ADR 明确覆盖关系，再设计实现和最小可玩验证。原型期不以旧法术/存档兼容阻止理论修正。

### 现实桥接与同一世界请求

桥接层把鼠标、键盘、手柄、AI 或已授权实体事件转成同一请求 `{执行实体, 程序, 目标/方向意图, 发起时刻, 授权来源, 可用付款账户}`；世界再独立检查存续、能力、权限、来源、法力、状态容量与耗时。`准星方向` 是输入意图而不是免费探查到的敌人位置；按下/松开是会话意图而非自然力，AI 不因无鼠标而得到额外探查。模拟时间、接触和事件序属于世界因果；墙钟、渲染帧、HUD、音效、调试面板、存档与配置属于运行/展示层。界面只能显示获准快照及明确的未知/拒绝，暂停只冻结模拟推进，不创造余额或重排事件。相同世界初态、授权、请求及模拟时间线应得到同一结算，来源设备和帧率不改变法力账或因果顺序。

## 八、反例的逐笔结算与未闭合处

每行均按“**来源与付款 → 作用 → 反作用/耗散 → 失败 → 账本**”核对；法力记 `M`，材料/结构记 `X`，环境可用差异记 `U`，程序工作记 `T`。旧稿 `P` 独立补给候选已被普通驱动 B 排除；原有动量/动能仍作为物理状态记账。这是**候选结算**，尚无最终换算常数。默认演化不用逐帧付 `M`，仍须有物理来源与去向；新主动驱动必须付款。失败不得提交成功效果，合法尝试价和已完成工作另记。

| `100/20` 挪用 L1–L2            | 有报价的攻击在同刻阶段 3 可支用 100，阶段 4 的 20 维持另结；阶段 2 事先授权的补源可先到，阶段 5 再依结构判生命。多付 20 只买该价函数允许的作用。                      | 攻击前结构已毁则拒；无新源时维持欠费使结构失稳但不立即宣告死亡；同刻事件补源来不及倒救；早一刻已到期的维持不能被“同刻优先”后移。 | 攻击须独立报价；K0 只覆盖已登记样例，真实失供 X 与身份连续性待证。                |
| 连续碰撞、场外与遗体再损 C2–C3 | 球撞墙、两人或遗体，每次用更新后的动量和 `X` 生成独立 `C-i`；活体是否死亡另有 `L`，遗体仍会受损；开放场外移交明确范围外状态。                                         | 擦边无 `C`；第二次不能重用第一次的速度/储能；球上术式拒绝仍留两次自然事实；越界不能自动删球或记命中，遗体不能“二次死亡”。        | 接触稳定序/容差、护体耦合、场外接管与材料损伤阈值。                               |
| 无源/额外供能 E1–E2            | 创建取现有材料；稳定物无需周期维持。不稳定球仅从自有或获准有限储备付款；额外注入作为独立 `Tx`，实际覆盖后续维持才可能延长结构存续。                                   | 无源无转入，欠维持按结构失稳而不因余额零即删球；注入未被结构使用不赠寿命，已做功不可再退款。                                     | 创建/维持报价、材料稳定性、注入效率与终止残余去向。                               |
| 创建者死亡                     | 阶段 5 撤去来自死者的未来提款、控制及失效订阅；已存在的球或信标保留结构、余额与已付惯性，但依死者授权的程序停止；有自身独立身份、账户与授权的人工生命依自身合同继续。 | owner 名称不授予死后私权；死者派生 grant 及首批独立死后 grant 均使后续 `S` 拒绝，先前 `C/Tx/A` 不回滚。                          | 首批独立死后 grant 关闭；未来开放才需签发者、期限、额度、字段、撤销与退款受益人。 |
| 回收循环 R1                    | 受限域仅允许有标识的可用来源和逐笔报价；已付环境散逸直接回收保持域外，循环不凭此增加可用余额。                                                                        | 从已付分区取回同一 `M` 再造球、同时保留旧做功/结构的请求拒绝；不能把拒绝说成已证明开放域无套利。                                 | `U` 的边界、收集效率/启动价、全循环上界与允许开放的材料域。                       |

上述反例中 `待定价` 指结构与权限可能合格但缺可信价格；`不可表达` 指作用或材料不在已选窄域；`身份未定` 指生命连续证据不足。三者均不产生成功效果，且各自已提交的先前事实保持不变；玩家可见的拒绝只能使用获准字段。后续模块引用此总账并补本模块参数或验收，发现相反结论即交 Version PM 收束。

### 六项选择在同一模型中的含义与硬缺口

下表的字母是制作人此次方向选择。玩家效果是待验证的策划解释；优势、代价及未闭合点不是制作人对参数的背书。旧[设计审核选项](./design-review-findings.md#六类未决取舍结论证据与提交制作人的问题)和[整版设计表](./world-rule-design.md#提交设计审核的未决取舍)成文在反馈之前，其“均未选定”已经过时；细则应按本表修订，不把旧表作为平行规则。

| 选择                     | 玩家可见的因果、理由与代价                                                                                                                                                                               | 仍待证明或升级                                                                                                                                              |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **有效质量/接触/材料 A** | 用有限形状、有效惯性、双边冲量与可损材料解释擦边、撞墙、护体、遗体再损；玩家能预期自然碰撞和付费术式是两笔。比只显示动量更能兑现统一世界，但须维护材料和接触状态，重做现行固定命中与 `Battle.separate`。 | 最小几何/材料维度、接触阈值、结构致伤精度及性能界；不得从 A 推出完整刚体。                                                                                  |
| **普通驱动 B**           | 修士起步、机关推杆与球主动转向均从获准 `M` 付价；滑行/接触按默认演化。来源易对账，玩家会感到普通行动也受法力约束，旧自动 `Wm` 补给失效。                                                                 | M1/A1 有条件的 K0/V0 代谢与 A0 每段驱动报价仍待实测及整版采纳，域外代谢和补给可得性未闭合；若无法给可玩的常规移动，应携体验代价升级，不能偷加独立免费 `P`。 |
| **法力做功/环境/回收 B** | 保留总量转移和可标识去向，先只允许已声明来源、容量与报价的转入/作用；已付散逸的直接回收及不能证明上界的转换暂不可表达。比宣称环境自由回收更易避免显见循环，代价是玩家暂不能自由吸取所有环境法力。        | `U` 的可观察性、转换/散逸函数、回收上界及是否扩开放域；仅靠禁止循环不能证明完整世界无套利。                                                                 |
| **生命/身份 B**          | 失供先退化或休眠，及时补源及修复可恢复生命；余额零或 HP 零不强制抹除实体。玩家可以救回人工生命或修士，代价是必须另给同一身份的连续性判据与可读反馈。                                                     | 可恢复/不可恢复阈值、修复后的身份、遗体回路是否可启动；“复苏”不自动断言原身份延续。                                                                         |
| **元法术 B**             | 缩小可编辑材料域，在域内证明读取、转移、施力、有限局部改变等确为不可组合的作用；护送、追踪和自修复仍是普通程序。这样避免“任意改结构”吞掉规则，代价是域外想法会明确报不可表达。                           | 材料白箱粒度、修复所需原子与逐项不可约证明；信标修复若超出域须升级，不能偷偷开放万能修复。                                                                  |
| **载体/授权 B**          | 修士、球、机关、人工生命按结构容量、能力、有限记忆和授权判断程序能否运行；遗体死后独立执行首批关闭；玩家能解释“为什么这台机关可以、那颗球不可以”。代价是需显示容量、权能、死亡后状态与拒绝原因。         | 容量单位、授权转移/撤销、事件可见字段及死亡后的有限独立权限；不得沿用 Actor 类型白名单。                                                                    |

六项选择使反证有明确方向，但仍没有最终价格、材料域、复苏身份与回收证明。若模块设计需要新增可对外生效的物理精度、开放环境回收、判定“同一人”、扩大材料写入或永久死亡后控制等不可逆解释，须带玩家效果、备选、旧规则影响与反例升级制作人；本正文不代为批准。未闭合的调用在候选合同中标“不可表达/待定价”，不能用预设效果填洞。

## 九、反证清单与真正未决的问题

以下反例能否在**不加实体类型豁免**的情况下成立，是理论是否自洽的验收：

1. 稳定石块和稳定材质法球在无施法时长期存在；不稳定术式球即使没有敌人也会散逸。多注入法力能否延长，须从结构用途而非任意“存活秒数”推导。
2. 法球撞墙、撞修士或只擦边经过：自然冲量、双方材料损伤、碰撞事件、法术效果与法球解体各自独立结算，任何环节失败都没有额外免费伤害。
3. 同一作用使非生命球破裂、修士组织受损、已死遗体再次破损：都按结构规则改变；只有修士的自主维持失败才叫死亡。
4. 高护体目标承受攻击：作用被偏转、吸收或传递到哪里？护体自身是否付费或损坏？效果不能凭固定减法凭空消失，也不能产生“最低一滴血”超出输入。
5. 从世界收回已支付的法力，再次造出完全相同的球：若环境及所有账户都回到起点，不能同时留下额外效果；可用性或其他真实来源必须下降。
6. 零法力修士、有余额但缺少维持回路的球、有回路但无授权的机关：生命、存在、施法分别按结构、来源、程序和权限判断，不用类别短路。
7. 同一抽象施法意图来自鼠标、手柄、妖兽 AI 或球上事件回路，世界的付款和效果合同相同；关闭渲染或改变帧率结果也相同。
8. 修士余额 `100`，下一次已登记 K0 样例窗口需 `20`：若其他条件不变，攻击花 `80` 尚可在到期时付 20；攻击花 `100` 且无新来源则本窗维持欠费，须由真实 `N→X` 和回路证据再判 `critical/dormant/dead/unknown`，不因余额零自动越过死亡界。及时获准补源只有按六阶段实际到账才有用；额外攻击效果只来自已报价的多支付 `20` 或确有的结构储能。
9. 修士从静止起跑再撞墙：身体做功须扣实际来源，墙承受反作用，停下时动量和运动能量进入墙体、身体形变或环境；墙是否受损由结构决定，不由“碰墙事件”免费扣血。
10. 法球滑行、付费转向并连续撞上两名修士：滑行不重复收费，转向改变动量即使动能近似不变也须有作用来源；每次碰撞分别改变双方运动与结构，球上触发法术另行付费，不能把同一份运动效果、damage 池和事件计成三次伤害。
11. 玩家只用同一组基础操作编写“首次撞墙反弹、第二次碰撞才释放法术”的球：球必须拥有可付款的事件响应和跨次有限记忆；它不能因不是 Actor 而失去施法资格。
12. 玩家把相同的探查、判断和施力程序交给法球、机关或人工生命：差异只来自结构能力、权限、储备与环境，不能由引擎替其中一种类型自动注入“追踪”或“自我修复”分支。
13. 一个玩家新设想的行为未出现在预设与敌方技能中：若可由已有原子作用组合，策划不新增专名元法术；若确实缺不可再分的世界作用，先重新界定该作用及其跨实体价格，再扩展世界。

六类问题的本轮推敲结果见上表；每一类都给出可成立的最小结论与仍未决的界限。反证清单不是可直接派发的开发任务：只要材料、普通驱动来源、法力做功换算、生命阈值、元法术最小集或通用程序载体任一项还需靠实体专名特权才能成立，就必须继续修订这篇理论。

### 本轮详细策划的闭合边界

本轮承接已完成的 `mds-supply/mds-ledger/mds-life/mds-capacity` 四项直接前驱及[主策退回结论](./design-review.md)；上一轮 `mdq-*` 是历史条件基线。有限二维接触、逐种材料与逐包梯度、`A0/P0/D0/R0/K0/V0` 条件报价、M1/A1 四链与连续身份、逐体程序容量和整程序工作都有可复算的窄域候选；**逐包上游取得、装载及封印的实测仍无证**，正功/代谢的纸面成功账不能登记为可执行成功，攻击仍为 `unknownPrice`。六阶段唯一 `C/N/X/Tx/A/L` 归属与失败不回滚继续成立，实体不凭名称获得生命或施法特权。接触未裁定、价证缺失、材料域外、容量未知和身份未知各有不同余态；本轮增量仍待主策复审，任务交付不代替设计通过。

**仍须审查**的是证书尺度与系数是否可信，R0/K0/V0 候选价是否采纳、域外读取/维持及超出 M1/A1 窄域的普通身体代谢怎样报价，开放环境回收如何证无套利，关键生命回路何时可编辑，连续身份最低证据是否足够，以及未来若开放非零死后独立授权如何确定签发者、预付来源、期限、额度和字段。首批关闭的路径不能在信标、遗体或旧预设中暗开；当前信标的域内修壳不承诺同身份复苏。改变已采纳 ADR 或超出制作人已选方向时，须附玩家效果、备选、代价、推荐理由、旧规则影响和反例交制作人；当前不启动游戏开发。

## 修订纪律

从范围修订 `9` 起，本文是本版本**唯一可编辑的世界理论正文**。每次制作人提出问题，先指出它挑战哪条前提或推导，改动相应段落，再同步修改反例和状态表；若新解释与旧段落冲突，直接重写旧段落，不并列保留两种结论。早期按问题分开的草案只留历史指向，不能再作为平行规则引用。确认之前不写新的已采纳 ADR、不选实现切片、不把例子拆成代码任务。
