# 设计审核节点任务（范围修订 13）

**问题**：本轮六项 `mdq-*` 详细策划已交付，但[节点总结](./module-design.md)仍记录物理工作包和摄取包上游未证、tick 报价及机关方向记忆槽不一致。逐体证书和纸面验收尚不能自行证明完整方案闭合。

**范围与成果**：只设 `mdq-world-review` 一项主策复审成果。独立核对[制作人意图](./intent-alignment.json)、[上轮退回合同](./design-review.md)、六份细则、[唯一世界理论](./world-theory-draft.md)、未列举玩法和旧原型；在[审核记录](./design-review-findings.md)逐项写出已覆盖、缺口或待制作人判断及证据。批准范围内的文档矛盾可同步修订，共同公理仍只维护一篇正文。

**验收与边界**：重点复算有源做功、材料/法力账、生命及容量证书、H/B、普通行动、100/20、跨入口等价和失败余态。无证格保持未知或拒绝；若方案仍不闭合，明确退回详细策划的合同。真正的新产品解释或不可逆取舍先给制作人通俗比较与推荐。纸面方案不算实际可玩，不选择开发切片，也不修改游戏代码或测试。

[机器合同](./design-review-tasks.json)列稳定 ID、交付物、验收、必要输入和独占写入路径；单项任务没有同节点依赖或写入冲突。共享 `design-review.md` 节点总报告和 `docs/status.md` 留给 Version PM 收束。制作人审阅完整方案前，不进入游戏开发。
