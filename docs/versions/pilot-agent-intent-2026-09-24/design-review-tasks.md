# 设计审核节点任务（范围修订 13，六模块补全后复审）

**问题**：上一轮[主策审核](./design-review.md)退回共同报价、材料精度、生命身份与授权等未闭合合同；[本轮详细策划](./module-design.md)已接纳六项 `mdc-*` 成果，但模块交付不等于整体规则成立。**范围**：在制作人已选的 A/B/B/B/B/B 方向内，核对唯一世界理论、五份细则、相邻玩法与推演台—演武场完整体验。**非目标**：重选已定方向、安排内部审核步骤、规划后续节点、选择开发切片、修改游戏或测试。

本节点只需一项可独立验收的成果：`mdc-world-review`。主策交付[逐项审核记录](./design-review-findings.md)，对前轮退回原因和本轮模块主张逐项给出闭合、缺口或待制作人判断的结论及定位证据。审核须用接力护送、自修复信标、`100/20` 储备、碰撞、回收等反例核算来源、权限、自然事实、付费作用、时序与失败；检查玩家从推演台编辑、预算、推演、到演武场绑定观察、再返回同一本法术书修改的成功、拒绝和空状态，并与旧代码、测试、可体验入口及 ADR 对照。

本轮六项 `mdc-*` 任务是已接纳的**前一节点成果**，写在读取路径中；本节点没有同节点前驱。审核记录及必要时修订的[唯一理论正文](./world-theory-draft.md)和五份模块细则归此任务独占写入，无同节点冲突。共同公理与反例只维护在唯一正文。若发现超出已批准方向的产品解释或不可逆选择，审核记录给出通俗选项、玩家效果、代价和推荐理由，供制作人判断；不以任务合同批准新规则。旧 `world-rule-design.md` 只作历史对照。

[机器合同](./design-review-tasks.json)列明稳定 ID、交付物、验收、依赖及独占读写范围。节点总报告 `design-review.md` 和 `docs/status.md` 留给 Version PM 收束；制作人审阅完整方案前不进入游戏开发。
