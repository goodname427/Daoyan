# 设计审核节点任务（范围修订 13）

**问题**：[详细策划汇总](./module-design.md)记录六项 `mdz-*` 成果均已交付，但首批范围未闭合：物理、账本与程序给 D1 单步和 B4 惰性修壳条件正例，[唯一理论](./world-theory-draft.md)仍称 J1→H2 为唯一正向证书，[玩家桥接](./player-bridge-design.md)将 D1/B4 排除在首批体验外。条件纸面例不等于已可玩，也不构成制作人对范围的确认。

**范围与成果**：只设 `mdz-world-review` 一项。主策对照[制作人意图](./intent-alignment.json)、批准范围、[上一轮退回合同](./design-review.md)、六份模块设计及交付结果，在[审核记录](./design-review-findings.md)独立裁定同版范围与因果、来源、价格、生命、程序容量和六入口同书流程。接力护送、信标及未列举的相邻情形用于反证；逐项给出已覆盖、缺口或待制作人判断及定位证据。

**验收与非目标**：可在已批准原则内补齐的矛盾写成精确退回合同；首批范围、新产品解释或不可逆规则若需制作人选择，先比较玩家效果、收益、代价并给推荐理由。区分纸面推导与开发后原读、实扣、容量、实玩证据。此审核不修订六份模块细则，不选开发切片，不改游戏实现或测试，也不批准开发。完整方案可审阅时才建议交制作人。[机器合同](./design-review-tasks.json)声明稳定 ID、输入、验收和独占写入路径；单任务无同节点依赖或写入冲突。`design-review.md`、`design-review.json` 和 `docs/status.md` 留给 Version PM 收束。
