# 详细策划退回补全任务（范围修订 13）

**问题**：[主策复审](./design-review.md)确认 D0/P0 接触与有限作用、同刻顺序、首批死后授权关闭已有纸面候选；获准 read、生命 maintain/preserve 无独立报价，生命临界与同一身份无可执行判据，两条整链只能条件式成立。**范围**：只补四处直接受影响的模块设计及纸面验收。**非目标**：重派已闭合物理或程序模块、扩写版本策划、修改游戏/测试、预拆内部步骤、规划后续节点。完整方案仍须主策复审并交制作人；当前不批准开发。

| 模块 | 独占任务与策划交付 | 相对上一轮新增的判断、反例和直接验收 |
| --- | --- | --- |
| 读取与维持资源报价 | `mdo-mana` · [法力账本](./mana-ledger-design.md) | 独立报价 read/maintain/preserve 的范围、工作量、来源、tick/神识及毛界；重算获准空查询、隐藏目标、100/20 和补源。向生命交维持/保存证书，向程序交读取价。 |
| 生命临界与身份连续 | `mdo-life` · [生命与身份](./life-identity-design.md) | 引用报价与已提交 X/Tx，给修士/人工生命共用的临界、保存截止、不可恢复和 LifeId 判定表；验最后一击、及时补源、遗体修壳、复制分叉与撤权。向程序交死亡屏障。 |
| 统一世界理论与跨模块因果 | `mdo-theory` · [唯一理论正文](./world-theory-draft.md) | 核对六阶段合同；逐笔闭合接力护送和活跃信标惰性修壳，列空/越权读取、欠费、缺料、创建者死亡、复苏域外及已付事实。向桥接交可宣称的结果与准确断点。 |
| 玩家意图与纸面验收 | `mdo-bridge` · [玩家桥接](./player-bridge-design.md) | 将实价空查询、身份未知和拒绝映射到推演台—演武场—返回的成功/失败/空/域外脚本；核五类入口同请求等价及敌方修士同规则。 |

依赖为 `mdo-mana → mdo-life → mdo-theory → mdo-bridge`；理论任务也直接消费报价。每项只写表中一份文件，写入范围互不重叠。[物理材料](./physics-material-design.md)、[实体程序与授权](./programmable-spells-design.md)及旧 `mdn-*` 结果是只读前驱。Version PM 独占 `module-design.md`、`docs/status.md` 和跨模块一致性收束；候选参数仍非制作人批准。

若出现真正超出已批准方向的取舍，应先写各方案的玩家效果、优势、代价、推荐理由、ADR 与旧原型影响，再升级评审。[机器清单](./module-design-tasks.json)含稳定 ID、交付物、验收、依赖、读写范围。此节点只形成可执行的纸面验收，实际可玩证据留后续开发及候选阶段。
