# module-design 本轮任务：首批 A 玩家桥接范围

问题：最新 `mdae` 主策复审确认 J1/D1/B4 的同版条件纸面账及扩展边界可复核，但玩家桥接现行正文仍称 A/B/C 待选，并保留“仅 J1”的当前分支。范围修订 13 不变；制作人只选定首批 A，尚未批准完整详细策划或游戏开发。

本轮只产出一份可独立审阅的模块成果。物理、账本、程序、生命和唯一世界理论保持只读；共享 `module-design.md` 与 `docs/status.md` 由 Version PM 在模块交付后核对和收束。未来法球再次付费响应、更多预设和敌方修士仅用于反例，不列入首批交付。

| 模块及任务                       | 独占交付物                | 相对上轮新增判断与直接验收                                                                                                                                                                                                                                                                                                             |
| -------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 玩家意图桥接 `mdaf-bridge-scope` | `player-bridge-design.md` | 把已选 A 投影到 J1 杆推、D1 起步、B4 首撞后普通壳修补的编辑、预算、绑定、观察及返书路径；修正第 3、11、45、66、115、129 行及关联开放/未开放/空态提示。用 D1/B4 被错判未开放、B1 再撞换版或容量未知、改书后沿用旧报价、事件重投为反例；逐项对照现行权威来源与六类余态，定向反查理论及模块总览消费者。只形成纸面方案和开发后可执行验收。 |

任务无本节点内部前驱；旧 `mdad` 和 `mdae` 成果只读。`contextPolicy=fresh`：旧桥接推理已多处重复误把范围写成待选，需按制作人已定范围重新判玩家状态，旧同键数值仍须逐项核对。独占写入范围仅为桥接正文，任务 ID 未沿用任何历史 `stageTasks`。

跨模块合同：范围以制作人决定、意图记录和唯一理论为权威，桥接负责玩家投影，Version PM 核模块总览；物理以 `S0-physical-v1/seed-physical-v1`、`JH-v1/D1-v1/B4-v1`、`slice-*`、`C-B1-01` 核来源、自然先史、`E0/12`、`q`、热与材料；账本按 `receiptId/payerId/grant/PriceVersion/readId` 分开 J1 本人 32 M、P0 1、P2 2、可选 P1 1 与跨账户 35/36 M，并独立核 D1 26/40、B4 34/50；程序以 `book-mdu-01/v1`、J1 同一 AST 纸面别名、D1/B4 独立假设和逐体容量/tick/S 证书核覆盖，生命以 `LifeId/assessmentId` 限定普通壳修补。桥接按 `factId/requestId/effectId` 核成功、拒绝、空、未知、域外、竞争及已付和自然事实的保留。

验收只用定向文档检查和可复算纸面初态、逐步账目、反例。真实原读、逐付款方实扣、规范 hash、本体容量与 VM 消耗、六入口及推演台到演武场再返书的实际体验，待游戏开发获批后执行；若反查发现需要改写只读权威或新增世界规则，标明消费者和阻断归属，由 Version PM 或主策处理。
