**跨模块合同**：物理交有来源的 E0/材料包与独立 C/N→X；账本消费包并交 payer/grant、毛价与 Tx↔A；生命消费自然输入和净到账并交 LifeId/DeathBarrier；程序消费结构、价格及撤权并交容量和整链界；理论只维护共同规则与事实重放。[机器合同](./module-design-tasks.json)列直接依赖和互斥写入。已闭合的[玩家桥接](./player-bridge-design.md)只读；其中 `mds` 证书引用须标历史条件稿，ADR-0018 须改称运动供能与命中守恒，由 Version PM 汇总时修文并核对模块一致性。共享 `module-design.md`、`design-review*` 和 `docs/status.md` 不分派给这些任务。

交付只需可审阅的规则、反例及未来可执行验收。若批准窄域无法签正向来源或唤醒路径，明确不可执行和玩家代价；需开放 `M→E0`、环境回收、关键材料编辑或独立死后授权时，先由主策以通俗方案的效果、优势、代价与推荐理由升级制作人，不作为既定任务。主策独立复审后才考虑提交完整方案，当前不进入开发。
