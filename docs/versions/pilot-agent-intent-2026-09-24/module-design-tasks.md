**上下游与顺序。** 物理拥有接触、材料与读投影；账本拥有价格、付款与收据；程序拥有共享 AST 的设计身份与容量证；生命拥有身份及死亡授权；唯一理论归并因果，桥接投六入口，ADR 决定旧语义覆盖。按物理 → 程序 → 生命 → 理论 → 桥接 → ADR 交付，写入路径互不重叠。各任务按场景、事实、切片和价版键定向反查现行消费者，只读命中段，对照来源结论；实质冲突列阻断。JSON 逐项列明读写范围、反例及验收。

**边界。** 模块正文只保留稳定游戏合同和运行待验项；任务完成、主策轮次和总览阻断由 Version PM 在 `module-design.md` 收束。ADR 采纳是覆盖旧运行语义的架构门禁，提案交付不等于采纳或实施。真实授权、原读、收据、规范 AST/hash、球容量、VM 实耗及六入口实玩留开发和候选验收。物理、程序、生命、桥接续接原正文；理论因反复把流程状态当游戏阻断、ADR 因职责转为采纳决策，使用 fresh。新增玩家规则或不可逆取舍交主策判断是否升级制作人。
