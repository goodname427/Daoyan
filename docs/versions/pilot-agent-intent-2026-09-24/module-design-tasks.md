**合同与顺序。** 物理独占十九读的端点、字段、版本、自然事实和 `E0/q`；账本独占 `mdai-B4-audit-v1` 逐项正价、付款与收据，生命独占 `LifeId/assessmentId`，账本和生命本轮只读。依赖为物理 → 程序 → 唯一理论 → 桥接。J1 本人 `32 M`、P0 本人 `1 M`、P2 本人 `2 M`、可选 P1 本人 `1 M`，分账后跨账户 `35/36 M`；D1 自付 `40 M/余14`；B4 自付条件 `44 M/余6`，不得串账。程序按同 AST/hash 设计身份或有据别名、投影 hash、价版和容量版出证；理论与桥接按同 `B4-v1/slice-B4-01/readId/priceVersion/receiptId` 消费。成功、拒绝、空、未知、域外及竞争逐项核自然事实、已付和未执行锁，直接验收须对照现行权威结论。

各任务定向反查本轮变动事实键在其他现行模块与唯一理论的命中段，列待同步消费者或阻断。`module-design.md`、`docs/status.md` 和主策复审材料由 Version PM 收束。四个 ID 均不复用历史 stageTasks；物理旧 pending 前提反复滞留，故用 `fresh`，其余同一正文及已核推理用 `continue`。若发现新增玩家规则或不可逆取舍，交主策判断；策划交付只定义未来可执行验收，不伪称运行证据。
