# 玩家意图桥接与推演—实战体验策划

**状态**：`pilot-agent-intent-2026-09-24` 策划修订 2、范围修订 13 的 `module-design / mdo-bridge` 纸面交付，承接已批准的 [mdo-theory](./world-theory-draft.md) 只读结论，并服从其唯一共同因果正文。已批准的 [mdn-bridge](./tasks/module-design-mdn-bridge.json) 仅作历史只读输入，不是本任务依赖；本文补齐新证书到可见字段的映射，以及接力护送、活跃信标的双场景矩阵。不代表整版主策审核通过、候选参数获批或游戏已实现/可玩。

## 问题、范围与边界

玩家需要用同一本法术书从编辑、预算和单步观察进入实战，再能定位失败并回来修改。当前接口把 DSL/蓝图、推演和演武分别实现；若鼠标、帧率或 UI 直接决定世界作用，NPC、法球或事件程序便不能复用同一规则。本模块规定玩家意图如何变成通用请求、共享法术书的体验闭环及反馈可读性，不另造物理、法力、生命或施法规则。

**范围**：现实输入适配；意图与执行请求边界；推演台—演武场往返；请求、账本与世界反馈的呈现；空状态、拒绝、旧原件诊断；面向四种执行载体的一致性验收。

**非目标**：新增元法术、敌方修士或手柄实现、预设内容制作、数值定价、物理/生命规则裁决、旧存档自动改写。本节点不为预设或敌方修士创建制作/开发任务；二者只列为后续验证对象。

**验收**：任一入口只提供同一设备无关意图字段；同一程序与相同授权、资源、目标、时刻产生相同请求及相同成功/拒绝/空结果；玩家可沿一条连续流程完成 DSL 或蓝图编辑、预算检查、单步推演、绑定实战、观察自然与付费响应、失败定位并回到同一法术书修改。

## 设备无关意图与统一请求

现实设备只能表达玩家想做什么；屏幕像素、键名、hover 和输入采样不属于世界事实。适配器把设备事件归一为如下候选结构；这是跨入口合同建议，不是已经存在的公共 TypeScript 类型。AI 决策和实体事件也进入同一语义边界，但事件是已提交事实触发，不伪装为玩家按键：

| 字段                         | 含义与限制                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `actor` / `program` / `slot` | 发起实体、共享法术书中的程序标识、触发槽；由上层绑定解析，不从设备身份推导权能。事件唤醒可无玩家槽。                |
| `kind` / `phase`             | 设备无关动作和 `press`、`hold`、`release`、`cancel` 等边沿；仅表达输入，不直接写世界状态。                          |
| `aim` / `move`               | 可选方向或移动意图快照；鼠标位置先经视口变换为方向，键盘/手柄按同一坐标约定归一；不隐含实体位置 setter 或探查授权。 |
| `targetHint`                 | 可选非权威目标提示/句柄。核心仍须检查可见性、字段权能、距离、能力和提交时目标状态；UI 命中测试不能授予查询权。      |
| `simTime` / `sequence`       | 世界模拟时刻与稳定序号，由模拟调度器赋值；不得由设备时间戳或渲染帧决定结算顺序。                                    |
| `grant` / `payer`            | 经验证的权限上下文及本次有限付款账户；适配器只携带引用，不签发授权，不从创建者身份推断未来余额。                    |
| `source`                     | `player`、`ai`、`entity-event` 等审计来源标签；只用于解释和诊断，不参与价格、权限或结果分叉。                       |

每条意图还须有可追溯 `intentId/causeId`、共享法术书 `programHash` 和版本；它们关联输入边沿、推演步骤、实战请求、日志和源位置，不赋予重复提交权。世界请求由可信模拟调度器把意图解析成 `executor/programId/instructionId/targetOrDirection/simTime/grantId/payerAccountId/causeId/snapshotVersion`，作用节点另带 `descriptorId/version` 与 `requestId`。其中 `targetHint` 只能促使获准查询；位置、目标私值、物理 `A/C/X`、法力交易 `T`、生命阶段和身份必须由世界验证或已提交事实给出，绝不从适配器、准星或 UI 状态直接写入。重复 `requestId` 返回原结算，不按按键重复、设备轮询或重绘重复收费。

`actor + program + phase + intent payload + simTime/sequence + 已授权 grant + 有限 payer` 进入共用请求验证。验证依序检查程序/载体结构与能力、字段和目标权限、材料域、静态及动态预算、公开参数报价、最新状态、余额/容量预留；提交点统一记录交易、物理/结构作用与已提交事实。未证明价函数的 `unknownPrice` 或域外 `unexpressible` 在作用前拒绝，不能拿旧价格补足。不同入口只有在程序版本、执行结构、输入载荷、世界初态与随机种子、目标可见性、授权、账户、模拟时刻及事件序均相同的条件下才要求同请求、同价、同结果；任一条件不同，差异须能由字段解释。不得为了表面等价抹掉真实状态差异。

### 请求事实、共同报价与世界账序

显示层消费唯一世界规则产生的报价与结算事实，不自行估价。每个作用的共同报价沿用前驱 `Quote(x) = (pM, pAttempt, Wmax, ΔQ[k]max, τmax, Smax, reserve, settle, certificate)`：描述符及版本、作用/材料量、来源换算、环境可用量 `U`、付款方和授权范围形成报价输入；报价输出列毛法力扣款、合法尝试价、做功上界、材料差量、tick/状态峰值、预留与结算凭证。价格证据未完备则为 `unknownPrice`，材料/状态不在可表达域则为 `unexpressible`；两者都不能渲染为 0、有限折扣或“可试试看”。真实尝试价只按已验证、已执行且有目录报价的合法工作结算，同工作成功时抵扣一次；前驱没有给出可用尝试价时，本模块不补造它。

玩家反馈把**请求来源**（玩家输入、AI 决策或带订阅身份的事件）、**实际执行者**、**授权签发者/范围/到期**、**有限 payer 与资金来源**分开列示。显示材料 `Q[k]` 的类别与本笔差量、去向和损耗；精确材料位置、目标私有余额、`LifeId`、结构拓扑只在对应字段 grant 允许时出现。身份关系字段沿用前驱 `same/new/none/unknown`；遇到 `identityRelation=unknown` 时明确显示“身份待判”，冻结旧身份私权且不推断新旧身份。拒绝可以显示通用类别与玩家自身程序节点，不得借报价差额、响应时长、事件文案或空/拒绝区别泄漏目标存在。程序执行、环境自然变化、预授权补源、主动作用、维持/失稳、身份撤权、事件响应引用各自 cause/transaction/作用 ID，不将来源标签当权能。

对所有界面和入口执行相同六阶段顺序：①自然接触与结构事实 `C/X`；②本刻之前已获准且到期的补源；③到期主动作用；④到期维持与失稳；⑤生命阶段/身份判断及撤销派生授权；⑥按模拟时刻、世界序号、订阅序号派发事件。阶段相对次序沿用理论正文候选合同，具体阈值仍待评审。阶段⑥触发的程序不能倒流到本刻②补源。账目以模拟时刻及稳定世界序为准，绝不以设备回调、鼠标事件、渲染帧、面板打开或通知到达次序为准。`DeathBarrier` 是授权检查边界：控制者死亡先撤销其派生 grant、终止受控会话并关闭其账户接收，再处理结算和获准终止摘要；只有预先签发且仍有效的死亡后有限授权、独立结构与付款来源齐备时，残余程序才可继续。

### 瞄准、时间、暂停和表现审计

- **瞄准**：设备适配只给方向快照；程序需目标位置时须显式发出获准查询并支付实际读取成本。命中框、hover、锁定/吸附不是读取授权。准星方向可以本地显示；目标是否存在、身份、距离和材料不得由私有查询拒绝的 UI 旁路暴露。
- **模拟时刻**：调度器产生单调 `simTime/worldSequence`，并在快照中注明时间与版本。渲染频率、采样、后台节流或慢帧追赶不得多造/少造交易、tick、事件或材料变化。墙钟映射与追赶上限尚待定义，不可作为跨入口等价条件。
- **暂停/恢复**：冻结模拟、世界派发、维持结算和世界表现推进；真实 UI 可以继续绘制静态面板，但不生成世界事实。暂停间的按下/保持意图不得偷结算；恢复先按规则清理到期状态，再按模拟时刻、稳定序和去重 ID 处理显式保留意图。松开、取消、缓存容量及队列溢出须有可见且一致的拒绝/释放结果；其具体边沿策略是待定义配置合同，不能随设备实现分叉。
- **表现**：分栏呈现自然 `C/X`、付费主动作用、读取、转入、材料变化、资源/tick/神识、身份变化和事件事实。音效、动画、命中闪光、预测轨迹只标注已经提交的 cause/transaction 或明确标为预测；掉帧、重复绘制、特效关闭不得改变账序。私有字段及拒绝原因按 grant 裁剪，连错误提示差异也不得推断隐藏目标。
- **配置/存档**：映射、死区、边沿去抖和焦点配置只转换意图；它们不能签 grant、改 payer、改模拟时刻或覆盖世界事实。游戏存档保存共享法术书、版本/哈希、属性及绑定引用；加载旧内容先保留原字节/版本和诊断，不静默迁移 DSL、AST、授权、材料来源、价格或身份。只有逐项证明权限、状态、报价、材料及结果等价的显式转换才可提出迁移；旧绑定失效需标红并指回原程序，不自动换成新预设。

**特权审计的反例**：把鼠标点在敌人身上、提高渲染帧率、暂停后连点、打开 HUD/调试面板、切到手柄配置、导入旧绑定，都不能直接取得目标私有 `LifeId`、余额或材料位置，也不能增加免费观察次数、缩短 tick、补回法力、制造材料或改变同刻提交序。获准公共展示字段与付费私有读取的边界尚待统一 UI 合同；未定前面板只给已授权摘要，不能靠遮住文字却保留区别性提示泄密。

#### 逐步体验的可见反馈合同

下表规定完整流程每一步展示什么；“不可见”意味着权限裁剪或候选数值尚未闭合，必须说明通用原因，不能用猜测值替代。

| 步骤             | 共同报价、来源与材料                                                                                                               | 临界/身份、授权及事件事实                                                                                                   | 不得显示或必须说明                                                                                        |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 空书/新建        | 无世界请求、无报价、无付款方、无材料变化。                                                                                         | 无事件、生命或授权变化。新 DSL/蓝图只创建书内草稿。                                                                         | 无默认法术、隐藏预设或伪绑定；演武显示“暂无可绑定法术”。                                                  |
| 编辑与预算       | 展示同一 AST/描述符版本对应的静态毛法力/tick/神识与容量上界、动态项、来源要求及材料域；无执行来源、无交易。                        | 不推断目标生命/身份或签发授权；无事件事实。                                                                                 | `unknownPrice`/无界必须标待定价或拒绝，域外修复标 `unexpressible`；不以 0、旧价格或仅有余额宣称可执行。   |
| 单步推演         | 每步引用共同报价证书及有限 payer；列已付 `T`、预留、材料 `Q[k]` 差量、退还/损耗和已做 tick，禁止重复扣费。                         | 标当前可公开阶段摘要及 grant 字段范围；六阶段里的已提交 `C/X`、身份撤权及事件因果按各自序号列出。                           | 无 grant 的目标属性、私有 `LifeId`、来源余额或材料位置显示“字段未授权/目标不可判定”；仅预估的作用标预测。 |
| 演武绑定/配置    | 指向同一程序哈希、属性与绑定版本；绑定不报价、不付款、不搬材料。                                                                   | 不因槽位或玩家身份增加权限；无事件。                                                                                        | 缺程序、能力、授权或预算时列本地可修复项目，不展示隐藏目标状态；保存配置不改世界序。                      |
| 请求、成功或拒绝 | 成功展示来源、执行者、payer、报价/实扣、工作及 `Q[k]`；拒绝展示已提交独立付款、合法尝试（若有证书）、已执行 tick、预留释放和余态。 | 只展示 grant 允许的临界阶段/身份关系；事件只显示有订阅权限的字段与 cause/sequence。死亡先撤销派生权，残余行为核对独立授权。 | 欠费、撤权、目标失效只显示不泄密类别；没有报价证书或材料域外时明确不可执行，不显示伪成功动画。            |
| 观察与返回修订   | 观察快照展示实际读取报价、payer、获准字段、观测模拟时刻；页签往返不产生额外交易。                                                  | 旧事件/身份摘要保持原 cause、grant 与时间，不因打开面板刷新为新读数。                                                       | 目标无权读取字段保持不可见，不用陈旧快照冒充当前；诊断指回原程序哈希与源位置。                            |

## 玩家完整体验闭环

1. **进入一本书**：推演台显示当前法术列表与选中程序。空书提供“新建 DSL / 新建蓝图”动作和说明；不存在可绑定法术时演武场显示引导而非空白槽或伪造默认程序。新增或切换程序只更新共享法术书。
2. **编辑**：玩家可选 DSL 或蓝图编辑同一 AST；语法/图结构诊断附程序名、节点/`sourceSpan` 和可操作定位。非法草稿留在编辑器供修正，不进入可执行程序；不因切模式或页签切换丢失未保存草稿，精确自动保存策略待配置合同定义。
3. **检查预算**：对书中可解析程序运行静态分析，分别显示法力、tick、神识上界及动态/无界项、列表容量和拒绝原因。上界不得低于相同输入实耗；静态通过不是运行时授权、目标存在或余额充足的保证。
4. **单步推演**：在受控场景对一段程序逐步执行，区分计算步、显式世界查询/作用、已付款、拒绝与仍在持续的自然演化。可查看本步上下文、账本变化、目标字段裁剪与 VM 状态；重置推演只重置沙盒会话，不倒转共享实战或真实外部状态。随机源与时刻需可重放，否则明确标为非确定输入。
5. **绑定整备**：到演武场从同一本书选择程序绑定槽位，调属性并核对缺失引用、结构/资源不足、预算或神识峰值问题。绑定只指定执行程序，不赋予其新权限、目标字段或无限法力。当前代码支持暂停时整备及往返保留配置；新规则需保证书版本更新同步且可指出绑定引用哪个程序版本。
6. **开始并观察**：玩家以统一请求触发程序。界面同时呈现自然 `C`（无需程序也会发生）和付费主动 `A` /读取 /转移 /事件响应，逐笔列付款来源、结果和剩余状态。玩家能区分已提交效果、惯性/自然后果、仍运行会话与单纯动画；不同载体共用反馈词汇。
7. **失败定位**：拒绝显示稳定原因类别及程序节点：无载体能力、权限/字段越界、目标消失或不可见、动态报价/余额/容量不足、缺材料/反作用、队列或执行上限、静态不合法。只揭示有权知道的内容；先前已付读取、转入、已做 tick、自然事实和其他响应保留，未提交原子作用不得显示为成功或扣取该作用价。仅按前驱的合法尝试工作条件单列已发生的 `attemptQuote/attemptId`；工作单价未闭合时拒绝该路径，不假定免费或捏造价格。动态目标拒绝不得泄露其私有存在。
8. **返回修改**：点击诊断回到同一共享法术书中的法术及 AST/DSL 源位置；保留原绑定关系和可解析内容。修改后重新分析、推演，再回演武场复测。离开和返回不能生成第二份“战斗副本”，也不能使已提交 write 因编辑而回滚。

### 相同初态的往返验收脚本

先固定书版本与 `programHash`、程序 `R` 的 AST、执行者结构与记忆、授权与有限付款账户、目标及材料、环境 `U`、模拟时刻/世界序和随机种子，保存为初态 `S0`。在推演台用 DSL 或蓝图编辑 `R`，另一路编辑方式应归到同一 AST 作用节点；对两种表示运行同一分析，核对法力毛支出、tick、神识/结构峰值、列表容量、动态项和 `unknownPrice` 提示。随后从 `S0` 单步推演：记录意图 ID、`requestId/causeId`、获准读取、报价/尝试工作、交易 `T`、自然接触 `C`、主动作用 `A/X`、生命判定及每笔失败余态；沙盒重置后同种子复现相同顺序。

再用同一 `S0` 和程序版本到演武场绑定、开始，分别把鼠标、键盘、将来手柄的相同边沿/方向归一，也把 AI 决策或获准实体事件映射到等价请求。比较的是提交前的规范请求和之后的逐笔反馈，而非页面像素或动画帧；推演沙盒与实战世界不共享运行状态。让一次后续请求因余额、撤权或材料变化拒绝，沿 `instructionId/sourceSpan` 回推演台同一本书修改 `R`，重新预算、单步推演和绑定复测。先前实战已提交的 `C/T/A/X` 不因重编而撤销；书版本变化后，旧诊断仍指向旧 `programHash`，不能错误定位到新节点。此脚本是未来实现与体验验收条件，现行页面只提供编辑、推演、绑定和战斗的局部入口。

纸面脚本逐步检查：**(a)** 空书时两场景均无报价/交易，创建草稿后共享书版本递增而世界状态不变；**(b)** DSL 与蓝图得到同一 AST 哈希时，预算显示同一 `Quote(x)` 版本、材料域、来源要求和动态/未知项；**(c)** 推演每一步对照报价证书、授权裁剪、`T/C/A/X`、身份状态与事件顺序，空目标仅在已授权查询成功时显示空集合并计真实读取，未授权时与隐藏目标统一显示不可用；**(d)** 演武选择绑定不创建付款或授权，开始后只按模拟序提交；暂停后配置/页签可变但时刻、交易、材料和事件序不变，恢复按合同处理边沿及待处理队列；**(e)** 返回时原草稿、同一书 owner、属性配置、绑定引用及原诊断哈希保持可追踪，修订生成新哈希并重新预算，不回滚已提交世界事实；**(f)** 成功、拒绝、空书、空目标各自以独立的 `S0` 重演，不能在同一条已变更世界中假称初态相同。

### 玩家可读的逐笔诊断

诊断卡统一呈现“哪个程序版本、哪次来源/触发、由谁执行、哪个授权与有限账户、请求哪笔、当前结果、已付什么、还剩什么、如何返回修改”。原始 `requestId/causeId`、`descriptorId/version`、`instructionId/sourceSpan` 可供定位，但对玩家先显示法术名、DSL 行或蓝图节点和具体修复建议。对他者字段、事件是否存在及余额仅展示 grant 允许的投影；调试视图也遵守同一裁剪。

| 情形           | 玩家文案与账目                                                                                                                                                                                                                                                    | 不能暗示的结论                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 成功作用与来源 | “已从授权账户付本笔作用价”；列毛扣、到账/损耗、预付来源、材料 `Q[k]`、反作用与热/废料去向，分列已付观察和自然 `C`。合法尝试工作若与成功报价重叠，只抵扣一次。                                                                                                     | 创建者、owner 或 controller 身份自动提供未来法力；旧固定价格足以覆盖新做功。 |
| 临界/身份      | 生命阶段只引用已提交结构事实与获准阶段摘要；显示“临界/休眠/死亡/身份待判”及对应模拟时刻。域内普通修补可成功，但同一 `LifeId` 仍须连续证据和未越关键回路阈值。                                                                                                     | `M=0`、HP 或实体句柄单独证明死亡/复苏；修补外壳自动复活原身份。              |
| 越权与无能力   | “此结构不能执行/探查/施力”或“此授权不覆盖该操作/字段/账户”；不给不可探查目标的存在、精确身份及私有价差。死者派生 grant 撤销，独立残余程序也须核对事先签发的期限、额度、结构和付款来源。                                                                           | 玩家、敌人、法球、机关因入口或类型得到豁免；旧 owner 关系可当死后授权。      |
| 待定价与域外   | `unknownPrice` 显示“当前作用价或来源换算未定，暂不能执行”，标出缺少哪项价函数/环境 `U` 证明；`unexpressible` 显示材料 D 外的请求和可改写的域内部分。静态卡不把动态、无界或未知显示为零。                                                                          | 给出伪有限总价、借旧 `0.8` 换算执行、用普通改接复苏生命关键回路。            |
| 后笔拒绝       | 对最新状态撤权、目标消失、欠费、缺材料、`staleMemory`、队列/容量上限，列未提交的本笔作用及释放的预留；已付 `read`、转入、VM tick 和独立 `attemptQuote/attemptId` 仍列账。尝试价只在通过预检、完成目录已报价的可审计世界工作时收，成功时同工作项抵扣；缺价不执行。 | “失败完全免费”或“已经造成作用”；用不同拒绝文案泄露私有目标。                 |

`S0` 相同并不表示两次实战可复用同一运行中世界；比较须重建隔离初态。报价、权限和材料在原子提交前再校验；若 `S1` 先用掉共享余额或材料，`S2` 的拒绝与剩余状态按模拟时刻/世界事实序/订阅序解释，不以输入回调或 UI 帧顺序解释。若 `S1` 引起生命死亡，派生 grant 撤销与后续事件裁剪按前驱六阶段顺序执行。

## 请求与反馈案例矩阵

用同一程序 `R`：接收一次合法意图/已授权事件，读取获准的自身或目标快照，做有限计算，按自身结构和有限 payer 请求一种可报价局部作用；若失败则记录诊断。它使用前驱规定的同一 AST 描述符、程序哈希、价格目录和失败码；如含记忆、订阅或并发 VM，结构与神识容量均须足够。四种载体从相同 `S0` 的公共规则出发，只改变真实能力、grant、目标、材料及余额。玩家输入适配只造相同请求；同一条件下对修士、法球、机关和敌方修士的请求字段、报价规则、拒绝类别、账目与已提交反馈必须一致。程序可因载体能力不同成功或拒绝，反馈必须指出能力差异，而不能因“玩家/敌人”标签改规则。

纸面比较的固定公共初态包括相同 `R/programHash`、描述符/价格证书版本、请求 payload、目标与 `Q[k]`、环境 `U`、世界时刻/序、授权字段和可用 payer 余额。先跑**公共基线**：四者都具备运行 `R` 所需程序槽、结构容量、感知/执行能力和独立有效 grant 时，应产生等价规范请求及报价；不同 actor ID 只影响审计标识。再逐次只改变一个条件：

| 单变量条件                 | 请求报价、余态和可见反馈（对四种载体同规则）                                                                                                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 成功                       | 只有报价证书、材料域、有效 grant、结构能力、有限余额及容量均通过原子重验才提交；记录来源、payer、`T`、`Q[k]`、`C/A/X`、tick 与事件 cause。法球不借创建者未来余额，机关没有“静态所以免费/无权”的例外。       |
| 欠费                       | 账户不足时拒绝未提交作用，显示自身可知余额不足、未提交价及已释放预留；此前合法读取/转入/tick 和有证据的合法尝试工作照记。目标私有价/余额仍裁剪。                                                            |
| 待定价                     | 缺 `Quote(x)` 证书、来源换算或有限上界时为 `unknownPrice`，禁止执行，不能套旧 0.8 比例或报价 0；同一证据缺失产生同类结果。                                                                                  |
| 域外修复                   | 对 `D` 外材料或生命关键回路请求标 `unexpressible`；不扣该原子作用价、不改材料/身份，不以视觉修好作为事实。可表达的独立步骤可单独形成请求与账目。                                                            |
| `identityRelation=unknown` | 缺连续结构/记忆/控制证据时显示“身份待判”，冻结旧身份私权；不自行分配 `same/new`，不因载体类型不同而改变。                                                                                                   |
| `DeathBarrier` 后          | 控制者死亡撤销派生授权并关闭账户接收；无有效预签死亡后 grant 的四种载体均拒绝后续请求。有效独立残余授权仅在自身结构、期限、额度及付款来源满足时允许继续，绝不继承死者权限。                                 |
| 空目标/旧原件              | 获准查询返回成功空集并按读取报价付款，未获权的隐藏目标统一返回不泄漏拒绝。旧法术/存档原件按版本隔离保存；只有权限、状态、报价、材料及结果逐项证明等价才能提出显式迁移，否则诊断到旧源位置并拒绝新规则执行。 |

未来将同一纸面脚本分别用于玩家修士与敌方修士，记录可比较的规范请求、授权差异和观战可见投影；当前没有新规则敌方修士体验，现有妖兽 AI 只能证明原型入口。预设仅可作为之后固定程序/初态的测试夹具，须先有独立批准与制作工作，本任务不创建预设、不改敌方行为或游戏测试。

| 同一请求阶段 | 修士                                                                        | 法球                                                                    | 机关                                                                    | 敌方修士（后续验证对象）                                                        |
| ------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 成功         | 有执行/感知结构、授权和余额时按相同请求提交；展示交易、局部作用与自然后果。 | 具备程序槽、传感/执行结构且有预付池时通过相同校验；不借创建者未来收入。 | 有实际推杆/执行能力和权限时可成功；固定不等于无权或必失败。             | 具备同等结构和授权时预期与玩家修士同请求、同价、同反馈；尚无此玩家可验证对象。  |
| 拒绝         | 缺能力、越权或欠费使用共通拒绝码；不把角色身份当豁免。                      | 缺程序槽/推进能力或无预付来源时相同拒绝类别；既有惯性是自然事实。       | 缺对应执行能力或材料时拒绝该原子作用；不可移动自身不等于不能施力。      | 同一规则拒绝且不泄露对方私有字段；敌方行为/观战反馈尚待对象验证。               |
| 空目标       | 获准查询而目标集为空，返回成功空结果并计实际读取费；作用不发生。            | 同一空集合语义，不因自动追踪而假造目标或免费扫描。                      | 同一空集合语义，不因场景机关可见而绕过查询权限。                        | 同一空集合语义；敌我阵营不改变空结果与私有字段裁剪。                            |
| 往返/诊断    | 回推同一本书的 `R` 和失败节点；修复后重新绑定或沿用现绑定。                 | 说明这是相同 AST 的载体能力差异；不静默改成玩家修士版本。               | 指明所缺执行结构、权能或材料；玩家可修改请求/目标范围而非 UI 强制成功。 | 若未来验证发现差异，作为规则一致性 finding 回到统一合同，不分派本节点制作任务。 |

若目标在提交前消失、撤权或变不可见，响应为不泄密的拒绝；未提交本笔原子作用不生效、不扣该作用价，合法尝试价、已做 tick 及先前独立付款按各自已提交事实列账。若依法查询后确为空，则为带时刻的成功空结果并按真实读取计价。已提交的先前转入、查询、自然接触和其他响应不撤销。此矩阵沿用 `mdr-spells` 的原子提交和权限裁剪候选规则，不重新定义其成本。敌方修士及新预设只是后续验证对象，本节点不制作、不排开发；现有妖兽 AI 也不等于已验过敌方修士的新程序装载。

## 失败、空书、旧原件与往返验收

| 场景       | 玩家应看到的状态                                                                                                                                | 可验证边界                                                                                                                                               |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 成功       | 同一意图 ID 下的请求、已授权字段、报价/实耗、提交事实及自然后果；双场景可回看程序和来源。                                                       | 不重复计价；分析上界不低于 VM 实耗；动画不代替结算。                                                                                                     |
| 拒绝       | 可修复原因、相关 DSL 行/蓝图节点、请求来源标签和已经发生的费用/保留状态。                                                                       | 无私有数据旁漏；提交前失败不伪装成功；已发生的其他因果不回滚。                                                                                           |

## 未闭合规则与评审边界

需后续在整版审核/对应规则合同闭合：输入映射配置 schema、意图去抖和边沿语义；暂停输入缓存/取消和恢复序；模拟时间与墙钟追赶上限；UI 公共可见字段和 hover/目标提示信息权限；材料 D 白名单与粒度、`M→功/X`、环境 `U`、合法尝试工作价、结构/神识容量数值；生命连续阈值、死后独立 grant 签发者和期限；动态报价与提交日志可见粒度；存档旧原件隔离/迁移交互和回滚；敌方程序观察权限与玩家可见摘要。参数不在本模块猜定，且应服从 `mdr-spells`、世界理论与核心不变量；相应调用在规则闭合前保持待定价、不可表达或拒绝执行。

推荐体验是统一请求诊断、用同一法术书在推演和实战之间可逆地定位问题。其代价是 UI 需显式显示自然变化与付费作用、动态拒绝和权限裁剪，信息量高于单一“施法成功/失败”提示；但能让玩家判断程序、资源和世界结果之间的因果。若受限 UI 信息规则阻碍玩家理解，请在模块评审列明效果、替代方案与理由后升级，不用免费探查补体验。

### 输入等价性记录表

针对同一条规范意图，分别从鼠标、键盘、手柄、AI 和实体事件适配器生成请求记录。实体事件必须使用相同的已提交事件先史；AI 必须只消费被授予的观察。先把所有输入映射到相同 `actor/programHash/slot/kind/phase/aim/move/targetHint`，再由模拟调度器赋相同 `simTime/worldSequence`。逐项比较**请求 payload、报价证书与毛报价、实扣/来源、已裁剪反馈、提交的余态及 cause/sequence**，不得只比 UI 或动画。记录未通过时只接受由真实能力、授权、材料、余额、观察范围或事件先史差异解释的结果；来源标签本身不改变规则。

### 跨入口等价、暂停边沿、旧内容与 ADR 覆盖

本轮对齐后的条件预算以资源目录的原子工作为准：H1 `R0(1,2,2)` 为 `9 M/10 tick/S8`，H2 `P0` 为 `12 M/6 tick/S4`，两笔毛额 `21 M`、目录工作 `16 tick`；普通 A0 起步 `12 M/6 tick/S4`、续步 `19 M/6 tick/S4`，两笔毛额 `31 M`、目录工作 `12 tick`。若 H 在 J1 执行，必须在装载前验证一个 `64 B` 方向记忆槽、传感器、推杆、锚链及本体一帧/两引用的同刻峰值；在 M1 执行也须计方向槽，若先起步再施力则另加 `12 M/6 tick` 与独立物理包。推演台静态证书和演武场观察还须逐路径加 AST 判断、记忆写入、订阅/信封、唤醒与并发工作；`600 tick` 单响应限额只是上限，不能把两原子和当作整程序已获证的 `τmax`。数值对齐不补出预封存包上游、逐体结构测量或独立攻击价，矩阵中的成功格继续是条件候选。

鼠标、键盘、手柄、AI、实体事件及敌方修士为六种输入来源。将它们各自映射为相同规范请求元组 `{actorId,executorId,programHash,action/target-or-direction-intent,simTime,grantId,payerId,requestSequence}`；在上述固定 S0、包/结构版本、可见字段、证书、先史、余额和种子下，逐一比较同 Quote 或 `unknownPrice`、同实扣 `Tx`/逐种 `Q[k]` 差、同 grant 双时点字段裁剪、同 `causeId/worldSequence`、同拒因类别及已提交余态。鼠标坐标、键盘边沿和手柄轴值只用于形成同一个方向/动作意图；AI 只消费获准观察；实体事件必须来自相同已提交先史；敌方修士无阵营折扣、隐式追踪或额外探查权。物种/设备/阵营标签不是价格或授权输入；结果差异只能由明确不同的能力、grant、payer、材料、可见范围、容量或因果先史解释。

暂停期间模拟时刻、世界序号、自然事件、付款、VM、窗口与队列处理均冻结。暂停边界前已采样但未提交的按下/释放边沿标记为过期并丢弃；恢复时不重放、不合并 held 状态、不补发暂停期间周期输入。只接受恢复之后取得的新 `inputSequence` 和完整新按下边沿，松开后再按才形成下一次意图。逐次记录暂停前末序号、暂停/恢复边界、过期序号、恢复后新序号及队列快照；六入口使用同一规则。暂停不延长游戏内截止窗口之外的逻辑时间（因模拟冻结，窗口也不前进），不得从墙钟/渲染帧补造请求。死亡 `DeathBarrier` 先撤派生 grant、停止接收并按程序证书清理未用预留，再处理同刻后续派发；先前已提交事实保留，`postDeathGrantUnavailable` 对各入口一致。

旧 DSL 与蓝图按原字节、AST/版本、hash、`sourceSpan`/节点留档，只能隔离预览；不自动改写或静默升级。旧预设逐字段保留为旧版输入，不自动替换新证书预设。敌方修士与 AI、鼠标等遵循相同规范请求，不继承旧阵营价、owner 私权或追踪例外。旧槽位绑定按旧 `bookId/bookVersion/programHash` 留作不可执行诊断引用；不自动重绑新 hash。存档文件原样保留，新增迁移只写旁路候选，绝不覆盖原件。旧 `damage/life/owner/HP`、分池、专名追踪及旧价格不能直接等价为新 `Quote/Tx/A/LifeAssessment`；仅逐项证明权限、价格、材料/包、余态、事件因果等价的字段可显式映射，其余拒绝或隔离并显示诊断。任何迁移先产生可审阅新 hash 和逐字段差异；不能证明等价须另有批准迁移策略，不能靠导入或绑定静默接受。
