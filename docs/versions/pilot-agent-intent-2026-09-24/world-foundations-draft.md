# 世界底层规则：供制作人审阅的候选模型

- 版本：`pilot-agent-intent-2026-09-24`；范围修订：`7`；状态：**部分原则已获制作人确认，其余为候选解释**。生命定义、法力守恒与世界/桥接分层见[补充草案](./life-and-world-boundary-draft.md)。
- 问题：现有规则能给法术计价，却不能从共同原理推出生命、法球寿命、回蓝和非生命施法。若直接实现更多法球功能，只会增加例外。
- 范围：先证明一套规则能解释修士、法球和其他实体的结构、变化、施法、资源、失效；审计属性与元法术边界。非目标：本阶段不写游戏实现、不定具体数值、不排预设或敌方技能、不承诺旧原型兼容。
- 验收：每个现象都能列出初始状态、触发、执行者、资源来源、状态变化与终态；不能仅以实体类别、倒计时或“策划设定如此”作解释。反例推不通即修改公理，不进入开发。

## 先说明哪些不能从现有三件事推出

制作人已经认可元法术、法力、耗时是核心，但三者只描述**如何请求改变世界以及请求的代价**。它们本身不能决定什么叫实体、为什么实体会散逸、肉身何以死亡、碰撞后残骸去哪。若声称只凭这三项就推出全部物理和生命，是把缺失的规律藏在代码里。因此建议补充尽可能少、对所有对象都适用的世界公理；这属于本轮待评审设计，不冒充已定规则。

1. **世界是有来源的状态。** 世界包含空间中的结构、运动、可用法力及法力来源。创建、移动、损伤、转移、消散只会按规则改变这些状态；不存在凭实体名字得到的免费效果。制作人已确认法力只能从一处转移至另一处；世界可以是开放的，但每笔跨边界转入或转出必须标明来源、接收处及速率上限。
2. **实体是能持续辨认的组织结构。** 实体不是“修士类”或“法球类”，而是一组有构成、连接关系、稳定性、局部资源池和可选器官/术式回路的结构。相同的结构稳定、受力、损伤、修复规律适用于所有实体。结构失效后可留下物质、散逸法力或碎片；不等于整个对象被无解释地删除。
3. **自然演化与主动施法共享同一状态账本。** 制作人已确认：惯性、碰撞、材料散逸和生理代谢按世界默认规律随时间演化，无需每帧运行玩家法术；法术是实体向世界或其他实体转移法力，以请求改变世界或实体的手段。需读取受保护信息的术式也按世界交互计价。组合、循环、追踪、爆炸流程属于普通法术。自然过程仍有来源与边界，不能伪装成免费元法术。
4. **施法是执行结构的行为，不是生命特权。** 一个实体要自行施法，须有保存程序与工作状态的结构、事件或主动调用入口、执行能力、权限和可支付账户。每步占用时间与工作状态；读取或影响世界时付法力。没有这些条件，生命体也不能施法；具备这些条件的非生命造物可以施法。创建者可注入程序、法力及有限授权，但不能使造物无限支用自己未来的资源。

这四条合起来可以压缩成一条总原则：**同一种有来源、有时长、受结构和权限约束的状态转移规则，作用于世界中所有实体。** “法术世界”不是说石头静止也在偷偷施法，而是可编排干预世界的途径由同一套元法术提供。

一个最小演算可以暴露隐藏例外。对任何实体，都先记结构状态 `S`、本地可用法力 `M`、运动状态 `V`、可运行程序与授权 `P`。经过同一段模拟时间，`S` 只因材料自然散逸、碰撞/术式损伤及有来源的修复而变化；`M` 只因有来源的转入、已付的元操作及损耗而变化；`V` 只因惯性、接触和有来源的施力而变化。`P` 决定能否响应事件和执行法术，不能凭空增补 `M` 或 `S`。这不是最终数值公式，而是任何公式必须满足的收支边界。

例如一名修士用已有法力和材料造出一颗会散逸的球，并给它刻入“碰撞时释放伤害，随后解构自身”的程序及有限余额：创建改变材料和两方资源池，发射改变球的 `V`；飞行时环境逐渐改变其 `S`；碰撞提交接触事实，再由球的 `P` 执行程序、扣 `M`、作用敌人的结构并解构自己的 `S`。若球在碰撞前已无 `M`，伤害术失败；它仍可能碰撞、反弹或因自然撞击破损，但不会自动产生约定的法术伤害或被无因删除。把同一个回路装在机关上，它也能执行；拆掉修士的执行结构，修士也不能执行。这两个反事实用来检验规则是否真的不看类别。

## 从规则推导具体问题

| 制作人提出的现象                       | 同一模型给出的因果链与可检验预测                                                                                                                                                                                                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 什么是血量，为什么修士会死亡？         | `HP` 建议只作**关键功能结构完整度的界面读数**，不是本体物质，也不是被扣到零才触发的宇宙定律。损伤改变结构；当维持生命的连接、代谢或自我修复条件失效，修士死亡，施法/控制权按终态规则终止。身体或残骸仍可存在。低 HP 与死亡如何对应须由关键结构模型定义，不能反过来用 HP 归零定义生命。                   |
| 法球为什么存在有限时间？               | 如果它由会散逸的结构构成，环境演化使连接或结构储能持续下降；低于稳定阈值时解体。初始构成、环境、预付维持和后续补给共同决定实际时长，**不预设固定秒数**。稳定材质的球可以长期存在；无施法余额的球也可能留存。                                                                                             |
| 法球为什么碰敌后消失？                 | 碰撞本身只产生接触、动量与可能的结构损伤事件。若它装载“接触时释放伤害并解构自身”的法术，该法术付费、转移效果且消耗结构，才会消失；若没装载或付款失败且碰撞未毁坏结构，它不该凭空消失。可以反弹、停下或留下失效外壳。                                                                                     |
| 非生命的法球怎么施法？                 | 创建者刻入程序和事件响应回路，交付本地执行所需的有限法力、状态容量、执行吞吐与授权。碰撞事件唤醒回路，回路调用元法术；它与修士受伤响应使用同一执行合同。一个没有回路的普通球不能施法。                                                                                                                   |
| 为什么有些修士能吸收更多法力？         | 至少区分法力**储量上限**、从某来源**吸收速率**、可用来源及转换效率。容器较大只决定能装多少，不自动回满；收集结构较强、来源更丰富或转化路径更有效，才会在相同时间获得更多。用一个 `manaRegen` 常数无法说明这些差异。                                                                                      |
| 恢复法力是否可为元法术？               | 建议有一个原子的**从已知来源向储池转移/转化可用法力**操作：检查来源余量、传输上限、容量、权限和损耗，原子记账并耗时。玩家可称它“汲取/恢复法力”。持续恢复只是定时反复调用它的普通法术或具有同样账本的自然过程；`mana += x` 不是它的语义。若通用资源转移元法术已能完整表达这件事，就不另立一个同义元法术。 |
| 为什么施法有快慢，法球是否有施法速度？ | 同一程序需要相同的逻辑工作量，但执行结构每秒可完成的工作不同。修士的神经/术式网络、法球的刻印回路都可有吞吐；没有执行结构就没有施法速度。提高吞吐缩短实际时间，不凭空减少程序工作量或元法术法力价。                                                                                                      |
| 为什么法球飞行、追踪、爆炸、伤害？     | 创建或发射时的冲量使它惯性飞行；持续加速要有驱动结构和来源。追踪是定时感知目标、计算、施加新冲量的普通程序；爆炸是触发后把有限储能或法力转成范围效果并改变自身结构的程序。法术伤害需明确目标、效果、付款和能量来源，不能由 `damage` 字段在碰撞分支里自动发生。                                           |

一个重要修订是：先前“**法球不能自行恢复法力**”应解释为**当前默认法球没有收集结构、来源和授权，所以不能恢复**，而不是宇宙禁止非生命体恢复。若未来给某造物装上合规的吸收器，规则应允许它付出相同代价吸收法力；否则“实体统一”仍是名义上的。这是从制作人新问题推导出的推荐，尚需制作人认可。

恢复操作还要解决零余额边界：不能要求先从空池支付一笔法力才准吸收，否则零法力者永久无法恢复。候选结算是从来源的**总转出量**分账：净额原子存入目标池，转换损耗和启动费用转入世界或其他明确接收处；若没有可用来源或净额不足则失败。自动吸收也必须受收集结构、速率、来源及相同账本约束，不能绕过元操作账本。来源是否为环境灵气、物品储能或另一实体，属于后续世界设定与数值设计。

## 属性审计：哪些是根，哪些只是读数

当前 [`Attributes`](../../../src/core/attributes.ts) 把十项并列，容易误以为数字本身就是世界原因。候选分类如下；具体可见属性和计算式要在规则获认可后再定。

| 当前属性      | 候选解释                                 | 本轮判断                                                                   |
| ------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| `hpMax`       | 关键结构可承受损伤的界面化读数           | 非世界公理；死亡由功能结构失效决定。                                       |
| `manaMax`     | 储池容量                                 | 可保留为结构能力，增加上限不会创造当前法力。                               |
| `manaRegen`   | 一段时间内实际汲取/转化的结果            | 不应是无源自动加法；必须由来源、收集器、速率、消耗导出。                   |
| `shenshiMax`  | 程序可占用的工作状态容量                 | 是否继续称“神识”、能否由非生命回路拥有，尚待验证；不应只按修士境界授予。   |
| `speed`       | 身体或驱动结构在供能条件下的主动运动能力 | 不能代替真实速度、惯性与可用驱动。                                         |
| `castSpeed`   | 执行结构的工作吞吐                       | 所有能本地施法的实体均可有；与逻辑耗时和法力价分离。                       |
| `power`       | 具体效果的输入能量、转化效率和目标耦合   | 全局伤害倍率缺因果，应逐效果解释，不能创造免费伤害。                       |
| `manaCostMul` | 真实算法/器件效率可能影响某些转换损耗    | 任意全局折扣会破坏元法术价格和资源守恒；优先由工作量、转换效率和损耗计算。 |
| `perception`  | 感知器件、范围和信息权限                 | 范围增大有结构、工作或法力代价；不自动授予读取权。                         |
| `armor`       | 材料结构和防护术式对特定作用的抵抗       | 不是对所有伤害恒定减去一个数；抵抗可能损伤自身或耗能。                     |

由此，**属性表应是世界状态和结构能力的视图，不是十个可以独立任意改写的根本变量**。这并非立即删掉所有界面数值，而是要求每个数字能追溯到构成、程序、资源与效果机制。要改变关键能力，法术必须改变其来源结构或运行状态，并支付对应代价。

## 元法术的不可拆判据与账本

候选判据：一项元法术只表示世界内核必须原子完成的最小读取或状态转移；若已有元法术加普通计算和控制流能产生完全等价的结果（包括时间、权限、资源、事件顺序），它是普通法术。注册表已有/没有某条方便函数不决定它是否原子。感知一个获准状态、转移可用法力、施加冲量、改变结构连接等是**待证明候选**；追踪、持续回蓝流程、碰撞爆炸流程不是。创建实体是否不可拆、结构修复和伤害是否同一个原子转移，仍须通过等价性和账本反例确定，不在这里冒称已证明。

每次主动施法至少记录：触发事件、承载程序的实体、控制者、付款账户、工作状态占用、逻辑工作量、实际耗时、元操作前后状态、法力来源与去向。自然演化也记录输入、结构变化和去向。**法力支付世界 I/O 并不意味着法力就是所有物理能量**；已有运动/伤害储能与不可兑换世界功率需分单位核对，未来世界模型必须说明它们与法力的转化边界，不能把账本单位悄悄混成一项。更优算法只能通过减少实际读取、世界作用、状态占用或执行工作省成本。

## 压力测试与尚未解决的设计选择

以下反例若无法从同一规则推导，就不能宣称世界已自洽：稳定物质球为什么会不会消失；散逸球加大初始结构投入能活多久；回路无余额而球体完好时留下什么；收集器装在球上能否恢复法力；无收集器修士为何不回蓝；修士生命终止但肉身仍完整时授权与结构如何分离；同一次碰撞中自然冲量、法术伤害、自解构分别由谁结算；被打坏的法球能否修复；创建者死后，造物已有的有限授权如何继续；两个实体争用同一来源是否会超额取得。

上一轮提出的三项世界观取舍，制作人已分别校准：

1. **生命与实体存在要分开：已确认。** 生命究竟是什么仍须给出可操作定义，见[补充草案](./life-and-world-boundary-draft.md)。
2. **法力恢复有显式来源：已确认并收紧。** 法力只能从一处转移至另一处；不能把损耗解释为法力凭空消失。默认法球没有吸收能力是候选解释。
3. **自然规律不逐帧施法：已确认。** 没有法术时世界按默认规律演化；法术是实体付出法力给世界或其他实体，按程序改变世界或实体。设备输入不属于世界规则，详见[补充草案](./life-and-world-boundary-draft.md)。

当前推荐这套模型作为**下一轮策划要证明或推翻的假说**，不是可直接实施的规格。主策需要写出最小状态变量、转移式、元法术最小集与单位账本，再用上述反例和修士/法球/稳定造物/机关四类实例演算。只有证明无特殊豁免、与制作人对齐并形成覆盖旧 ADR 的新决策后，才选择小规模实现切片及预设、敌方修士的展示方式。
