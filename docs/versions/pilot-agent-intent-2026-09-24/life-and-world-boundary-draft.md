# 生命、法力守恒与现实交互边界：策划草案

- 版本：`pilot-agent-intent-2026-09-24`，范围修订 `7`。与[世界底层规则](./world-foundations-draft.md)共同阅读。
- 已由制作人确认：生命与实体存在分开；法力只能从一处转移至另一处；没有法术时世界仍按默认规律运行；法术是实体支付法力给世界或其他实体以改变世界或实体的手段；鼠标左键等现实操作仅传达意图。
- 仍待论证：生命的可操作定义、最小世界状态与完整转移式、所有桥接入口的最终接口。本稿不是开发授权。

## 生命应是什么

先排除几个容易误用的定义：**存在不等于活着；会移动、会响应事件、能施法、拥有法力或拥有 HP，都不等于活着。** 法球可以具备这些能力而不是生命；修士死亡后肉身仍然存在，甚至其中独立刻入的术式在有限授权下仍可工作。

建议把生命定义为一种**持续的自维持组织过程**，而不是一个物种标签或一条血量数值。一个实体处于生命状态，应同时满足：

1. 它有可辨认的内外边界和相互依赖的关键结构；维持的对象是这套组织关系，不只是某块材料尚未散开。
2. 它从可追溯的外部来源取得维持所需的物质或能量，并通过内部调节把关键状态维持在可存续范围内；无需创造者持续替它逐步发命令。
3. 遇到一定扰动时，它能凭自身组织发现失衡、调节和修复，使维持过程继续。单个“每秒给自己加 HP”的脚本不足以证明这一点；是否能维护关键结构、如何付款和从哪里取得补给都要可追溯。

这是一种**功能定义**，不预先规定必须是血肉、必须有意识或必须会繁殖。若未来造物真的具备完整自维持组织，它可能是人工生命；若制作人希望“生命”还必须有魂魄/元神，那么魂魄也须作为有状态、有来源、有作用和终态的世界组成部分被定义，而不能凭类别直接附加。意识、人格和施法能力是另外的问题，不作为生命的同义词。

**死亡**是该实体的关键自维持循环在当前状态下失效，无法仅靠其正常可得的补给继续维持。它不是物质清零，也不是简单的 `HP=0`；外部修复若重建了关键组织，可讨论复苏，其代价和身份连续性须另行定义。界面可以用 HP 表示“距离关键失效还有多远”，但 HP 是测量或压缩展示，不能反过来成为死亡的根因。机关停机是功能失效，普通法球解体是结构失效；除非它们满足上述生命条件，不把两者随意叫作死亡。

反例检验：石头长期稳定存在但无自维持调节，因此不是生命；普通法球带有碰撞施法回路，能施法但没有生命过程；修士法力为零仍可能活着，因为生命维持还可依靠食物、呼吸等非施法来源；修士死亡后身体可残留；高度自主、会吸收来源并修复关键组织的造物，不能仅因为“人工”就被规则排除在生命之外。**哪些具体结构对修士生命必需、复苏后的身份是否连续，仍属世界设定待决，不冒充已经推导完毕。**

## 法力与法术的交易边界

制作人确认的“只能转移”比上一稿的“有来源”更严格。候选账本必须满足：一次法力转移在原子结算中同时记录**来源减量、去向增量**；法术向世界支付的法力进入世界的法力池或其他明确接收处，向实体支付则进入获准的目标池。所谓转换损耗、手续费和溢出，也须有接收处，不能用 `mana -= n` 表示法力凭空消失。世界若是开放系统，边界外转入/转出须显式记录为外部账户。法力和动能、热、结构等其他量之间如何换算，尚需另立清楚的规则，不能擅自说法力就是全部能量。

法术的世界内定义可先写作：**具有执行能力与授权的实体，按程序向世界或另一实体转移法力，以请求一个有界、可核验的世界状态读取或改变；世界在付款、权限、时间与结构条件满足时提交效果。** 读取世界也属于要付费的交互，但不必造成被读对象的变化。组合术编排这些交易，元法术只保留不可再组合的原子交易。没施法时，碰撞、惯性、材料变化和生命代谢仍按默认世界规律运行，其来源与去向同样可解释。

因此恢复法力是从环境、物品或另一实体等**已存在账户**向接收实体转移。零余额启动可以由来源支付启动成本并把净额转入，费用转给世界账户；具体转移元法术和规则未定。生命本身不享有自动回蓝，法球也不因非生命身份被禁止回蓝。任何持续恢复都要说明它依赖的收集结构、来源、转移速率、授权和时间。

## 三层边界与判定方法

| 层               | 它负责什么                                                                                 | 例子                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **世界规则**     | 实体状态、时间、自然演化、法力账户与转移、权限、施法、碰撞、损伤、生命过程、事件及失败结果 | “拥有该回路和余额的实体收到碰撞事件后，可请求施放已装载法术”。       |
| **意图桥接层**   | 把现实的人、设备或外部 AI 的选择变成与设备无关的请求；做身份与目标转换、去抖和有界排队     | “左键按下”或手柄按钮都映射为“控制者请求实体开始施放某个已绑定法术”。 |
| **展示与实验层** | 把可获知的世界结果呈给玩家，提供编辑、暂停、重开、导入、调试和原型设定                     | UI 显示血量、视角跟随角色、用编辑器载入法术、重置演武场。            |

判定一个概念属于哪层，可以连续问：**换成手柄、触屏、AI 或服务器调用后，它还应原样存在吗？** 若答案是否，它通常属于桥接。**在没有玩家和屏幕时，世界仍需结算它吗？** 若答案是，它属于世界规则。**它能否绕过世界权限、付款或因果？** 若能，桥接或实验工具越界了。原型管理操作可以直接设置初始条件，但必须明确只用于场景建立，不伪装成实体在世界中免费完成的行为。

最小意图入口应使用世界语义，例如“请求开始/持续/结束某次施法”“请求移动方向”“请求瞄准世界位置”“请求绑定/装载术式”。请求携带控制者、目标实体、模拟时刻或顺序、所选术式/会话，不携带 `mouse`、`KeyP`、屏幕像素或操作系统时间。世界验证实体是否存在、控制权、程序、资源、耗时和状态，再产生统一结果。玩家、妖兽 AI 与自动机关都经相同入口；来源可影响授权，不能改变计费或效果法则。

跨入口验收：同一初始世界状态与同一抽象意图序列，分别由鼠标、触屏、脚本或妖兽 AI 提交，世界结果应一致；改变帧率或暂停墙钟时长，模拟时间内的施法、法力转移和生命过程结果不变；关闭画面与声音仍能无头复现碰撞、事件、死亡及账本；把 `mouse` 改名或取消绑定只影响控制方式，不改变元法术语义。未通过这些检验，就不能说世界与桥接真正解耦。

## 对齐状态

法力守恒转移、自然规律与施法边界、现实输入不是世界规则，是制作人本轮**明确确认**的方向。生命定义及其反例、三层职责和意图入口是主策建议，尚需继续论证；尤其应检验人工生命、复苏与魂魄的世界设定，不能把这三项建议写成制作人已批准的最终公理。规则模型与边界获得制作人认可后，才写覆盖旧 ADR 的正式决策和最小实现路径。
