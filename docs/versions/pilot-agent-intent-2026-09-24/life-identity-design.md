# 生命维持与身份连续性：模块详细策划

**边界**：`pilot-agent-intent-2026-09-24`，承接范围修订 `13`、策划修订 `2`、已批准的六项 A/B/B/B/B/B 方向和主策 `changes-requested` 退回意见。本文件是 `module-design / mdc-life` 的生命与身份细则；直接前驱 `mdc-mana` 已交付，统一世界理论独占共同顺序与反例总账。下文的临界与身份规则是待主策和制作人审核的候选合同，不修改已采纳 ADR，也不授权开发。

## 问题、范围与验收

**问题**：生命不能等同于实体存在、HP 或法力余额；若新生命来自真正自维持的人工造物，必须说明它何时成为一个新的生命、旧生命是否延续，以及死亡事实如何撤销程序权限。**范围**是定义生命回路的状态所有权、失供/临界/休眠/复苏/死亡状态机、身份事实及交给程序和界面的接口。**非目标**是给出生命数值、材料白名单、复苏手段价格、存档迁移方案或改写旧 ADR。

验收为：同一套判据适用于修士和人工造物；区分修士、人工生命、法球、稳定物与遗体的存在、生命和可施法；列清结构、回路、供能、控制权的归属与跨模块接口；用 100/20 最后一击、及时补源、死亡后再损和信标修复逐项核验成功、失败及空状态；向程序和界面发布有权限的死亡/身份事实；显式定位旧 HP、自动回复、固定寿命和 ADR 0017/0020 冲突。

## 设计原则与认识状态

制作人已确认生命与实体存在分开，真正能自维持的人工造物可算生命，并选择允许休眠及修复后复苏、身份规则另定。策划采用的推荐原则是：**生命是由有边界的关键组织和回路持续实现的过程；身份是跨状态变化的连续性记录；施法资格是独立的能力、授权、程序和可支付来源判定。** 活着不自动等于能施法，能施法也不证明是生命。

以下是待评审模型，不是代码现状或已批准的不可逆公理：

1. 生命实例 `LifeId` 在自取来源、反馈调节和关键组织维持回路经事实确认成立时创建；实体 `EntityId` 标识当前可辨认结构。创建者、所有者和材料来源都不是 `LifeId`。一体多生命、复制与分裂归属尚未定稿，不直接复用实体 ID 充当生命身份。
2. 生命周期候选为 `nonliving`、`viable`、`critical`、`dormant`、`dead`，判定不足时另记 `unknown`，不把未知伪作死亡。实体结构状态另记 `intact`、`damaged`、`fragmented`、`dissolved`。生命判定取决于实际回路、关键组织、已完成的有源维持、可逆储存条件和连续证据，不由 `hp == 0` 或 `mana == 0` 单独触发。
3. 失供先造成可记录的维持缺口与功能退化。`critical` 表示关键功能已有危险，但尚未证明身份不可恢复；`dormant` 表示主动功能暂停且保存义务仍可履行、回路与连续记录仍可追踪。两者均须保留有效的后续补源或修复路径，不能靠界面文字制造可逆性。越过经未来规则定义的不可恢复界后 `dead` 为原 `LifeId` 的终态；一般修复不撤销死亡。
4. “复苏”在策划中只指未确认死亡的原 `LifeId` 从 `critical/dormant` 恢复到 `viable`。死亡后旧材料若再形成自维持闭环，先判新生命和新 `LifeId`；是否存在例外的同一身份复归仍是理论缺口，不能从材料、记忆或名称相似自动推断。修好非生命结构而未闭合回路，仍为 `nonliving`。

### 同一身份所需的连续记录

建议把**过程连续而非材料相似**作为同一身份的默认判据：初次成立时签发一次不可复用的 `LifeId`，随后每次结构、维持和生命阶段变化沿同一因果链追加记录。至少保留 `{lifeId, entityId/部位映射, 关键回路版本, 记忆与调节载体的保存状态, 供能/维持交易 ID, 结构变化 X ID, prior/next, causeId, simTime, worldSequence, 证据完整性, 授权变化}`。死亡、遗体瓦解或跨域移交不删除既有链；换壳、修补只改变映射，不能重签旧 ID。隐私字段留在生命模块，普通事件只给获准摘要。

判 `same` 的必要条件是：原 `LifeId` 尚未确认不可恢复死亡，关键回路或其可验证保存态从前一状态连续承接，记忆/调节载体没有无来源的复制跳跃，材料变化和供能交易可顺序追溯，且修复后的回路实际重新承担维持。满足这些条件才可从 `dormant/critical` 发布同一身份复苏；材料相同、程序脚本相同、控制者相同、余额充足都不足以单独证明。已确认 `dead` 后形成闭环或独立复制体，默认 `new`；缺记录、跨域断链、复制/分裂无法区分时标 `unknown`，冻结旧身份私权，等待产品与架构决策，不擅自归 `same`。`none` 只用于确知无生命身份的结构。回路最低保留度、记忆损失容许度、断链重建与死亡例外均未获批准，故此为候选证据门槛而非最终阈值。

建议的模块消息为：`LifeTransition {lifeId, entityId, priorState, nextState, causeId, simTime, worldSequence, irreversible?, identityRelation, continuityRecordRef, revokedGrantIds}`。事件引用已提交的物理 `C/A/X` 事实或资源 `T` 交易，不重复扣款或改结构。`identityRelation` 仅使用经规则确认的 `same`、`new`、`none` 或 `unknown`；未知时不得向玩家/程序谎报同一身份。维持请求为 `MaintenanceDemand(lifeId, circuitId, dueAt, requiredSupply?, allowedSources, authorityRef, preservationMode)`；生命模块提出真实义务，法力账本报价并办理付款，未知价为待定价而非零。账本返还 `TransferResult(transactionId, sourceId, grossDebit, netCredit, lossDestination, availability, refundBeneficiary)` 和维持结算；**预留、未来退款、环境总量都不是已到账供能**。物理层以 `RepairResult(causeId, changedPartIds, materialLedgerIds, structureVersion)` 回报实际域内结果后，生命模块才复核回路。

同一模拟时刻继承[唯一世界理论的六阶段权威候选顺序](./world-theory-draft.md#同刻权威顺序f3f4-的共同因果合同)：①自然接触及结构 `C/X`，②在此刻之前获准且到期的补源，③到期主动作用，④到期维持及默认失稳，⑤生命/身份判定与撤权，⑥事件派发。阶段内按单调 `worldSequence` 对最新状态逐笔复检；生命模块在阶段⑤统一发布事实，事件响应若另行改变结构，须在下一响应/逻辑边界前重判并撤权。阶段⑥由本刻接触唤醒的信标补源不能倒流到阶段②救本窗口；已提交攻击或接触不因后死回滚。确切回路阈值、数值容差、死亡后独立授权范围尚未闭合；这套顺序是候选策划而非 ADR 0020 已被覆盖。

## 存在、生命与施法是三个维度

## 失供、临界、休眠与恢复流程

建议的判定顺序是：结构/回路改变 → 计算此刻可用供给及已提交维持 → 更新欠账/功能退化 → 判定是否仍可维持关键组织 → 发出阶段变化 → 程序权限按变化处理。生命模块不把待结算的来源转账视为已到账。回路、组织、材料供给和控制者是不同事实：创造者可以消失而独立预授权回路继续工作；创造者的控制权不得因此转移给回路或尸体。

- **失供与临界**：供给低于真实义务时只记录短缺并按回路受影响次序退化。部分功能丧失不等同死亡；显示具体回路/能力降级及未知阈值。若请求的驱动/术式仍有执行结构和授权，可按剩余来源付款；生命维持不可从未经授权的其他账户暗扣。
- **休眠**：尚未确认死亡且组织可保存的生命可进入休眠候选态。主动取源/行动回路可以暂停，保存组织和连续记录的回路仍须说明真实材料条件、环境及有来源的持续义务；仅有“休眠”标记而保存条件已断不算可逆。原生命主动程序和生命派生控制权按休眠限制停用，独立预授权按自身期限与来源另判。休眠不冻结物理世界时间。保存成本、允许窗口及自发/受控进入条件未定。
- **及时补源**：在阶段②之前已有授权的转入可用于本刻阶段④维持；转入的毛支出须覆盖净到账、启动价和散逸。若缺口已发生而原身份尚未死亡，补源只阻止后续退化或为修复创造条件，不回滚已发生损伤。阶段⑥事件才触发的转入仅供下一逻辑边界使用；即使同一 `simTime` 也不能撤销阶段⑤已提交死亡。
- **修复复苏**：修复先由材料系统核验来源、权限、域和结算并提交结构变化，生命系统再检查回路和身份阈值。缺材料/越权/报价未知时不产生结构修复或生命变化；修好一般结构不保证重建生命回路。若关键回路落在已选窄材料编辑域之外，信标可完成域内修补，但复苏请求仍属不可表达，不能从修补结果推断同一身份；此边界与[理论 B4](./world-theory-draft.md#跨实体与边界反例的交易明细)一致。

**人工造物的 B 路径**：创建只迁移有来源材料、付费形成结构，初始仍为 `nonliving`；外部注能或持续脚本也只证明账户/程序存在。它实际具备可追踪的自主取源接口、反馈调节、关键组织回路，且能从有限获准来源逐笔付维持义务时，生命模块才建立新 `LifeId`。源断后沿与修士相同的真实材料失稳进入 `critical`，若保存结构和供能义务能成立才可转 `dormant`；在未死窗口内补源并域内修好回路后，沿连续记录复苏为同一身份。若回路不可恢复或连续记录断裂，分别为原生命死亡或身份 `unknown`；在死后重组的新闭环默认新身份。创造者的控制 grant、人工生命自己的取源许可及其 `LifeId` 各自独立：创造者死亡只撤其派生权限，不凭血缘/所有权抹除人工生命或转移其账户；造物失去授权也不等于立即死亡，但它不能越权取得下一笔维持来源。

以下量值都未获批准：临界前允许欠供时长、每种回路的关键阈值、休眠保存需求/最长时间、复苏材料域、死亡不可逆判据、身份记忆/组织最低连续度。**相对同刻顺序已由世界理论给出候选结论**，不能再列为全然未知；物理容差、具体价/工作上界和身份阈值仍须设计评审及必要的新 ADR 闭合。下节进一步固定可复核的判定方法，不把未获批数值写成事实。

## 本轮临界、窗口与 LifeId 判定合同

### 先判存在，再判生命，最后判身份

每个模拟边界先用物理提交的结构版本判**实体存在**：有可追溯的材料部位及连接构成一个可辨认局部组织时，`EntityId` 指向这份结构；局部受损、停机或生命死亡均不销毁句柄。结构确已失去可辨认边界时，句柄终止，但材料和历史 `LifeId` 留在各自账本。只知目标离开模拟域或缺结构快照时返回 `existence=unknown/out-of-scope`，不能写“瓦解”。物理 `X`、材料去向及跨域接收凭证是存在判据的证据，HP、余额、动画计时与可被选中均不是。

对存在的结构，生命模块登记候选**关键回路集合** `K`：可辨认边界和关键组织、从有限合法来源自行取得维持所需供给的结构、感知自身偏差并调节的反馈通路、保存这些功能所需的组织与控制状态。外部操作者逐刻直接指挥、单纯预装脚本、持续注能或余额充足都不能代替自取源与反馈。每条回路记录物理部位/连接版本、输入来源及权限、输出与废物去向、可测功能裕度和可验证的维持义务。修士的代谢/调节与人工生命的构造回路逐项使用**同一个字段和状态机**；材料种类、意识、主人或 `Actor` 类型均不成为身份捷径。新结构首次通过闭环、实际付清首个需要付款的维持窗口，并能对一次有界扰动反馈时，才创建新 `LifeId`；若当时尚无到期窗口，只能标 `candidate/unknown`，不能由空账推成活着。没有自取源和反馈的球、机关、石块仍是 `nonliving`，即使它们执行程序。

每个回路 `k` 的候选配置须公开版本化的 `requiredFunction(k)`、维持周期或到期时刻 `due(k)`、已结算供给 `settledSupply(k)`、可保存裕度 `reserve(k)`、不可逆结构界 `fatalBoundary(k)`、保存环境范围和最长可恢复时限 `recoveryDeadline(k)`。临界不是一个通用 HP 数，而是**下一到期窗口**内至少一条关键回路的实际功能或已付款供给低于其已声明最低界，同时尚有经过物理与账本证明的保留/补救路径。`viable` 要求本窗口全部关键回路功能达界，已到期的维持已结清，并能由自身取源/反馈继续调节。`critical` 可失去主动能力，但仍有连续承载体，且存在在截止前获准、可报价、有材料与结构能力的恢复路径。若只有“也许有办法”而无证书，回报 `unknown` 和缺失证据，不宣称可逆。

**维持窗口**从上次实际完成维持的 `simTime` 到下一 `due(k)`，不是显示帧或 ADR 0017 的统一 `0.25s` 控制租约。窗口需由真实结构、供给率、耗散与环境给出有限上界；每次 `C/X`、供给 `T` 或环境变化按新版本重算，不追改已提交交易。到期欠费只形成带时间戳的缺口及默认失稳，随后查功能裕度；欠费一瞬不自动死。可逆休眠必须有意或被动进入的物理机制、仍连续的关键承载体、已证实的保存环境和到期保存成本、下一检查/救援截止时刻。允许调节与行动停顿，但每一保存窗口仍付清真实义务或由有证据的无源稳定条件承担；不能用 `dormant` 标签暂停世界时间或免费冻结组织。保存条件失效则重新判 `critical/dead/unknown`。具体周期、裕度、环境界及保存价均尚未获批，不能在运行合同中填默认零或无限期。

**不可逆损坏**须由已提交 `X` 及版本化材料/回路证书证明：关键组织的连续承载体已断且没有在已声明恢复域、剩余材料和截止时限内可行的因果延续路径，或有记录的保存时限已越过并造成无法保留控制/记忆载体的实际退化。满足该正面证据才把原 `LifeId` 判 `dead`，一次提交终止序号；以后同一 ID 绝不返回 `viable`。仅因当前窄编辑域不能修关键回路，结论是“该操作不可表达”，**不自动推出宇宙中不可恢复或已经死亡**。材料响应、合法来源、窗口参数或域外历史未知时，身份/生命判定分别给 `unknown`；对已知结构缺陷仍可报告 `critical` 风险，但不得伪造死亡时刻。`dead` 不等于遗体瓦解，死亡后 `X` 仍按物理事实追加。

### 同一 LifeId 的连续性证明

`LifeId` 在首次确认闭环时由生命模块签发，永不复用；`EntityId` 可以因换壳或跨域映射改变。每一次迁移、损伤、休眠与修复在前一记录上追加 `{lifeId, previousRecordId, worldSequence, simTime, entity/partMap, X/C/A/T refs, circuitVersion, preservationWindow, memoryCarrierVersion, regulationStateVersion, controlLineage, grantChanges, evidenceStatus}`。其中**记忆**包括可保存的调节/学习状态与其变更来源，不要求每条个人回忆完好；正常遗忘、受伤与合法改写可有损，但损失必须被记录且剩余调节载体能够承接原过程。**控制**指维持回路的内部控制状态连续及外部 grant 的签发/撤销谱系，不能把创建者控制权当作生命身份。物理部位替换须有原载体到新载体的实际迁移或在线交接记录；复制出两个同时自维持的分支时，不能给两者同一个旧 ID。

同一身份复苏须同时证明：原 ID 没有已确认的 `dead` 屏障；关键组织/保存态沿唯一因果链跨过全部窗口；记忆与调节状态有逐版来源且没有无法区分的复制分叉；控制谱系能说明谁在每段维持及修复中有权操作，死亡/休眠限制没有被绕过；修复后的回路已实际承担新的维持，而非只把外壳接好。满足后从 `critical/dormant→viable` 仍用旧 ID。若旧 ID 已正证死亡，后来形成闭环须签新 ID；若旧 ID 是否死亡、迁移是否连续或复制分支归属缺证，标 `identityRelation=unknown`，隔离依赖旧身份的私有权能，不据材料相似、姓名、脚本或记忆内容推 `same/new`。确知从未有生命闭环才是 `none`。此判据给出证据结构；最低裕度、可接受的记忆/控制损失及复制分支裁决仍需制作人取舍和覆盖 ADR。

## 死亡与身份事实的程序授权和界面暴露

死亡事件向程序模块提供获准的最小事实：实体句柄或不可见目标、`lifeId`（仅获准者）、`prior/next`、`identityRelation`、不可逆判定或 `unknown`、原因 `C/A/X/T` ID、模拟时刻/世界序号和撤销摘要。连续记录的私有细节只通过另行授权的查询接口取得；不得把记忆、账户、grant 令牌或遗体私有字段塞进通用事件信封。订阅在创建时声明字段、对象、期限和配额，提交与派发时复检；死亡/结构失效的撤权在事件响应前提交且不能因队列满漏掉。未自动撤销的独立预授权必须有明确持有人、期限、额度/操作域和终止条件。

推荐权能规则：死亡提交后停止死者作为生命主体的主动程序调度和新权限签发；取消其拥有的维持/持续控制会话；阻止向死者账户提款、自动回复和死亡退款；清理由旧 grant 派生的子权限。物理实体可继续运动/受损。独立法球或信标只有自身程序、结构、授权和预付资源齐全时继续；不因所有者死亡继承所有者权限。程序只能依据可见事件采取后续行动，不能把 `dead` 状态写回 `alive`；新生命须走新身份创建/确认合同。

界面按查看者权限分别呈现 `结构存在/范围外未知/已瓦解`、`生命阶段/无生命/不可探查`、`身份关系 same/new/none/unknown`、`施法能力/授权/余额是否可用`；每条已知事实标注观察时刻、来源和待定阈值。临界与休眠显示实际缺失的回路/供能及“可逆条件待定”，死亡显示原身份终止而遗体仍可受损；域内结构修复显示“结构已修复，生命/身份未确认”。无目标、无读取权或记录断链时显示空结果/不可探查/身份未知，不用过期 HP 条、所有权颜色或画面消失推断死亡，也不泄露私有状态。

### 交给程序模块的事实与桥接投影

生命模块只签发已提交、版本化的 `LifeAssessment`：`{entityRef, existence, lifeState, lifeIdRef?, identityRelation, circuitVersion?, structureVersion?, dueAt?, recoveryDeadline?, evidenceStatus, causeRefs, simTime, worldSequence}`。`lifeIdRef` 对无权订阅者是不透明引用；`unknown` 不编造一个待继承的 ID。死亡另给一次性 `DeathBarrier {lifeIdRef, terminalSequence, reasonRefs, residualEntityRef?, revokedSubjectGrantRefs, capacityAfter, accountCloseRef}`；已死遗体再损只更新 `ResidualStructure {entityRef, structureVersion, remainingExecutionParts, materialRefs, causeRefs}`，不重发 DeathBarrier。休眠/临界也向程序送能力变化和下次维持窗口；这些消息均在阶段⑤撤权后、阶段⑥可见事件之前提交，不依赖队列容量完成清理。

程序模块必须在每次尝试、订阅派发和提交前读取**当前**结构能力与 `capacityAfter`：实际执行部位、有限记忆/神识承载、感知与施力部位、付款账户及其额度、有效 grant。生命状态不是免费容量；`viable` 也可能没有执行结构，遗体若保有执行结构也不取得死者主体权限。`dead` 立即撤销以该 `LifeId` 为主体的控制、未来输入、动态订阅、监控、维持会话和提款，关闭原账户并幂等清算；已经提交的 `A/X/T`、惯性和独立有效行为按 ADR 0020 存续。独立行为须在死亡前获合法、有限期限/额度/字段的授权，另有自身结构、工作和预付来源；创建者、owner 或残余材料不自动签发新 grant。`unknown` 时禁用仅凭“同一生命”才能行使的私权，保留不依赖该身份且仍有效的独立能力；缺证不能被程序层默认为 `same` 或 `new`。

桥接只按当前查看者的字段权限输出 `LifeDiagnostic {observedAt, entityExistence, lifeStateOrHidden, identityRelationOrUnknown, dueWindowOrHidden, deficientCircuitOrHidden, preservationDeadlineOrHidden, repairDomainStatus, capabilityReason, evidenceFreshness}`。公开诊断优先给“下一窗口何时到期、已知缺的是供能/结构/权限、结构修复是否仅在窄域、身份连续性是否缺证”；不公开他人记忆载体细节、具体账户来源、完整 grant 或隐藏关键回路。权限不足显示 `不可探查`，证据不全显示 `unknown`，范围外显示 `范围外未知`，三者不同；若获准读取到“外壳已修、回路未恢复”，分别显示两项，不合成“已复活”。推演台/演武场只投影这些事实，不按 HUD 计时、动画或旧 HP 推导状态。

## 当前代码与采纳 ADR 的冲突定位

| 现行事实                                                                                                                                                                                                                                        | 与新合同的差异及后续处理                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`src/core/world.ts`](../../../src/core/world.ts) 的 `Actor` 同时保存 `hp/hpMax`、`mana/manaRegen`、`alive` 与 `deathTimer`；`tickActor` 按 `manaRegen` 增余额，`applyDamage` 扣 HP、归零后设死亡计时；`updateActorMotion` 周期补 `movePower`。 | 这是旧原型生命与自动资源回复路径，不是来源可追踪的回路维持模型。HP 可以是展示/受损摘要候选，但不得成为生命身份、失供或死亡唯一裁决；自动回复必须审查真实来源，不能换名沿用。                                                                               |
| [`src/game/battle.ts`](../../../src/game/battle.ts) 给玩家/敌人配置固定 `hpMax`/`manaRegen`，按 `alive` 更新，维护/蓄力处理以目标死亡中断；弹道有 `life` 秒倒计时并过期删除。                                                                   | Battle 适配层的目标存活、法术会话中断和弹道寿命均属旧局部合同。固定寿命可表示原型边界，不得直接解释新世界实体消失；法球失供、稳定物、遗体和范围外实体要按结构/来源/移交另判。                                                                              |
| **ADR 0017** 已采纳统一实体句柄、descriptor/binding 控制、能力拒绝及 `commit/overlay/maintain`；属性表仍含 `hp/hpMax/manaRegen/lifetime`，维持周期现为 `0.25s`。                                                                                | 可复用其能力拒绝、原子提交、权限与有界生命周期控制的实现边界。若把 HP 写入改成结构/生命事件、将固定维持周期改为回路供给、把 lifetime 从存在判定剥离或引入 `LifeId`，都改变已采纳属性/控制合同；需明确新 ADR 的覆盖条款和旧字段处置，不能由本策划默默废止。 |
| **ADR 0020** 已采纳事件快照/有界队列、执行上下文、授权与终止清理；死亡撤销相关权限并禁止死者账户自动回复/退款，遗体期间不退款。                                                                                                                 | 事件稳定排序、不得泄露未授权字段、终止幂等及退款去重可直接继承。新生命身份、休眠、同一身份复苏、人工生命回路与遗体继续事件如何适配需补合同；死亡后独立程序/授权不得扩大为死者主体继续施法，若要变更 ADR 0020 的死亡边界需新 ADR/明确覆盖。                 |

当前代码和 ADR 测试证明的是旧原型合同；没有实现证据证明本模块的身份、临界、及时供给、死亡后再损或信标修复语义已运行。旧存档中的 HP、寿命、余额或法球实体不应被推断成新的回路、历史供给或 `LifeId`。

## 尚待产品/架构闭合

| 未决规则                                                            | 为什么不能在此定稿                                                                                               |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 关键回路的最小定义、供给需求、欠供累积方式与临界/死亡阈值           | 决定玩家是否能挪用最后资源及是否可预测；100/20 只检验账本，不决定死亡时刻。                                      |
| 休眠可保存的组织、记忆及持续成本；苏醒条件与窗口                    | 决定失供玩法、实际时间体验和同一身份边界。                                                                       |
| 身份连续证据的最低强度：记忆/回路可损程度、断链、复制与分裂如何归属 | 本文推荐过程连续记录和死后新 `LifeId`，但临界阈值与例外是新产品语义；不能凭 `EntityId`、材料相似或程序状态暗定。 |
| 人工生命的自取源能力边界，以及被创建者撤权/死亡后的独立性           | 关系到用户控制、授权撤销和自主角色行为；来源余额本身不能证明生命。                                               |
| 遗体私有身份数据哪些可探查，独立死后程序的预授权粒度与持续时间      | 关系到程序权限及 ADR 0020，需和 `mdr-spells` 合并审议。                                                          |
| 何种材料域能修复回路、何种结果构成新生命                            | 依赖物理材料闭包和法力价/上界；必须拒绝未报价的万能修复。                                                        |
| 已定候选六阶段顺序的物理容差、具体临界判值及 HUD 可见性             | 相对顺序由理论给出；数值和字段权限仍须跨模块复审，不能由渲染回调决定。                                           |

**制作人待判断的身份取舍**：

| 选项                            | 玩家效果                                                                                                | 优点与代价                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 甲：过程连续，**推荐**          | 临界或有证休眠者可在截止前获源、修复并以原身份醒来；已证死亡后新闭环取得新 ID；证据断链显示 `unknown`。 | 救援窗口、死亡撤权与“同一个人”说法可追因，也与已选休眠 B 一致。代价是结构/记忆/控制版本与保存条件必须持久记录，且分裂时暂不能给旧身份。 |
| 乙：修复后均签新 ID             | 即使刚进入休眠、完整保留记忆的角色获救，也视为新生命。                                                  | 判定简单，但玩家期待的“救回原人”落空，原授权与关系全部重建。                                                                            |
| 丙：材料或记忆相似即可沿用旧 ID | 死后重装、复制记忆也可能以原身份回来。                                                                  | 复活体验更宽，却可使两个分支同时持同一权利、绕过死亡撤权；须先另定复制归属与私权规则，当前不可按此执行。                                |

推荐甲只确定证据**类型与决策次序**；最低组织裕度、记忆损失可接受界、保存时长和复制分支裁决仍需制作人判断，缺证时保持 `unknown`。关键回路不在窄材料编辑域时，信标只能修域内结构；“同一身份复苏”保持不可表达，不以更便宜的价、现有 `life` 字段或新增复苏元法术绕开。

**本轮闭合边界**：已承接 `mdc-mana` 的来源总转出、到账时序、维持不赊账、已做功不退款和未知价拒绝，接上世界理论六阶段顺序、`mdc-physics` 的 `C/A/X` 唯一结构事实；存在/生命分判、证据化临界和死亡、窗口重算、同一身份所需记录、六项逐刻反例及下游投影形成可审阅的候选合同。临界/死亡数值、休眠保存价、记忆与控制最低连续度、人工生命取源范围、窄域能否修关键回路仍是理论或产品缺口。此文不等于理论定型、ADR 覆盖、代码运行或游戏开发许可；Version PM 仍须做整版一致性审核。
