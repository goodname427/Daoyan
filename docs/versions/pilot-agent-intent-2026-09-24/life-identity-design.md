# 生命维持与身份连续性：模块详细策划

**边界**：`pilot-agent-intent-2026-09-24`，承接范围修订 `13`、策划修订 `2` 和已批准的 A/B/B/B/B/B 方向。本文件是 `md-life` 模块策划，不是制作人对阈值或身份规则的最终批准，不修改已采纳 ADR，也不授权实现。

## 问题、范围与验收

**问题**：生命不能等同于实体存在、HP 或法力余额；若新生命来自真正自维持的人工造物，必须说明它何时成为一个新的生命、旧生命是否延续，以及死亡事实如何撤销程序权限。**范围**是定义生命回路的状态所有权、失供/临界/休眠/复苏/死亡状态机、身份事实及交给程序和界面的接口。**非目标**是给出生命数值、材料白名单、复苏手段价格、存档迁移方案或改写旧 ADR。

验收为：同一套判据适用于修士和人工造物；区分修士、人工生命、法球、稳定物与遗体的存在、生命和可施法；列清结构、回路、供能、控制权的归属与跨模块接口；用 100/20 最后一击、及时补源、死亡后再损和信标修复逐项核验成功、失败及空状态；向程序和界面发布有权限的死亡/身份事实；显式定位旧 HP、自动回复、固定寿命和 ADR 0017/0020 冲突。

## 设计原则与认识状态

制作人已确认生命与实体存在分开，真正能自维持的人工造物可算生命，并选择允许休眠及修复后复苏、身份规则另定。策划采用的推荐原则是：**生命是由有边界的关键组织和回路持续实现的过程；身份是跨状态变化的连续性记录；施法资格是独立的能力、授权、程序和可支付来源判定。** 活着不自动等于能施法，能施法也不证明是生命。

以下是待评审模型，不是代码现状或已批准的不可逆公理：

1. 生命实例 `LifeId` 在生命被确认成立时创建；实体 `EntityId` 标识当前可辨认结构。两者一对多/多对一的变更规则尚须定稿，禁止直接复用实体 ID 充当生命身份。
2. 生命周期状态建议为 `nonliving`、`viable`、`critical`、`dormant`、`dead`；实体结构状态另记 `intact`、`damaged`、`fragmented`、`dissolved`。状态由回路可用性、组织结构、已承诺供能及不可逆阈值共同判定，不由 `hp == 0` 或 `mana == 0` 单独触发。
3. 失供先导致回路欠账/功能退化；若能以获准来源在不可逆阈值之前恢复条件，可复苏。达到死亡阈值后死亡事实不可由一般修复撤销；若仍有材料可重新组织出生命，则创建新 `LifeId`，不得称作原身份自然复活。
4. 可观察到的“复苏”可分为：同一 `LifeId` 从休眠回到活动；原生命越过不可逆死亡后，在旧材料上形成新生命（新 `LifeId`）；没有生命回路的实体被修好但仍非生命。该术语边界与死亡阈值是未决产品规则。

建议的模块消息为：`LifeTransition {lifeId, entityId, priorState, nextState, causeId, simTime, irreversible, identityRelation, revokedGrantIds}`。事件引用已提交的物理事实或资源交易，不重复扣款或改结构。`identityRelation` 仅使用经规则确认的 `same`、`new`、`none` 或 `unknown`；未知时不得向玩家/程序谎报同一身份。维持请求为 `MaintenanceDemand(lifeId, circuitId, dueAt, requiredSupply?, allowedSources, authorityRef)`；确切需求、周期和报价由后续产品/账本规则决定。结构恢复必须由 `RepairResult(causeId, changedPartIds, materialLedgerIds)` 回报后再评估回路。

同一模拟时刻若自然结构变化、资源供给和主动程序竞争，先按物理/资源各自权威顺序提交事实，生命模块在每一提交边界重新判定；已达到的死亡不可被同刻迟到的补给抹除。对于补给与临界同刻的先后、队列序号及数值稳定性，必须由后续统一世界时序合同确定并测试，不能由 UI 回调顺序决定。

## 存在、生命与施法是三个维度

| 对象/情形                            | 实体存在                                     | 生命状态                                                                              | 可施法状态                                                                                                                   |
| ------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 修士，回路完整且有能力/权限/支付来源 | 结构存在                                     | `viable`；受损时可进入 `critical`                                                     | 有可执行结构、程序授权和资金时可施法；任一条件缺失即不可施法，不因存活免价。                                                 |
| 人工生命                             | 结构存在                                     | 只有实际拥有自取来源、反馈/调节回路和足以维持关键组织的闭环才算生命；需与修士用同判据 | 与修士相同，按结构能力、授权、程序和支付分别判定。只按固定脚本重复动作不自动构成生命。                                       |
| 法球                                 | 球壳/结构存在                                | 默认非生命；若未来实际满足同一自维持回路判据才可另判，不因会响应事件而成为生命        | 失供后已付惯性、自然运动及获准被动行为可继续；主动施法须各自有能力、授权和来源。有限寿命字段不能代替存在规则。               |
| 稳定物（石块、无源稳定球、机关）     | 结构存在且按默认规律演化                     | `nonliving`，除非具备实际生命回路                                                     | 有程序结构、感知/执行能力、授权和资金时可施法；稳定存在不等于有施法权。                                                      |
| 遗体/死亡生命的残余结构              | 可持续存在、继续受损、修复或瓦解             | 原 `LifeId` 为 `dead`，不可二次死亡；是否可休眠或复苏只适用于未越过死亡阈值的身份     | 死亡撤销原生命的运行/控制授权；只可运行独立预先授权且边界明确的遗体程序。遗体材料可被获准读取/改动，不自动暴露身份私有信息。 |
| 已瓦解/无可辨认结构                  | 该实体结构不再存在；材料仍按物理账本去向处理 | 死亡事实仍在身份记录中，不因结构消失删除历史                                          | 无可执行结构则不能施法；其他实体不得继承死者账户或权限。                                                                     |

“有实体句柄”“能被目标选择”“有法力余额”“当前在场”都不是生命证明。实体移除/范围外未知也不自动等于死亡；死亡与瓦解必须分别报告。

## 失供、临界、休眠与恢复流程

建议的判定顺序是：结构/回路改变 → 计算此刻可用供给及已提交维持 → 更新欠账/功能退化 → 判定是否仍可维持关键组织 → 发出阶段变化 → 程序权限按变化处理。生命模块不把待结算的来源转账视为已到账。回路、组织、材料供给和控制者是不同事实：创造者可以消失而独立预授权回路继续工作；创造者的控制权不得因此转移给回路或尸体。

- **失供与临界**：供给低于真实义务时只记录短缺并按回路受影响次序退化。部分功能丧失不等同死亡；显示具体回路/能力降级及未知阈值。若请求的驱动/术式仍有执行结构和授权，可按剩余来源付款；生命维持不可从未经授权的其他账户暗扣。
- **休眠**：尚未死亡且组织可保存的生命可进入休眠候选态。休眠须明确哪些回路停止、哪些保存义务继续、记忆/程序是否冻结及由谁授权；休眠不冻结物理世界时间，也不隐式延长固定寿命。具体保存成本与允许窗口未定。
- **及时补源**：只有在临界提交前，来源有权、转账成功且接收端/回路可用时才可阻止后续退化或满足维持。补源不回滚已发生损伤，不抹除已发布的历史事件；若短缺已导致可逆功能下降，可在付费修复/自然恢复规则允许下恢复。
- **修复复苏**：修复先由材料系统核验来源、权限、域和结算并提交结构变化，生命系统再检查回路和身份阈值。缺材料/越权/报价未知时不产生结构修复或生命变化；修好一般结构不保证重建生命回路。

以下量值都未获批准：临界前允许欠供时长、每种回路的关键阈值、休眠保存需求/最长时间、复苏材料域、维持先于主动请求还是相反、同刻排序、死亡不可逆判据、身份记忆/组织最低连续度。实施前应由版本级设计评审确认可读体验与反例，并按架构影响确定是否新增/覆盖 ADR。

## 死亡与身份事实的程序授权和界面暴露

死亡事件向程序模块提供最小事实：`lifeId`（仅获准订阅者可见）、实体句柄、状态变化、死亡是否不可逆/规则置信状态、原因事实 ID、模拟时刻、已撤销 grant 列表。不得把死者全部记忆、账户、授权令牌或遗体私有字段塞进通用事件信封。订阅权限在创建时声明范围与寿命；死亡只按规则撤销生命派生权限，未自动撤销的独立预授权必须有明确持有人、期限、额度/操作域和终止条件。

推荐权能规则：死亡提交后停止死者作为生命主体的主动程序调度和新权限签发；取消其拥有的维持/持续控制会话；阻止向死者账户提款、自动回复和死亡退款；清理由旧 grant 派生的子权限。物理实体可继续运动/受损。独立法球或信标只有自身程序、结构、授权和预付资源齐全时继续；不因所有者死亡继承所有者权限。程序只能依据可见事件采取后续行动，不能把 `dead` 状态写回 `alive`；新生命须走新身份创建/确认合同。

界面按查看者权限分别呈现 `结构存在/未知/已瓦解`、`生命阶段/无生命/不可探查`、`身份关系 same/new/unknown`、`施法能力/授权/余额是否可用`。可显示“遗体可继续受损”“结构修复不代表复苏”等可理解说明。HUD 不得以单一红色 HP 条冒充死亡判定；存在或身份不获准时不泄露，通过探查获得的字段应标记观测时刻和来源。

| **ADR 0020** 已采纳事件快照/有界队列、执行上下文、授权与终止清理；死亡撤销相关权限并禁止死者账户自动回复/退款，遗体期间不退款。                                                                                                                 | 事件稳定排序、不得泄露未授权字段、终止幂等及退款去重可直接继承。新生命身份、休眠、同一身份复苏、人工生命回路与遗体继续事件如何适配需补合同；死亡后独立程序/授权不得扩大为死者主体继续施法，若要变更 ADR 0020 的死亡边界需新 ADR/明确覆盖。                 |

当前代码和 ADR 测试证明的是旧原型合同；没有实现证据证明本模块的身份、临界、及时供给、死亡后再损或信标修复语义已运行。旧存档中的 HP、寿命、余额或法球实体不应被推断成新的回路、历史供给或 `LifeId`。

## 尚待产品/架构闭合

| 未决规则                                                                                 | 为什么不能在此定稿                                                                        |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 关键回路的最小定义、供给需求、欠供累积方式与临界/死亡阈值                                | 决定玩家是否能挪用最后资源及是否可预测；100/20 只检验账本，不决定死亡时刻。               |
| 休眠可保存的组织、记忆及持续成本；苏醒条件与窗口                                         | 决定失供玩法、实际时间体验和同一身份边界。                                                |
| 身份同一性判据：记忆、连续过程、关键材料/组织或其他证据如何组合；复苏与复制/分裂如何归属 | 新产品语义，不能由 `EntityId`、材料相似或程序状态暗定。需提供玩家能理解的推荐选项与代价。 |
| 人工生命的自取源能力边界，以及被创建者撤权/死亡后的独立性                                | 关系到用户控制、授权撤销和自主角色行为；来源余额本身不能证明生命。                        |
| 遗体私有身份数据哪些可探查，独立死后程序的预授权粒度与持续时间                           | 关系到程序权限及 ADR 0020，需和 md-spells 合并审议。                                      |
| 何种材料域能修复回路、何种结果构成新生命                                                 | 依赖物理材料闭包和法力价/上界；必须拒绝未报价的万能修复。                                 |
| 同刻供给、死亡、伤害和事件派发的权威序及 HUD 可见性                                      | 跨模块公共时序和信息权限，须在整版策划核对后落合同。                                      |
