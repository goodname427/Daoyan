- 版本 ID：`pilot-agent-intent-2026-09-24`；策划修订：`2`。
- 状态：**主 Agent 解读草稿**。制作人已退回修订 1；本稿仍须由正式主策、独立审查和制作人立项评审复核。没有开发批准。
- 本版游戏问题：上个版本把大量列举能力做了出来，但代理验收只能证明这些能力与已写合同一致；制作人尚未确认策划是否抓住原话背后的**可组合世界法术框架**。本次先重新解释上版方向，再选择一个小的、能在推演台到演武场真实体验的修正切片。

## 首页结论：原话、推断、待确认

**制作人明确表达的方向。** 上版原始方向从“补齐六项属性和减速、破防示例”升级为“属性驱动、统一实体、资源守恒和事件化法术”，并明确说这些不是只加几个控制入口。制作人要求世界效果可归因、有权限、有代价；角色移动和法球行为也在其中，同时说明自然惯性与 UI 不必每帧执行玩家 DSL。原话还提出 Projectile 可持有注入资源、事件与行为法术，并要求推演台、演武场和旧法术书形成完整往返。来源是已归档版本状态中的 `direction` 和三轮 `scopeRevisions`；旧策划及其验收是对这些话的一次解释，不是原话本身。

**本轮策划推断的系统原则。** 玩家应能用同一套受能力、权限、事件和资源账本约束的法术程序组合世界行为；法球推进、事件响应和未来实体行为不能只能从一张硬编码行为菜单里选。这里的“万物皆法术”要求每个主动世界效果可解释、可组合、可结算，并不意味着自然物理、界面刷新或所有 AI 决策都要逐帧运行玩家 DSL。这是从原话推导出的原则，仍待制作人确认。

**推荐玩家体验（待确认）。** 玩家在推演台编写一个主法术和一个可复用的碰撞响应法术；主法术创建并预先供能给法球，把响应绑定到该法球。推演能说明绑定、授权、预付资源、触发和耗尽。进入演武场后，法球碰撞时以明确的实体上下文运行响应，账本可看到法球花了哪笔已授权资源；换目标、改响应或停止供能会产生可预测的不同结果。返回推演台修改同一份法术书，再次实战。具体绑定语法、账户划分与失败形式留给详细策划和 ADR，不在本稿冒充已决定方案。

**开放假设。** ①“Projectile 可拥有行为法术”是否意味着玩家可给法球装载自定义响应程序，而非仅调用现有固定推进/追踪模式；②碰撞响应法术是否是验证这条原则的最小可玩切片；③该程序应只消耗法球预付额度，还是允许创建时显式授予的有限付款授权。若制作人更重视另一个未覆盖体验，应在立项评审调整切片，不能把本推断直接派发开发。

## 用未点名情形检验原则

以下都是策划推断，不是制作人新增承诺：

1. **法球碰撞后触发另一法术。** 若原则成立，响应应使用法球获准的信息与资源，在碰撞时明确结算；没有预付或授权就拒绝，不暗扣已离开的施法者法力。只支持固定“追踪/推进”动作不足以自然表达这种组合。
2. **陷阱或护盾在主人离开后等待事件。** 仍须有存续状态、归属、事件订阅额度及耗尽/死亡边界；不能因不叫 Projectile 就获得免费意识或伤害。本版不实现陷阱/护盾，只用它检验合同是否能推广到未来实体。
3. **两个事件响应争用同一笔储能。** 应有稳定顺序、原子扣款、失败隔离和可观察账目；若只在一个响应时正确，原则尚未覆盖组合场景。本版只选择一个响应切片，完整多响应规则留作风险与后续边界。

## 建议的最小修正切片与验收

若制作人在立项时认可上述原则，本版建议只做**“已供能法球的玩家自定义碰撞响应”**。详细策划先确定响应装载方式、执行上下文、能力与信息白名单、预付资源或有限授权、神识/tick 预算、递归/重入上限，以及创建者死亡和法球消失时的清理或退款。若改动已采纳实体、事件或资源 ADR，先提交新的 ADR 说明覆盖与回退。Version PM 在详细策划后再拆每个节点的任务；Feature PM 的内部步骤由其自行决定。

可观察验收：玩家在推演台编写并检查两个法术，创建、供能、绑定响应；演武场能看到碰撞触发、账本变化和实际效果，回到推演台修改后再次实战。同一法球无额度、目标不可见或已失效、重复碰撞、法球消失及创建者死亡时，不得免费施法、透视或重复退款。与现有固定法球行为、六项属性、减速/破防预设及旧法术书往返共存；旧合法法术不得静默改变。独立 QA 应检查相同原则在上述失败与相邻情形中的表现，而非只验证单个演示脚本。

非目标：重做六项属性、替换整套实体系统、让所有自然物理逐帧运行 DSL、一次实现陷阱/护盾等所有相邻情形、重构 Agent 调度框架、自动发布大版本。若主策复核发现“可装载行为法术”其实已有完整玩家入口，应撤销这一候选缺口，重新提出有证据的一项小切片，不能为了凑任务重复开发。
