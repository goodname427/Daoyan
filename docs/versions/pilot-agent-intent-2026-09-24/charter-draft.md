# 版本策划案：Agent 意图对齐与交付稳定性试运行

- 版本：`pilot-agent-intent-2026-09-24`；策划修订：`1`；状态：**待制作人立项评审**。
- **制作人明确方向与举例**：Agent 容易把制作人举的例子当成封闭需求；想法尚不完整时直接开发，可能耗费一整天才发现偏离。先形成可评审的小范围策划，获批后仅试运行一个最小、可真实体验的对齐闭环，并观察交接、审查、门禁、恢复与成本。这里的“例子被当成封闭需求”是制作人指出的失效模式，不是一份已列齐的具体功能清单。
- **策划推断的共通原则**：具体例子是发现系统意图的线索；主策先把原始信号、可推广原则、相邻情形与边界连成可检验的解释，再推荐完整体验，无法从原话确定的取舍保持开放。
- **推荐体验（待确认）**：制作人用自然语言表达想法；立项待办先展示原则、推荐体验和开放假设，可确认或退回；同一草案据反馈修订并再次呈现，批准后才进入详细策划与开发。试运行选择这一条从表达、补全、退回修订到批准的闭环，具体呈现方式和试点切口由立项评审确认。
- **待确认假设**：①本版以立项前意图对齐的真实往返作为唯一产品改进，是否符合制作人所说的最小闭环。②摘要加完整策划链接是否足以让制作人及时看出原则偏差。③三个未逐项指定相邻情形的推荐处理是否符合制作人隐含意图。这些都不是已批准产品取舍。

## 问题、目标与范围

当前工作流可检查策划文字是否齐全，却不能仅凭代理审核证明主策理解了制作人的未尽之意。若把举例直接拆成开发任务，错误方向直到昂贵的开发后才显露。本版目标是在立项前形成制作人可判断的系统解释，并在获批后用一个真实往返验证对齐闭环及交付稳定性，而不把格式校验当作方向批准。

本策划阶段只交付本案与同修订的 `intent-alignment.json`。立项**以后拟议**的唯一改进，是在既有 `charter-draft → charter-review` 门禁上试运行“原则摘要 → 制作人自然语言退回 → 同一草案修订 → 制作人确认”的完整对齐往返；不新增独立审批节点。试点应使用本版的真实方向、待办与修订记录，使制作人能从摘要打开策划、指出偏差，再看到修订后的摘要与记录。若立项认为该切口不符方向，先退回本案重新对齐，不自行换成另一个开发范围。

适用于新正式版本立项前的方向整理，尤其是以例子表达系统想法、跨模块语义或预计大规模开发；局部明确修复不新增审批，已获批旧版本不追改，代理审核不能代替制作人批准。意图记录的格式检查、独立代理审查只验证结构和推理一致性，不能推定制作人已认可隐含取舍。

## 完整体验、失败恢复与可观察验收

1. 制作人用自然语言给出方向或例子；主策保留原始信号，写出原则、至少两个未点名的相邻情形、推荐体验、边界及开放假设，生成同修订的意图记录。缺失、格式错误或版本/修订不符时，版本策划不能交付到立项待办。
2. 立项待办先展示可读的原则与推荐体验摘要，并能查看完整策划和意图记录。制作人无需拆工程任务，可直接确认或退回。退回后在**同一草案**保留反馈和修订脉络，再次展示与新修订一致的摘要；无反馈时不假定批准。
3. 只有制作人明确确认完善后的方向，才进入详细策划；详细策划及主策审核继续核对原则和相邻情形。若仅对原例子打补丁，应退回策划；遇到需制作人取舍的假设，应升级而非自行批准。
4. 获批后的试点按一个有界节点任务交给 Feature PM，合同列目标、交付物、验收、依赖、来源修订和写入范围。交接只传有来源的直接前驱结论。观察任务接收、实际产物、退出状态及交接中是否重复读取整版原文。
5. 独立审查读取合同与实际差异，并检查退回、空待办、修订往返和越界情况。Feature PM 对本任务做定向检查；集成最终树由版本验证责任者仅运行一份有效的完整门禁，QA 复用同树、同命令及配置指纹的证据。若输入、代码、测试或配置变化使证据失效，记录原因并在新树重跑，不能把两棵树的结果拼成一次通过。
6. 失败保留原命令、退出码和未关闭问题，优先从原任务恢复点修复、复验，仅失效受影响任务和下游证据。相同问题无进展重复时停止循环、交主 Agent 核查；产品取舍才返回制作人。候选体验仍需制作人判断，试点结果不能代替其立项或候选批准。

上述第 2 至 6 项是**立项后试运行的验收与观察计划**，当前没有发生退回、批准、交接、审查、完整门禁或恢复，不记录为实际通过。策划阶段的可观察交付仅为本案、结构化记录及其一致性校验。

## 观察记录方法（立项后计划）

按版本、节点、任务、运行轮次和最终验证树分别记计划与实际。实际 Agent 调用逐次记录角色、任务、开始/结束时间、结果和日志来源；只累加有 token footer 的已知用量，报告为**已知 token 下界**，同时列缺失用量的调用数，未知不得记为零或用参考阈值代填。重复读取记录路径、读取者、轮次、原本已有的直接依赖摘要来源及再次读取原因；必要的独立审查取证单列，不盲目算浪费。完整门禁记录每次命令、退出码、树与配置指纹、是否仍有效和失效原因，统计实际全量执行次数，而不是把目标“一份有效结果”写成实际只运行一次。返工记录退回来源、未关闭 finding、受影响范围与复验结果；耗时按实际时间戳区分模型调用、子进程等待、制作人等待、恢复和空闲。当前这些实跑指标均为**未知/未发生**，待立项后采集，不填零。

## 非目标与立项待决

不启动详细设计或开发，不重构整个调度框架，不修改游戏玩法，不自动发布或决定大版本发布，不要求制作人选模型、拆任务或指定测试，不让代理审核替代制作人批准。本版也不把既有合成测试或历史用量当作试点实际结果。

请在既有立项评审中判断首页三项开放假设，并确认上述唯一试点切口及相邻情形的推荐行为。若无法可靠确认原则，退回同一策划修订流程；批准事实只能来自制作人明确反馈。
