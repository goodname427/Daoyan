## 问题与本版目标

上版从属性、统一句柄、资源账本、事件和法球行为出发，做出了可运行的原型，但仍用固定寿命、HP、自动回复、专名追踪和命中伤害等分别解释现象。制作人用法球、最后一击和碰撞等例子追问的是**同一世界规律能否支撑玩家自行编写未被策划逐项预设的法术及实体行为**；代理验收不能代替对这个意图的确认。

本版本先完成一套从少量共同前提出发、能被跨实体反例检验的完整规则方案：无施法的默认物理；有来源的法力与做功；实体创建、稳定、瓦解；生命维持与死亡；自然和术式造成的结构损伤；具能力与授权实体的原子作用、感知、有限状态、事件响应和时间成本。法术可编程性是验收对象，预设和敌方修士是将来验证规则的对象，不是可表达行为的白名单。世界公理、推导现象、数值表达与现实桥接在唯一正文中分层。

## 意图边界

制作人**确认**元法术必须不可由其他元法术组合，法力只能从来源转往去向，无施法时仍有默认世界规律，生命与实体存在分开，具完整自维持能力的人工造物可成为生命；鼠标左键只是传达施法意图。制作人提出近似现实的施力碰撞及挪用生命储备来检验理论，并明确涌现式可编程世界是目的。**探索方向**是不可逆熵；**策划推断**是用有限结构、物理储备、环境可用性和同一请求合同解释这些现象。有效物理精度、法力与做功换算、生命阈值、元法术最小集及通用程序载体仍待评审，不把推断冒充制作人已确认的法则。

## 推荐的完整玩家体验

玩家在**推演台**选取同一法术书，自行组合获准探查、计算、转移/施力/结构作用、有限记忆及事件响应，查看静态上界、动态项、权限与材料/来源需求；可以导入展示规则的预设，但不被预设限制。玩家给修士、法球或机关配置同一段有界程序，去**演武场**绑定并实际观察：目标可见且授权、材料和储备充分时完成动作；无权读取、余额不足、结构失效、因果/容量超限时显示不同失败；球失去主动驱动仍可滑行，碰撞自然作用与触发术式分别记账。玩家回推演台检查实扣、事件时刻和失败原因，修改程序后再赴演武场，同一本法术书和同一世界结算保持一致。敌方修士最终也用同一请求合同，不能为敌人暗设免费追踪或资源。

当前[推演台](../../../src/app/LabView.tsx)、[演武场](../../../src/app/CombatView.tsx)和[法术编写指南](../../reference/spell-authoring.md)已有编辑、预算、绑定与实战的往返入口；这段推荐体验中的通用程序装载、材料/生命显示和跨实体事件编程**尚未实现**，本轮不把文字当成已体验功能。

## 范围、非目标与旧原型影响

本轮只修订[唯一理论正文](./world-theory-draft.md)、本策划范围和[修订 2 意图记录](./intent-alignment.json)，逐笔检验法力守恒与回收、施力碰撞、结构损伤、稳定造物与人工生命、法球额外供能及创建者死亡、场外/擦边/命中、`100` 点中挪用 `20` 点维持储备；审计现有十项属性、94 项公开元法术职责、价格与算法工作量，并用未命名的“接力护送”和“遗体旁的自修复信标”检验跨实体组合及失败边界。未能给出可信换算或身份阈值的地方列为未决，不藏入数值参数。

本轮**不**写新的已采纳 ADR、不改游戏代码、不定平衡数值、不预选创建注能/组合运动/碰撞施法或其他开发切片、不进入详细策划与排期。旧法术、旧存档和专名元法术可能需要重做或移除；原型期允许经明确影响说明后调整，不用兼容掩盖无源效果，也不在当前文档中改变 [ADR 0017](../../adr/0017-统一实体控制属性模型.md)–[0020](../../adr/0020-事件执行上下文与生命周期.md) 的现行代码约束。若将来批准新规则，先裁定 ADR 覆盖及用户数据保留方式。协作调用、token 下界、缺失用量、重复阅读与返工只是节点过程观察，不是游戏主题。

## 供制作人评审的验收与取舍

1. 理论从同一组候选公理解释修士、法球、石块、机关和人工生命的存在、能力、施法、生命、损伤、死亡或瓦解；不依赖实体名称、固定寿命或独立伤害数来补洞。
2. 每个指定反例都能说清来源、付款、作用、反作用或耗散、失败及账本；当前不能闭合的有效质量/结构、普通驱动来源、法力做功与可用性、生命阈值、原子最小集、程序载体六类问题有显式未决结论。
3. 感知、计算、原子作用、有限记忆和事件再启动在同一实体合同下组合；“接力护送”“自修复信标”等未指定情形能区分缺能力、缺授权、欠费和缺材料。追踪若可由获准观察与施力组成，不以专名元法术取代组合。
4. 鼠标、手柄、AI 与实体事件都转成设备无关的施法意图；相同世界状态、权限、来源与模拟时序有相同结算。界面与存档不提供私有探查或免费法力。
5. 旧策划、代码、可体验路径和 ADR 的覆盖/缺口/待判断均有可定位证据；新理论与现行约束冲突的位置和原型重做影响公开。文档评审只验内容和定向检查，**不冒充**游戏运行体验或完整代码门禁。

请制作人重点判断：推荐的最小物理与结构抽象是否保留希望的玩法空间；普通驱动是否必须同法力统一换算；生命的休眠、复苏与身份连续性要到何种精度；环境法力可用性是否成为显式世界状态；以及愿意以多大原型重做代价换取真正的跨实体编程。其余原子粒度、价格参数和程序容量仍需推导与反证，**大方向基本认可不等于这些取舍或立项获批**。制作人审阅完整方案后，再决定是否进入后续策划以及如何验证；此处不指定开发顺序。
