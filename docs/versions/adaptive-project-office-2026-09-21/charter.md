# 自适应项目中枢版本策划案

- 版本 ID：`adaptive-project-office-2026-09-21`
- 状态：制作人已授权推进
- 方向日期：2026-09-21

## 版本目标

把项目中枢从固定三栏页面升级为可组合的制作人工作台，并让常驻秘书真正以正式版本承接制作人的新方向。制作人应能清楚看到 Agent 正在做什么、自由调整阅读空间，并在不理解内部命令的情况下持续推动项目。

## 重点模块

1. 左、中、右三栏保持稳定；每栏内部的纵向区域可独立折叠、调整高度和拖动排序，布局偏好持久化。
2. Agent 详情使用聊天式公开工作日志，展示任务输入、公开计划与进度、工具动作、文件变更、测试、错误、决策和阻塞；不展示模型私有思维链。
3. Agent 运行时长由浏览器每秒本地更新，并在后端状态到达时校准。
4. 制作人的新方向在没有活动版本时自动立项；活动版本中按范围冻结状态合并或进入下一版本候选，问题、回复、继续和状态查询不得误建版本。
5. 常驻秘书按风险决定详细策划、测试、候选构建等阶段是否需要完整执行或可记录理由后跳过，同时保留制作人必须参与的产品门禁。
6. Feature Agent 保留类型检查和受影响路径的定向自测；独立测试 Agent 负责验收、集成、主线回归和缺陷复验，缺陷在开发与测试之间闭环。
7. 秘书启动和对账时识别已经交付的旧运行，清理陈旧的自动恢复记录，避免重复派发。

## 非目标

- 不展示或存储模型私有推理、隐藏思维链和内部安全信息。
- 不在本版本改动游戏玩法或法术系统。
- 不恢复已暂停的手机 Sites 方案。
- 不要求制作人使用 Feature PM、恢复、版本状态等内部命令。

## 版本验收

- 折叠任一区域后其余区域正常铺满；纵向区域可以折叠、调高和排序，刷新后仍保留偏好。
- 点击 Agent 后，中间工作区提供连续、可审计、近似聊天记录的公开活动流；制作人能看懂当前阶段、最近动作、改动和验证结果。
- 运行时长在两次后端同步之间每秒变化，重新同步后不明显跳错。
- 新方向能够自动形成正式版本或明确进入下一版本候选，并记录采用的阶段策略；不会因一句问题或“继续”建立空版本。
- 已交付运行不会继续显示为待恢复，也不会在秘书重启后再次启动。
- Feature 定向自测、独立验收与缺陷复验均有自动化证据；完整门禁和桌面实际体验通过。

## 本次纵向切片

- 左侧流程、Agent、开发任务、版本缺陷，以及右侧制作人待办、秘书对话均成为可独立折叠的工作区区域；拖动标题可在同栏排序，区域底部的分隔条可调整高度，偏好仅保存在制作人当前浏览器。
- 运行中的 Agent 以服务端最近一次同步的时长为基线，在浏览器内每秒递增；下一次状态刷新会以服务端数据重新校准。
- 本切片不改变秘书调度、正式版本状态机或游戏运行时；后续阶段策略、旧运行对账和独立测试闭环继续由现有守卫与版本流程承接。
