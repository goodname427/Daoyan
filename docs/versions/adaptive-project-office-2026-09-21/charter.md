# 自适应项目中枢版本策划案

- 版本 ID：`adaptive-project-office-2026-09-21`
- 状态：制作人已授权推进
- 方向日期：2026-09-21

本轮独立审查修复补齐拒绝决策的持续推进阻断、制作人待办与具体决策门禁的关联，以及缺陷复验与当前修复轮次/代码修订的绑定；保留旧状态的读时兼容，不补造历史批准或测试证据。验证结果见 [2026-09-21 开发记录](../../dev/2026-09-21.md)，本修复不代表正式版本已验收。

本轮行为复审补齐等待上下文中新方向的独立路由、被阻塞到期重试的事件休眠，以及 Feature 最新自测和所有修复策略共用的候选 QA 门禁。新方向中的审批词不批准旧门禁，后续失败不能被历史通过或空缺陷列表掩盖；保留现有状态与迁移格式，验证结果详见当日开发记录。

## 版本目标

本轮交付前修复补齐三处保守边界：普通回复与模糊输入不误立项；缺失或损坏的既有恢复证据持续阻止派发，直到内部恢复证据并重新对账；主题相似不能直接批准相反或变化的方向，已过首次草案阶段的非同一方向进入范围评审。状态格式保持兼容，实际验证与环境限制记录在当日开发日志，不表示制作人体验或正式版本验收已经通过。

把项目中枢从固定三栏页面升级为可组合的制作人工作台，并让常驻秘书真正以正式版本承接制作人的新方向。制作人应能清楚看到 Agent 正在做什么、自由调整阅读空间，并在不理解内部命令的情况下持续推动项目。

## 重点模块

1. 左、中、右三栏保持稳定；每栏内部的纵向区域可独立折叠、调整高度和拖动排序，布局偏好持久化。
2. Agent 详情使用聊天式公开工作日志，展示任务输入、公开计划与进度、工具动作、文件变更、测试、错误、决策和阻塞；不展示模型私有思维链。
3. Agent 运行时长由浏览器每秒本地更新，并在后端状态到达时校准。
4. 制作人的新方向在没有活动版本时自动立项；活动版本中按范围冻结状态合并或进入下一版本候选，问题、回复、继续和状态查询不得误建版本。
5. 常驻秘书按风险决定详细策划、测试、候选构建等阶段是否需要完整执行或可记录理由后跳过，同时保留制作人必须参与的产品门禁。
6. Feature Agent 保留类型检查和受影响路径的定向自测；独立测试 Agent 负责验收、集成、主线回归和缺陷复验，缺陷在开发与测试之间闭环。
7. 秘书启动和对账时识别已经交付的旧运行，清理陈旧的自动恢复记录，避免重复派发。
8. 版本没有制作人、额度或外部访问阻塞时必须持续推进；无需执行的节点明确显示理由并从进度分母移除。

## 非目标

- 不展示或存储模型私有推理、隐藏思维链和内部安全信息。
- 不在本版本改动游戏玩法或法术系统。
- 不恢复已暂停的手机 Sites 方案。
- 不要求制作人使用 Feature PM、恢复、版本状态等内部命令。

## 版本验收

- 折叠任一区域后其余区域正常铺满；纵向区域可以折叠、调高和排序，刷新后仍保留偏好。
- 点击 Agent 后，中间工作区提供连续、可审计、近似聊天记录的公开活动流；制作人能看懂当前阶段、最近动作、改动和验证结果。
- 运行时长在两次后端同步之间每秒变化，重新同步后不明显跳错。
- 新方向能够自动形成正式版本或明确进入下一版本候选，并记录采用的阶段策略；不会因一句问题或“继续”建立空版本。
- 已交付运行不会继续显示为待恢复，也不会在秘书重启后再次启动。
- Feature 定向自测、独立验收与缺陷复验均有自动化证据；完整门禁和桌面实际体验通过。

## 本次纵向切片

- 左侧流程、Agent、开发任务、版本缺陷，以及右侧制作人待办、秘书对话均成为可独立折叠的工作区区域；拖动标题可在同栏排序，区域底部的分隔条可调整高度，偏好仅保存在制作人当前浏览器。
- 运行中的 Agent 以服务端最近一次同步的时长为基线，在浏览器内每秒递增；下一次状态刷新会以服务端数据重新校准。
- 首个界面切片不改变秘书调度、正式版本状态机或游戏运行时；其后的内核切片已把阶段策略、旧运行对账和独立测试闭环接入现有守卫与版本流程。

## 内核架构与迁移边界

本轮交付前独立审查追加恢复与证据修复：恢复操作确认具体等待快照并跨重启保留；Feature PM 请求产品决定前写入 `waiting-producer` 恢复点；自然语言承诺变化即使带“继续/恢复”或存在相似运行事实也进入范围路由；修复及旧修订冲突使 QA 失效；看板不读取原始模型日志。字段在 v1 扩展内可选，缺失不补造批准，显式损坏拒绝写入。下文历史门禁数字不作为本轮证据；本轮执行结果见开发记录，未进行生产迁移或正式版本发布。

本次仅复核架构决策与迁移边界，保留已有实现及测试。补充放行合同包括：隔离仓库版本种子与关联运行目录、记录源文件不存在以完整回退、核验多份快照冲突与归档修复。运行时规范化已只迁移真正缺失的扩展，显式损坏假值会停止写入和派发。公开日志的并发测试只证明进程内串行化。设计合同已同步 ADR-0016 和规格；完整迁移工具、生产演练与独立版本验收仍由秘书收束，本轮测试结果单独记录。

本次架构边界复核进一步明确：正式版本读取可能恢复事务并写盘，生产备份必须先于读取恢复；预览只在隔离副本执行。规格已列出两文件事务、跨状态收件、通知发送及迁移后增量的中断恢复合同。设计采纳不等于生产迁移或版本验收，整组数据校验、升级/降级演练及最终审查由秘书收束。

本次强制接管复核保留既有界面与相关运行改动，并补齐事务扩展预校验、嵌套状态校验和跨状态收件目标锚定。规格保留兼容落地矩阵和回退判定：完整中断故障注入、生产备份及保留增量的降级演练仍是版本放行条件。读时迁移不是生产迁移完成，范围基线的 approved 也不是制作人立项批准。

2026-09-21 已完成“确定架构决策与迁移边界”设计产物：[ADR-0016](../../adr/0016-自适应版本编排与兼容迁移边界.md)、[内核规格及验收矩阵](../../specs/2026-09-21-adaptive-project-office-kernel.md)。自动立项只建立待评审草案，冻结后新方向默认进入候选；阶段策略不能跳过立项评审、不可逆决策批准与最终制作人体验。迁移保留现有状态、审批和证据，恢复前对账全部运行/跟踪/重试项，待审开发运行不得等同正式版本验收。
