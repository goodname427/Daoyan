# 自适应项目中枢模块详细策划

- 所属版本：`adaptive-project-office-2026-09-21`
- 阶段：详细策划（`module-design`）
- 执行策略：完整执行；旧状态没有阶段策略，按 `legacy-unknown` 保守迁移
- 日期：2026-09-21
- 依据：[版本策划案](./charter.md)、[自适应编排内核规格](../../specs/2026-09-21-adaptive-project-office-kernel.md)、[ADR-0016](../../adr/0016-自适应版本编排与兼容迁移边界.md)

## 结论

本版本需要四个相互配合的模块：可组合工作台、公开活动投影、正式版本自适应编排、以及阶段证据与质量闭环。它们已有首个可运行纵向切片；本阶段将后续工作限制为补齐并验证既有合同，不重新设计游戏运行时、通讯通道或第二套项目状态。

不存在需要制作人选择的产品分歧，也没有新增不可逆架构决策：状态所有权、事件驱动边界和 v1 兼容策略继续遵循 ADR-0016。生产状态迁移、降级演练和候选体验不是本阶段产物，不能因本文档完成而视为已验收。

## 共同边界

| 边界       | 规则                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 状态所有权 | 常驻秘书拥有收件、运行对账、跨版本候选和通知；正式版本拥有范围、风险、阶段策略、审批、工作项、测试和缺陷；Feature PM 运行目录只提供执行证据。 |
| 触发方式   | notice guard 仅由消息、任务/PM 进度、PM 退出、恢复定时器或外部通知唤醒。空闲时不轮询项目、不调用模型。                                        |
| 公开性     | 工作台只能读取白名单公开事件、进度心跳、恢复点中的调度状态和截断/脱敏摘要；不得读取原始模型日志、私有推理、凭据或完整本机路径。               |
| 状态一致性 | 内部阶段的交付报告不是阶段批准、QA 通过或版本验收。guard 重新读取持久正式版本、校验产物和角色证据后才可登记节点并推进。                       |
| 兼容性     | v1 编排扩展缺失时保守补齐风险与完整策略；显式 `null`、错误类型或未来版本停止写入和派发。不得补造历史批准、测试或交付。                        |

## 模块一：可组合项目工作台

### 问题与目标

固定三栏页面无法让制作人把有限屏幕空间分配给当前最重要的流程、Agent、任务、缺陷、待办或对话。工作台要让制作人在不理解内部命令的情况下查看一个正式版本、调整阅读空间、处理明确待办并继续对话。

### 组成和状态

| 子模块         | 输入与状态所有者                                  | 交互与可见结果                                                                      | 边界                                                     |
| -------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 版本与流程导航 | `/api/dashboard` 的当前/历史版本投影              | 选择版本、流程节点、Agent、工作项或缺陷；中间区域只显示当前选中详情                 | 历史版本只读；选择不改变正式版本状态。                   |
| 三栏布局       | 浏览器本地 `daoyan-secretary-workspace-layout-v1` | 左、中、右栏可调宽、折叠和恢复；任一栏折叠后剩余栏填满可用宽度                      | 布局偏好不进入秘书、正式版本、导出快照或跨设备同步。     |
| 栏内区域       | 同一浏览器布局偏好                                | 流程、Agent、工作项、缺陷、待办和对话可折叠、调高、拖动排序；高度过多时各栏独立滚动 | 窄屏只提供流程/详情/控制台导航，不启用区域高度拖动。     |
| 制作人控制台   | 待办和消息 API；秘书为写入所有者                  | 显示推荐方案与备选项；提交决定只关联其 `decisionGateId`；继续对话进入同一收件入口   | 看板不得把一个待办操作当作阶段批准，也不得直接推进节点。 |

### 规则与异常状态

- 布局记录损坏、未知区域或不合法尺寸时回退默认布局，不影响项目数据或待办。
- 没有当前 Agent、工作项或缺陷时显示明确空状态；不能用历史版本或原始日志填充。
- 运行中的 Agent 时长以服务端最近同步为基线，每秒本地递增；下一次服务端同步重新校准。停止、等待或快照中的 Agent 不伪装为运行。
- Sites 导出是脱敏只读快照：清除 PID、运行目录、实时活动和本机路径；它不是移动控制面，也不是状态真相。

### 验收

- 桌面端可完成选择、三栏折叠/恢复、栏宽调整、区域折叠/调高/排序，刷新后保留布局；溢出时底部区域仍可滚动到达。
- 窄屏切换可到达流程、详情和控制台，且不会出现桌面高度拖动控件。
- 处理一个推荐待办只改变该待办关联的门禁；历史版本不可写。

## 模块二：公开 Agent 活动投影

### 目标

将“当前在做什么”变成连续、可审计且制作人可理解的活动流，同时保持私有推理和运行机密不离开运行目录。

### 数据流

```text
Feature PM 结构化公开事件 + progress 心跳 + 恢复点调度状态
        -> 白名单、脱敏、截断和事件 ID 去重
        -> dashboard API 的 Agent/activity 投影
        -> 工作台活动流或 Sites 脱敏快照
```

- 允许类别为输入、计划/进度、动作、文件、测试、错误、决策、阻塞和用量；未知字段一律不展示，未知 token 显示不可用而非零。
- 同一路径追加在进程内串行化，事件 ID 幂等、序号单调；该保证不放宽单写者或跨进程锁要求。
- 进度心跳和恢复点是当前公开运行状态，可覆盖陈旧的事件描述；原始 `.log` 不是回退数据源。
- 缺少结构化事件的旧运行显示“公开证据不可用”，而非尝试从私有输出推断活动。

### 验收

- 活动流能分别显示阶段、动作、文件和测试；详情被截断，私有思维、凭据、完整路径及原始日志哨兵文本均不可见。
- 运行中与已退出/子 Agent 仍存活的状态不会互相混淆；重新同步后时长和阶段以服务端事实为准。
- 并发写入和重复 event ID 不产生重复公开事件或序号碰撞。

## 模块三：正式版本自适应编排

### 方向收件和版本去向

| 输入 / 前提                      | 必须结果                                         | 禁止结果                            |
| -------------------------------- | ------------------------------------------------ | ----------------------------------- |
| 无活动版本的确认新方向           | 建立待立项评审草案并保留来源请求                 | 自动批准开发。                      |
| 未冻结活动版本内的同一承诺       | 形成范围修订、更新风险事实；改变承诺进入范围评审 | 词面相似就沿用旧批准。              |
| 已冻结版本的新方向               | 写入下一版本候选并说明去向                       | 自动开启下一个正式版本。            |
| 问题、状态查询、无目标回复、继续 | 答复事实、保留待确认或对账后恢复已批准事项       | 建立空版本、虚构任务或批准门禁。    |
| 等待制作人期间的新方向           | 继续按方向规则独立路由                           | 把“确认/审批”等词消费为旧门禁回复。 |

同一请求 ID 必须重放原结果。pending intake 必须在正式版本写入前记录目标版本和预期去向；活动版本已变化而原操作尚未落盘时公开阻塞，不重新计算并投向新版本。

### 风险、策略与持续推进

- 风险记录至少包括等级、影响范围、状态迁移、跨进程并发、外部依赖、可回退性、评估者、时间、依据和策略修订。模型路由等级不是风险事实。
- 当前版本采用完整执行：`legacy-unknown` 不能支持缩减或跳过模块设计。后续策略变更只能追加新修订，并关联范围修订；理由和执行结果分开保存。
- 固定的方向、版本策划、立项评审、候选制作人体验和归档不可跳过。被主策升级的详细策划和不可逆决策变成制作人门禁。
- 无制作人、账号、额度或外部访问阻塞时，guard 先对账全部活动/跟踪/延迟恢复项，再为当前内部阶段建立一个持久任务。跳过节点需公开理由且不计入进度分母，不能伪装成完成。
- PM 已退出但其子 Agent 仍占用工作区时继续跟踪；恢复证据缺失、损坏或无法识别时记录 `missing` 并停止整队列派发，不能把干净工作区当作完成。

### 阶段交付接口

每个内部阶段都有 `docs/versions/<version-id>/<stage>.md` 作为公开结论。阶段 Agent 的 `report.json` 必须同时为“已交付”且独立审查通过；guard 仍须验证阶段专用 JSON（策划审核、任务拆分、开发、QA 或缺陷复验）及当前 Git 修订，才可原子写入正式版本。这一阶段只新增 `module-design.md`；不创建 `design-review.json`、`task-breakdown.json` 或任何后续阶段文件。

### 验收

- 相同请求重放不重复建草案、范围、通知或批准；承诺变化不被主题相似吞没。
- 一个活动版本在无真实阻塞时不会停在普通内部节点；有制作人门禁、运行占用或缺失证据时不会越过。
- 策略为 `skip` 的节点显示公开理由且不纳入进度；本版本的完整策略仍要求真实模块策划产物。

## 模块四：阶段证据、独立 QA 与缺陷闭环

### 角色和证据规则

| 环节         | 负责者             | 必需证据                                                             | 不得替代               |
| ------------ | ------------------ | -------------------------------------------------------------------- | ---------------------- |
| Feature 开发 | Feature Agent      | 每个工作项当前范围的类型检查、定向测试、代码修订和公开证据           | 不能声明独立 QA 通过。 |
| 版本 QA      | 独立测试 Agent     | 当前范围和候选修订、通过命令、验收/集成/回归套件、公开证据和缺陷清单 | 不能修改产品实现。     |
| 缺陷修复     | 修复 Agent         | 每个未关闭缺陷的修复证据                                             | 不能自行关闭缺陷。     |
| 缺陷复验     | 第二个独立测试身份 | 缺陷 ID、当前修复轮次、修复修订、范围修订及回归命令                  | 不能复用旧轮次 QA。    |

修复、失败或阻塞会使受影响的旧 QA 结论失效。候选构建在 execute、reduced 和 skip 修复策略下均只接受当前范围、独立身份、包含成功命令和回归的可信 QA；已测试修订后的 `docs/` 外变化必须阻止推进。

### 本阶段适用性

本阶段只定义证据合同和后续验收，不产生实现工作项、QA 结论、缺陷或候选构建。因而不提前编造 `task-breakdown.json`、`development.json`、`qa.json`、`bugfix.json` 或候选通过记录。

### 验收

- 同一身份即使更换代码修订也不能同时作为 Feature 与独立 QA。
- 失败命令、缺少公开证据、过期修订或旧修复轮次均不能通过候选/缺陷关闭门禁。
- QA 发现缺陷时登记为失败并进入修复；复验通过前缺陷不能关闭。

## 迁移、部署与不适用内容

本阶段不执行生产 `.daoyan-agent/` 迁移、备份、升级、降级、账号配置、发布或制作人候选体验。它们不适合伪装成模块策划完成，后续执行时必须满足：停写并核实写进程退出、备份秘书/正式版本/事务/运行证据的原始字节、在隔离副本预览、校验 current/历史/事务及引用关系、保留迁移后的增量并提供安全降级投影。读时 normalizer 和两文件事务恢复不等于这些演练已经完成。

本版本也不改游戏核心、DSL、资源、存档、战斗、钉钉通道协议或暂停的 Sites 远程控制方案。工作台仅消费项目编排投影，`src/core/` 继续与浏览器和 UI 无关。

## 后续阶段输入

- 主策审核应审查本文四模块边界、现有 ADR/规格的一致性和未覆盖的产品冲突；若无新冲突，结论写入 `design-review.json`。
- 任务拆分只对审核后的、仍需要代码或迁移演练的工作形成稳定 ID、依赖和可观察验收；纯复用事实不制造占位项。
- 版本排期、开发、QA、缺陷修复、候选与制作人体验必须各自生成真实证据，不能借用本文作为完成证明。
