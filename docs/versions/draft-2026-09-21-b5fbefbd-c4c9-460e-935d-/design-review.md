| 跨实体属性一致性   | 通过 | `damage`、`speed` 等是稳定逻辑属性；同一 `强化伤害`/`调整速度` 对火球、自己和敌人走同一入口。目标 binding 只声明能力、存储和持久化方式，差异由关系、抗性与实际效果进入价格，不生成 Actor/Projectile 两套元法术。 |

## 审核修订

审核前的新创建入口缺少旧 `发射` 的 `起点`，无法满足“不静默改变起射位置”的迁移承诺；属性表又把弹体 `damage/speed` 与 Actor `power/speed` 分列，未落实同一控制法术跨实体工作。主策已直接修正 `module-design.md`：

- 创建入口改为 `(起点, 方向, 速度, 基础伤害, 存活时间)`，并为旧单步发射和可证明等价的分步创建链定义空间、伤害与资源锚点。
- 引入稳定逻辑属性 descriptor 与目标 `ControlPropertyBinding`；同一属性可由目标声明 write 或 maintain，但公开元法术不得检查实体种类。
- 将 write 细分为一次 commit 与可撤销 overlay；位置和剩余寿命只接受 `时间=0` 的 commit，避免有限位置回弹和寿命快照复活。
- 明确无限 maintain 的静态表示、每 `0.25` 秒法力实扣、tick 执行债务、核心控制会话所有权和瞬发租约立即释放边界。

## 后续阶段约束

- 任务拆分必须先建立 ADR 工作项，固定逻辑属性/binding、时间与覆写、控制会话、周期预算、价格配置和 AST 迁移合同；共享合同未采纳前，不得并行实现元法术或 UI。
- 核心任务须覆盖同一 `damage` 与 `speed` 属性在 Actor、Projectile 及缺失能力对象上的同路径测试，并以无头测试证明没有 `kind` 分支。
- 迁移任务须分别覆盖旧 `发射`、可合并分步链、句柄逃逸/重赋值而不可合并的链、旧自身/目标属性法术和未解决诊断不覆盖可运行 AST。
- 后续 Feature PM 与 Version QA 按既定生命周期承担完整门禁、集成迁移和候选验证；本审核不生成任何实现或测试通过证据。
