# 统一实体创建、控制与属性模型：模块详细策划

- 版本 ID：`draft-2026-09-21-b5fbefbd-c4c9-460e-935d-`
- 阶段：详细策划
- 策略：完整执行；本文件只固定游戏产品的实现合同，不登记版本节点或生成后续阶段证据。
- 公开结论：已将统一创建、属性控制、无限时间、定价和兼容边界细化为可实现、可测试的合同；进入开发前必须先采纳本文列出的 ADR。

## 问题、范围与非目标

现状中 `发射` 直接生成已激活弹道，`创建弹道` 则必须再调用方向、速度、威力和激活四个 Projectile 专用入口；Actor 的临时修正又绕开了弹道控制。它们使同一件事按存储种类分叉，也无法解释无限时间为何有时一次付费、有时持续付费。

本模块把“创建持续前进、可伤害的弹体”和“以属性改变实体状态”收束为两套玩家合同：一个创建入口，以及一组每项都归一为 `(目标, 效果, 时间)` 的具名属性控制入口。目标、所有权、抗性、能力和生命周期决定结果；`Actor`、`Projectile` 只是在其上声明不同能力的现有存储，不得成为元法术分支条件。

不在范围内：完整 ECS、额外实体原型、伤害类型或随机豁免、神识强度、修改 AST 的单一 IR 地位、冷却回归、工作流控制面或 `.daoyan-agent`。数值会以本文件的归一化公式和测试锚点实现，再由版本测试调整配置系数；不得另改语义。

## 公开规则

### 1. 统一创建

玩家入口定为 `创建弹道(起点: vec2, 方向: vec2, 速度: num, 基础伤害: num, 存活时间: num): entity`。创建成功即按当前发射的安全偏移规则从指定起点生成、激活并返回句柄；方向为非零有限向量并归一化，速度、基础伤害和存活时间为正有限数。它保留现有每位所有者 16 枚上限、命中/过期清理和“创建失败返回空”的契约。创建和激活不再暴露为两步核心玩法。`起点` 不能省略：它既允许从自身前方发射，也保留现有 `发射` 可由计算位置起射的组合能力。

`发射(起点, 方向, 威力)` 与旧的一参 `创建弹道(寿命)` 都只作为迁移输入：规范化器将前者按旧的 `380` 速度、`2.4` 秒寿命、起点偏移和威力结算转换为新调用，返回的句柄在原语句位置被丢弃；新入口的定价锚点必须让这组兼容参数与旧调用的法力、tick 和伤害结果一致。旧“创建 → 设置方向/速度/威力 → 激活”只有在同一顺序语句块内句柄未逃逸、未重赋值且各参数可保序合并时才自动折叠，并以旧四步价格之和作为迁移等价锚点；单独的一参创建或不能证明等价的控制链要求玩家显式补齐参数，不能猜测配置。目录、蓝图、默认法术和参考只展示新入口。迁移是 AST 到 AST 的规范化，不引入第二套 IR；无法无损转换时给出位置明确的诊断，保留原文且不静默改变伤害、方向、寿命或资源结算。

### 2. 属性描述符与能力

核心新增独立于实体种类的 `ControlPropertyDescriptor`，定义稳定属性键、统一效果类型和领域校验；每个实体再通过 `ControlPropertyBinding` 声明它是否具备该属性，以及该属性在该实体上的 `write`/`maintain` 实现、写入策略、关系许可、抗性读取、效果合并/撤销和定价强度函数。公开元法术只选择稳定属性键并提交 `(目标, 效果, 时间)`，世界只通过目标返回的 binding 回答可否控制；不能以 `kind`、`ownedProjectile` 或存储数组选择实现。

同一稳定属性可以由不同实体以不同存储方式实现，但效果含义不变。例如 `调整速度(目标, 倍率, 时间)` 始终改变目标的运动速度倍率：弹体可以把它一次性写入自身状态，Actor 可以把它实现为需要持续维持的修正。这个差异来自 binding 明示的持久化能力，不来自元法术检查 Actor/Projectile 类型。首批合同如下：

| 稳定属性键            | 统一效果 / 校验                   | 首批 binding 与模式                                                                                  | 时间支持                         |
| --------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------- |
| `position`            | 目标坐标 `vec2`，有限并经边界裁剪 | Actor、Projectile：`write/commit`，均走 Transform 写入                                               | 只接受 `0`；一次定位，不占有目标 |
| `rotation`            | 朝向 `vec2`，有限非零并归一化     | Actor aim、Projectile 方向：`write/overlay`                                                          | 正有限或 `0`                     |
| `speed`               | 运动速度倍率 `num`，正有限        | Projectile：`write/overlay`；Actor：`maintain`，映射到现有 speed modifier                            | 正有限或 `0`                     |
| `damage`              | 对外伤害倍率 `num`，正有限        | Projectile：`write/overlay`，作用于其命中伤害；Actor：`maintain`，映射到现有 power/对外伤害 modifier | 正有限或 `0`                     |
| `lifetime`            | 剩余存活秒数 `num`，正有限        | Projectile 与未来显式寿命对象：`write/commit`                                                        | 只接受 `0`；一次写入后正常倒计时 |
| `perception`、`armor` | 描述符指定的正倍率或有向增量      | 当前 Actor：`maintain`；未来实体只有声明同一属性 binding 后才可复用                                  | 正有限或 `0`                     |

`hpMax`、`manaMax`、`manaRegen`、`shenshiMax`、`castSpeed`、`manaCostMul` 在本版本仍不是公开控制入口：它们影响资源、施法安全或需要额外的上下限规则。描述符缺失即是明确能力拒绝，而不是用类型分支或默认写入替代。

具名节点保留可读性，例如 `设置位置(目标, 目标点, 时间)`、`设置朝向(目标, 方向, 时间)`、`调整速度(目标, 倍率, 时间)`、`强化伤害(目标, 倍率, 时间)`、`设置存活时间(目标, 秒数, 时间)`、`调整感知(目标, 倍率, 时间)` 和 `调整护体(目标, 增量, 时间)`；它们均只把固定属性键与第二参数交给同一个 `applyEntityControl`。因此同一个 `强化伤害` 必须能作用于声明 `damage` binding 的火球、自身和敌人，模式、关系、抗性及实际效果由 binding 参与定价，但不得分叉成弹道版和 Actor 版元法术。旧 `疾行/迟滞`、`增威/虚弱`、`洞察/蔽识`、`护体/破防` 在迁移期分别规范化为显式目标的同一属性调用，运行时返回 `bool`；不能留下另一套自身实现或价格。

### 3. 时间、写入与维持

`时间` 保持 `num`，避免为当前 AST 引入一套只服务时长的联合类型：正有限数表示秒数，`0` 表示无限，负数、NaN、Infinity 一律非法。当前所有可用旧控制只接受正数，故 `0` 不会改变已合法法术的结果。

| 模式/策略       | 有限时间                                           | `时间 = 0`（无限）                       | 停止与状态                                                                           |
| --------------- | -------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| `write/commit`  | 首批明确拒绝，不能静默忽略时间                     | 执行一次不可回滚到旧快照的写入           | 世界后续正常模拟或合法写入可继续改变该值；不占有施法实例                             |
| `write/overlay` | 写入带到期时刻的覆写层；到期恢复仍有效的下层值     | 写入无到期覆写层                         | 同控制者同属性的新写入替换本层；目标、binding 或属性生命周期失效时移除               |
| `maintain`      | 建立由施法控制会话拥有的维持租约，最迟在到期时结束 | 同一租约无到期，但仍受控制会话和资源约束 | 法力不足、`结束施法`、实例完成/打断、目标/binding/权限失效时原子移除；不保留半个效果 |

`write` 的模式由目标的 binding 结构化声明；调用方和 UI 可在控制前探查，运行时不能因实体种类临时猜测。有限 `write/overlay` 不制造周期扣费，但时长进入起手价；`时间=0` 的任何 `write` 都只付一次，因为它不占有施法实例。`write/commit` 用于定位、剩余寿命等无法合理“恢复旧快照”的状态，只接受 `0`，避免位置回弹或寿命倒计时被旧值复活。

`maintain` 必须绑定到核心层可无头运行的施法控制会话；Battle 只负责把真实施法实例的共享法力账户、取消和时钟接入该会话。法术作者可在 duration/channel 或条件循环中以 `结束施法` 主动释放；实例正常完成或被战斗打断也释放其所有租约。瞬发法术建立的租约会随该次施法结束立即释放，目录必须明确提示，不能让玩家误以为它会脱离施法持续存在。

维持结算为固定 `0.25` 秒：先验证目标、binding、权限与法力，再原子扣法力、登记本周期 tick 工作并刷新效果；法力不足时在本周期效果生效前移除租约。tick 是施法执行工作量而非余额，不存在“tick 不足”；周期 tick 进入所属施法的执行债务，并继续由 `castSpeed` 映射为真实时间，不得在 UI 或 Battle 中另造一套时间货币。多个来源按稳定控制记录序号合并，`add` 先求和、`mul` 后相乘；同一控制会话、目标和属性的更新替换旧记录，不叠加。

这以 binding 明示的持久化能力而非“弹道/Actor”分支区分一次性写入和持续维持。它也避免永久 Modifier 的现有 `duration <= 0` 隐式约定继续扩散：新控制记录必须显式携带 `propertyKey`、`mode`、`writePolicy`、`expiresAt | null`、`controllerSessionId | null`、稳定序号和结算状态。

### 4. 权限、抗性与成本

关系倍率固定为自身 `1`、自有 `1`、友方 `2`、非己方 `8`；非己方另有严格为正、不能被效果值抵消的控制门槛。binding 提供按稳定属性键读取的非负抗性 `r`（缺省为 `0`），只能使价格升高。权限先于效果写入判定；无效句柄、缺描述符/binding、禁止关系、非法效果或不受支持的时间均返回 `false`，状态不变。失败尝试是否收取基础探查成本继续遵守 VM 的效果前定价规则，但绝不创建覆写或租约。

对一个归一化控制请求，法力与 tick 都按同一结构计算：

```text
起手 = 关系固定门槛 G + 关系倍率 A × (属性基础 B + 实际效果强度 S + 有限 overlay 的时间项 D) × (1 + r)
维持每 0.25 秒 = A × (维持基础 M + 实际效果强度 S' + 时间项 Q) × (1 + r)
```

`write` 只结算起手；`maintain` 结算起手加每个成功结算周期。`G`、`B`、`M`、`S`、`D`、`Q` 都分别为法力和 tick 配置，且均为正或零的有限数；起手 `B` 必须为正，非己方 `G` 必须为正，任何关系都不能被效果为零、时长为零或抗性抵消成零成本。实际效果强度以应用前后可观察变化计算，同一 `damage`/`speed` 倍率因目标当前基值不同可以价格不同，但仍走同一公式。未知目标、模式、关系、抗性或效果报告“基础 + 动态”；静态已知项和运行时实扣使用同一个 descriptor/binding 定价函数。

以下为归一化验收锚点（不是最终平衡表）：令自身/自有、友方、非己方的 `A=1/1/2/8`，非己方 `G=4`、其余 `G=0`；一次有限 overlay 的 `B+S+D=5 tick/mana`、无限 write 的 `B+S=3`。在 `r=0/1` 时，友方有限起手为 `10/20`，非己方为 `44/84`；友方无限写入为 `6/12`，非己方为 `28/52`。自身/自有对应 `5/10` 与 `3/6`，始终大于零。同一 descriptor 的 `maintain` 每周期也必须按相同的 `A × (1+r)` 单调放大。测试应逐项证明：己方不为零、非己方门槛存在、提高抗性不会降低任一资源，并且 `damage`、`speed` 等同一属性跨现有存储只经 binding 分派，不经实体类型分支。

静态预算必须显式表达起手和周期两部分：已知有限 `maintain` 可报告“起手 + 每周期 × 最多周期数”，未知目标或模式保留动态项；`时间=0` 的 `maintain` 必须标记为无界维持并显示周期法力/tick，绝不能宣称有限总上界。当前 `MetaCost` 只有单次调用数值，开发前 ADR 必须固定向后兼容的周期预算表示和 VM/Battle 结算接口；不得把预计全部周期费用预扣，也不得让分析器与实际逐周期实扣使用两套公式。

## 交互、状态与失败边界

推演台的元法术卡片显示属性、效果域、模式、时间 `0=无限`、所需能力和“基础 + 动态”价格；静态分析未知目标不虚构最终数值。成功创建返回可传给全部属性节点的句柄。控制失败显示为 `false` 和可解释原因（失效、缺能力、无权限、参数非法、余额不足）；不创建部分覆写、残留租约或无声降级。演武场在维持期间显示该施法实例的持续法力/tick 和结束原因，主动结束、法力耗尽、目标死亡/移除、能力丢失和权限变化都应可观察。

现有 Transform 的边界裁剪继续适用于 `position`；它是一次定位，不建立“定住目标”的免费持续效果。旋转对 Actor 改变 aim、对弹体改变运动方向，二者使用同一向量语义；生命周期写入不得复活已移除实体或突破原型数量上限。创建入口写入弹体基础伤害并只按一次既有施法者威力规则生成命中伤害基值；后续 `damage` 控制统一施加对外伤害倍率，不能在控制和命中两个位置重复乘算，也不能因控制者与所有者不同而偷换倍率来源。

## 兼容、持久化与回退

旧 `发射` 可按前述兼容锚点无损转为新创建调用；旧一参 `创建弹道` 与四个专用设置/激活调用只在能证明顺序、句柄和价格等价时组合迁移，否则给出定位到调用链的诊断，不能在运行时以旧的 Projectile 专用分支长期兼容。旧两参 `设置位置` 规范化为 `时间=0`；旧弹道方向/速度/威力控制和自身/目标属性控制分别映射到对应稳定属性，并显式补齐目标与时间。默认法术书先迁移；导入或本地法术书若诊断未解决，不覆盖最后一次可运行的规范化 AST。存档中的既有 `Modifier.duration <= 0` 保持旧存档读取语义；新 `ControlRecord` 若不存在不补造，若字段损坏则丢弃该记录并写出诊断，绝不猜测其控制者或无限结算历史。

开发前 ADR 必须固定：`时间=0` 与 commit/overlay/maintain 的 DSL 契约、逻辑属性和目标 binding 的职责、覆写优先级与同源替换、核心控制会话与 VM/战斗生命周期的所有权、周期预算/执行债务、抗性和价格配置、旧调用诊断/转换以及回退策略。回退仅允许停止展示新入口并保留可读旧法术与存档；已规范化的新三参数控制不能被降级为类型专用调用。

## 实施边界与任务输入

1. 在 `src/core/` 建立逻辑属性 descriptor、实体 binding、能力查询、控制记录、关系/抗性/价格、控制会话和 VM 可计量的维持结算；核心保持 Node 无头可运行。
2. 迁移创建入口与旧 DSL 规范化，再把属性和 Transform 控制全部接到单一执行路径；删除玩家可见的专用弹道控制链。
3. 让 Battle 只把施法实例资源钩子、时钟、打断和 `结束施法` 接入核心控制会话；每 0.25 秒的规则、原子扣费和清理语义留在可无头验证的核心，不得藏进 UI 或实体种类。
4. 更新默认法术书、蓝图节点、推演台/演武场反馈和自动生成的参考；补迁移诊断与存档边界。

实现前应建立 ADR；任务拆分阶段再产出可执行 JSON 清单和排期。本阶段不适用：任务拆分、排期、开发清单、QA/缺陷报告、候选体验和发布材料，因它们属于尚未到达的后续生命周期节点。
