# 统一实体创建、控制与属性模型：模块详细策划

- 版本 ID：`draft-2026-09-21-b5fbefbd-c4c9-460e-935d-`
- 阶段：详细策划
- 策略：完整执行；本文件只固定游戏产品的实现合同，不登记版本节点或生成后续阶段证据。
- 公开结论：已将统一创建、属性控制、无限时间、定价和兼容边界细化为可实现、可测试的合同；进入开发前必须先采纳本文列出的 ADR。

## 问题、范围与非目标

现状中 `发射` 直接生成已激活弹道，`创建弹道` 则必须再调用方向、速度、威力和激活四个 Projectile 专用入口；Actor 的临时修正又绕开了弹道控制。它们使同一件事按存储种类分叉，也无法解释无限时间为何有时一次付费、有时持续付费。

本模块把“创建持续前进、可伤害的弹体”和“以属性改变实体状态”收束为两套玩家合同：一个创建入口，以及一组每项都归一为 `(目标, 效果, 时间)` 的具名属性控制入口。目标、所有权、抗性、能力和生命周期决定结果；`Actor`、`Projectile` 只是在其上声明不同能力的现有存储，不得成为元法术分支条件。

不在范围内：完整 ECS、额外实体原型、伤害类型或随机豁免、神识强度、修改 AST 的单一 IR 地位、冷却回归、工作流控制面或 `.daoyan-agent`。数值会以本文件的归一化公式和测试锚点实现，再由版本测试调整配置系数；不得另改语义。

## 公开规则

### 1. 统一创建

玩家入口定为 `创建弹道(方向: vec2, 速度: num, 伤害: num, 时间: num): entity`。创建成功即从施法者前方生成、激活并返回句柄；方向为非零有限向量并归一化，速度、伤害为正有限数，时间为正有限秒数。它保留现有每位所有者 16 枚上限、命中/过期清理和“创建失败返回空”的契约。创建和激活不再暴露为两步核心玩法。

`发射(起点, 方向, 威力)` 与旧的一参 `创建弹道(寿命)` 都只作为迁移输入：规范化器将前者按旧的 `380` 速度、`2.4` 秒寿命和原起点语义转换为新调用；后一种必须要求显式补齐方向、速度、伤害，不能猜测配置。目录、蓝图、默认法术和参考只展示新入口。解析到无法无损转换的旧调用时给出位置明确的迁移诊断，保留原文且不静默改变伤害、方向、寿命或资源结算。

### 2. 属性描述符与能力

核心新增独立于实体种类的 `ControlPropertyDescriptor`。每个描述符声明：稳定属性键、效果类型和验证、读写能力、`write`/`maintain` 模式、关系许可、抗性读取、效果合并和撤销、定价强度函数。世界只通过“目标是否提供该描述符和写能力”回答可否控制；不能以 `kind` 或 `ownedProjectile` 选择实现。

首批描述符如下。`位置`、`朝向`、`速度`、`伤害`、`存活时间`是弹体可声明的状态；Actor 只声明其实际拥有的子集。`移动速度`和现有基础属性仍是属性，但不等同于弹体 `速度`。

| 属性键                                     | 效果类型 / 校验                 | 首批模式   | 需要能力                      | 首批实体声明                          |
| ------------------------------------------ | ------------------------------- | ---------- | ----------------------------- | ------------------------------------- |
| `position`                                 | `vec2`，有限且经场地边界裁剪    | `write`    | transform + property:position | Actor、Projectile                     |
| `rotation`                                 | `vec2`，有限非零，归一化        | `write`    | transform + property:rotation | Actor 的 aim、Projectile 的方向       |
| `velocity`                                 | `num`，正有限                   | `write`    | movement + property:velocity  | Projectile；Actor 仅在未来声明后可用  |
| `damage`                                   | `num`，正有限基础伤害           | `write`    | property:damage               | Projectile；有伤害输出的未来实体      |
| `lifetime`                                 | `num`，正有限剩余秒数           | `write`    | property:lifetime             | Projectile 与明确声明寿命的未来实体   |
| `speed`、`power`、`perception`、`armor` 等 | 描述符指定的加法/倍率与领域校验 | `maintain` | modifiers + 对应 property     | 当前 Actor；未来拥有 Modifiers 的实体 |

`hpMax`、`manaMax`、`manaRegen`、`shenshiMax`、`castSpeed`、`manaCostMul` 在本版本仍不是公开控制入口：它们影响资源、施法安全或需要额外的上下限规则。描述符缺失即是明确能力拒绝，而不是用类型分支或默认写入替代。

具名节点保留可读性，例如 `设置位置(目标, 目标点, 时间)`、`设置朝向(目标, 方向, 时间)`、`设置速度(目标, 速度, 时间)`、`设置伤害(目标, 伤害, 时间)` 和 `迟滞(目标, 倍率, 时间)`；它们均只把固定属性键与第二参数交给同一个 `applyEntityControl`。旧自身增益在迁移期可解析为显式 `目标=自身` 的同一调用，运行时返回 `bool`；不能留下另一套自身实现或价格。

### 3. 时间、写入与维持

`时间` 保持 `num`，避免为当前 AST 引入一套只服务时长的联合类型：正有限数表示秒数，`0` 表示无限，负数、NaN、Infinity 一律非法。当前所有可用旧控制只接受正数，故 `0` 不会改变已合法法术的结果。

| 模式       | 有限时间                                                     | `时间 = 0`（无限） | 停止与状态                                                                                  |
| ---------- | ------------------------------------------------------------ | ------------------ | ------------------------------------------------------------------------------------------- |
| `write`    | 写入一个带到期时刻的覆写层；到期撤销，恢复当时仍有效的下层值 | 写入无到期覆写层   | 后续同控制者对同属性的合法写入替换本层；目标失效、能力/权限失效或属性生命周期结束时移除     |
| `maintain` | 建立由施法实例拥有的维持租约，至到期前按结算间隔重新确认效果 | 同一租约无到期     | 法力不足、施法实例调用 `结束施法`、实例被打断、目标/能力/权限失效时原子移除；不保留半个效果 |

有限 `write` 不制造周期扣费，但其时长进入起手价；无限 `write` 只付一次，因为它不占有施法实例。`maintain` 必须绑定到当前施法实例：法术作者可在 channel/条件循环中以 `结束施法` 主动释放；实例正常结束或被战斗打断也释放其所有租约。维持结算为固定 `0.25` 秒，先检查目标、权限和余额，再原子扣法力、记 tick、刷新该租约的效果；任一步失败都撤销该租约本轮及未来效果。多个来源按稳定创建序号合并，`add` 先求和、`mul` 后相乘；同一来源同属性更新替换旧租约，不叠加。

这以“效果的控制模式”而非“弹道/Actor”区分一次性写入和持续维持。它也避免永久 Modifier 的现有 `duration <= 0` 隐式约定继续扩散：新控制记录必须显式携带 `mode`、`expiresAt | null`、`controllerCastId` 和结算状态。

### 4. 权限、抗性与成本

关系层固定为自身 `1`、自有 `1`、友方 `2`、非己方 `8`；这已使己方为正成本、非己方有不可绕过的固定门槛。描述符另提供非负抗性 `r`（缺省为 `0`），只能使价格升高。权限先于效果写入判定；无效句柄、缺描述符/能力、禁止关系、非法效果或时间均返回 `false`，状态不变。尝试成本仍遵守现有 VM 规则。

对一个归一化控制请求，法力与 tick 都按同一结构计算：

```text
起手 = 关系层 A × (属性基础 B + 效果强度 S + 有限 write 的时间项 D) × (1 + r)
维持每 0.25 秒 = A × (维持基础 M + 效果强度 S' + 时间项 Q) × (1 + r)
```

`write` 只结算起手；`maintain` 结算起手加每个成功结算周期。`B`、`M`、`S`、`D`、`Q` 都分别为法力和 tick 配置，且均为正或零的有限数；起手 `B` 必须为正，非己方的 `A=8` 不能被效果为零、时长为零或抗性抵消。未知目标、关系、抗性或效果仍报告“基础 + 动态”；静态已知项和 VM 实扣使用同一个描述符函数。

以下为归一化验收锚点（不是最终平衡表）：令一次 `write` 的 `B+S+D=5 tick/mana`、无限 `write` 的 `B+S=3`，`r=0/1`。自身/自有、友方、非己方的起手分别为 `5/10/40` 与 `10/20/80`；无限写入分别为 `3/6/24` 与 `6/12/48`。同一描述符的 `maintain` 每周期也必须按同样的 `A × (1+r)` 单调放大。测试应逐项证明：己方不为零、非己方门槛存在、提高抗性不会降低任一资源，且同一实体能力在不同现有存储中得到相同公式路径。

## 交互、状态与失败边界

推演台的元法术卡片显示属性、效果域、模式、时间 `0=无限`、所需能力和“基础 + 动态”价格；静态分析未知目标不虚构最终数值。成功创建返回可传给全部属性节点的句柄。控制失败显示为 `false` 和可解释原因（失效、缺能力、无权限、参数非法、余额不足）；不创建部分覆写、残留租约或无声降级。演武场在维持期间显示该施法实例的持续法力/tick 和结束原因，主动结束、法力耗尽、目标死亡/移除、能力丢失和权限变化都应可观察。

现有 Transform 的边界裁剪继续适用于 `position`；旋转不改变 Actor 移动朝向之外的行为，弹体旋转同步其运动方向；生命周期写入不得复活已移除实体或突破原型的数量上限。伤害写入的效果是“基础伤害值”，当前施法者 `power` 的放大只在创建/伤害实际结算的既有位置应用，避免控制时与命中时重复乘算。

## 兼容、持久化与回退

旧 `发射` 可无损转为新创建调用；旧一参 `创建弹道` 与四个专用设置/激活调用应在解析/规范化阶段给出组合迁移诊断，不能在运行时以旧的 Projectile 专用分支长期兼容。默认法术书先迁移，导入和本地法术书保持原始文本直到玩家接受诊断后的规范化结果。存档中的既有 `Modifier.duration <= 0` 保持旧存档读取语义；新 `ControlRecord` 若不存在不补造，若字段损坏则丢弃该记录并写出诊断，绝不猜测其控制者或无限结算历史。

开发前 ADR 必须固定：`时间=0` 的 DSL 契约、覆写优先级与同源替换、租约与 VM/战斗生命周期的所有权、抗性描述符和价格配置、旧调用诊断/转换以及回退策略。回退仅允许停止展示新入口并保留可读旧法术与存档；已规范化的新三参数控制不能被降级为类型专用调用。

## 实施边界与任务输入

1. 在 `src/core/` 建立描述符、能力查询、控制记录、关系/抗性/价格和 VM 可计量的维持结算；核心保持 Node 无头可运行。
2. 迁移创建入口与旧 DSL 规范化，再把属性和 Transform 控制全部接到单一执行路径；删除玩家可见的专用弹道控制链。
3. 让 Battle 管理施法实例租约、每 0.25 秒结算、打断和 `结束施法` 清理；不得把周期费用藏进 UI 或实体种类。
4. 更新默认法术书、蓝图节点、推演台/演武场反馈和自动生成的参考；补迁移诊断与存档边界。

实现前应建立 ADR；任务拆分阶段再产出可执行 JSON 清单和排期。本阶段不适用：任务拆分、排期、开发清单、QA/缺陷报告、候选体验和发布材料，因它们属于尚未到达的后续生命周期节点。
