## 问题与价值

当前 `发射` 直接生成已配置、已激活的弹道，而 `创建弹道` 需要再用四个弹道专用控制元法术配置和激活；它们描述的是同一种“创建可造成伤害并沿方向持续前进的实体”，却迫使玩家学习两套写法。已有统一句柄与能力判定，但弹道方向、速度、威力和激活仍按 Projectile 专用入口及所有权分叉；属性控制、位置控制和持续效果也没有同一套“目标、效果、时间”语义。

本版本让玩家以同一套可组合规则创建和控制实体：能否控制由能力与权限决定，代价由所获效果、所属关系、抗性和维持时间决定，而不是由实体存储类型决定。这样既能把火球、自身和敌人的同一属性控制写成同类法术，也让“永久写入”和“持续压制”在资源上可预测、可解释。

## 范围

1. 合并 `发射` 与 `创建弹道` 的玩家语义，形成一个创建“持续前进且可造成伤害的实体”的统一入口；默认法术、目录和参考文档只向玩家呈现该入口。旧名称的兼容策略在详细策划确定，不能保留两套会继续分歧的核心行为。
2. 将可控状态扩展为统一属性：至少涵盖位置、旋转/朝向、伤害强度、移动速度、存活/持续时间及现有可修正属性；每个属性显式声明值类型、可写能力、时间语义、效果验证和抗性来源。
3. 将实体控制元法术统一为 `(目标, 效果, 时间)`：`目标` 为不透明实体句柄，`效果` 是属性对应的请求值或变更，`时间` 为有限时长或无限；省略目标的自身便利写法只能是语法糖，运行时仍归一为同一契约。
4. 以属性元数据而非 `Actor`/`Projectile` 类型分支判定控制：目标必须具备该属性及相应写入能力；缺失、失效、无权限或参数非法时返回 `false` 且不产生部分修改。
5. 建立统一控制成本：法力与 tick 同时反映效果强度、关系门槛、目标抗性和持续/维持时间。自身与己方/自有实体有折扣但始终保留正的最小成本；非己方有不可绕过的固定门槛，抗性只会提高而不会降低成本。
6. 支持无限时间，并以结构化效果语义区分一次性写入与持续维持；维持会在整个有效期持续结算资源，直至法力耗尽、施法者主动结束、目标/能力/权限失效或有限时间届满。

## 统一控制语义（策划基线）

每个可控属性声明 `controlMode`，这是属性/效果的能力元数据，不是实体类型判断：

| 控制模式               | `时间 = 有限值`                                    | `时间 = 无限`                                              | 资源结算                                                                    |
| ---------------------- | -------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| `write`（一次性写入）  | 写入请求值；若属性支持临时覆写，覆写在该时长后撤销 | 写入持续到后续合法写入覆盖、实体失效或属性自身生命周期结束 | 仅在成功写入前收取一次法力与 tick；无限不产生按秒费用                       |
| `maintain`（持续维持） | 在该时长内保持/重复施加效果                        | 维持至法力耗尽、主动结束、控制失效或目标失效               | 起手成本后，按固定结算间隔持续收取法力与 tick；任一笔无法支付即原子停止维持 |

`时间` 的含义因此由效果的 `controlMode` 决定：例如把法球的速度、方向或伤害值写入为无限，是对具有对应属性的实体的一次性持久配置，不因为它是弹道而获得特例；对目标施加“保持减速”则是 `maintain`，无论目标是自身、友方、敌人或未来实体。属性若不声明该模式，能力判定必须明确拒绝。有限 `write` 的撤销/覆盖规则、多个维持来源的叠加规则和结算粒度属于详细策划的明确合同，不得留给具体实体临时决定。

这比“Projectile 无限免费、Actor 无限按秒收费”的类型规则更统一：同一属性在任意实体上的相同效果走同一模式；对象差异只通过其声明的能力、归属、抗性和生命周期进入结果。

## 成本与权限基线

一次控制的法力与 tick 都采用同一可审计的组成：

`总成本 = 属性基础成本 + 效果强度成本 + 关系门槛 × 抗性系数 + 时间成本`

- 关系门槛按自身、自有、友方、非己方分层；前两类也有严格大于零的起手成本，非己方有不可绕过的固定门槛。
- 抗性来自目标对该属性/控制类别声明的数值或函数；它只单调增加门槛与持续结算，不改变能力失败的确定性语义，也不引入随机成功率。
- `write` 的时间成本只结算一次写入所需 tick；有限期的临时写入还按有效时长计入可观察的效果价格。`maintain` 则把时间成本拆为起手与每个结算间隔的法力、tick，确保无限控制不会免费占有世界状态或施法时间。
- 动态预算继续遵守“有限请求不设人为上限、未知目标状态显示基础 + 动态”的既有契约；实际实扣不得低于已承诺的门槛，也不得超出分析/运行时定价合同。

详细策划必须为各关系层、至少两档抗性、有限/无限 `write` 与 `maintain` 给出示例表及单调性测试，避免只写原则而无法平衡。

## 非目标

- 不将 `Actor`、Projectile 或未来实体重写为完整 ECS，也不以本版本引入无关实体种类。
- 不改变 AST 作为共享 IR、核心无 UI 依赖、神识/法力/tick 的基本职责，亦不恢复法术冷却。
- 不引入随机控制成功率、按实体类型硬编码的无限时间例外，或凭空赋予目标未声明的属性。
- 不在本版本改变工作流控制面、`.daoyan-agent` 状态、版本节点登记或发布流程。
- 不承诺本阶段确定具体数值、兼容移除日期或 DSL 语法细节；这些须在详细策划中依据测试与现有法术书确定。

## 玩家流程

1. 玩家在推演台查看统一实体创建和属性控制元法术，能看到 `(目标, 效果, 时间)`、所需能力、一次性/持续维持语义及“基础 + 动态”成本说明。
2. 玩家创建一枚伤害弹体，直接指定方向、速度、伤害和持续时间；得到的句柄可继续交给同一套属性控制法术。
3. 玩家对自身、己方实体或敌方实体使用同一个属性控制法术。系统依目标能力、归属与抗性给出相同的成功/失败语义和不同的法力、耗时。
4. 玩家把可写属性以无限时间写入时，只支付一次；对可维持效果使用无限时间时，能观察到持续法力与 tick 占用，并能主动结束。
5. 目标失效、失去能力/权限或法力无法支付时，控制明确停止或返回 `false`，没有半次写入、无声降级或按实体类型的隐性例外。

## 验收标准

- [ ] 面向玩家的元法术目录和默认法术不再把“发射”和“创建弹道”呈现为两种核心能力；统一入口能生成、伤害、沿方向持续前进，并返回可继续控制的实体句柄。
- [ ] 所有新增或迁移的实体控制接口均可归一为 `(目标, 效果, 时间)`；自身便利语法与显式自身目标行为、价格和失败结果一致。
- [ ] 对同一已声明属性，火球、自身、敌人或未来实体使用同一控制实现路径；差异只能来自能力、归属、抗性、生命周期或实际效果，测试不得以 `kind` 专门分支证明行为。
- [ ] 位置与旋转/朝向作为属性可经统一元法术读取/控制；没有对应能力的实体会确定性拒绝，且目标状态保持不变。
- [ ] `write` 与 `maintain` 的有限和无限时间分别遵守本策划案的资源与停止规则；无限 `write` 不产生周期收费，无限 `maintain` 在法力、主动结束或控制失效时停止。
- [ ] 自身/自有控制有正成本；非己方控制有固定门槛；在相同效果、关系和时长下，提高抗性会单调提高法力与 tick 成本。
- [ ] 静态分析、VM 实扣、战斗运行和元法术参考对同一调用显示一致的基础/动态预算；非法参数、句柄失效、能力缺失和无权限控制都不产生部分修改。
- [ ] 现有合法法术书和存档有明确迁移或兼容诊断；旧入口不会静默改成不同伤害、方向、时长或资源语义。
- [ ] 推演台与演武场完成创建、控制、无限维持、主动结束、法力耗尽和能力拒绝的真实体验闭环。

## 建议阶段策略

按“完整执行”基线推进，固定顺序和门禁如下：

1. **制作人评审（当前交付后的固定门禁）**：评审本策划案的价值、范围、非目标、`write/maintain` 语义和验收标准。通过前不进入详细策划。
2. **详细策划与架构决定**：盘点现有元法术、默认法术书、AST/类型、World 能力和 VM 生命周期；在实施前写 ADR，固定属性描述符、控制模式、叠加/撤销、兼容与一次性创建入口的不可逆合同。
3. **任务拆分与排期**：按共享契约/核心与 DSL、元法术迁移、UI/参考、存档迁移、集成与体验拆分依赖和波次；冻结范围后才进入开发。
4. **开发与独立测试**：先完成 Node 可运行的核心纵切，再迁移玩家入口和界面；普通缺陷集中登记，在版本测试阶段统一修复、复验和闭环。
5. **固定收束门禁**：Feature 完整门禁、版本集成/迁移/打包验证、候选真实体验和制作人候选评审。任一失败按同一版本修复；仅产品方向冲突、不可逆架构取舍、状态失真、高风险偏航或外部访问阻塞才中断上报。

## 风险与待详细策划收束项

- **高风险语义变更**：永久 `write`、有限覆写与多来源 `maintain` 的优先级会影响已有属性修正和存档。详细策划必须先给出 ADR、迁移表和回退边界，再改 AST/VM。
- **兼容风险**：旧 `发射` 与弹道专用调用可能存在玩家法术；需以解析/规范化或明确诊断迁移，不能在保留同名时悄然改变资源与战斗结果。
- **资源风险**：持续 tick 占用不得绕过同槽互斥、法力不足或静态预算显示；需要覆盖并发维持和法力耗尽。
- **范围约束**：本版本只处理游戏实体/法术模型；任何工作流控制面问题独立由主 Agent 维护，不混入版本承诺。
