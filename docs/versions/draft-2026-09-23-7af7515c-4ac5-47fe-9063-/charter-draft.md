## 问题、价值与反馈归属

上一版已有统一句柄、能力 binding、七项控制入口与周期收费，但运动和施法状态分散；弹道按固定速度自行移动并按基础伤害命中，尚无支付、存能、运动和伤害之间的守恒解释。现有 `speed` 是移动倍率或弹道标量，并非实际速度向量。战斗层直接移动 Actor 与 Projectile；`onDamage` 主要服务受击打断。按键槽位持有施法实例，尚不能完整表达两个蓄力流程或一个事件触发多个法术。生命上限、法力上限、法力回复、神识上限、施法速度及法力消耗倍率还不是公开统一控制能力，旧入口映射和示例难找。

玩家应能用同一套**属性、权限、事件与资源账本**理解角色、法球和未来实体：知道效果为何发生、何时停止、谁支付了成本，并在推演台设计、演武场验证。上一版候选体验中“控制元法术变少”“减速、破防示例难找”和后续六项属性补全，归入本案的发现与属性范围，不重复立项；上一版归档不追认本案能力。详细策划可以调整系数和语法，但不得默删下面的可观察语义。

## 范围与统一语义

1. **可审计实体**：在统一句柄下由能力声明行为，不按 `kind` 硬编码。内部最小状态包含位置、旋转/朝向、实际 `velocity: vec2`、`speedMax` 上限、力/冲量和运动来源、当前与上限生命/法力、神识上限及占用、逐属性抗性、所有者/阵营、控制会话、事件和必要历史。历史保留期限及容量有界；缺能力不补默认值。Projectile 可拥有储能、事件和行为法术，不自动获得回蓝、免费意识或 Actor 属性全集。
2. **可归因世界效果**：读取或改变世界走授权、定价和可审计通路。生命经伤害/治疗变化；`velocity` 经力、冲量和物理积分变化；`speedMax` 只限制驱动或允许速度，不冒充实际速度。既有直接设位置应作为独立高价、可解释的位移/传送效果，说明边界和碰撞。角色移动、法球行为也受世界效果合同约束；自然惯性、UI 和物理积分不必逐帧调用玩家 DSL。
3. **守恒账本**：跟踪施法者扣款、向实体注能/储能、创建与冲量、持续推进/追踪、事件扫描、命中转伤害、损耗、可退款余额及终止原因。一次付费冲量后的正常惯性不按帧收费；持续推力、主动转向和追踪逐周期从存量或明确授权的施法者账户扣费，耗尽即停止主动行为。命中伤害不得超过可用伤害能量，运动能量不能被重复当伤害消费。创建费与存能分列；已做功、已扫描、已伤害不退，只可按明定规则退未用余额。同一笔法力不得同时算储能、推进与伤害。
4. **事件与意图解耦**：物理按键只是外部玩家意图，不是唯一法术生命周期。一个事件可按稳定顺序绑定多个法术。受击、碰撞、法力耗尽、实体消失等离散被动事件定义来源、归属、时序、并发、去重、重入上限与失败隔离，不产生免费 VM 或免费读世界。主动持续监控必须显式开启，并声明范围、频率、权限及持续法力/tick/神识费用；关闭、耗尽、死亡或目标失效即停。实体行为的执行上下文、账户归属及控制者消失后的责任由新 ADR 论证。
5. **两种蓄力**：支持“按下蓄时、松开瞬发”和“按下创建法球、持有期间周期注能、松开发射”。均明确按下、持有、释放、打断、取消、死亡、耗尽、目标消失、暂停/继续的状态转移与退款边界。输入可以触发意图，中途注能、事件响应和法球行为由会话或实体合同持有。
6. **发现与连续性**：六项新属性、旧控制名映射、能力、权限、时间、价格与失败原因在推演台可查。提供可预览、选择性导入的“对手减速”“对手破防”预设自定义法术；现有法术书用户也可导入、推演、绑定、实战，不覆盖同名法术。旧存档和旧合法法术统一经 AST 规范化迁移，无法证明兼容时给定位诊断并保留原件及最后可运行状态。

## 属性读取、修改与失败合同

“本人”只表示实体对自身状态的合法读取；他人持有句柄不自动得到信息。内部状态可完整审计，玩家属性面板只显示自己、明确公开的目标信息、成功付费探查获准的快照和必要事件摘要。日志及错误消息不能泄漏私有数值。读取拒绝返回统一的不可探查结果；失效句柄、缺能力、越权、非法参数或不支持时长的控制返回 `false`，按现有尝试价结算且无部分效果。资源、tick 或状态容量不足走 VM/会话失败路径并清理，不能伪装为领域拒绝。

| 属性/状态                    | 读取权限与感知                                                  | 合法改变途径及失败边界                                                                                                |
| ---------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 位置、朝向                   | 自身/自有物可读；他方须在感知范围并付费，遮蔽或抗性可拒绝/加价  | 运动积分和有源冲量改位置；朝向可限时控制。直接设位置仅独立高价效果，检查边界、碰撞及权限。                            |
| `velocity`、运动来源         | 自身/自有物可读；他方须可感知并具 Movement，来源细节默认私有    | 力/冲量、碰撞或明确运动效果改变；改 `speedMax` 不直接改已有速度。                                                     |
| `speedMax`                   | 本人可读；他方付费且目标允许探查                                | 有期限的增减走统一 binding；抗性、幅度与周期收费。降限后超速如何处理先由 ADR 固定，不暗中抹去动能。减速预设用此语义。 |
| 当前/上限生命                | 本人可读；他方仅获准生命探查可见精确值                          | 当前值只由伤害/治疗改变；`hpMax` 只改上限，不治疗/复活。降限裁剪当前值，到期不返还；无 Vitality 拒绝。                |
| 当前/上限法力、回复率        | 本人可读；他方逐项获准资源探查，精确余额门槛高于上限            | 当前值仅由支付、注入/转移、退款和按世界时间回复改变；`manaMax` 不注能，降限裁剪不返还；`manaRegen` 不当场回蓝。       |
| 神识上限/占用                | 本人可读；他方上限可获准探查，占用与 VM 内部状态默认私有        | `shenshiMax` 改后续分配容量；既有占用不删除，超额时禁新分配但允许释放。                                               |
| `castSpeed`、`manaCostMul`   | 本人可读；他方须逐属性获准付费探查                              | 前者仅改以后 tick 的真实推进，不删除工作；后者仅影响后续可折扣项且有正下界，自身控制及资源转移按不可折扣保底结算。    |
| 护体、伤害、感知、抗性、归属 | 自身/自有物按能力可读；他方仅白名单属性可探查，抗性细节默认私有 | 既有属性按统一控制；破防预设作用于护体。抗性和归属转移须专门获准效果，不能借普通控制重设。                            |
| 会话、事件、历史             | 内部可审计；玩家只见有权参与的会话及必要摘要                    | 权威世界结算事件；历史只追加有界摘要，不借日志触发免费探查。                                                          |

感知须覆盖允许探查的新增属性：先查能力、可见性、距离、归属及敏感级别，再按距离、双方神识、目标对应抗性与信息精度定价。自身私有探查可较低价但世界读取仍为正价；自有物和敌方不因句柄同类而同价。神识不足、越距、不可见或无权限不返回真实值；失败价和返回形状不能成为精确属性的侧信道。详细策划给完整白名单/拒绝矩阵并与静态动态预算对齐。

## 六项属性的效果、时间、抗性和代价底线

六项由能力 binding 提供，不按 Actor/Projectile 类型分叉。预计沿用 `(目标, 效果, 时间) -> bool` 及 `maintain`：正有限秒数到期，`0` 为会话有效期间无限但持续收费；起手、首周期、每 0.25 秒续费及尾周期按模拟时间结算，暂停不计时。自身/自有、友方、非己方分别有关系价，非己方有固定正门槛；逐属性抗性非负且单调加价。每项起手及周期的法力和 tick 基础价严格为正，效果或收益时长增加不降价。精确系数、合法区间、同源更新和多源合成在详细策划给数值样例与证明。

| 属性          | 效果与限制                                 | 成本与防套利要求                                                             |
| ------------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| `hpMax`       | 正上限，超出当前生命裁剪；不治疗、不复活   | 上限增量、潜在受益和维持时长入价，降限不产生可退款生命。                     |
| `manaMax`     | 正上限，超出当前法力裁剪；不注能           | 可多容纳资源量及维持时长入价，到期不返还裁剪资源。                           |
| `manaRegen`   | 有界非负回复率，仅按世界时间及当前上限回复 | 每周期新增可得法力不高于不可折扣周期费，并保留正余量；叠加及并发不净产法力。 |
| `shenshiMax`  | 正容量，既有占用保留，超额时禁新分配       | 额外容量、控制记录本身占用与维持都收费，不能无限复制控制。                   |
| `castSpeed`   | 正且有安全界；只加快后续 tick 的真实推进   | 时间收益增加法力/tick 价；不加快世界续费时钟，不清旧债。                     |
| `manaCostMul` | 严格正且有保底下界，不追改已付费用         | 潜在折扣收益进不可折扣价；自身控制、注能、监控及最低世界 I/O 不能变零价。    |

静态预算遇关系、抗性、时长、事件次数或未来注能未知时显式标动态/无界；仅确定输入可称有限上界，且不得低于实扣。神识静态容量纳入订阅、会话、实体行为和历史缓冲，动态峰值由共享账户限制；tick 是工作债务，不可因余额不足免除已发生工作。详细策划用自回蓝、自降耗、提速及叠加的反例证明无免费循环。

## 建议分期：同一版本的三个纵向闭环

范围较大，建议按依赖分波实施；立项评审后由详细策划和 Version PM 冻结。这不是平行版本，前两波完成也不代替全版候选验收。

1. **状态、权限与运动**：可审计状态、`velocity/speedMax`、力/冲量、角色与直线法球；自身/获准目标探查、属性面板及事件摘要。推演台看到读改价格，演武场观察一次冲量后惯性、上限减速与越权拒绝。
2. **能量与资源属性**：储能、注能、持续推进/追踪、命中伤害和损耗账本，与六项属性控制、当前值语义、防套利价一同落地。体验供能不同的法球、耗尽停止、增益成本、减速/破防预设；旧书和存档迁移随波完成。
3. **事件与蓄力**：离散被动事件、多法术订阅、付费主动监控和两种蓄力。推演台复现、演武场实战、暂停/取消/死亡/耗尽及退款可观察。跨波资源上界、迁移和 UI 回归后进入版本 QA、缺陷修复及制作人候选体验。

若任一波无法在同版闭环，须公开范围与风险，提出保留全部核心目标的分期方案并重新走制作人范围评审，不得暗删事件、能量或蓄力目标。

## 可实测端到端验收

1. 推演台分别构造一次冲量滑行、持续推进、主动追踪法球并在演武场发射：第一种停供后按惯性运动，后两种逐周期扣费并留轨迹；储能耗尽时主动行为停止。命中伤害、剩余能量及损耗可核对，不重复消费或凭空续航。
2. 自身私有资源/占用探查返回获准信息并付费；越距、无权限、无能力、高抗性探查按合同拒绝或加价，面板与日志不透视。Actor、Projectile 和合成能力实体按相同能力语义通过或拒绝。
3. 受击、碰撞、法力耗尽、实体消失各可复现；单事件绑定两个法术时顺序、资源争用、重入上限和归属确定。主动监控显式开启且持续付费，关闭或耗尽不再扫描；离散被动事件不为逐帧观察付费。
4. 两种蓄力均在推演台和演武场完成按下、持有、松开；蓄时瞬发与创建后周期注能再发射可区分，打断、取消、死亡、耗尽、暂停/继续的余额、已付工作和未用储能退款符合账本。
5. 六项属性分别验证自身、自有、友方、对手的能力、抗性和时长。上限增减不凭空治疗/回蓝；回复只按模拟时间；降神识不删除活跃状态；提速不删 tick；降耗不折扣自身维持。故意套利场景下已知静态价/动态标记与实扣一致。
6. 玩家从旧名、新属性或元法术目录找到统一入口；现有书可预览并选择导入对手减速、破防，重复或同名冲突不损坏原书。两例能编译、推演、绑定并实战观察效果与结束原因；推演台和演武场往返保留书与绑定。
7. 旧合法法术、旧存档、本地自动保存及导入导出完成迁移或定位拒绝；原文和最后可运行状态不丢，未来格式不覆盖当前状态。版本 QA 覆盖成功、失败、空状态、并发、耗尽和桌面/窄屏实际体验。

## 非目标与阶段门禁

- 本阶段不实现代码、不冻结 DSL 事件语法、平衡系数或 UI 布局；详细策划和必要 ADR 先论证。也不要求完整 ECS、云存档、所有实体拥有生命/施法/回蓝能力，或把物理与 UI 每帧做成玩家元法术。
- 不恢复冷却，不建立第二套 IR 或绕过共享账户，不让属性面板成为全知调试器；工作流控制面不在产品版本范围。
- 普通缺陷在版本测试和修复阶段登记。只有真实阻塞、重大方向冲突、高风险不可逆选择或必须由制作人恢复的外部访问才立即通知制作人。
- 制作人先评审本案；未批准不进入详细策划。获批后再形成详细策划和 ADR、任务拆分与范围冻结、开发、独立版本测试、缺陷修复和候选体验。各节点留证据与简报，由 notice guard 对账并原子登记；本文件不手工推进状态。
