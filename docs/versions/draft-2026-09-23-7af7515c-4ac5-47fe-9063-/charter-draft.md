## 问题与玩家价值

上一版已建立统一实体句柄、能力判定和七项公开控制属性，但生命上限、法力上限、法力回复、神识上限、施法速度、法力消耗倍率仍只能通过基础配置或兼容旧入口间接影响，玩家无法用同一套目标、效果、时间规则编写完整的增益与减益。统一后的元法术目录也让旧入口数量变少，缺少合并映射和可直接导入的减速、破防例子，已有法术书用户很难发现并体验能力。

本版以**属性驱动、统一实体、资源守恒和事件化法术**为主目标：玩家从属性能力和事件出发组合可理解的法术，在推演台观察预算与结果，在演武场绑定验证。目标拥有该能力才可被控制；增加生命、法力、执行空间或效率必须付出可解释的法力与 tick，不能靠自身增益形成免费循环。

## 同主题反馈合并与版本边界

| 反馈                                                                   | 本案中的唯一归属                                                                           |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 上一版候选体验提出元法术数量变少、减速与破防示例不可发现，随后再次退回 | 合并为“入口可发现性与可导入预设”一项，覆盖现有法术书，而非仅首次安装默认文本；不重复立项   |
| 补全六项属性、当前资源与上限、施法中神识、自我增益定价                 | 合并为“属性与资源守恒”一项，由同一 binding、定价与验收矩阵处理                             |
| 当前未冻结草案的后续方向修订                                           | 将属性驱动、统一实体、资源守恒、事件化法术作为版本主目标；保留上述两项具体承诺，不另立版本 |

上一版的归档只说明当时范围的交付事实，不把本案中的六项新控制、入口说明、预设或事件化法术追记为上一版已交付能力。旧候选反馈的历史归属保留；本案是下一正式版本的待评审范围。

## 范围与策划基线

1. **统一属性能力**：为六项缺失属性建立与现有 `position/speed/armor` 一致的逻辑属性描述、目标 binding、效果校验、抗性与生命周期；玩家入口仍表达 `(目标, 效果, 时间) -> bool`。Actor 当前具备完整属性；其他实体只在声明能力时支持，不因为统一句柄凭空获得生命、法力或神识。
2. **当前值与上限**：当前生命、当前法力与各自上限分开。提高上限不凭空回复当前值；降低上限立即把超出部分裁到新上限，到期恢复上限也不返还已裁掉的资源。法力回复只随模拟时间结算，不在施加控制时回填；死亡、失效或无法支付的控制按现有生命周期清理。神识是活跃 VM 状态容量，调整上限不创造或销毁已分配状态。
3. **效果、时间和限制**：六项 Actor 数值属性原则上以可撤销的 `maintain` 控制生效，正有限时间到期，`0` 为持续至会话结束或控制失效；每 0.25 秒续费，有限尾周期仍收费。效果叠加、同源更新、不同来源优先级和旧 Modifier 兼容沿统一控制合同，详细策划给出逐属性表与迁移规则。非法数值、越界、无能力、无权限和无效目标明确拒绝且不产生部分资源变化。
4. **资源守恒**：沿用自身/自有、友方、非己方关系层与目标属性抗性。每项起手和每周期的法力与 tick 均有严格正的基础价；非己方保留额外门槛，效果收益和抗性增加不能降低价格。法力回复增益的每周期费用须覆盖同周期可获得的额外法力并有正余量；降低法力消耗倍率不能把任何实扣压到零，也不能折扣自身起手或续费以返还投入。施法速度只改变真实推进速度，不删除 tick 工作；神识上限提升仍占用有界状态并付费。详细策划须给出定价公式、资源套利反例与上下界证明，静态预算不得低于实测。
5. **事件化法术**：让法术能以可观察的世界事件为触发条件，走现有 AST、分析器、编译器、VM、同一施法账户与控制生命周期；事件产生、消费、重复触发、终止和资源计费都可追踪。首批事件种类、触发上限及旧法术兼容合同在详细策划与 ADR 中确定，至少形成一个玩家可在推演台与演武场完成的触发闭环。不得由事件回调绕过法力、神识或 tick 预算。
6. **发现与示例**：元法术目录展示旧名称到统一入口的映射、目标能力、效果方向、秒数/无限、起手与周期成本，以及失败原因。提供对手减速、对手破防等有名称和说明的预设自定义法术，已有法术书用户可以预览、选择性导入、编译、推演、绑定和实战；导入不覆盖同名用户法术，失败不破坏原法术书。

### 六项属性的效果与成本要求

下表规定玩家可见行为，具体系数与安全界在详细策划中按核心测试确定。`maintain` 均先收起手价，再按模拟时间付法力和 tick；目标抗性逐项读取且非负，提升抗性只增价、不随机改变成功率。

| 属性                       | 效果与当前值语义                                         | 限制及成本中的收益量                                                               |
| -------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 生命上限 `hpMax`           | 改上限，当前生命只在超上限时裁剪；不治疗、不复活         | 正上限、死亡目标不可借此恢复；增量及受益时长进入双资源价格                         |
| 法力上限 `manaMax`         | 改上限，当前法力只在超上限时裁剪；不注入法力             | 正上限，失效后不返还法力；增量和可能多容纳的资源进入价格                           |
| 法力回复 `manaRegen`       | 改每秒回复率，按世界时间逐步回复且受当前上限约束         | 不允许负回复或无界收益；新增可回复量与持续时间进入周期价，禁止净产法力循环         |
| 神识上限 `shenshiMax`      | 改后续可分配容量；已活跃 VM 的占用仍真实计数             | 上限降低到已用量以下时禁止新分配，现有状态不被静默删除；容量增量与维持占用进入价格 |
| 施法速度 `castSpeed`       | 改后续 tick 对应的真实时间，不改已记 tick 或世界周期时钟 | 正且有安全界；速度收益进入法力和 tick 价格，不得加速免费续费或抹掉工作债务         |
| 法力消耗倍率 `manaCostMul` | 改后续世界 I/O 的实扣倍率，不追改已扣费用                | 严格正且有下界；折扣收益进入价格，自身控制按施加前基准与不可折扣的保底价结算       |

对敌降低这些属性也用同一逻辑属性、能力和抗性路径；收益量按实际可观察变化计，不允许用负值、零倍率或叠加顺序绕过价格。详细策划须明确各属性允许的效果区间、归一化、同源替换和多源合成，再冻结可实现合同。

## 非目标

- 本阶段不决定精确系数、具体 DSL 事件语法或扩展 API；改变共享 IR、资源语义、持久化或事件所有权前必须先写 ADR。
- 不把所有实体改成完整 ECS，不让 Projectile 自动拥有 Actor 的生命、法力或神识属性。
- 不把提高上限解释为治疗、回蓝或恢复已消耗神识；不恢复法术冷却或建立第二套元法术执行路径。
- 不自动改写、覆盖现有用户法术书；不追认上一版候选反馈为已交付，也不在本阶段发布或手工推进版本节点。

## 玩家流程与验收标准

1. 玩家在推演台搜索任一旧控制名或新属性，看到对应统一入口、能力要求、效果、时间单位、抗性、基础/动态及周期代价；不存在的能力有明确说明，不误认为功能缩水。
2. 已有法术书用户预览并选择导入“对手减速”“对手破防”；重复导入与同名冲突有清晰结果，原法术、绑定和本地存档不丢失。两例在推演台编译/推演，并在演武场绑定后对敌生效、持续扣费、到期/主动结束/法力耗尽时停止。
3. 对六项属性分别验证自身、友方和对手控制的允许与拒绝路径；`时间=0`、有限时间、续费、同源更新、抗性提高与能力失效均可观察。无效请求返回失败，不留半效果。
4. 分别验证提高/降低生命与法力上限前后当前值、到期恢复、死亡边界；法力回复只按时间增加且不超过上限；神识上限跨过活跃 VM 已用量时不破坏既有状态，之后的分配按新上限判定。
5. 自身回复、施法提速、降耗及组合叠加均不能生成零价、负价、免费无限维持或净产法力循环。起手、0.25 秒续费、tick 债务、共享账户和静态预算/实测有同一解释；至少覆盖一条故意套利的反例。
6. 至少一条事件触发法术能在推演台复现触发/未触发结果，并在演武场绑定实战；并发、重复触发、终止与资源上界可验证，旧合法法术保持原有可运行结果或给出定位兼容诊断。
7. 推演台、演武场、元法术参考与法术编写指南使用一致名称和资源语义；页签往返、导入后恢复、错误和空状态可实际体验。

## 建议阶段策略

1. **制作人评审**：当前策划案先交制作人确认价值、版本主目标和范围；未获评审通过前不进入详细策划。
2. **详细策划**：盘点现有 binding、世界时间、VM 共享账户、旧兼容入口、法术书导入与事件来源；形成逐属性效果/时间/限制/抗性/法力与 tick 示例表、资源套利证明、事件合同、迁移和回退方案。凡影响共享 IR、运行态资源或事件所有权的不可逆决定先提交 ADR。
3. **任务拆分与范围冻结**：按核心属性与资源、事件管线、玩家入口与预设、持久化兼容、文档和集成体验分依赖波次；以完整执行策略排期，不删除固定门禁。
4. **开发、独立版本 QA、候选体验**：先交付 Node 可运行核心纵切，再接推演台和演武场；Feature PM 在最终代码树完成完整门禁，版本测试覆盖资源套利、旧书迁移和实际战斗，缺陷修复复验后请制作人进行候选体验。通过前不归档、不发布。
