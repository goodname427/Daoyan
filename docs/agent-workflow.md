# 制作人与常驻秘书

项目只保留一种日常工作范式：**制作人只和常驻秘书对话，秘书负责其余工作。**

制作人提供产品方向、体验反馈和大版本发布决定，不判断任务复杂度，不拆任务，不选模型，不指定测试，也不管理 Git。秘书维护跨 Feature、跨版本的长期队列和项目现状，再把实际交付派给 Feature PM。

## 日常使用

直接在当前 Codex 对话中描述想法即可，例如：

> 我希望推演台能对比两次法术测试的资源曲线。

当前主 Agent 应把消息交给常驻秘书。需要从本机终端直接投递时，只使用下面的入口：

```bash
npm run secretary -- "我希望推演台能对比两次法术测试的资源曲线"
```

常驻守卫未运行时会自动启动。首次部署也可以显式启动：

```bash
npm run secretary:start
```

查看当前正在做什么、排期和最近完成节点：

```bash
npm run secretary:status
```

当秘书确实需要产品取舍时，直接在对话中回答。终端入口为：

```bash
npm run secretary -- --decision "采用方案 A，兼容已有存档"
```

版本方向仍通过同一个秘书入口提交：

```bash
npm run secretary -- --version "推进到下一个稳定可玩版本"
```

制作人无需使用 `producer*` 命令。它们是 Feature PM 的内部交付和故障恢复工具，见 [`operations/feature-pm.md`](./operations/feature-pm.md)。

## 角色定义

| 角色       | 生命周期                | 负责什么                                              |
| ---------- | ----------------------- | ----------------------------------------------------- |
| 制作人     | 项目全程                | 定方向、反馈体验、决定大版本发布                      |
| 常驻秘书   | 跨 Feature 和版本       | 对话、查重、排期、项目问答、进度汇报和 Review 暂停    |
| Feature PM | 一项 Feature 或一个版本 | 任务合同、Agent 分派、验证、独立审查、恢复和 Git 交付 |
| 执行 Agent | 一个小任务              | 实现或审查指定范围                                    |

“秘书”只指常驻秘书。旧文档中负责单次 Feature 的“秘书”统一称为 **Feature PM**。

## 汇报节奏

常驻秘书只发简短摘要，详细信息保留给状态页和未来的可视化界面：

- 收到方向：说明已完成、正在做、已排期，或已经加入队列。
- 小任务完成：报告任务标题及所属 Feature 或版本。
- Feature 完成：报告可体验结果，并自动继续队列。
- 版本完成：报告 Review 节点并暂停后续排期。
- 需要决定：说明具体产品冲突；技术故障由系统自动恢复，不上抛给制作人。

每个小任务事件都持久记录任务标题、父级、版本、完成时间和运行目录。守卫重启后按稳定任务键去重，不重复汇报。详细状态位于 `.daoyan-agent/secretary/state.json`，事件历史位于 `.daoyan-agent/secretary/events.jsonl`，具体运行证据位于事件中的 `runDirectory`。

## 休眠与唤醒

常驻秘书由外部 notice guard 承载，不让模型永久运行。它只在以下事件到达时被唤醒：

- 制作人提交消息；
- PM 写入任务、Feature 或版本进度；
- PM 子进程退出；
- 已登记的恢复时间到达；
- 通讯网关收到外部消息。

没有事件时进程阻塞休眠，不轮询项目，也不调用模型，因此空闲 token 消耗为 0。语义 Agent 只在新的人类消息需要查重或澄清时短暂运行；任务完成通知由结构化状态直接生成，不消耗模型 token。

## 自动边界

秘书和 Feature PM 自动决定拆分、模型、实现、测试、文档、提交、推送和普通 tag。只有以下情况会停下来询问制作人：

- 产品体验方向发生真实冲突；
- 不可逆地改变已采纳的核心架构；
- 大版本即将发布；
- 缺少必须由制作人提供的外部账号、凭据或素材。

版本到达 Review 节点后不会自动越过制作人。普通 Feature 完成后，若队列还有任务，秘书会继续推进。

## 当前部署范围

本机 notice guard、持久队列、任务节点事件、HTTP 收件口和 webhook 出站适配已经属于仓库能力。聊天软件机器人、公网网关、TLS、凭据和系统登录自启动属于部署配置，尚未绑定某一家平台。

架构边界见 [ADR-0012](./adr/0012-事件驱动常驻秘书与交付PM分层.md)，故障恢复和低频命令见 [`operations/feature-pm.md`](./operations/feature-pm.md)。
