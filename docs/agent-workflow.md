# 制作人与常驻秘书

项目只保留一种日常工作范式：**制作人只和常驻秘书对话，秘书负责其余工作。**

制作人提供产品方向、体验反馈和大版本发布决定，不判断任务复杂度，不拆任务，不选模型，不指定测试，也不管理 Git。秘书维护跨 Feature、跨版本的长期队列和项目现状，再按正式版本阶段调度主策、策划、Version PM、Feature PM 和测试 Agent。

## 日常使用

直接在当前 Codex 对话或已绑定的钉钉机器人中描述想法即可，例如：

> 我希望推演台能对比两次法术测试的资源曲线。

两种入口进入同一份秘书队列和版本状态，钉钉只是移动端通讯 View，不拥有独立排期。需要从本机终端投递或诊断时，使用下面的后备入口：

```bash
npm run secretary -- "我希望推演台能对比两次法术测试的资源曲线"
```

常驻守卫未运行时会自动启动。首次部署也可以显式启动：

```bash
npm run secretary:start
npm run secretary:open
```

`secretary:open` 打开本机项目中枢。制作人可以切换当前和历史正式版本，查看版本环节及全部关联文档，检查运行中、休眠、等待或暂停的 Agent 及其可审计上下文，直接处理自己的待办，并在同一页面与秘书交流。历史版本只读。

查看当前正在做什么、排期和最近完成节点：

```bash
npm run secretary:status
```

当秘书确实需要产品取舍时，直接像正常对话一样回答：

```bash
npm run secretary -- "采用方案 A，兼容已有存档"
```

询问进度、增加方向或要求继续也完全相同：

```bash
npm run secretary -- "现在法术系统做到哪一步了？"
npm run secretary -- "继续按当前排期推进"
```

“继续”不是礼貌性确认：秘书必须把它关联到当前运行或第一项已批准排期。处于延时恢复的任务会改为立即重试并启动 Feature PM；已经运行时会明确回复对应任务；没有可执行排期时会说明正在等待新方向，不得承诺并未发生的推进。

制作人不需要标记这句话是问题、回复、Feature 还是版本。秘书结合近期对话、当前等待事项、运行状态和项目文档自行判断；无法立即回答的开发方向进入队列，能回答的问题会直接回复。消息与答复会持久保存，守卫重启后仍能延续上下文。

制作人无需使用 `producer*` 命令。它们是 Version PM 和 Feature PM 的内部批次交付与故障恢复工具，见 [`operations/feature-pm.md`](./operations/feature-pm.md)。

## 角色定义

| 角色       | 生命周期          | 负责什么                                              |
| ---------- | ----------------- | ----------------------------------------------------- |
| 制作人     | 项目全程          | 定方向、评审立项、体验候选版本、决定大版本发布        |
| 常驻秘书   | 跨 Feature 和版本 | 唯一对话入口、总状态、调度、待办、问答和通知          |
| 主策       | 一个正式版本      | 版本策划、模块边界、策划审核和跨模块一致性            |
| 策划       | 一个模块或阶段    | 详细策划、规则边界、验收与任务拆分                    |
| Version PM | 一个正式版本      | 依赖、优先级、工作量、范围冻结、测试收束和候选构建    |
| Feature PM | 一项 Feature      | 任务合同、Agent 分派、验证、独立审查、恢复和 Git 交付 |
| 测试 Agent | 一个测试阶段      | 版本验证、主线回归、Bug 登记与复验                    |
| 执行 Agent | 一个小任务        | 实现或审查指定范围                                    |

“秘书”只指常驻秘书。旧文档中负责单次 Feature 的“秘书”统一称为 **Feature PM**。

## 汇报节奏

常驻秘书只发简短摘要，详细信息保留给项目中枢：

- 收到方向：说明已完成、正在做、已排期，或已经加入队列。
- 小任务完成：报告任务标题及所属 Feature 或版本。
- Feature 完成：报告可体验结果，并自动继续当前版本排期。
- 版本策划完成：通知制作人评审，收到自然语言回复后继续或退回主策。
- 候选版本完成：通知制作人体验；通过后归档，反馈则进入修复回环。
- 需要决定：说明具体产品冲突；普通技术故障由系统自动恢复，账号、额度或外部访问阻塞则暂停并通知。

每个小任务事件都持久记录任务标题、父级、版本、完成时间和运行目录。守卫重启后按稳定任务键去重，不重复汇报；近期制作人消息和秘书答复也保存在状态中供后续对话使用。详细状态位于 `.daoyan-agent/secretary/state.json`，事件历史位于 `.daoyan-agent/secretary/events.jsonl`，具体运行证据位于事件中的 `runDirectory`。

项目中枢中的 Agent 数量只统计真实存活的执行进程；notice guard 空闲时显示休眠而不是执行中。桌面工作台顶部保留基础状态栏，左侧统一选择正式版本、流程节点、Agent、开发任务和版本缺陷；中间是 VS Code 式单一阅读区，每次只显示所选条目的节点详情与文档、Agent 持续公开记录，或任务/缺陷详情；右侧保留制作人待办和常驻秘书对话。三栏可拖动调宽、折叠和恢复；左、右栏内部的工作区区域还可独立折叠、调高和拖动排序，偏好只保存在当前浏览器。窄屏则以流程、详情、控制台导航切换，不启用区域高度拖动。Agent 记录只展示任务输入、结构化计划所产生的公开阶段、动作、修改文件、测试、错误和截断输出，不展示模型私有推理，也不以模态框打断阅读。制作人待办可以一键采用秘书推荐方案，也可以选择备选方案并补充说明；额度类临时阻塞默认登记恢复时间自动重试。

Feature PM 的执行与修复 Agent 按风险等级分别有 12、25、40、60 分钟的时限，仍每 20 秒写入心跳、进程身份和存活状态；因此正常的长任务会持续可观察，而只在其所属等级超时后才会被恢复流程中断。规划、审查和交付验证使用独立时限，避免把它们误判为执行 Agent 超时。

## 休眠与唤醒

常驻秘书由外部 notice guard 承载，不让模型永久运行。它只在以下事件到达时被唤醒：

- 制作人提交消息；
- PM 写入任务、Feature 或版本进度；
- PM 子进程退出；
- 已登记的恢复时间到达；
- 通讯网关收到外部消息。

没有事件时进程阻塞休眠，不轮询项目，也不调用模型，因此空闲 token 消耗为 0。语义 Agent 只在新的人类消息需要查重或澄清时短暂运行；任务完成通知由结构化状态直接生成，不消耗模型 token。

## 自动边界

秘书和 Feature PM 自动决定拆分、模型、实现、测试、文档、提交、推送和普通 tag。只有以下情况会停下来询问制作人：

- 产品体验方向发生真实冲突；
- 不可逆地改变已采纳的核心架构；
- 大版本即将发布；
- 缺少必须由制作人提供的外部账号、凭据或素材。

正式版本内部各阶段和 Feature 完成后，秘书会继续已批准排期。版本归档后进入休眠，等待制作人给出下一版本方向，不再从 `docs/status.md` 自动制造正式版本。版本策划、被主策升级的模块策划、候选版本体验、账号额度、鉴权、产品冲突、不可逆决策或大版本发布会暂停并通知；制作人的下一句自然语言会被关联到相应恢复点。

## 正式版本与开发批次

正式版本依次经过方向、版本策划、制作人评审、详细策划、主策审核、任务拆分、版本排期、开发、版本测试、缺陷修复、候选构建、制作人体验和归档。机器状态位于 `.daoyan-agent/releases/`，长期档案位于 [`versions/`](./versions/README.md)。

原 `producer:version` 已改名为内部的 `producer:batch`。开发批次可以顺序交付多个 Feature，但不能自行立项、跳过策划评审、宣布版本通过或触发发布。

## 当前部署范围

本机 notice guard、持久队列、任务节点事件、HTTP 收件口、通用 webhook 与钉钉 Stream 通道已经属于仓库能力。钉钉绑定需要在部署机器提供企业内部应用凭据与制作人白名单，凭据不进入仓库。

钉钉首次绑定使用 `npm run secretary:dingtalk:setup` 在本机隐藏输入凭据；制作人无需把 Secret 发给 Codex 或秘书。向导完成后会自动重启守卫并显示连接状态。

原手机版 Sites 仅保留为可恢复的只读快照实验，当前暂停投入和发布维护；它不是秘书入口，也不是项目状态真相。独立移动看板可在通讯闭环稳定后，继续复用现有 HTTP 状态接口建设，不需要改动秘书内核。

事件驱动边界见 [ADR-0012](./adr/0012-事件驱动常驻秘书与交付PM分层.md)，正式版本定义见 [ADR-0013](./adr/0013-正式版本生命周期与可视化秘书.md)，故障恢复和低频命令见 [`operations/feature-pm.md`](./operations/feature-pm.md)。
