# 架构总览

```text
DSL 编辑器 ─┐
            ├→ Spell AST → 静态分析器
蓝图编辑器 ─┘           ├→ 编译器 → 字节码 → VM → World
                        └→ DSL 序列化

App 共享状态 → 推演台
             └→ 演武场 → BattleRuntime → Canvas / 音频 / 粒子
```

## 模块职责

- `src/core/`：类型、AST、元法术、分析、编译、VM 与世界；不依赖 UI。
- `src/game/`：默认法术、战斗运行时、表现资源与外部元法术加载。
- `src/app/`：React 工作区、编辑器、HUD、Canvas 渲染和用户交互。
- `test/`：核心逻辑、战斗逻辑和 jsdom 渲染测试。
- `e2e/`：真实浏览器中的产品工作流与错误捕获。

## 状态所有权

- 应用层拥有共享法术源码和演武配置；应用层的版本化存储边界负责本机恢复、导入、导出和迁移，核心与游戏层不访问浏览器存储或文件 API。
- 推演台负责产生有效法术源码；演武场只消费源码。
- DSL 与蓝图都经由 AST、分析器和编译器验证，不建立第二套执行语义。

## 当前世界模型

- 玩家与妖兽统一为 `Actor`；Actor 与 Projectile 共用同一、不复用的 `entity` 句柄空间。
- 统一句柄不等于统一属性全集。Actor 和 Projectile 保持不同结构，操作通过 Identity、Transform、Vitality、Caster、Movement、Projectile 与 Modifiers 能力判定。
- 旧的生命、伤害和目标属性元法术也通过统一句柄检查所需能力；能力缺失时按查询中性值或控制 `false` 确定性失败。
- Projectile 可由 DSL 创建为未激活对象，再由所有者配置、激活和探查；旧 `发射` 保留为兼容入口。
- 法术节奏由法力、tick、输入边沿和同槽施法占用约束，不再维护法术冷却或冷却倍率。
- 句柄、能力、属性和实际资源公式详见 [`../reference/entities-and-attributes.md`](../reference/entities-and-attributes.md)。

重要取舍见 [`../adr/`](../adr/)，不可破坏的规则见 [`invariants.md`](./invariants.md)。

## 项目编排边界

项目秘书与正式版本编排位于 `scripts/`，不进入上述游戏运行时。秘书拥有消息、候选、运行队列与通知，正式版本拥有范围、风险、阶段策略、审批和验收；Channel 与看板读取同一份事实。v1 信封内的可选编排扩展提供保守读时迁移：旧状态补完整执行策略而不补造批准、测试或交付，未来或损坏扩展会停止自动写入和派发。守卫在选择新任务前对账全部 active、tracking、retry-wait 及活动指针项；待审开发运行停止重试但不代表正式版本通过体验。公开活动使用独立白名单事件日志，未知 token 保持不可用，详见 [ADR-0016](../adr/0016-自适应版本编排与兼容迁移边界.md) 和[内核规格](../specs/2026-09-21-adaptive-project-office-kernel.md)。

读时规范化与待恢复写事务使用同一扩展校验：未来版本或损坏的嵌套记录会在触碰 current、历史和事务文件前拒绝。新代码兼容旧数据仍不等于允许旧代码写新状态；生产升级/回退必须核实全部写进程退出，并通过备份、预览及保留增量的降级工具演练。关闭派发不等于停写。

正式版本读取入口会先恢复待写事务，可能重写 current/历史；迁移预览必须先备份原始文件，再使用隔离副本。两文件事务不覆盖秘书收件与通知，跨状态一致性依赖请求重放，外部通知保持至少一次投递。具体中断位置与放行条件见内核规格，不能把读取兼容视为完整迁移工具已经交付。
