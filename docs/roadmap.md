# 产品路线图

- 最后更新：2026-09-13
- 当前阶段：0.2 可玩原型持续迭代

路线图表达方向，不替代 [`status.md`](./status.md) 的当前任务，也不替代 [`specs/`](./specs/) 的验收标准。

## 已完成的基础

- [x] 三资源模型、受限 DSL、AST、静态分析、编译器与 VM。
- [x] 玩家与妖兽同构、分帧施法、弹道、属性、生命周期与按键状态。
- [x] 元法术分类注册与 Electron 外部扩展入口。
- [x] 推演台 DSL 编辑、单次推演、元法术查看和蓝图双向转换基础。
- [x] 演武场属性、绑定、开始、暂停与页签往返同步。
- [x] Vitest、覆盖率、Playwright、构建、Git hooks 与 CI 门禁。

## 近期：让“编写到实战”稳定好用

- [x] 补齐法术编写、元法术、实体与属性的玩家参考文档。
- [ ] 决定元法术 vNext 分类、统一实体、动态计价和静态分析契约。
- [ ] 单步推演、变量观察和资源时间线。
- [ ] 蓝图撤销/重做、搜索、框选、复制粘贴和完整控制流。
- [ ] 法术书与演武配置持久化，包含导入、导出和版本迁移。
- [ ] 关键编辑与实战路径的稳定视觉回归。

## 中期：形成可重复游玩的成长循环

- [ ] 境界与资源上限成长。
- [ ] 秘籍、元法术和属性词条掉落。
- [ ] 敌人组合、场景目标和风险收益选择。
- [ ] 失败、复盘、调整法术和再次挑战的完整闭环。

## 后期探索

- [ ] 识海常驻变量与跨法术状态。
- [ ] 受 fuel 和神识约束的“轮回术”递归能力。
- [ ] 秘籍分享、社区挑战和可复现战斗种子。
- [ ] 当表现压力需要时评估 Canvas2D 到 PixiJS 的迁移。

新方向进入开发前先建立功能规格；改变核心语义或模块边界时增加 ADR。
