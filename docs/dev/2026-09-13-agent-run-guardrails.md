# Agent 运行护栏

## 问题

`2026-09-13T08-08-50-120Z-继续推进后续的开发任务` 把模糊续作原样交给 Terra。执行、审查与修复阶段长时间没有可见进度，最终在第二轮完整门禁失败后退出，用户感受为“卡死”。该次已知模型消耗为 314,576 tokens：执行 119,642、审查 108,504、修复 86,430。

## 根因

- 本地路由没有把“继续”解析为 `docs/status.md` 的具体下一项，执行者需要自行探索待办。
- 子进程只在结束时产生结构化结果，没有稳定心跳或运行状态文件。
- 模型阶段没有硬时间上限。
- 执行者、父进程和审查者可能重复运行完整门禁；审查提示还鼓励读取过宽的仓库上下文。

## 调整

- 模糊续作优先解析“当前首要任务”，其次读取“下一阶段候选”的第一项；具体方向保持原样。
- 长阶段每 20 秒输出心跳并更新运行目录的 `progress.json`。
- 在 `agents/policy.json` 配置分层执行、审查、修复超时，以及规划和完整门禁超时；超时停止明确的子进程树并返回 124。
- 执行 Agent 只运行聚焦测试与 `npm run verify`，父进程统一运行一次 `npm run verify:full`。
- 父进程生成 `review-input-*.patch`，包含基线差异和适量的未跟踪文本文件；超大差异与二进制只列清单，审查者不得重复运行门禁或扫描无关历史。

## 验证

- 路由测试覆盖具体方向不变、模糊续作选择首个状态候选以及新版策略校验。
- 使用 `npm run producer:plan -- "继续推进后续的开发任务"` 验证真实 `docs/status.md` 可以将模糊方向解析为元法术与实体模型 vNext 任务，并路由到 Sol high。
- `npm run producer:doctor` 通过，并生成状态为 `finished`、退出码为 0 的 `progress.json`。
- `npm run verify:full` 通过：46 个 Vitest、11 个 Playwright E2E、覆盖率、沙盒和生产构建全部成功。
- 独立 Terra low 审查因账户额度在前序异常运行中耗尽而未能返回结果；主秘书已审查完整差异并补上超大/二进制审查输入保护，待额度恢复后由后续调度运行继续验证独立审查路径。
