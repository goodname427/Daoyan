## 后台审批接续

问题、范围和原会话只读诊断见 [前一日记录](./2026-10-03.md#后台应用许可没有接收端)。本次由主 Agent 维护控制面，不代写游戏，不代工作流角色实玩或签字。此前在正式恢复流程外直接唤起原执行会话做只读诊断已停止；后续游戏工作只走原恢复点。

独立审查指出：前台手动展示成功不能证明正式后台收到许可；原日志重定向会吞掉请求，新建会话的拒绝路径遗漏会话保存，审核修复入口仍可能回落 never。现接入每 PM 私有管道，只有宿主及 guard 接收实际许可 URL，模型/检查进程移除管道秘密；guard 直接向已配置制作人通道投递短期许可，不写工作区 outbox、日志或状态。状态仅存无 URL 摘要，后台没有通道或投递失败即停止。曾考虑公开展示别名，独立审查发现 GET 可以还原许可凭据，已完整移除该方案。

拒绝与取消使用官方 turn/interrupt，错误路径保留审批阻断标记并保存首次持久会话；执行、同范围审核修复与后续恢复均禁止因此升级模型或自动重试。只允许 Electron 应用空表单，其他应用、敏感动作和跨会话请求不批准；完整游戏验收仍由原角色完成。正常 EOF 后给 App Server 两秒退出，必要时只清理本次创建的进程树。

验收包含后台 stdout 重定向集成、私有管道凭据隔离、没有接收通道、投递失败、旧请求/跨来源提交、拒绝/超时中断和合法 16 秒慢投递。完整门禁由正常提交/推送钩子执行；结果收据在本次控制面运行目录。真实 notice guard 与监督自动化没有为测试启动。
