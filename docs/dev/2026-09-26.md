## 制作人校准：先解释存在，再选切片

制作人认可统一执行和计费的方向，但明确指出法球固定寿命仍无法用同一世界规则解释，要求所有实体的存在、维持与消失都有共同因果；先前推荐的开发闭环暂不采纳。项目仍处原型验证期，旧内容兼容无需成为设计约束。主 Agent 使用正式生命周期 API 合并范围修订 4，旧范围修订 3 的任务合同自动失效；守卫保持暂停，旧 `tracking/missing` 运行证据保留，不触发旧合同续跑。

代码核查：`创建弹道` 接受“存活秒数”并按秒数收费，`Battle.updateProjectiles` 每帧递减 `life`，到零调用 `removeProjectile`。这只规定何时移除，没有给出结构失稳、维持停止或其他可推广的存在理由；多付法力买秒数也不能单独构成世界内解释。策划草案改为先比较结构、稳定性和维持来源的候选机制，用稳定造物、长期供能法球、无供能法球及失去维持能力的修士检验同一规则。现在不选开发切片、不排预设或敌方技能实现，也不为旧法术和存档预设迁移方案。

结构化意图记录通过 `parseProductIntentAlignment` 校验；`npm run docs:check` 与 `git diff --check` 通过。更新后的 `npm run verify:full` 退出 0：标准与覆盖率测试各 493 条、浏览器 E2E 25 条及沙盒、生产构建通过。这些验证不表示候选存在模型已获制作人确认或已实现。

为使草案给出可审阅的推荐，而非只列问题，补明候选解释：“结构完整度 + 构成材料稳定性 + 有来源的维持”。若灵力结构按统一环境规律散逸，法球寿命由初始结构与散逸/补给推导；稳定物质造物则可长期存在。修士也按结构规则受损与修复。施法余额与结构完整度分开，耗尽施法资源不自动使实体消失。此机制仍待主策证明和制作人评审，未固定材料、散逸率或数值。

## 制作人再校准：从世界根基推导属性与生命

制作人指出此前存在模型仍未解释血量与死亡、法力吸收差异、施法速度、非生命实体施法的根本。他只认定元法术、法力和耗时的核心地位，建议把法力恢复也纳入元法术候选；要求先真正说通世界，再开发。使用正式生命周期 API 把方向并入未冻结草案，形成范围修订 5，旧任务合同继续失效，守卫保持暂停。

代码核查确认当前 `World.tick` 对 Actor 按 `manaRegen * dt` 无源加法力，`damage` 仅对 vitality Actor 扣 HP 并在零值设 `alive=false`，`Battle.updateProjectiles` 对 Projectile 的 `life` 独立倒计时及命中移除，`Battle` 的施法吞吐只读取 Actor 的 `castSpeed`，`hitProjectile` 在碰撞分支直接释放 damage 池。这些是现状与问题证据，不代表新模型已实现。

新增[世界底层规则候选](../versions/pilot-agent-intent-2026-09-24/world-foundations-draft.md)：明确三项既定核心不足以独自推出存在和生命；补充有来源状态、统一结构、自然演化与主动元法术、结构承载执行四项待评审公理，逐项推导制作人所问现象，审计十项属性，并保留反例与三项世界观取舍。默认法球不能回蓝暂解释为没有收集结构和来源，而非非生命实体被禁止；这仍待制作人认可。本轮仅完善策划模型，不进入游戏开发、预设或敌方技能排期，也不写覆盖旧 ADR 的正式新 ADR。

## 制作人确认守恒与自然规律，并提出桥接层边界

制作人确认生命与实体存在分离，但要求生命定义足够准确；法力只能从一处转到另一处，恢复不是产生新法力；没有法术时世界继续按默认规律演化，法术是实体向世界或其他实体付法力以改变状态。同时指出左键仅是现实玩家传达施法意图的桥接，要求主动审计其他类似逻辑。当前草案通过正式生命周期 API 记录为范围修订 7；已有范围修订 6 先行记录桥接层方向，保留其审计，不覆盖或重写。notice guard 仍暂停，未进入开发。

新增[生命及世界边界草案](../versions/pilot-agent-intent-2026-09-24/life-and-world-boundary-draft.md)。生命候选定义为有边界、外部补给和内部调节修复的持续自维持过程；它不同于存在、血量、施法和意识，人工生命、魂魄和复苏仍待论证。法力账本改为每笔转移同时记来源和去向，所谓损耗转入世界或其他明确账户。设备输入、屏幕坐标、墙钟和表现属于桥接/展示；世界只接受抽象意图并按同一会话、授权、时间和资源规则结算。

现状核查：`CombatView` 将鼠标/数字键及屏幕坐标传给 `Battle`；`src/core/input.ts` 和 `src/core/metas/input.ts` 把“按键按住/按下/松开/蓄力”暴露为法术可读的核心接口，妖兽无按键时读取默认 false/0；`Battle` 混合物理槽位队列、AI 计时和施法会话；浏览器帧时间、暂停、重开、HUD、推演台和属性配置也都需要明确桥接边界。这里只登记结构问题与候选接口，不在规则评审前改代码。

## 熵方向作为世界规律候选

制作人认可人工造物若具有完整自维持组织也可算生命，进一步提出世界沿不可逆方向演化、法球凝结与生命维持须付法力、失去维持的法球逐渐消散。该方向以正式生命周期 API 合并为未冻结草案范围修订 8，明确保留探索性质；notice guard 仍暂停，未启动游戏开发。

新增[熵方向候选](../versions/pilot-agent-intent-2026-09-24/entropy-direction-draft.md)：把不可逆默认演化作为方向和闭环禁套利约束，结构稳定性决定是否持续需要法力；法术向世界或目标转移法力以有意改变局部状态，付出的法力总量仍在，但空间分布和可用性可能下降。法球创建拆成结构来源、组织成本和可用施法储池；生命是自主付费维持关键组织的过程，欠费后先失稳，达到阈值才死亡。稳定石块和稳定材质造物可不付持续维持费，局部自然结晶不违反整体熵方向；熵本身不足以直接决定寿命、价格或伤害，尚须材料和效果规则。

同步修正旧草案中“生理代谢自然发生、修士零法力可靠食物和呼吸免费维持”的表述：若采纳制作人的新方向，维持关键生命组织必须有法力转移与来源；零可用余额不必立刻死亡，但不能无限免费维持。代码核查发现 `World.tickActor` 无来源 `manaRegen × dt`，普通运动的 `movePower` 亦按模拟时间自动补回，法球仍按固定 `life` 移除；这些都是后续模型和 ADR 需要覆盖的原型事实，本轮不逐点改游戏逻辑。
