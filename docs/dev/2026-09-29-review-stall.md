# 2026-09-29 开发审查停滞诊断

- 问题：正式开发 `dev-world-a` 的 World/VM 接入缺口连续四轮独立审查仍未关闭，伴随问题与代码行号逐轮变化，原先以整组路径精确匹配的停滞判断持续重置，自动修复已进入第五轮。
- 范围：审查停滞以最高等级主要 finding 的首个实现路径为稳定范围，忽略行号与伴随 finding；同一主要文件连续三轮仍有同等级阻断时停止自动复审。恢复时优先从本运行的审查 JSON 重建连续轮数，避免旧快照中重置的计数继续放行。
- 非目标：替 Feature PM 实现世界规则、把独立夹具算作现有 VM 实测、自动改写正式版本状态或批准新产品公理。
- 验收：更换标题、行号和其他 finding 后仍累计同一主要文件的高等级阻断；不同文件不误累计；定向测试、类型和最终控制面门禁通过。已运行的正式任务需先保全草稿和恢复点，再于安全节点同步修复并核查其真实阻断，不盲目续跑。
- 集成复核：原 PM 退出后，主 Agent 用带名称的 Git stash 保全七条开发草稿，在干净树把主干控制面合入正式分支，再恢复相同草稿；实际树的控制面定向测试、类型检查与 `git diff --check` 均通过。恢复前发现“无关控制面提交”路径仍会清除历史停滞计数，因此进一步让审查历史优先于旧快照计数，并在重新调用审查模型前拦截已达阈值的运行。
