## 同一模块文档续接执行会话

- 问题：此前 `agent-dispatcher` 对每次执行均使用 `codex exec --ephemeral`；恢复点只复用完成任务和有限前驱摘要，主策打回同一文档后新任务仍从空会话开始，重复读取权威文档。此前文档中“上下文复用”不等于真正的模型会话续接。
- 范围：只对正式详细策划中恰有一份模块 Markdown 交付的执行与审查修复任务持久化会话 ID。Version PM 在新任务合同中决定 `continue` 或 `fresh` 并说明理由；秘书核对同一范围修订、同一文档、同一模型与推理配置以及会话可恢复性，满足条件时通过显式 ID `codex exec resume` 续接。`fresh` 隔离上一任务，但本任务内部步骤和修复可继续新会话。旧任务无该字段时自动判断。轮次与已知用量用于诊断，不再设固定续接次数。新合同和当前权威优先；会话丢失时新开上下文。索引只在本机运行目录外保存，不随 Git 交付，不与其他模块共享。旧的 ephemeral 会话无法追溯，首次接入后才有可续接记录。
- 验收：纯函数与本地持久化测试覆盖精确文档键、范围变化、跨模型、Version PM 新开决定、无固定轮次上限及 CLI 参数；定向 dispatcher 恢复测试确认原文件级恢复仍有效。最终集成后验证真实 CLI 的会话 ID、续接与失败回退，并比较接受任务的用量和返工，避免只看单次调用成本。
