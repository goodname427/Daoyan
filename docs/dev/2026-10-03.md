# 2026-10-03 工作流修复

## 问题与范围

开发门禁交接的临时 Version PM 任务在原指令中限定三份文档，但它早于标准正式任务合同，审查修复器只对标准任务注入写入边界。独立审查指出另一角色的策划验收报告后，修复 Agent 修改了合同外两份报告文件。主 Agent 中断该轮；共享树的五份草稿与原恢复点保留，秘书守卫暂停。

本次仅修复控制面：识别该旧交接任务的三份归属文件，在修复提示和提交前执行同一边界；审查要求修改其他角色文件时，直接停止该修复并交由原归属角色。产品规则、游戏代码与正式运行状态不在范围内。

## 验收标准

- 旧交接任务只能写 `development.json`、`development.md` 和 `roadmap-handoff.md`。
- 跨归属审查 finding 不再启动此任务的修复 Agent。
- 原五份草稿不被本次控制面交付提交或清理；正式分支待安全节点同步主干并复核实际树。

## 集成门禁时序修正

正式树首次完整门禁的 611 项单测中，秘书看板两项收件测试在 Windows 并行负载下超过原 20 秒等待上限；单独重跑该文件的 20 项全部通过，失败项分别约 2.6 秒和 5.7 秒。只延长异步收件诊断等待及两项外层测试时限，不改变正式秘书运行逻辑或验收结论。定向重跑与格式检查通过；合入后仍需在正式树重跑完整门禁。

## 当前 CLI 模型可用性

2026-10-03 对本机 Codex CLI 做仅回复文本的连接检查：`gpt-6-luna` 返回 HTTP 400，明确说明 ChatGPT 账号不支持该模型；先前同环境的 `gpt-6.1-sol` 也返回相同拒绝。`gpt-5.6-luna` 与原归属 Agent 使用的 `gpt-5.6-sol` 可正常完成请求。为避免秘书与执行 Agent 在恢复后空转，暂时将策划、执行、审查和秘书分流指向已验证可用的 5.6 系列，保留原任务的模型使用历史；待 CLI 实际支持新模型后再审计切回。此变动会改变验证配置指纹，正式树必须重新取得匹配收据，不复用旧指纹的门禁结论。

## CLI 工作流 Agent 的真实操作入口

问题：独立策划 Agent 的 Edge 扩展持续在读取浏览器请求头策略时失败，而 Codex 桌面内置 Browser 不提供给 CLI，反复请求浏览器权限不能让该 CLI 会话获得玩家页面。制作人要求由原工作流 Agent 本人完成验收，不由主 Agent 或新派 Agent 代签。

范围：仅为需要实玩的正式任务提示补充正常的 Electron 原生窗口操控路径；保持原角色、任务边界、独立签字和阻断规则。非目标：修改游戏、绕过浏览器安全拒绝、用 E2E 代替实玩或清除既有 blocked 历史。

诊断：重启后本机 Vite 在 `localhost:5173` 正常监听，Electron 显示「道衍 · 推演台」。原 `da-a-flow` CLI 会话通过已安装 computer-use Skill 的 `node_repl`/`@oai/sky`，只读获取了该 Electron 窗口状态，未输入或修改文件；随后同一会话开始按 UI 实际操作。由此证实本机不必为该任务安装 Chrome。工作流提示现在优先说明原生窗口路径，并要求无法操作时如实保留阻断、避免相同失败循环。定向测试 85 项通过，独立主干工作树的完整门禁退出 0：585 项单测、25 项浏览器测试与生产构建；正式分支同步及实际树复核仍待安全节点。
