# 2026-09-21 自适应项目中枢纵向切片

## 问题与范围

上一版工作台只能调整三栏宽度，左、右栏内部的流程、Agent、交付信息和对话会争夺固定空间；运行时长也只会随三秒一次的服务端刷新改变。本次完成已批准 `adaptive-project-office-2026-09-21` 的首个可体验切片：同栏区域可折叠、调整高度、排序并持久化，选中运行中 Agent 的时长每秒本地更新。

不改动秘书调度、正式版本状态机、公开活动过滤规则或游戏玩法；布局偏好只保存在当前浏览器，不写入正式版本档案。

## 实现与验证

- `secretary-dashboard` 以区域 ID 保存顺序、折叠状态和高度；标题可拖动排序，键盘和指针都可调整区域高度，窄屏继续使用既有三栏导航而不启用高度拖动。
- 运行时长优先使用 Agent 稳定的 `startedAt` 在浏览器内每秒更新，并以看板 API 的 `elapsedSeconds` 和快照时间校准；后台三秒刷新或新事件到来不会让计时回跳。
- Playwright 覆盖运行中 Agent 的本地秒级计时、Agent 区域折叠后的刷新持久化、稳定的“折叠 / 展开 Agent”可访问名称，以及键盘高度调整；既有守卫辅助测试覆盖测试结束时等待隔离服务真实退出，避免清理临时目录与后续用例竞争。

## 交付门禁修复

- 完整门禁中的“未激活弹道”回归用例曾把更新后的敌人坐标作为静止弹道的基准。战斗帧末的实体分离可合法移动重叠敌人，造成与弹道生命周期无关的失败；用例现固定比较创建时的弹道横纵坐标，同时继续验证未碰撞、寿命递减、过期移除及名额归还。
- 独立审查发现布局恢复会按标题重建区域按钮的可访问名称，遗漏中文动词与英文 `Agent` 之间的空格，导致持续运行的 E2E 无法再次定位 `折叠 Agent`。区域现在拥有稳定的显示名数据；恢复布局后的名称与初始渲染一致。
- 同一条 E2E 在折叠后展开 Agent 区域并按键盘“调高”时，曾把折叠态的紧凑标题高度写回布局偏好；弹性收缩随后可能令 `ArrowDown` 的结果反而低于操作前。现在会在折叠前保留已展开高度、展开时不采样紧凑态，并让用户明确调整过的区域占用其保存的高度，因此键盘增高可观察且刷新后稳定。
- 同栏拖动以目标区域为稳定落点：向下拖动放在目标之后，向上拖动放在目标之前；预览阶段不再反复改写 DOM 顺序，只在松手时移动一次，避免连续 `dragover` 令区域来回抖动。
- 长期操作说明已同步：`agent-workflow.md` 明确栏内区域的本地折叠、调高、排序与窄屏边界，避免把浏览器布局偏好误解为正式版本状态。

## 修复验证

- 独立审查发现两个或更多区域被调高后，固定高度与其余区域最小高度会超过左、右栏可用高度；此前栏容器隐藏溢出，导致底部任务、缺陷或秘书对话无法抵达。栏现在在横向保持裁切、纵向提供滚动，因此保留用户明确调整的区域高度，同时让后续区域可访问。E2E 将两个左栏区域连续调高到发生溢出，并验证滚动到底部后版本缺陷区域完整可见。
- 第二轮独立审查发现运行时长以状态更新时间补秒时，后台刷新会反复重置基线，新事件还可能让显示倒退。前端现在以 `startedAt` 计算稳定下界、以服务端快照校准；常驻秘书 API 也返回真实运行秒数和当前快照时间。E2E 会跨过一次三秒刷新并验证计时单调递增。

- 已通过 `npm run typecheck`、`npm run lint`、`npm run format:check`、`npm run docs:check` 与 `git diff --check`。
- 已两次尝试 `npm run test:e2e -- e2e/secretary-dashboard.spec.ts`；当前受限环境在 Playwright 启动前拒绝创建子进程（`spawn EPERM`），因此目标 E2E 仍需在允许 worker 子进程的本机或 CI 门禁复验。
