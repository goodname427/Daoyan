# 秘书强制接管模式

- 日期：2026-09-14
- 状态：已实现，待完整门禁

## 背景

执行 Agent 可能在已经修改工作区后因为超时、进程启动失败或审查通道异常退出。仅依赖指纹一致的普通续跑会拒绝现场，自动识别也无法覆盖所有遗留场景，导致制作人必须重新把问题转交给主 Agent。

## 本次调整

- `npm run producer -- --takeover "方向"`：新建运行并接管当前脏工作区。
- `npm run producer:resume -- --takeover ".daoyan-agent/runs/<运行目录>"`：对指纹变化的旧运行强制接管。
- 接管时写入 `takeover.json`，保存原因、基线提交、工作区指纹、改动摘要和未跟踪文件清单。
- 强制接管会清空旧任务的完成记录与旧审查结果，重新执行任务合同，避免把部分改动误判成已完成。
- 执行 Agent 会收到保留现场、识别相关改动并审查后继续的明确提示；验证、独立审查、修复和 Git 交付仍由秘书负责。

## 边界

强制模式不是跳过保护：它只把“是否接管不一致现场”的决定从人工清理转为制作人显式授权，之后仍必须通过 `verify:full`、独立审查和 Git 交付。普通续跑依然在没有 `--takeover` 时拒绝一般性的指纹不一致。
