# Agent 故障恢复与秘书接管

## 问题

`2026-09-13T12-16-42-135Z` 运行已完成实现和 `npm run verify:full`，但独立审查的 `gpt-5.6-sol` 在重连后报告 `Selected model is at capacity`。调度器将这个临时服务故障直接冒泡给制作人，也没有生成最终报告或可机读恢复点。

## 调整

- 新增故障分类：容量、超时、重连、网络和限流属于临时故障；额度、登录和鉴权属于外部阻塞；其余属于执行失败。
- 执行者的临时故障先在原模型重试，再由更高层级模型接管当前工作区。
- 独立审查和审查修复使用策略化备用链。高级审查默认从 Sol 回退到 Terra，仍失败才使用 Astra。
- `--deep-plan` 调用失败时回退到本地零 token 路由，不因可选的第二意见中断交付。
- 从基线建立后持续写入 `recovery.json`。恢复点保存由 `HEAD`、已跟踪差异和未跟踪文件内容组成的 SHA-256 指纹；只有当前工作区匹配时才跳过已通过任务，避免在实现被重置或混入外部改动后误提交。
- 续跑会重新完成固定门禁和审查，并能继续推送已经创建的提交。
- 最终中断会写入 `report.json` 和 `report.md`，状态为“可恢复中止”，并给出不需重述需求的续跑命令。

## 验证结果

- 路由单测由 11 项增加到 13 项，覆盖审查备用链去重、临时故障、外部阻塞和普通执行失败。
- `npm run producer:doctor` 在 Windows 上识别 `codex-cli 0.154.0-alpha.6.2` 与 npm 11.16.0。
- `npm run producer:plan -- "修复秘书临时故障恢复"` 以零 token 生成 Terra 产品纵向切片计划。
- 伪造指纹不匹配的 `recovery.json` 后运行 `producer:resume`，调度器在调用模型或 Git 交付前拒绝续跑。
- 首轮 Terra 独立审查发现恢复点未绑定工作区；修复后的聚焦复审结论为 `PASS`，无交付阻断问题。
- `npm run verify:full` 通过：64 个 Vitest 测试、12 个 Playwright E2E、覆盖率、沙盒和生产构建全部成功。
