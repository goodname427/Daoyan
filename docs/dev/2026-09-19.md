## 演武属性越界存档拒绝

- 问题：持久化边界此前只验证属性是否为有限数字，导入 `manaCostMul: -1` 或 `castSpeed: 0` 等越界数据后仍会传入 Battle，可能使法力消耗变成负值或令施法无法正常推进。
- 修复：演武场控件与持久化层现共享同一份属性范围契约。存档可省略历史版本中尚未存在的属性以使用默认值；但已给出的属性对象若不是记录，或其中已给出的属性不是有限数字或不在范围内，则整份存档安全拒绝，不替换当前状态。
- 覆盖：新增持久化单元用例，拒绝负法力消耗倍率、非正施法速度及超出上限的生命值；范围契约不再在 UI 和导入边界各自复制。

## 未来版本本地存档保护与交付状态校正

- 问题：启动时若本地存档来自未来版本，读取边界会安全拒绝它，但 `App` 随后以默认状态挂载，首次自动保存会把该默认 v1 数据写回同一键，破坏本应保留的原存档。

## 交付门禁回归修复

- 问题：持久化 E2E 曾把注释当作法术书的保存内容，但编辑器保存的是解析后的 AST 再序列化，注释不属于该持久化契约；蓝图框选用例的起点在布局变化时可能不再落在 React Flow 画布上，导致仅保留搜索定位留下的单个选中节点。
- 修复：持久化用例改为修改并断言会经过 AST 序列化保留的 `@cooldown` 语义；框选用例在拖拽期间按住 Shift，使 React Flow 即使将起点命中判为非画布元素也进入多选路径。
- 范围：只修正既有持久化和蓝图交付门禁的测试契约；不改变存档 schema、DSL 注释策略、蓝图交互语义或后续版本候选。

## 持久化导入绑定显示修复

- 问题：导入的法术书可能不包含槽位此前绑定的法术。状态仍会正确恢复，但原生选择框没有匹配选项，会把该槽位显示为空值，导致持久化 E2E 门禁失败且玩家无法辨认待修正配置。
- 修复：演武场为不在当前法术书内的已绑定法术保留一个明确标示“当前法术书中不存在”的选项。绑定值因此可见、可导出且可由玩家重新选择；战斗层原有的不存在法术不可施放保护保持不变。
- 覆盖：渲染测试构造只含“基础剑气”的导入法术书和“疾风步”槽位绑定，断言演武场仍保留该选择值；既有 Playwright 流程覆盖界面导入后的同一行为。
- 验证：`npm run typecheck`、`npm run lint` 与 `npm run format:check` 通过。早期受限环境的聚焦 Vitest 与目标 Playwright 在子进程启动前受 `spawn EPERM` 影响。

## 存档规范化复核

- 复核发现：原有存储边界验证了 DSL 能解析，却仍会把原始编辑文本直接写入自动存档和导出文件；这会使注释等不属于 AST 的草稿内容进入可交换存档，和格式契约不一致。
- 修复：存储边界现统一将通过解析的法术书回序列化为规范 DSL；自动保存、导出和导入后的后续写入共享该结果。浏览器拒绝写入本地存储时单独提示，避免误报为 DSL 错误。
- 覆盖：新增单元断言，确认含临时注释的有效编辑文本保存后仅保留规范 DSL。`npm run typecheck`、`npm run lint`、`npm run format:check` 通过；早期受限环境的聚焦 Vitest 在 Vite 配置加载前受 `spawn EPERM` 影响，后续成功的完整交付门禁已覆盖该限制。
