# 2026-09-20 项目中枢工作台

## 问题、范围与验收

运行中 Agent 仍以模态框显示旧式详情，无法像阅读工作流一样持续跟进公开进度；三栏固定宽度也不适合不同桌面。中央还会同时堆叠节点文档、任务、缺陷和 Agent 区域，阅读焦点不明确。此次只改项目中枢和 Feature PM 时限策略，不改秘书调度、游戏核心或正式版本流程。验收为：左侧可统一选择版本节点、Agent、开发任务和版本缺陷，中央每次只阅读所选条目的内容；桌面三栏可调宽、折叠和恢复；窄屏仍可在流程、详情和控制台之间操作。

## 实现

- 看板接口将恢复点、结构化任务和受限日志摘要转换为最多 24 条公开活动；调度器在每项任务前后对工作区文件指纹做差分并记录真实改动文件，并从 Agent 的公开交付摘要抽取其实际报告的验证命令。路径脱敏、私有推理来源整条拒绝、单条截断后才进入前端。静态快照清空活动流。
- 移除 Agent 模态框，左侧统一选择器驱动中间的单一阅读区：节点显示详情和文档、Agent 显示持续公开活动流、开发任务和版本缺陷显示各自详情；顶部状态栏和右侧秘书会话/待办保持各自职责，未选中的中央区域不占空间。
- 增加鼠标/触控拖动和键盘可达的分隔条，三栏均可折叠和恢复；窄屏关闭这些桌面控件，继续使用既有分区导航，点击 Agent 会直接进入其公开记录阅读区。
- 私有推理标记会拒绝整条来源文本，而不是只移除标记，以免思维内容残留在 API 或界面；拖拽以起始面板宽度和三栏最小宽度计算，避免连续 pointermove 累积偏移。
- 执行与修复 Agent 依风险等级从旧的分钟级短时限调整为 12/25/40/60 分钟；20 秒心跳、进程身份和存活检测不变，使长任务持续可观察且只在对应等级真正超时时才触发恢复。

## 验证

- 定向 dashboard 单测覆盖公开活动契约、私有推理拒绝与快照活动清空。
- Playwright 覆盖单一中央阅读区的节点、Agent、任务和缺陷选择、无模态框、调整左栏、折叠恢复以及窄屏流程入口。
- 调度策略测试断言 20 秒心跳及 12/25/40/60 分钟执行/修复时限。
- 策略校验同时拒绝非正整数的阶段时限；测试覆盖规划、审查、验证的独立时限以及无效执行时限。

## 审查修复

- `.document-workspace` 的 `display: grid` 会覆盖浏览器对 `hidden` 的默认样式，导致切换到任务或缺陷后其仍与详情叠放。现以工作台全局 `[hidden] { display: none !important; }` 明确收起非活动中心视图，并让 Agent 阅读区在初始 HTML 中也保持隐藏，直至左侧选择它。
- 看板服务测试的恢复点夹具包含私有阶段，但其最新 `progress.json` 明确记录了公开的“深度规划”。活动流按当前进度优先，继续显示该公开阶段；断言改为验证这一优先级，同时仍验证恢复点和任务中的私有文本不会泄露。
- 本环境中 Vitest 在加载 Vite 配置时被系统拒绝创建 esbuild 服务（`spawn EPERM`），因此定向 `npm test -- secretary-dashboard test/agent-routing` 与完整 `npm run verify` 的最终测试阶段均未能执行；后者此前的 typecheck、lint、format、文档子门禁均已通过，`git diff --check` 亦通过。
- 本轮独立代码审查复核了三种折叠状态的 grid 轨道、`hidden` 覆盖规则、窄屏滚动定位、活动流来源与路径/私有推理过滤；未发现新的功能性问题。桌面自动化同样受当前环境禁止创建 Playwright worker 影响，留待秘书的完整门禁环境复验。
- 秘书看板的制作人体验门禁测试不再以固定等待或看板字段短轮询猜测新方向是否已处理。测试先取得 `/api/intake` 返回的请求 ID，等待 guard 在状态持久化后原子写出的对应答复，再断言候选方向进入 backlog 且正式版本仍停在制作人体验门禁；这在慢速或覆盖率环境下仍以真实处理完成事件为准。
