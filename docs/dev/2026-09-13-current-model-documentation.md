# 当前玩法与 vNext 讨论文档

## 背景

玩家反馈目前不知道如何编写新法术，也不清楚可用元法术；同时认为基础能力不足，难以组合更深的效果。在改变核心规则前，先从代码建立准确、可维护的现状文档。

## 实现

- 新增法术编写指南，覆盖 DSL、类型、列表、生命周期、范例、资源与失败排查。
- 新增由元法术注册代码自动生成的完整参考表，并让 `docs:check` 检查是否过期。
- 新增当前 Actor、Projectile、属性、修正与资源公式说明。
- 将五类元法术、统一实体、动态价格、强度输入与移除冷却记录为讨论稿。
- 同步 README、文档入口、状态、路线图、术语、架构总览和项目长期记忆。

## 重要结论

- 当前 Projectile 不是 DSL 可见实体，元法术价格也不随距离、目标神识或强度变化。
- 动态价格会与“静态上界可信”产生直接冲突，实施前必须确定预算与场景上界契约。
- 可选属性建议通过能力组件表达，而不是让统一实体拥有大量散落的 `undefined` 字段。
- `结束施法` 不属于按键状态；“法力消耗影响时间”与当前施法速度职责冲突，需要确认是否为表述笔误。

## 验证

- `npm run docs:check`
- `npm run verify`
