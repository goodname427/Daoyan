## 踩坑记录

1. **for 循环的栈残留**：用 `PEEK` 复制栈上元素计算 `i < len` 时，
   `len` 会残留在栈上，导致后续 `PEEK` 取到错误位置。
   解决：加 `SWAP` 指令，比较后交换并弹出残留值。
2. **循环退出跳转未回填**：`JMPIFNOT` 默认跳到 0 号指令，表现为函数反复重入。
3. **静态分析与 VM 必须逐项对齐**：漏算 `CALLUSER` 的 1 tick、循环的 3 tick 开销，
   会导致「静态上界 < 实测」。已加单测守卫。
4. **分析器漏算 return 表达式**。
5. **Electron 打包卡在 winCodeSign**：解压需创建符号链接，普通权限 Windows 会失败。
   解决：`build.win.signAndEditExecutable = false`。
6. **测试里给妖兽设 `behavior = null` 不等于定身** —— 会落进 shooter 分支继续走位，
   导致飞剑被躲开。要定身必须 `speed = 0`。
   （这件事本身也验证了「躲位」机制确实生效）

## 阶段四：产品化包装（完成）

用户要求把原型包装成「更像游戏」，分三个模块执行。全部按方案落地。

### 模块 1：推演台完善

- **1.1 元法术文件拆分**：`src/core/metas/*.ts`，`import.meta.glob` 自动收录（纯 Node 兜底）；
  外部扩展走 Electron 主进程扫描 `metas/*.js` + 渲染进程动态 import（`docs/扩展元法术.md`）；
  `applyMetaOverrides()` 支持定价覆写。`defMeta` 幂等 + 注册表挂 `globalThis`，修掉 HMR 报错
- **1.2 法术生命周期**：`SpellMeta`（instant / duration / channel）+ DSL `@kind=` `@period=` `@duration=` `@cooldown=` 注解；
  `CastInstance` 状态机：持续类按周期重复执行、引导类大幅减速、冷却、可打断
- **1.3 蓝图节点图**：`NodeGraph.tsx`（React Flow）—— AST→图只读渲染，端口按类型着色、连线即数据流；
  反向编辑（拖节点/连线产出 AST）是下一迭代

### 模块 2：战斗优化

- `Actor` 接入 `AttributeSet`（hp/mana/shenshi/speed/castSpeed/power/manaCostMul/cooldownMul/perception/armor）
- `Modifier` 系统（加法/乘法、可限时，先加后乘）；属性同时影响**效果**与**消耗**
- 属性类元法术：护体/疾行/明心/增威/节流/聚气/洞察/迟滞/虚弱/蔽识/破防
- VM 计费乘 `manaCostMul`；神识上限读 `attr.shenshiMax`；伤害乘 `attr.power`；感知半径乘 `attr.perception`；
  施法 tick 预算乘 `attr.castSpeed`；冷却乘 `attr.cooldownMul`

### 模块 3：游戏表现

- **3.1 精灵图**：`src/game/sprites.ts` 程序化生成 spritesheet（离屏 Canvas 绘制），无外部美术依赖；
  动画状态机 idle/run/cast/hurt/death；`Animator` 由战斗事件驱动状态
- **3.2 音频**：`src/game/audio.ts` WebAudio 程序化合成音效（cast/shoot/hit/hurt/death/backfire/wave）；
  首次交互解锁自动播放
- **粒子**：`src/game/fx.ts` 命中/死亡/反噬的打击感来源
- 核心层只产 `FxEvent`（发生了什么、在哪），表现层在 `Renderer` 消费 —— 核心不反向依赖渲染
