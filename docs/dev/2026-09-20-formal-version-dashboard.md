# 2026-09-20 正式版本与可视化秘书

## 背景

制作人重新定义了完整版本流程，并要求常驻秘书继续作为唯一入口，同时提供可视化状态、节点证据、制作人待办和直接对话。旧 `producer:version` 实际只是多个 Feature 的开发批次，不能继续代表正式版本。

## 实现

- 新增正式版本持久状态与管理工具，覆盖 13 个固定阶段、审批、待办、任务、缺陷、范围冻结、健康度和进度。
- 将旧版本调度命令降级并改名为 `producer:batch*`，仅作为已批准开发阶段的内部能力。
- notice guard 新增本机项目中枢和 API；浏览器只读取结构化状态，不触发模型轮询。
- 新方向统一进入候选池；制作人门禁期间只有明确通过或明确修改意见才改变版本状态。
- 节点文档只允许读取 `docs/versions/`，并使用真实路径校验阻止符号链接或 Windows 联接逃逸。
- 看板提供版本流程、节点详情、证据、制作人待办、任务、缺陷和秘书对话，桌面与窄屏均完成体验检查。

## 审查修正

独立审查发现并推动修复了六类问题：审批角色与历史记录隔离、制作人待办自动生成、中性回复误判、新方向绕过正式版本、文档链接逃逸，以及对应测试缺口。最终定向复审通过。

## 验证

- `npm run verify:full`
- 101 个 Vitest 测试通过。
- 18 条既有游戏 Playwright E2E 通过。
- 新增可视化秘书 Playwright E2E 通过。
- 生产构建和无头资源沙盒通过。

## 后续

当前纵向切片建立了可信的状态机、档案和交互面。下一步是让专业 Agent 根据阶段事件自动产出策划、任务、测试与报告，并将恢复、额度和外部访问阻塞统一映射到版本节点。
