# 2026-09-14 版本级调度

## 背景

制作人希望从“每次派发一个 feature”提升为“持续迭代一个版本后再介入 Review”。现有 feature 级调度和门禁已经稳定，因此新增外层编排，不改变子运行的交付语义。

## 实现

- `scripts/version-dispatcher.ts` 冻结 `status.md` 候选，顺序调用 feature 级调度器。
- `version.json` 持久化每轮状态、子运行目录、尝试次数和提交。
- feature 失败后先普通恢复，第二次使用 `--takeover`；已交付 feature 在版本续跑时直接跳过。
- 最后再运行一次完整门禁，生成带 token 汇总和延后任务的 Review 报告。

## 决定

本次队列使用有界快照，默认最多两个 feature，命令行只能调低而不能突破策略上限。这保留长运行能力，同时防止大型候选集合一次吸入过多上下文。该选择是可配置工作流策略，不需要 ADR。

## 审查修正

独立审查发现了四个长运行阻断边界，已在交付前修正：强制接管前核对外层指纹；自动补记已交付但未回写外层清单的 feature；制作人补充决策后显式授权子运行越过同一决策门；最终门禁复用策略超时并在 Windows 上终止整个进程树。
