# 2026-09-14

## 蓝图编辑交互切片

- 问题：蓝图图编辑缺少安全回退、节点检索和多节点操作；条件节点只能表达成立分支，重复与释放的参数无法在节点内编辑。
- 范围：在 `NodeEditor` 中为节点、连线和拖拽位置加入会话内撤销/重做；提供调色板过滤与图内节点定位；启用 React Flow 框选；将 `if` 的 `else` 连线映射到既有 AST 的 `els`，并补齐重复次数、释放变量的输入。
- 非目标：不改变 AST、DSL、分析器或 VM 语义；不保存编辑历史；不实现嵌套分支自动布局。
- 验收：浏览器流程覆盖新增节点后的撤销/重做、搜索、条件否则端口；图编译仍经由 AST、静态分析、DSL 序列化与既有编译器。

## 蓝图 E2E 严格定位器修复

- 问题：条件否则端口的 E2E 断言在初始图已有多个条件节点时使用全局可访问名称，触发 Playwright strict mode 失败，无法证明新加入的节点具备端口。
- 修复：断言改为锁定调色板新加入的最后一个 React Flow 节点，并在该节点内查找“条件不成立分支出口”。
- 验证：`typecheck`、`lint`、格式、文档检查和差异空白检查通过。目标 Playwright、Vitest 与完整门禁均在启动 Vite/esbuild 或 Playwright 子进程前被受限环境的 `spawn EPERM` 阻断，未产生用例失败结果。

## E2E 门禁环境修复

- 问题：外部环境设置 `NO_COLOR` 时，Playwright 会为 WebServer 和 worker 注入 `FORCE_COLOR=1`；新版 Node 为每个此类子进程报告冲突警告，导致交付门禁不干净。
- 修复：`scripts/run-playwright.mjs` 在启动 Playwright 前仅移除继承的 `NO_COLOR`，并保持原有 `playwright test` 参数、退出码、工作目录和其余环境不变；`test:e2e` 统一使用该入口。
- 非目标：不修改 Playwright、Node 或应用的颜色策略，也不改变任何 E2E 用例或运行配置。
- 验证：在 `NO_COLOR=1` 下执行 `npm run test:e2e -- --help` 可正常进入 Playwright Test CLI 且无颜色冲突警告；类型、lint、格式和文档检查通过。`npm run verify:full` 已执行，但 Vitest 加载 Vite 配置时被当前受限环境的 esbuild `spawn EPERM` 阻断，未能进入 E2E 与构建阶段。

## 蓝图编辑接管审查与交付补强

- 审查：保留工作区中本 feature 已有的编辑器、E2E、状态和 Playwright 入口改动；未触及无关现场。历史快照原本依赖渲染时闭包，节点文本参数也会直接修改 React Flow 数据，导致历史分支或撤销参数编辑时可能错位。
- 修复：历史游标改由 ref 保持最新值；所有节点参数经受控更新写回节点数组并进入历史；搜索结果现在选择并居中图中节点。`if` 的图布局将 `then` 与 `else` 都计入深度和纵向占位，避免分支与值节点重叠。
- 覆盖：E2E 补充重复次数编辑的撤销/重做，以及含 `else` 的 DSL → 蓝图 → AST → DSL 往返；原有用例覆盖节点新增、连线、搜索、条件端口与无控制台错误。
- 验证：`typecheck`、`lint`、格式、文档检查通过；`npm test` 在加载 Vite 配置前被受限环境禁止 `esbuild` 子进程（`spawn EPERM`）阻断，未进入用例执行。按秘书要求未运行 `npm run verify:full`。

## 蓝图参数历史门禁修复

- 问题：独立审查的浏览器门禁发现，编辑“重复次数”为 `3` 后撤销，历史中的节点数据已回到 `1`，但页面仍显示 `3`，导致撤销/重做不能交付。
- 修复：节点内全部可编辑的输入和选择框改为受控字段，始终渲染当前 React Flow 节点数据；因此历史恢复不仅替换图数据，也会同步刷新已挂载的表单控件。
- 覆盖：`blueprint editing tools` 的重复次数撤销/重做 E2E 回归覆盖初始值 `1`、编辑值 `3` 与来回恢复。
- 验证：`typecheck`、`lint`、格式、文档检查和 `git diff --check` 通过；目标 Playwright 命令在启动浏览器相关子进程前被受限环境的 `spawn EPERM` 阻断。两次尝试读取可用浏览器也因浏览器策略加载失败而无法进行实际 UI 回归。

## 蓝图删除历史与交互门禁补强

- 问题：React Flow 在删除含连线节点时分开通知边与节点的移除，旧逻辑会为两次通知分别记录历史，第一次撤销会留下无连线节点；搜索定位与拖拽框选只有筛选层面的间接覆盖。
- 修复：删除通知现在在当前微任务结束后合并为一个图快照，因此节点和关联边会一同撤销/重做；不改变普通连线删除的历史行为。
- 覆盖：E2E 现在点击搜索结果并断言节点选中及视口变换，执行跨两个节点的拖拽框选并断言选中数量；另建回归用例连接节点后删除，验证一次撤销恢复节点及边、重做再次同时删除。
- 非目标：不引入跨会话历史、嵌套分支自动布局或后续持久化功能。

## 蓝图编辑 E2E 门禁修复

- 问题：节点搜索结果可正确列出多个同名“若”节点，但回归用例使用了会命中全部结果的严格定位器；删除回归则点击了新“调用（施法）”节点中央的原生选择框，未先选中节点，因此 `Delete` 不会触发 React Flow 的删除流程。
- 修复：搜索结果为图节点 ID 提供稳定的数据定位；回归用例按刚加入节点的 ID 点击其搜索结果。删除用例改为点击节点标题并先断言选中，再按 `Delete`，覆盖真实的“选中节点后删除、撤销/重做恢复节点和连线”路径。
- 验收：本轮保持搜索、框选、条件双分支与会话内历史的既有范围；不扩展到跨会话历史或持久化。

## 蓝图框选交付门禁修复

- 问题：React Flow 在同时启用默认的鼠标拖拽平移和 `selectionOnDrag` 时，优先将普通拖拽解释为平移；因此框住两个节点后只保留先前搜索定位的单一选中节点，E2E 门禁失败。
- 修复：蓝图画布关闭普通拖拽平移，将无修饰键的画布拖拽明确留给部分相交框选；搜索定位与缩放控件仍提供导航。
- 验收：不改变 AST、DSL、历史范围或控制流语义；目标 E2E 的拖拽框选应同时选中条件与重复节点。
- 验证：类型、lint、格式、文档和差异空白检查通过。`npm run test:e2e -- --grep "supports undo, redo"` 在 Playwright 启动子进程前被当前受限环境的 `spawn EPERM` 阻断；`npm run verify:full` 同样在 Vitest 加载 Vite 配置、启动 esbuild 前被阻断，未能进入用例、覆盖率、E2E 或构建阶段。浏览器自动化服务也因加载请求头策略失败而不可用，未能补做实际 UI 操作。
