# 常驻秘书主流程与任务节点简报

## 背景

制作人明确要求只保留一种日常范式：制作人只向常驻秘书表达方向，不直接推动 Feature PM，也不接触恢复、接管和诊断命令。原文档虽然已经引入常驻秘书，仍把大量 `producer*` 指令放在制作人主入口中，并混用“秘书”和单次交付 PM。

## 改动

- 术语固定为制作人、常驻秘书、Feature PM、执行 Agent；“秘书”只指跨版本生命周期的常驻角色。
- `docs/agent-workflow.md` 压缩为自然语言对话与进程状态两个制作人动作；低频命令、恢复协议、运行目录和通讯部署迁入 `docs/operations/feature-pm.md`。
- Feature PM 的任务结果新增 `completedAt`；版本清单为已交付 Feature 保存完成时间。
- notice guard 由现有恢复点和版本清单文件事件唤醒，生成结构化 `task-complete` 事件。事件包含任务 ID、标题、Feature/版本父级、完成时间和详细运行目录。
- 常驻状态保存已汇报节点，稳定键由运行目录和任务 ID 构成；guard 重启后不会重复简报。任务通知不调用模型，可直接作为未来可视化界面的数据源。
- 《扩展元法术》从 `docs/` 根目录移入 `docs/reference/`，同步代码注释、历史链接和参考入口。
- 移除 `--version`、`--decision` 和 HTTP 消息分类字段。秘书结合等待事项、运行状态与项目事实识别问题、新方向、回复和继续请求。
- Feature 或版本完成后自动继续队列；队列为空时承接 `docs/status.md` 的下一项。额度或鉴权阻塞暂停并通知，制作人的普通回复会恢复原任务。
- 等待态的本地语义回退按“明确问题、继续指令、上下文回复”排序；同步当前 Codex CLI 参数，避免语义分流因废弃选项静默降级。

## 范围

本轮不实现任务可视化界面，不绑定具体通讯平台，不改变游戏玩法，也不把 Feature PM 变成长生命周期模型。空闲态继续只保留外部事件监听进程，模型调用为零。

## 验证

- 单元覆盖任务稳定键和跨重启去重。
- 实际后台生命周期已确认自然问题、新方向、继续请求、对话持久化、状态读取和停止；启用 Luna 的真实语义演练能把“多个独立功能的稳定版本”识别为 version 并拆为 3 项。
- `npm run verify:full` 通过：82 个 Vitest 用例、15 个 Playwright 流程、覆盖率、核心沙箱和生产构建均通过。
- 独立复审先后发现等待态回复与进度问题的优先级歧义，修复并补充回归测试后通过；当前 Codex CLI 的废弃参数也在真实演练前移除。
