# 2026-09-20 钉钉常驻秘书通道

## 背景

手机版 Sites 在制作人的手机环境中无法可靠交互，外部浏览器还存在 TLS 可达性问题。移动需求的核心是与常驻秘书沟通和接收进度，而不是复制完整桌面中枢，因此改用钉钉机器人承接移动入口，并暂停继续投入 Sites。

## 实现

- 新增平台无关的 `SecretaryChannel`、统一入站消息、通知契约和通道生命周期管理。
- notice guard 将持久事件发布给 Channel Hub；单个通道启动或发送失败不会影响其他通道和项目调度。
- 将原有出站 webhook 封装为独立 Channel，保留飞书、企业微信、Discord、钉钉与通用 JSON 格式。
- 使用钉钉官方 Stream SDK 接收文本机器人消息，不暴露本机公网端口。
- 钉钉入站使用 staffId 白名单，并以平台消息 ID 派生稳定收件 ID；平台重投和守卫重启不会重复排期。
- 即时答复关联回原消息的 session webhook，任务完成、阻塞和待办等异步事件使用机器人单聊接口主动发送。
- 凭据全部来自环境变量；缺失、无效或连接失败时通道被隔离，本机秘书照常运行。
- SDK 调试输出被固定关闭，防止连接配置中的 Client Secret 进入日志；启动连接设置超时，失败后主动释放资源。
- notice guard 启动语义 Agent、PM 和进程退出观察器时剥离钉钉、HTTP token 与 webhook 凭据，避免密钥扩散到开发子进程。
- `secretary:open` 启动浏览器时同样剥离通讯凭据；钉钉并发重投会共享首次持久化结果，只有 inbox 写入成功才统一 ACK。
- 外部通知先进入持久 outbox，按尚未成功的通道重试；原会话发送失败会降级为机器人主动通知。
- 离线通道仍写入待发目标；通道连接和历史 outbox 恢复移到后台，本机 HTTP 与 inbox 不等待外部网络即可开始收件。
- inbox 恢复会识别已保存的秘书事项、上下文回复和带来源请求 ID 的版本审批，避免崩溃重放导致重复任务或版本越级推进。
- `secretary:status` 增加钉钉配置提示，运维文档记录一次性部署步骤和安全边界。

## 验证

- 单元测试覆盖稳定收件 ID、通道故障隔离与超时、webhook 格式、钉钉配置校验、发送者白名单、消息去重、原会话回复、失败降级、主动通知和连接释放。
- 集成测试覆盖已提交 inbox 的崩溃恢复、版本审批不重复推进，以及 webhook 失败后保留 outbox 并自动重试。
- 完整门禁通过：124 项单元与集成测试、覆盖率检查、沙箱、19 项浏览器 E2E 和生产构建。
- 重启 notice guard 做进程级冒烟；未配置钉钉凭据时守卫正常启动并进入事件休眠，本机状态与既有排期保持不变。
- 钉钉真实连接需要企业内部应用凭据，将在制作人完成平台侧配置后进行联调。

## 边界

- 本轮不开发钉钉小程序或交互卡片，先完成可靠文本闭环。
- Sites 源码和历史部署保留，但暂停维护，不再作为近期移动入口。
- 项目状态仍以本机秘书目录、代码、测试和长期文档为准；钉钉不是第二份项目数据库。
