# 2026-09-20 项目中枢可观测性

## 背景

制作人无法从旧看板判断是否真的有 Agent 在运行、为什么暂停或归档是否完成；版本节点只能打开一份文档，页面需要整页滚动，待办也不能直接处理。

## 实现

- 正式版本每次写入同时保存按版本 ID 命名的快照，项目中枢可切换当前与历史版本，历史视图只读。
- 正式版本状态增加单调 revision、带进程身份的跨进程写锁、双文件事务标记和显式版本切换，避免 notice guard 与管理工具并发覆盖新状态；半提交会在下次读取时补完，死亡进程遗留锁会被回收，历史版本 ID 不允许被新立项覆盖。
- 归档变为原子终态：版本状态、归档节点和完成时间一次写入，旧的“归档节点仍进行中”状态会在 notice guard 启动时修复。
- 节点聚合显式证据和版本目录内全部 Markdown、文本与 JSON 文档；文档接口只允许读取所选版本明确关联且真实路径位于 `docs/` 内的文件。
- Agent 区从秘书队列、进程身份、恢复点、进度和结构化计划生成状态；dispatcher 会记录当前 worker 的 PID、启动标识、模型和角色，只有身份校验通过的 PM 与规划、执行、审查或修复 Agent 才计为运行，notice guard 空闲显示休眠。
- PM 异常退出但 worker 仍存活时，秘书继续展示并等待旧 worker，阻止重复 Agent 同时编辑工作区；worker 退出后才从恢复点接管。
- Agent 详情展示模型、阶段、耗时、重试时间、任务输入、验收标准、子任务、阻塞和截断后的操作输出，不暴露私有推理。
- 制作人待办提供推荐方案和备选方案。版本评审可直接通过或退回；Feature PM 临时阻塞可立即重试、延期自动重试或移入后续排期。
- 产品决策待办不能伪装成可重试故障；继续前必须填写制作人决定，正文通过 `--producer-guidance` 进入恢复 Agent 的任务上下文。
- 桌面端改为固定视口三栏工作台，各栏内部滚动；窄屏折叠为单列并避免横向溢出。
