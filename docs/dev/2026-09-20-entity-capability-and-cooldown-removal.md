# 旧元法术能力迁移与冷却移除

## 问题

生命、伤害和目标属性控制仍按 Actor 存储类型判断，无法遵循统一 `entity` 句柄的能力契约。玩家法术同时受冷却、法力、执行 tick、输入边沿和同槽施法占用限制，重复规则让再次施放时机不透明。

## 实现

- `生命` 改为查询 Vitality；能力缺失或句柄失效时返回 `0`。
- `伤害` 改为控制 Vitality；`迟滞`、`虚弱`、`蔽识` 和 `破防` 改为控制 Modifiers。控制成功返回 `true`，失败返回 `false` 且不产生部分修改。
- `World` 增加统一的 `entityWithCapability` 类型守卫入口，旧元法术不再自行按 Actor/Projectile 分支。
- 删除 `SpellMeta.cooldown`、`Attributes.cooldownMul`、战斗冷却表、默认法术冷却注解和演武场冷却展示。
- 旧 DSL 的 `@cooldown` 仍可解析，但不会进入 AST 元数据或规范化输出；旧存档的 `cooldownMul` 通过属性白名单丢弃。
- 玩家输入只接受一次按下边沿；同槽施法中以及按键尚未松开时均不重入，施法结束并松开后可立即再次按下起手。妖兽 `attackInterval` 保留为独立 AI 决策间隔。

## 验证

- 聚焦测试覆盖 Actor/Projectile/失效句柄的查询与控制结果、四种目标属性控制、无部分修改、旧 DSL 与存档规范化，以及“按下—施法结束—仍按住—松开—再次按下”的无冷却流程。
- 独立审查发现默认法术迁移到弹道后，持久化 E2E 仍尝试在“基础剑气”中替换旧伤害语句；用例现显式编辑并在重载后重新选择“爆炎咒”，确保断言验证真实保存内容。蓝图调色板新增节点同时改为确定性空位布局，避免随机重叠造成框选门禁偶发失败。
- 执行 Agent 的受管沙盒无法创建 esbuild、Playwright 和 Electron 子进程，因此只在该层完成聚焦逻辑验证；Feature PM 随后在正常本机环境运行正式门禁。
- 审查修复后的 `npm run verify:full` 通过：135 项 Vitest、覆盖率、资源沙盒、19 项 Playwright E2E 和生产构建全部成功。
- 独立审查确认实现与测试没有明确行为或架构缺陷；临时验证脚本已清理，文档状态已按真实门禁结果收束。
