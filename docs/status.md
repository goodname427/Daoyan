## 已具备

- 纯 TypeScript 无头核心：DSL、AST、静态分析、编译器、VM、世界与资源计量。
- 元法术按职责分类、动态价格静态上界、属性系统、法术生命周期和外部扩展入口。
- Actor 与 Projectile 使用统一实体句柄；法术可创建、配置、激活和探查有限寿命弹道。
- 旧的生命、伤害和目标属性控制已迁移到统一实体能力判定；法术冷却与冷却倍率已移除，旧存档字段会在规范化时清理。
- 推演台：单法术 DSL 高亮编辑、支持撤销/重做、搜索定位、框选与条件双分支的蓝图编辑、元法术查看、静态分析与单次推演。
- 演武场：基础属性、法术绑定、开始、暂停/继续、重开与实时战斗。
- 演武场支持不同槽位并发施法，并对并发 VM 实时共享法力与神识账户。
- 推演台与演武场共享法术书，演武场配置在页签往返期间保留。
- 法术书、演武属性与槽位绑定会自动持久化到本机；可导入、导出版本化 JSON，且可安全迁移旧格式。存档保存可解析 DSL 的规范化结果，注释草稿不构成持久化内容；导入属性必须满足演武场的合法范围，越界存档会被拒绝，不能破坏资源消耗或施法语义。若导入绑定引用的法术不在该存档法术书中，槽位会保留该绑定并明确标示不可施放，方便玩家修正。即使导入的完整规范法术书内容未变，已打开的演武 Battle 也会同步采用导入的属性和绑定；未来版本本地存档被安全拒绝后会原样保留，首次默认状态不会覆盖它。
- Vitest、Playwright、覆盖率、沙盒、构建、Git hooks 与 GitHub Actions 门禁。
- 制作人到常驻秘书的唯一入口，以及按风险选择 GPT-6 Luna、Sol、Astra 的 Feature PM 调度器；GPT-5.6 仅作故障回退。
- 事件驱动的常驻项目秘书：跨版本收件、查重、排期、任务节点简报、延时恢复与 webhook 通知；空闲时不调用模型。
- 钉钉常驻秘书通道：制作人可直接发送自然语言，答复回到原会话，异步进度与待办主动通知；通道与项目状态解耦，断线不影响本机秘书，失败通知由持久 outbox 恢复。
- 正式版本生命周期与可视化秘书：制作人可切换当前与历史版本，查看版本环节和全部关联文档，检查 Agent 的真实运行状态及可审计上下文，一键处理推荐待办，并直接与同一个常驻秘书交流。
- 手机版项目中枢的 Sites 快照实验已保留，但其候选排期已标记为由钉钉常驻秘书替代，不再计入待办；当前移动入口由钉钉承接。
- 玩家法术编写指南、由代码生成的元法术参考，以及当前实体与属性模型说明。

## 已知债务

- 蓝图编辑仍以单入口、显式连线为主；嵌套分支的自动布局与跨会话历史不在本轮范围。
- `生命`、`伤害` 和目标属性控制已接入能力判定；目标神识强度及扫描、旧发射等世界操作仍可继续迁移。
- Actor 与 Projectile 已统一句柄和能力查询，但仍以两个数组存储，尚未演进为通用组件存储。
- 推演台静态法力上界使用基础价格，尚未结合演武场的法力消耗倍率。
- 当前为单一浏览器本地存档；尚未提供多槽位、云同步或跨设备自动同步。
- UI 自动化已有主路径覆盖，视觉快照应在布局进一步稳定后逐步加入。
- Feature PM 仍按顺序编辑同一工作区；现按调用日志统计已知 token 和缺失调用，尚未汇总历史通过率，CLI 也不支持调用中的硬 token 上限。notice guard 可在进程退出或延期时间到达后接管恢复点，但系统重启后仍需由登录启动项或进程管理器拉起。
- 钉钉机器人代码和本地配置向导已具备，但企业内部应用、Stream 机器人、制作人白名单凭据仍需在部署机器完成一次性输入；系统登录自启动尚未配置。
- 手机版 Sites 是被钉钉入口替代的事件时点只读快照；当前移动网络存在 TLS 路由失败，且它不再作为远程交互候选或待办。
- 正式版本已经能按阶段持续派发和推进；当前阶段角色仍复用 Feature PM 交付内核，后续需继续拆出更精细的专用提示、模板和成本统计。
- 版本快照从本次能力上线后开始积累；此前未写入正式版本状态机的旧开发批次不会自动伪装成历史正式版本。
- 仓库历史尚无版本 tag；发布脚本暂以阶段四完成提交 `e4e71fe` 作为 0.2.0 基线，下一个正式 tag 建立后自动改用 tag。
