# 法术编写指南（当前实现）

这是一份面向新玩家的当前使用指南。只把公开元法术参考中列出的入口作为新法术写法；旧法术会在兼容边界尝试迁移，旧名不代表仍是新玩家入口。

下方历史示例若使用 `探查`、`生命`、`感知敌人` 或 `快照` 的裸值写法，须改为[逐属性探查](./entities-and-attributes.md#逐属性探查)的 `query` 成功分支；这些旧调用不会自动转成新读取。

## 从第一个法术开始

1. 打开推演台，点击“新建自定义法术”。
2. 在 DSL 模式输入法术；编辑器会自动解析并显示静态法力、耗时和神识上界。
3. 点击“推演一次”检查当前场景下的实测结果。
4. 切到演武场，绑定法术并开始实战。
5. 返回推演台继续修改；两个场景共享同一本法术书。

推演台“查看用户法术预设”提供“对手减速”和“对手破防”。先展开预览源码与推演配置，再勾选需要的法术并导入；两者是普通用户法术，可编译、推演和绑定，并非恢复旧的“迟滞”“破防”元法术。若书中已有同名法术，界面会同时显示原内容和预设内容并建议新名；原法术及演武绑定不会被覆盖。同一预设的内容已经存在时再次导入会跳过。

默认书中的“法球·冲量滑行”“法球·持续推进”“法球·目标追踪”可分别绑定实测。后两者从预付的运动池与扫描池按周期扣能；余额耗尽时不再主动推进，惯性仍保留。追踪和两个控制预设需要至少 80 神识；演武场可在基础属性中调整。推演台的元法术搜索支持“迟滞”“破防”等旧名，并指出现行入口、权限、起手与周期价及拒绝原因。

最小可用法术：

```daoyan
spell 试剑 {
  var self: vec2 = 自身位置()
  创建弹道(self, 准星方向(), 380, 20, 2.4)
}
```

这段代码先读取自身位置，再沿准星方向创建并发射一枚飞剑弹道。参数依次为起点、方向、速度、基础伤害和存活秒数；基础伤害会乘施法者的“术法威力”。

## 阅读法术的心智模型

法术从上到下执行。每个动作都属于下面三件事之一：

- **保存状态**：`var` 声明变量，占用神识，离开作用域或 `free` 后归还。
- **神识内计算**：数值、布尔、向量、列表下标等操作，通常只消耗 tick。
- **读取或改变世界**：调用感知、操控、属性元法术，消耗法力和 tick。

元法术参数会先求值。例如：

```daoyan
创建弹道(自身位置(), 朝向(自身位置(), 探查(target)), 380, 20, 2.4)
```

这里 `自身位置()` 调用了两次，因此也支付两次资源。缓存结果通常更省：

```daoyan
var self: vec2 = 自身位置()
创建弹道(self, 朝向(self, 探查(target)), 380, 20, 2.4)
```

## 类型与神识

| 类型                       | 含义                           | 单变量神识成本                      |
| -------------------------- | ------------------------------ | ----------------------------------- |
| `num` / `数`               | 数值                           | 1                                   |
| `bool` / `布尔`            | 真或假                         | 1                                   |
| `entity` / `实体`          | Actor 或 Projectile 的统一句柄 | 1                                   |
| `vec2` / `向量`            | 二维坐标或方向                 | 2                                   |
| `list<T, N>` / `列表<T,N>` | 最多 N 个元素                  | 1 点表头 + N × 元素类型成本         |
| `空` / `null`              | 无实体或无值                   | 作为 `any` 字面量使用，不可声明类型 |

列表必须声明容量：

```daoyan
var foes: list<entity, 4> = 感知敌人(self, 400)
```

扫描可能返回更多敌人，但这里只保留前 4 个。静态分析按容量 4 计算最坏情况，运行时按真实长度执行。

## 基本语法

### 注释与分号

`//` 和 `#` 都可以开始单行注释。行尾分号可写可不写。

### 声明与赋值

```daoyan
var damage: num = 20
var alive: bool = true
var target: entity
var origin: vec2 = 向量(100, 200)

damage = damage + 5
```

建议写明类型，尤其是列表和暂时没有初值的变量。

### 条件

```daoyan
if 自身法力率() < 0.2 {
  施加冲量(自身实体(), 数乘(准星方向(), 80))
} else {
  创建弹道(自身位置(), 准星方向(), 380, 20, 2.4)
}
```

支持 `+ - * / % < > <= >= == != && || !`。它们会转换为同名元法术，也可以写成 `加(a, b)`、`小于(a, b)`。

### 遍历与列表下标

```daoyan
var self: vec2 = 自身位置()
var foes: list<entity, 8> = 感知敌人(self, 460)

for foe in foes {
  if 生命(foe) > 0 {
    伤害(foe, 12)
  }
}
```

可用 `foes[0]` 读取列表元素，也可以对列表元素赋值。访问前应先用 `长度(foes)` 判断是否存在；越界读取会得到 `空`。

### 固定次数循环与中断

```daoyan
repeat 3 {
  创建弹道(自身位置(), 准星方向(), 380, 8, 2.4)
}
```

`repeat` 次数必须是代码中的非动态数字。`break` 可结束当前循环。递归和不定次数 `while` 当前都不支持，以保证资源上界可分析。

### 提前释放神识

```daoyan
var foes: list<entity, 8> = 感知敌人(自身位置(), 460)
var first: entity
if 长度(foes) > 0 {
  first = foes[0]
}
free foes
```

当大变量后面不再使用时，`free` 可以降低神识峰值。

### 自定义法术的参数与返回值

```daoyan
spell 双倍(value: num) -> num {
  return value * 2
}

spell 使用辅助法术 {
  var damage: num = 双倍(10)
  创建弹道(自身位置(), 准星方向(), 380, damage, 2.4)
}
```

自定义法术可以互相调用，但不能直接或间接递归。当前蓝图编辑器还不能完整编辑自定义法术调用；这种写法应使用 DSL。

## 创建弹道与统一属性控制

新法术创建弹道只用一个调用：

```daoyan
var shot: entity = 创建弹道(自身位置(), 准星方向(), 380, 20, 2.4)
```

它直接创建已激活弹道并返回统一 `entity` 句柄，不再要求先创建、再设方向/速度/威力、最后激活。方向必须有限且非零；速度、基础伤害和寿命必须是正的有限数。超过所有者弹道上限或参数非法时返回 `空`。

公开属性控制统一采用三个参数：

```daoyan
var self: entity = 自身实体()
var ok: bool = 调整速度(self, 1.5, 2)
```

其形状为 `(目标, 效果, 时间) -> bool`。可用属性入口及效果类型见[元法术参考](./meta-spells.md)。控制会先检查目标句柄、目标能力、权限、效果和时间；任一领域条件不满足就返回 `false`，目标不会被部分修改。尝试仍有资源成本；法力不足或 VM 资源错误会终止施法。

时间以秒计，正数为有限时长，`0` 表示无限。时间为零不等于免费：`write` 写入按一次起手预算结算；`maintain` 除起手外，每 `0.25` 秒先结算法力和 tick，再维持效果。

- `write/commit` 写入基础状态，不会在施法结束时回滚。当前位置与弹道存活时间控制要求时间 `0`。
- `write/overlay` 由世界持有覆写层，可在限时后移除；施法结束不会撤销。当前朝向及弹道速度/伤害覆写使用此模式。
- `maintain` 由施法会话持有。主动结束、施法正常完成或中断，以及目标/能力失效和资源不足都会清理对应维持记录。无限维持持续按周期收费。

目标缺少所需属性能力时会明确拒绝，不会因为它是 Actor 或 Projectile 而自动获得能力。各实体当前 binding 和合并方式见[实体与属性](./entities-and-attributes.md)。

旧法术书中的 `发射`、分步创建链和旧属性控制调用可能被 AST 兼容层规范化；无法安全保持语义的程序会诊断失败。编写新法术时始终使用本页及公开参考列出的新入口，不依赖旧语法。

## 生命周期注解

没有注解时，法术是瞬时法术。

```daoyan
spell 护体金光 @kind=duration @period=1.5 @duration=6 {
  调整护体(自身实体(), 6, 2.5)
}
```

| 注解                 | 当前含义                                                             |
| -------------------- | -------------------------------------------------------------------- |
| `@kind=instant`      | 执行一次后结束，默认值                                               |
| `@kind=duration`     | 在持续时间内按周期重新执行整个法术体                                 |
| `@kind=channel`      | 分帧执行一次，最长不超过 `duration`                                  |
| `@period=秒数`       | duration 法术的重复周期                                              |
| `@duration=秒数`     | duration/channel 的最长持续时间                                      |
| `@keys=虚拟键名`     | 声明一个可被 `按键...` 元法术读取的虚拟按键                          |
| `@charge=prepare`    | 按下开始准备，达到 `duration` 后松开才执行法术体一次；提前松开取消   |
| `@charge=projectile` | 按下创建未激活法球，每 `period` 秒注能，松开付款发射；法术体必须为空 |
| `@chargeMana=法力`   | 持球每周期注入 damage 池的法力，默认 5；1 法力转为 0.8 储能          |

法术没有冷却注解。一次施放结束后，玩家再次按下绑定键即可重新起手；施法仍在进行时，同一槽位不能重入。旧法术书中的 `@cooldown` 可兼容读取，但保存或导出时会被移除。

多个虚拟键的 DSL 往返还没有完整验证；当前范例只使用一个虚拟键。

## 常用写法

### 手动瞄准

```daoyan
spell 手动飞剑 {
  var self: vec2 = 自身位置()
  创建弹道(self, 准星方向(), 380, 22, 2.4)
}
```

优点是没有扫描敌人的成本；缺点是命中依赖玩家瞄准。

### 获取第一个敌人

```daoyan
spell 追踪一击 {
  var self: vec2 = 自身位置()
  var foes: list<entity, 4> = 感知敌人(self, 400)
  if 长度(foes) > 0 {
    var target: entity = foes[0]
    var targetPos: vec2 = 探查(target)
    创建弹道(self, 朝向(self, targetPos), 380, 20, 2.4)
  }
}
```

当前 `感知敌人` 按世界中的遍历顺序返回目标，并不保证距离排序。需要“最近目标”时应像默认的“基础剑气”一样逐个比较距离。

### 蓄力释放

显式蓄力会话可写成：

```daoyan
spell 蓄时剑 @charge=prepare @duration=0.8 @period=0.25 {
  创建弹道(自身位置(), 准星方向(), 380, 18, 2)
}

spell 持球 @charge=projectile @chargeMana=10 @duration=2 @period=0.25 { }
```

蓄时准备阶段只支付起手与周期工作费，效果在准备完成后的合法松开才执行。持球按周期从当前法力注入伤害池，松开后另付冲量费并激活；提前松开、打断、耗尽、目标消失或到期会结算未用余额。两种模式使用瞬时法术，持球法术体必须为空。按键意图在模拟更新中按序处理，暂停期间不会推进或扣费。

下面是旧版按键轮询写法，仍保留原语义：

```daoyan
spell 蓄力飞剑 @kind=duration @period=0.05 @duration=10 @keys=蓄力 {
  if 按键松开(0) {
    var held: num = 按键蓄力(0)
    if held >= 0.8 {
      创建弹道(自身位置(), 准星方向(), 380, 20 + 最小(held, 2) * 40, 2.4)
    }
    结束施法()
  }
}
```

## 主动监控

`开启位置监控(目标, 周期秒数, 周期次数)` 和 `开启生命监控(...)` 返回正数监控句柄；失败返回 `0`。范围固定为一个目标和一个字段，付款账户固定为施法者本人。周期至少 `0.25` 秒，须为 `0.25` 秒的整数倍；次数为 `1..256`。目标仍须满足该字段的能力、授权、可见性和距离要求。监控占用 1 神识，起手调用收 1 法力和 1 tick；每次到期先按该字段当前公开报价从本人账户扣法力并计 tick，成功后才更新快照，不享受法力消耗折扣。监控累计工作上限为 600 tick。

`读取位置监控(句柄)` / `读取生命监控(句柄)` 返回最近一次已付费快照，尚未扫描、无权或句柄失效时返回不可探查；读取缓存本身只消耗执行 tick。用 `查询可用` 检查后才能取值。次数用尽后不再扫描，最后一份快照保留一个声明周期；`关闭主动监控(句柄)` 可提前关闭。法力不足、死亡、目标失效、隐藏或撤权会停止监控，之后不再产生扫描费用。起手的静态预算标为动态，因为后续周期会按届时权限与公开价格重新结算。离散事件订阅不能提供持续逐帧观察。

## 如何理解资源面板

- **神识峰值**取变量同时存活时的最大占用，不是所有声明的简单总和。
- **法力预算**与**耗时预算**累加元法术、下标和被调用法术的已知部分；循环仍按声明容量或固定次数计算。
- 显示“`+ 动态`”时，请求值、目标距离、实体关系或分支结果要到运行时才能结算；此时面板数字不是全局上界。没有动态标记时才是同一输入下的静态上界。
- 演武场中法力实扣还会乘角色的“法力消耗”倍率，真实施法时间还会除以“施法速度”。当前静态面板没有把演武场属性纳入上界，这是已知限制。

完整公开元法术签名见 [`meta-spells.md`](./meta-spells.md)，实体属性和资源模型见 [`entities-and-attributes.md`](./entities-and-attributes.md)，资源模型的架构理由见 [`../adr/0001-资源模型-神识法力耗时.md`](../adr/0001-资源模型-神识法力耗时.md)。

## 常见失败

| 现象                   | 优先检查                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------- |
| 解析失败               | 报错行附近的括号、花括号、类型、逗号和函数名                                        |
| 未知元函数             | 名称是否存在于元法术参考；自定义法术是否仍在法术书                                  |
| 参数数量或类型不匹配   | 每个参数和返回值的类型；`entity` 与 `vec2` 不能混用                                 |
| 神识不足               | 列表容量是否过大；大变量能否提前 `free`                                             |
| 法力不足               | 循环中是否重复探查或控制；是否能把外部读取缓存到变量                                |
| 施法超时               | 循环容量、重复次数和嵌套调用是否过高                                                |
| 实战无效果             | 是否没有目标、句柄已经失效、目标缺少所需能力、弹道落空或施法被打断                  |
| 推演成功但实战消耗不同 | 动态请求、目标距离/关系、演武场属性倍率、真实敌人数、列表截断和法术生命周期是否不同 |

## 当前能力边界

- 没有字符串、字典、结构体、用户自定义实体类型、列表字面量和动态增长列表。
- 没有 `while`、协程、事件订阅、跨次施法常驻变量和递归。
- 元法术价格可随请求效果、距离与实体关系动态变化；面板会把运行时未知部分标为“+ 动态”。
- `entity` 可表示 Actor 或 Projectile；具体操作按 Transform、Vitality、Modifiers 等能力判断。
- 蓝图支持条件的 `then` / `else` 分支、会话内撤销/重做、节点搜索定位和部分相交框选；自定义法术调用、跨会话历史与嵌套分支自动布局仍不完整。
- 推演台已有单步执行、变量观察和资源时间线；跨次施法常驻状态仍不支持。
