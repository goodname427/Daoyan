# 实体与属性（当前实现）

本文描述当前代码的数据模型。统一句柄与动态价格已由 [ADR 0009](../adr/0009-统一实体句柄与能力判定.md) 和 [ADR 0010](../adr/0010-动态元法术价格与静态上界.md) 采纳。

## 当前世界对象

`World` 目前维护两个相互独立的集合：

```text
World
├─ actors: Actor[]
└─ projectiles: Projectile[]
```

### Actor

玩家和妖兽都是 `Actor`，共用属性、施法、受伤、临时修正和死亡逻辑。DSL 的 `entity` 是不透明数字句柄，可引用 Actor 或 Projectile；两个集合共用单调递增 ID，移除和 `World.reset()` 后也不复用。句柄只在所属 World 内有效，不能跨 World 传递或持久化。

Actor 除属性外还包含：位置、阵营、准星、当前生命、当前法力、半径、存活状态、法术绑定、AI 行为、硬直、施法减速和表现状态。

演武场允许一个 Actor 通过不同槽位同时运行多个施法实例。每个实例独立推进 tick 和生命周期，但所有实例共同使用 Actor 的当前法力与神识：元法术执行时实时扣除法力，变量存活时实时占用神识；返回、失败、打断或重开都会归还仍占用的神识。同一槽位在原实例结束前不能重入。

### Projectile

Projectile 具备 Identity、Transform、Movement 和 Projectile 能力，只有所有者、阵营、位置、方向、速度、伤害、半径、寿命、穿透次数、命中集合和激活状态。它没有 Actor 的 Vitality、Caster 或 Modifiers，不能增减生命、法力或临时属性。

`创建弹道(寿命)` 返回未激活实体的句柄，寿命允许 `(0, 5]` 秒；创建失败返回 `空`。每位所有者最多同时保有 16 枚，旧 `发射` 和未激活对象共用该上限。未激活对象不移动、不碰撞、不渲染，但仍消耗寿命并占用名额；过期、命中销毁或场景清理释放名额。

所有者可调用 `设置弹道方向`（有限非零向量，自动归一）、`设置弹道速度`（`(0, 600]`）和 `设置弹道威力`（基础值 `(0, 100]`，乘施法者有效 `power`）。配置速度和威力后，`激活弹道` 将其置于施法者前方。激活只能成功一次，飞行中仍可配置方向、速度和威力。

控制成功返回 `true`；无效句柄、其他所有者、能力缺失或非法参数返回 `false`，目标不变。尝试成本仍扣除；资源不足则由 VM 终止。`实体存在` 判断对象是否仍在世界集合中（Actor 死亡不等于已移除）；`探查` 可读取两种实体的位置，失效句柄返回零向量。

默认“御剑·手动”演示完整创建与配置链路。旧 `发射` 保留固定参数和 `void` 返回值，直接创建激活弹道；达到上限时不生成弹道或发射特效。

## Actor 属性表

当前每个 Actor 都必须拥有下面全部属性，没有“属性缺失”的表达。

| 中文名   | 代码字段      | 默认值 | 当前作用                                              |
| -------- | ------------- | ------ | ----------------------------------------------------- |
| 生命上限 | `hpMax`       | 100    | 决定生命上限；当前生命另存于 `Actor.hp`               |
| 法力上限 | `manaMax`     | 200    | 决定法力上限；当前法力另存于 `Actor.mana`             |
| 法力回复 | `manaRegen`   | 20     | 每秒恢复法力，不能超过有效法力上限                    |
| 神识上限 | `shenshiMax`  | 48     | VM 同时可持有的变量与列表空间                         |
| 移动速度 | `speed`       | 140    | 影响战斗层的连续移动；`移动()` 元法术当前不读取该属性 |
| 施法速度 | `castSpeed`   | 1      | 放大每秒可执行的 tick 数，数值越大施法越快            |
| 术法威力 | `power`       | 1      | 乘到伤害元法术数值，以及 `设置弹道威力` 的基础请求值  |
| 法力消耗 | `manaCostMul` | 1      | 乘到所有元法术的基础法力价格，越小越省                |
| 冷却时间 | `cooldownMul` | 1      | 乘到法术声明的冷却秒数                                |
| 感知半径 | `perception`  | 1      | 只放大 `感知敌人` 与 `快照` 的输入半径                |
| 护体减伤 | `armor`       | 0      | 每次受伤固定减免；最终伤害最低为 1                    |

战斗中的临时增益与减益保存在 `Modifier[]`：先合并加法修正，再乘乘法修正；持续时间结束后移除并重算有效属性。

## 当前资源公式

### 法力

每个元法术注册静态基础上界 `mana`，可选 `manaCost` 按本次请求给出动态基础价：

```text
本次调用实扣法力 = 运行时基础价 × 施法者有效 manaCostMul
```

有效请求的动态基础价为：`探查 = min(12, 8 + 距离 / 200)`（失效句柄为 8），`创建弹道 = 8 + 寿命 × 2`，`设置弹道速度 = 2 + 速度 / 100`，`设置弹道威力 = 2 + 基础威力 / 4`。后三者上界分别为 18、8、27。有限越界值按 `[0, 最大请求]` 钳制定价，非有限请求只收固定尝试成本，均不产生效果。基础探查成本保留多人场景中“快照用神识换法力”的优化空间。

VM 在扣费与执行效果前拒绝负数、非有限、超过注册上界或抛错的动态价格。静态分析器累加基础上界；与实扣比较时须使用同一有效 `manaCostMul`。推演台仍展示基础上界，尚未结合演武场倍率；目标神识强度与关系折扣尚未实现。

### 耗时

每个元法术注册固定 tick，参数表达式与列表下标也会产生额外 tick。演武场每帧推进：

```text
每秒可执行 tick ≈ 100 × 有效 castSpeed
```

因此 `castSpeed=2` 大约把相同 tick 数的真实施法时间减半。`manaCostMul` 不影响时间。

### 神识

神识是法术执行期间的变量空间：

```text
num / bool / entity = 1
vec2 = 2
list<T,N> = 1 + N × T 的成本
```

`shenshiMax` 是容量，当前没有独立的“神识强度”用于远程探查、抵抗控制或动态计价。

## 当前元法术对属性的使用

| 属性          | 会读取它的当前逻辑                              |
| ------------- | ----------------------------------------------- |
| `speed`       | 玩家和妖兽的连续移动；`疾行`可临时修改          |
| `castSpeed`   | 战斗层的 VM tick 推进；`明心`可临时修改         |
| `power`       | 伤害元法术与弹道威力设置；`增威`和`虚弱`可修改  |
| `manaCostMul` | VM 扣除所有元法术法力；`节流`可修改             |
| `manaRegen`   | 世界每帧回复；`聚气`可修改                      |
| `cooldownMul` | 法术触发后的冷却计时                            |
| `perception`  | `感知敌人`、`快照`的有效扫描半径                |
| `armor`       | `World.damage` 的固定减伤；`护体`和`破防`可修改 |

## 后续边界

1. 统一句柄与能力查询已实现，存储仍为两个数组，不是通用 ECS。
2. Actor 内部属性仍全部必填；旧 Actor 专用元法术尚未全量迁移到能力查询。
3. 没有神识强度，远程探查与控制也没有对抗计算。
4. 只有探查和新弹道链路采用动态价格，其余元法术仍为固定价格。
5. 冷却仍是法术生命周期和 Actor 属性的一部分。
6. 当前仅有弹道创建原型；护盾等其他原型需要独立规格。
