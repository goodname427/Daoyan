# 道衍 · 修仙编程 Roguelike（阶段一：核心验证）

玩家自由编写**功法 / 法术**，但每一项能力都必须用有限的资源去换。
核心理念：**把算法复杂度（时间 / 空间 / I-O）变成可消耗的游戏资源**，
逼玩家写出更优雅的解法，就像快速排序优于插入排序那样。

## 一、资源模型

| 资源     | 语义             | 对应算法概念 | 失败后果                            |
| -------- | ---------------- | ------------ | ----------------------------------- |
| **神识** | 持有状态的成本   | 空间 / 内存  | 声明变量时占用，超限即走火入魔      |
| **法力** | 与外界交互的成本 | I/O 开销     | 只有「看世界 / 改世界」的元函数收费 |
| **耗时** | 执行步数         | 时间         | 超过施法时间上限即走火入魔          |

**核心规则**：神识内运算（加减、比较、距离、取长度）**几乎不要法力**；
凡是「读一次世界」或「改一次世界」的操作都收高额法力。

于是最经典的权衡自然浮现——

> 朴素：拿到句柄后逐个查询 → 法力 O(n)
> 优化：一次批量读进神识 → 法力 O(1)，但神识 O(n)

而且**没有单一最优解**：敌人少时朴素更省法力，敌人多时批量更省；
批量要付神识租金，低境界根本撑不起；把列表容量调小能省神识，但会看漏目标。

## 二、当前进度（阶段一：无头核心）

已跑通，见 `npm run dev` 的实际输出：

```
【一】静态分析              法力上界 / 耗时上界 / 神识峰值
【二】敌人数变化            1 → 8 人，三种写法的法力·神识·耗时·命中对比
【三】境界 = 神识容量       24 / 39 / 64 三档，看哪个法术放不出来
```

关键结论（实测数据）：

- 敌人 1 个：朴素版 87 法力 < 慧剑 97 法力 → **朴素更优**
- 敌人 3 个：朴素版 107 法力 > 慧剑 97 法力 → **慧剑更优**（法力恒定）
- 慧剑要多花 15 点神识，**神识上限 39 以下直接走火入魔**
- 微剑把列表容量压到 4，神识只要 15，但场上 8 人时会**看漏最近的目标**

## 三、架构

```
DSL 文本 ─┐
          ├→ AST(IR，唯一真相) ─→ 静态分析器 ─→ 消耗面板
节点图 ───┘                  └→ 编译器 → 字节码 → 受限 VM → 世界
```

**AST 是唯一真相，且可 JSON 序列化**。因此：

- 现在用 DSL 验证玩法，**不浪费一行代码**
- 未来的可视化节点图只是「另一个产出同样 AST 的前端」
- AST 序列化后直接就是**秘籍分享码**

目录：

```
src/core/
  types.ts      类型系统 + 神识定价（资源模型的唯一来源）
  ast.ts        IR 定义
  meta.ts       元函数注册表与接口
  builtins.ts   基础术式库（⚠️ 这里就是整个游戏的平衡核心）
  analyzer.ts   静态分析：消耗上界、神识峰值、递归检测、类型检查
  compiler.ts   AST → 字节码
  vm.ts         受限虚拟机：fuel / 神识 / 法力 / 耗时计量
  world.ts      世界与实体
  dsl.ts        DSL 解析器（节点图的上位替代）
src/demo/        无头验证沙盒
```

## 四、语言规则（当前境界）

- 变量只有两种：**术式内变量**（作用域结束自动释放）与显式 `free`
- `for x in 列表`：最坏消耗按**列表容量**计，实际按真实长度计
- `repeat N`：N 必须是字面量，保证静态可分析
- **禁止递归**（静态分析会在创建阶段直接拒绝）
- 高阶「轮回术」解锁后：允许递归，但每次递归占一格神识（栈帧），
  深度天然被神识上限封死，并带 fuel 预算

DSL 语法示例见 `src/demo/spells.dy`。

## 五、命令

日常走这一步就够了：

```bash
npm start      # 一键体验（浏览器打开推演台）
npm run dist   # 打包成 exe（产物在 release/）
```

完整命令见 [`docs/workflow.md`](./docs/workflow.md)，常用项：

```bash
npm run verify     # 一键验证：类型 + lint + 格式 + 单测
npm run sandbox    # 无头沙盒：打印资源消耗对比表
npm run desktop    # 桌面窗口模式（Electron）
npm test           # 单元测试
npm run coverage   # 覆盖率（core 有阈值门禁）
npm run release -- patch --dry   # 预览下个版本的 CHANGELOG
```

## 六、后续路线

1. **单步推演**：逐指令执行 + 变量监视 + 消耗曲线（VM 已内置 `trace`）
2. **识海常驻变量**：跨法术共享、手动释放、持续占神识 —— 也是「功法/心法」的基础
3. **可视化节点图**（React Flow），产出同一份 AST
4. **最小战斗闭环**：可移动角色 + 弹道 + 敌人 AI
5. **境界成长 / 秘籍掉落 / 走火入魔**

技术栈说明：核心逻辑是纯 TypeScript、零 UI 依赖，可在 Node 下无头运行与测试；
渲染与外壳后加，不会反过来绑架架构。
